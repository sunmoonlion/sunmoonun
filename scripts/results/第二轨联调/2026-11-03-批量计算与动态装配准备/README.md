## 已实现的通用能力

compute原单项请求仍可用；新增同一工具的batch形式，每批1–50项、合计最多500个
输入引用。去重后一次经RunReader按原任务授权读事实；批内前项可以用batch:key引用。
每项照旧留一个c编号，实际存储将批内别名替换为真实c编号，原验收器可直接回查。
所有表达式通过后统一写入事务；任何一项失败、数据库写入失败、返回值超出MCP上限
均不留下半批计算记录。事实读取返回后再次核对任务可执行状态。

这是平台通用确定性算术；不加财务专用公式，不允许模型直接塞原始数字，不改作者
勾稽阈值、回测数量和验收规则。没有新增固定版本兼容分支，K31退役后保留本能力。
批请求实际只计一次工具调用，仍受原调用/预算/时间门约束；单批计算数由上述限额约束。

## 动态专家装配准备的实际发现

[依赖审计](dependency-audit.json)仅分析已有快照，记录文件摘要，没有冻结/接受新方法。

1. 固定准专家2.8的writeup依赖全部上游，依赖闭包为8步。仅增加planning、把forecast
   标为非必选，不会让“人均创收”问题省掉预测：其最终成稿仍强制依赖预测。
2. 20项合成方法夹具的最终交付闭包至少11步，其中包含估值链。它不能直接作为
   面向任何财务问题的精简专家，也未被作者接受为正式资产。
3. 当前运行契约把final_units全部视为必经；方法input_refs全部是必须绑定的上游。
   不能靠把必需输入删掉、空结果冒充或读隐式对话上下文，掩盖可选方法成果交付问题。

装配应先形成供作者核对的方案，沿用其已确认的分析、勾稽、管理层讨论、预测内容，
单列新增的选择条件/交付依赖。为历史指标、人均创收、预测分别列出必要方法与数据，
核对可选方法的结果怎样进入最终报告。若现有契约无法表达，必须正式演进统一输入
契约并更新生产者/消费者/冻结快照/验收回归，不能写财务演示分支。这项尚未实施，
不能用本次compute交付称正式动态财务专家已跑通。

现有部署侧动态作者名单还引用旧账号；后续需以登录主体复核zymun作者与sig-am
使用者的准确subject，分别配置测试与市场准入。不得按显示名换绑，也不改变
本人确认数据、方法接受和专家交付流程。本轮没有改该配置。
