## 二、knowlab 库备份（F05）

```bash
# 本地机。口令不落日志：从 knowlab 的数据库运行时 Secret 取 DATABASE_URL，在 postgresql-0 里 pg_dump
export KUBECONFIG=~/.kube/sunmoon-kind.config
URL=$(kubectl -n app-platform-dev get secret knowlab-database-runtime -o jsonpath='{.data.DATABASE_URL}' | base64 -d | sed 's#+asyncpg##')
mkdir -p ~/sunmoon-probe-runs/release-0042/backup && chmod 700 ~/sunmoon-probe-runs/release-0042/backup
# 在容器里要连 127.0.0.1：用服务名连自己会被网络策略挡住（2026-10-25 实测卡住）
URL=$(echo "$URL" | sed 's#@postgresql\.data-platform-dev\.svc\.cluster\.local:5432#@127.0.0.1:5432#')
kubectl -n data-platform-dev exec postgresql-0 -- pg_dump --dbname="$URL" --format=custom --no-owner </dev/null > ~/sunmoon-probe-runs/release-0042/backup/knowlab-$(date +%Y%m%d-%H%M).dump
unset URL; ls -l ~/sunmoon-probe-runs/release-0042/backup
```

要看到：dump 文件非空；`pg_restore --list` 能列出 `knowbot_draft`、`knowbot_request`。（命令里的 Secret 名与键在执行时核一次：`kubectl -n app-platform-dev get secret | grep knowlab-database`。）knowbase、knowmart、knowbench 的迁移都是只扩不缩，不单独备份；按 C-R11 回退靠重发旧钉。

## 五、回退

- knowbase、knowmart、knowbench：迁移只扩不缩，回退 = 重发旧钉（`PIN=keep` 时 sources.yaml 还是旧钉就直接再发一次，或 `git revert` 钉的提交）。
- knowlab：迁移后只要有新写入，`downgrade` 会拒绝；回退 = 第二步的备份 `pg_restore --clean` 回库 + 重发旧钉。备份之后、回退之前新写的东西会丢，回退前先告诉所有者。
- 身份 v6：Casdoor 里的改动（授权类型、12 小时、audience 应用）不回退，旧代码不受影响。
- 都不要 `prune`：集群声明是 `prune: false`，退役对象按名单精确删（C-R11）。
