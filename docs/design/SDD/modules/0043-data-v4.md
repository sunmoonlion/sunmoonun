## 二、knowbase 的数据模型

只写要有什么、有什么规矩，表名列名实现时按现有命名定。

### 2.1 资料、内容版本、读法；内容来源与取得依据

- **资料**：逻辑上的一份；挂描述、许可档、所有者、状态（正常、逻辑删、禁用）。
- **内容版本**：内容的一次替换（更正版、用户重传的修订）；一份内容（sha256、大小、内容类型、对象键）；只增不改。下文单说「版本」都指内容版本。
- **读法**：同一个内容版本的派生形态（正文、按页文字、表格、检索索引）；读法自己也有版本：加工器升级、质检标记改变都产生新的读法版本（第三轮评审 Q 六）。
- **内容来源**挂在资料与版本上：公开披露、为某用户采集、用户上传、产出转来。**取得依据**挂在用户与资料的关系上：上传、采集、购买、确认引用、订阅、产出。同一份内容，卖家是「我上传的」，买家是「买来的」；总栏按当前用户的取得依据分类。
- 上传同名同描述的新内容：用户选「作为新版本」或「另一份资料」，默认另一份。

### 2.2 使用权

- 所有者天然有；买家凭交易有，**只到交易那一个内容版本**（含这一版今后的读法）；公开原件的使用权就是第二区引用。
- 带：取得依据、适用版本、许可档、有效条件。**授权检查按本次使用的依据判断**，不只看资料当前的许可档：卖家改低许可、关店，只影响新的销售与公开用途，已成交的使用权按交易时的依据继续；内容被禁用、违规处置时才按规则收回（第三轮评审 L3-11）。买家注销即终止，内容不清除。
- 交易幂等：同一交易编号只建一条有效使用权；成交以使用权建好为准，失败可重试。
- 空间：资料算所有者的，直到最后一条别人的使用权失效；第二区引用不算空间。

### 2.3 同意依据

| 用途 | 什么意思 | 谁留下 |
| --- | --- | --- |
| `app:knowbench`、`app:knowlab` | 在这个应用的栏出现、可解析、可读 | 本人在总栏点；账号级默认（见下） |
| `market` | 交给 knowmart 待上架 | 本人在总栏点 |
| `expert:<专家>` | 绑给名下这位专家（下一版用）；交付时冻结成 `expert:<专家>@<版本>` | 本人在总栏点 |
| `platform:<应用>:<过程>` | 平台孵化、平台测试、交付审核、自助重跑 | 本人在 knowlab 选平台、交审、提交交付时 |
| `subscription:<订阅>@<修订>` | 订阅的长期范围同意：描述或网址范围、起止、用途、自动取得方式；可撤，续订出新修订 | 本人建订阅、续订时 |
| `processing:<内容版本>` | 让 knowfeed 加工这一份上传（只这一份、这个目的） | 本人上传时按页面说明采用加工 |

- 同意依据只能由用户本人留下：在 knowbase web端点，或在应用页面由应用后端凭本人令牌转交。
- 「展示给 knowbench」同时覆盖委托与会话（会话的范围宽得多），页面写明。
- **默认展示**：账号级「新数据默认展示给我的全部应用」开关默认开，只对「我上传的」「为我采集的」生效；买来的、产出转来的由用户点；用户第一次进 knowbase web端时把开关亮出来、点一下就是依据；迁移来的旧资料照原范围。
- 现有同意依据表的 `app` 列退役，含义并进用途。（第二轮写过的 `app:knowfeed` 删掉：质检不拿第三方数据对照，第三轮评审 F 2.5。）
- **逐项确认（7 天）和订阅范围同意是两种依据**；「确认不能被跳过」两种都适用。

### 2.4 公开原件层与第二区引用

- 公开原件存成 knowbase 的**资料**，所有者是保留编号 `public:disclosure`（不是用户也不是平台账号），原件版本与读法只存一份，和用户资料共用版本、读法、钉住、授权、读数留痕（10-27 改，原写「建在现有知识文档 `knowledge_document` 上」；设计见 [0047](0047-public-disclosures-facts-search.md) 第二节）。
- **第二区引用**：用户名下对某个原件的一条引用，就是一条取得依据为「引用」的使用权，**只记需求依据编号**（需求依据自己知道来自任务、订阅还是本人亲手提，0045 第 2.3 节）；状态：已确认等采、可用、采集失败、已取消、已撤回，失败、取消、撤回的也留着。（10-27 改：公开原件层对所有用户可读，受资格、权限、开关管；引用的用途是钉住与证据链，原写「没有可用的引用就读不到」，见 0047 第 2.2 节。）
- 公开原件许可档由系统定为「可以经专家给别人用」，不能当知识出售。网站审过不等于页面是法定披露：通用网页取来的按实际来源与审核规则定区和许可。

### 2.5 描述与词表

- 描述：主体（证券代码、渠道的机构编号、词表主体编号）、类型（封闭枚举）、报告期间、**披露时间**、格式；报告期间、源站披露时间、平台获取时间三个分开。
- **类型**（10-27 改为分维度，见 [0049](0049-document-types.md)；原写「词表第一版的类型：年报、半年报、一季报、三季报、临时公告、招股书、政策文件、统计数据、网页、其他表格、其他文本」）：描述分维度并列，类型（大类按发布者、细类是文献类型）、主体、期间、版本形态进键，事项、行业、语言、格式、研报属性只用来筛选；声明可写细类或大类；非定期报告的期间是披露时间窗。非上市主体的编号规则：发文机关、统计口径等用「类别前缀 + 统一社会信用代码或官方机构代码」，没有的由 knowbase 管理端登记分配。词表有版本号；声明契约引用同一份词表。
- 确认状态：入库质检过、用户确认过、自动识别未确认；只有前两种参与解析。迁移来的未确认描述，用户首次进入时引导确认。
- 描述改动留记录，不产生新的内容版本。

### 2.6 产出区

- 内容来源多一种：产出；产出区的资料不参与解析。
- **服务写入路**：应用后端（knowbench runner、knowlab）以服务身份替用户写产出，只能写进产出区：调用方应用、受益用户、任务或测试编号、运行编号，按（任务，运行编号）幂等，算进用户空间。测试证据只增不改。
- 自助测试证据的链路：用户 link →（设备令牌）knowbench 后端 →（knowbench 服务身份）knowbase 产出区；自报的不作数，靠过门时平台重跑核。
- 「转为数据」：用户在 knowbase web端点，新建一份资料（内容来源 = 产出转来，带出处），许可档默认「只许本人用」，上游受限的不得升档。

### 2.7 运行授权

| 改动 | 做法 |
| --- | --- |
| 授权项逐项记依据与所有者 | 一份授权可以有多项，每项记：钉住的输入组合（第 2.9 节）、权利依据（展示同意 / 使用权 / 冻结的绑定同意 / 第二区引用）、内容所有者；外层记过程与执行主体。knowbase 签发时逐项核，取代现在「`item.owner == grant.owner`」。一件委托可以同时读请的人的、买来的（卖家所有）、作者绑定的三种 |
| 受益人 | 专家绑定的数据：所有者是作者，受益人是请专家的人，依据是冻结的 `expert:<专家>@<版本>`；留痕两人都记 |
| 平台过程 | 依据 `platform:`；读的一方分运营（人）与机器（测试电脑），授权与留痕分开记；上限按过程配（拟：孵化 7 天、测试 14 天、交付审核 30 天）；过程结束、撤回、不受理立即撤 |
| 自助重跑 | 用户「提交交付」时同时记两种范围：机器重跑要读的冻结输入，审核员能看的清单与结果；重跑建新运行编号、申请新的机器授权，记明复核哪次自助测试；不复活旧授权，审核员不能凭机器授权看原始输入 |
| **加工**（新） | 给 knowfeed：只限一个内容版本、一个目的（上传加工依据 `processing:`；采来的原件重新加工依据原来的需求依据或公开原件层）、一段时限；只能读这一份、只能写回读法；knowbase 按「系统加工」留痕，用户在「谁读过」看得到 |
| 会话 | 每首读一份签一条小授权（一份一条，可以一次签多条），会话结束一并撤，不改「范围只能更小」；单段会话累计读到 50 份时在界面提示一次，不挡 |
| 运行中追加 | 任务在步骤边界停在「等数据」→ 用户确认 → **新签一条独立授权**覆盖新的几项（不扩大已签的）→ 清单出新修订、冻结部分不动 → 已读的不重读 → 继续；在用户 link 上跑的，表现为工具调用返回「等数据」。knowlab 固定测试集不在运行中追加 |
| 签的时机 | 解析阶段不签；开跑时签，与钉住同时完成 |
| **谁签委托**（10-27 改） | 本人签（开跑时本人在场）；**要补采而等数据的，齐了由执行的应用凭本人那次确认续签**（所有者 10-27 定「自动接着跑」，decisions ⑫）：knowbase 核确认是本人在这个应用上点的、7 天内、对得上这件任务与这张清单，签进去的只能是那一修订清单里的候选或冻结给这位专家这一版的绑定；签发人记 `confirmation:<编号>` |
| 时限 | 测试、委托 7 天，会话 24 小时，孵化 6 小时照旧 |

`RECEIVING_APPS`、`GRANT_PARTITION` 随分区一起退役，买来的落到哪由展示决定。

### 2.8 删除、撤权、清除

| 动作 | 做法 |
| --- | --- |
| 从栏里拿掉、取消展示 | 撤对应用途的同意依据：停新的解析和授权申请；已签的到期或任务结束为止。取消「绑给专家」只影响下一版，已冻结的不撤 |
| 作者删、卖家下架、卖家改低许可、关店 | 资料标逻辑删或改档：所有者栏里不显示或不再公开；只影响新的销售与公开用途（在售专家转「待处理」、知识条目下架）；买家已有的使用权、钉住的测试与专家版本照旧可读 |
| 撤回平台过程授权、订阅范围同意 | 撤同意依据并立即撤相关的全部授权；订阅不再生成新需求 |
| 禁用、违规处置 | 资料标禁用：停一切新读取，在跑的授权也撤；按处置规则收回受影响的使用权，留痕 |
| 注销、依法删除个人信息 | 真删内容，清单包括：knowbase 的原件、读法、产出区、描述字段、RAGFlow 的文档；knowfeed 的 30 天原件、作业与尝试里的内容片段、搜索与列的缓存、需求单里的说明与网址。按保留规则留编号级留痕；卖家注销买家不受影响、卖家名匿名；内容属于必须删的个人信息且已卖出的，通知、补偿买家 |

- **删除事件要写明对象与原因**（第三轮评审 L3-07）：撤某个人的关系，不删仍被别人合法引用的共享内容与索引；只有真正清除内容才删原件、读法和 RAGFlow 文档，并等所有回执。
- 现在的 `delete` 是删对象；改成逻辑删要迁移代码路径。
- 测试证据拆两半：结论、数值、判定理由留；引用的原始内容随依法清除一起清，复现不了判「证据不可复现」。

### 2.9 钉住的输入组合

运行输入引用一个不可变组合：**内容版本、读法版本、各自摘要**。清单 v2 的绑定、测试集、授权项、格子地址、数值验收都引用同一组合；读法换版本（重新加工、质检改标）不改旧组合。

## 三、按描述查与解析

### 3.1 声明契约：`knowbot-manifest/v2`

| 层 | 谁写 | 内容 |
| --- | --- | --- |
| 声明模板 | 作者在 knowlab | key、名字、说明；类型；期间规则（固定期间，或「最近 N 个完整年度 / 季度」，可加「截至任务日期已披露」）；格式；份数上下限；必填或可选；来源限制；表格类的表与列；口径；多候选时的优先策略 |
| 任务参数 | 请专家的人发起任务时 | 主体（一家或几家）；必要时覆盖期间 |
| 绑定 | 作者 | 资料加输入组合，随专家版本冻结、进版本摘要 |

- 声明结构与词表只定义一处（knowbase 管的跨应用契约），三个应用现在逐字段相同的 `DataNeed` 收成一份。
- **v1 专家的兼容分支**：在请的人有权用的云端范围里按旧声明由他明确绑定，随后照新的组合与授权检查；不自动补采，不恢复本地来源；到「财务分析与预测」第 2 版上架为止。第 1 版读 knowbase 数据集接口的那条路，兼容窗口内保留（生产上现在没有登记的数据集）。

### 3.2 按描述查与解析

- **按描述查**：只接受精确的键，只回答这一份在不在、在哪个范围里；同一用户短时间大量不同描述的查询限流。这是解析用的；给人用的网页全文搜（全市场能搜，资格、权限、开关管）见 [0047](0047-public-disclosures-facts-search.md) 第五节（10-27 改，原写「不开列表、浏览、模糊搜公开原件层的接口」）。
- **解析**：输入声明模板、任务参数、使用者、请的人；输出解析清单（全局唯一编号，存 knowbase）。每样一个结果：

| 结果 | 应用怎么办 |
| --- | --- |
| 已定（某个输入组合） | 照用 |
| 你有没放开（只对本人的数据提示） | 请他到 knowbase 放开 |
| 待确认（他名下还没有，不分是否已有别人要过） | 进确认清单 |
| 采不来（私有资料） | 告诉他去 knowbase 上传（直达链接） |
| 有歧义 | 开跑前请他选 |
| 等数据（knowbase 部分不可用、正在导入） | 不补采，任务等或报错 |
| 不能用（禁用、许可不允许这种用法） | 照实告诉他 |

- 解析时公开原件优先于上传；有偏好时偏好优先。「最新」只在声明允许时用，按「截至什么时候能拿到」算。
- 解析清单固定所用描述与词表的修订、时间口径；运行中冒出的新需求形成清单的新修订。

### 3.3 确认一次与入口分支

1. 应用先向 knowfeed 预切合待确认的那几项（只查来源目录：这类能不能取、网站待审没有、候选渠道的许可档、按队列估的预计时间，0045 第四节），满足不了的直接标出。
2. 把清单列给用户：总数、预计多久（保守地按全部要新取算）、每项的许可档；用户可以取消部分条目（可选的取消即降级，必填的取消即变更需求）。
3. 用户点一次，应用后端凭本人令牌交给 knowbase，knowbase 记一条确认：清单修订、任务、声明快照、确认的条目、**供给条件快照**（预切合结果与可接受的来源限制、用途条件）；回确认编号，7 天内有效、只对这张清单修订的条目有效。
4. **入口分支**（第三轮评审 L3-03）：
   - 本人已有合法依据、内容与读法都齐 → 已在第 3.2 节「已定」；
   - 本人还没取得、但内容与读法都齐 → knowbase 按确认建第一区关系或第二区引用，**立即完成**，不交 knowfeed；
   - 缺原件、缺读法、要刷新来源版本 → 应用把需求单交 knowfeed（带确认编号），以回执为准；knowfeed 受理前向 knowbase 核这个确认编号。
   「已有」必须满足本次的版本与时间条件；命中的需求项照实地立即就绪，看得出「这份公开披露以前有别的用户要过」，看不出是谁（所有者 10-26）。
5. **确认接口覆盖四种需求**（精确描述、给网址、订阅、按主题找勾选的候选），不要求每张需求单先有专家和声明。
6. **确认不能被跳过**：账号设置、应用默认、模型调用都不能免确认；偏好只记选哪份，不记免确认。订阅范围内每轮不再逐份确认，凭 `subscription:` 依据。

### 3.4 等数据与恢复

- 任务进「等数据」，带清单编号；进度由应用后端查 knowfeed 的需求单状态。
- **需求状态只由 knowfeed 通知**：knowfeed 交 knowbase 拿到回执后标「已就绪」或「部分就绪」，经发件箱通知提需求的应用；knowbase 只给 knowfeed 回执，把对应引用改成可用。应用重新解析，齐了就恢复；恢复时另核当前状态与清单修订，重复或乱序的通知不重复开跑。
- 供给完成的判据：原件已由 knowbase 接管、版本能定位、权限能校验、要的读法已就绪（检索索引就绪是单独一种读法状态）。
- 超时转用户看得见的失败，已定的部分留着；超时后到的数据留在用户栏里，不自动重启任务。已受理的作业不因确认过期受影响。

### 3.5 开跑前列出、可换、偏好

- 开跑前列出解析清单（每样用哪份、哪一版、为什么），默认直接跑，用户可以换，有歧义的必须选。
- 换过的记成偏好：**用户 × 使用者 × 声明契约版本 × 需求 key × 规范化的任务参数** → 资料与版本策略，存 knowbase；只是排序输入，每次仍核当前权利；词表改版、资料不可用时失效。
- knowbench「同一项目上次请这位专家用的那几份」改作偏好的来源。

### 3.6 开跑、钉住、校验

- 开跑时凭清单申请运行授权，与钉住同时完成；跨服务沿用幂等与失败交还。
- 钉住层复用 knowbench `workbench_task_data`（槽位、输入组合、摘要、授权编号、格子地址）；接口不再收本地来源，数据库仍容纳历史本地记录。
- 按声明核格式、份数、表头列、同一份不用两次（现在的 `choice_problems`）原样保留，用来核机器挑的结果；运行中追加的新项同样核。
- 必填缺了不算成功；可选缺了照做、记「不完整」；模型不能自己改声明。

### 4.3 knowmart

- **每个用户一家小店**（0018 第十一节第 7 之二小节）：首页是小店列表，**只列有在架供给或公开需求的店**，其余用户照样有店、能管自己的东西，但不进列表、搜不到（所有者 10-26 定）；小店详情页与「我的小店」是两种后端投影，不把整个「我的小店」返回给前端去藏。「我买到的」拆掉：知识在 knowbase 总栏「买来的」，请过的专家在 knowbench，订单记录留在小店「交易记录」（每行带直达链接）。
- **需求公开到小店要勾**：发需求时一个勾「公开到我的小店」，默认不勾；需求照样进需求大厅、匿名显示；卖家响应、成交时才见到店（所有者 10-26 定）。
- **小店的处置状态是持久的**：公开列表、条目发布、审核转公开、下单、请专家都核店铺当前状态；恢复店铺不自动恢复被单独下架的条目；停店不撤销历史订单的合法权益。店名默认取昵称，可改、留痕，受驻场规则禁止词约束；平台账号的店标「平台账号」；一店一主体，主体可改要重审、留变更历史，条目标当时卖的主体。
- **我的知识**没有上传；卖家在 knowbase 把资料展示给 `market`，资料进「待上架」（状态归 knowmart），填介绍、样张、价格、驻场规则后上架。
- **成交**：记订单后请 knowbase 给买家建使用权（交易那一版），不复制；`purchase-copy` 留给历史。
- **两种许可检查**：专家交付到本人自用，绑了「只许本人用」的也可以；公开供别人用，所绑每份要「可以经专家给别人用」；自用转公开时重查。知识上架要「可以出售」，公开原件与平台抽的表一律拒。knowlab 运营审核门预查，knowmart 收清单时硬查。
- 买来的继承卖家的转卖设置，不得升档；`no_resale` 限的是上架、交给 knowmart、绑给公开专家，不限下载。
- 违规下架收回买家使用权；卖家改低许可、关店、注销不影响买家已有的（第 2.2 节）；卖家注销时卖家名匿名。
- 小店与条目只按时间、类目、店名排，不做推荐、榜单、销量排序（第十一节）。

### 4.4 专家绑定数据

## 五、存储

按描述分类、按读法分表：

| 放哪 | 放什么 |
| --- | --- |
| 对象存储 | 原件，按摘要存 |
| knowbase PostgreSQL：目录与权利 | 资料、内容版本、读法、描述、词表、使用权、同意依据、引用、授权、留痕、解析清单、偏好、专家名录影子表 |
| knowbase PostgreSQL：正文 | 每个读法版本一行：标题、发布日期、正文 |
| knowbase PostgreSQL：按页文字 | 每个读法版本每页一行 |
| knowbase PostgreSQL：表格单元 | 基础地址是读法版本、表或工作表、物理行列；存原始值、值类型、解析值、来源位置（页码、坐标）、质检标记；科目标准名、报告期间、单位、口径是领域插件给的语义标注，不是所有表都有的主键（第三轮评审 L3-09） |
| RAGFlow（只由 knowbase 碰） | 检索索引（切段、向量、混合检索），扫描版与复杂版面的解析 |

**RAGFlow 的规矩**：
1. **knowbase 是真源，RAGFlow 只是派生**：一个 RAGFlow 文档对应一个读法版本（「内容版本 + RAGFlow 解析器版本」）；**索引从已固定的读法内容重建**，不重新解析原件；要重抽就是新的读法版本。
2. **只有 knowbase 碰 RAGFlow**，没有例外：检索一律经 knowbase，先核授权，只把钉住的那几版对应的文档编号交给 RAGFlow；**文档编号集合为空时不调 RAGFlow、直接回空**。扫描版、复杂版面由 knowbase 在建检索索引时交 RAGFlow 解析，**取回完整解析结果**（逐页文字、表格与坐标）存成读法；knowfeed 不碰 RAGFlow。
3. **删除写明对象**：撤某个人的关系不删共享索引；真正清除内容才删 RAGFlow 文档，拿到回执才算删完。现有客户端没有删的方法，要补。
4. **结构化的留在 PostgreSQL**。

- **数据集按「内容类型 × 解析配置」分，绝不按用户分**，由运维预建（现在数据面禁止程序建数据集）；隔离只靠文档编号限定；现在的「数据集白名单 + 单租户」校验按新划法改。契约测试：两份不同用户的资料进同一数据集，各自检索互不可见。
- **建索引是异步作业**，按回执就绪，不在入库事务里等（现有超时 300 秒）；索引作业归调度第四档，有任务等检索的提到第一档。恢复演练量一次「从读法内容重建全部索引要多久」，几天量级就把 Infinity 的卷一起备份。
- 检索限定已是现状：knowbase 现在就按 `dataset_ids + document_ids` 检索（第三轮评审 Q 一）。
- 向量模型随 RAGFlow 配置，实施时拿真实数据比过再定，比的时候把「按钉住版本限定」列入验收。

## 八、怎么验

两条端到端真跑：

1. **sig-am 自助孵化「财务分析与预测」第 2 版**：作者给主体、生成测试集、预切合、确认一次、等数据、开跑前列出、自助测试证据进产出区、提交交付、平台重跑、留痕可查、产出转为数据。
2. **knowmart**：开店、上架一份知识、另一账号从小店买、使用权可读、卖家下架或改低许可后仍可读、违规禁用后不可读。

反例：
- 不同用户的偏好不串；三个所有者的输入能在一件委托里合法共用，换成卖家另一份、作者另一版未绑定的被拒；
- 取消一条需求不取消别人的；迟到事件不复活任务；
- 原件已有但缺表能补加工、不重复下载、收到完成通知；更正版不会被旧命中吞掉；同址内容更新生成新版本、旧绑定不变；
- 自用专家能交付但不能绕过公开许可；取消「绑给专家」不坏已售版本；
- 删过的资料迁移后仍不可读；读法换版本不改变旧测试；
- 文档编号集合为空的检索回空；两个用户的资料在同一数据集里互不可见；共享版本删个人引用不影响别人检索，真正清除才删索引；
- 任意网址取不到私网地址，浏览器子请求打不到内部服务；
- 上传的资料加工完 knowfeed 不留副本；加工甲一份的授权读不到甲的另一份、乙的；
- 订阅跑过七天不要求逐份确认也不绕过范围同意，取消后不再新增；主题订阅未勾的不取；两个订阅共享来源、配额不同互不丢记录；
- 渠道回退不静默越过确认的用途条件；
- 店铺停用挡住新交易、保留已有权益；运行中追加需求新签授权、已读不重读。
