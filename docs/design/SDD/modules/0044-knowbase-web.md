# knowbase web端：我的数据总栏、展示按钮、上传（0044）

> 状态：**设计稿（2026-10-26）**，未实施。架构依据 [数据拓扑](../../../总纲/数据拓扑.md) 第三、六、七节；数据模型与接口见 [0043](0043-data-v4.md)。所有者 10-26：「knowbase的web端应该负责用户的上传，上传功能应该从knowfeed里剥离出来」「knowbench knowlab和knowmart没有上传入口，它们只有展示，在knowbase为各用户添加一个它采集和上传的所有数据的展示栏」「konwbase web端除了展示它的所有数据，还要为它的各个应用提供展示选择按钮。选择后数据直接在相应应用展示」（原话全文在提交 `149d6353` 的讨论记录第 3 条）。
>
> 单独一份 SDD，是因为它现在只有模板页（账 56、57），又是用户管数据的唯一入口；不单写会散在几份 SDD 里没人负责（评审 Q M-2）。

## 一、它是什么

- 用户管自己数据的唯一入口：上传、看、改描述、展示给哪里、绑给哪位专家、删、下载、把产出转为数据、看谁读过。
- knowbase web端是唯一直接对用户的 knowbase 端（数据拓扑第三节）。照模板的做法：浏览器 → knowbase web端服务端（会话、CSRF）→ knowbase 后端，凭用户本人令牌；前端不拿秘密。
- 登录：sunmoonai 组织，单点登录（和各应用网页端一样，会话 12 小时）。
- 现在只有模板页（首页、工具箱）；knowbench「云端知识库」页里已做的上传、列表组件可以搬过来改。

## 二、页面

### 2.1 总栏

- 只显示「我名下有的」，四类分栏：**我上传的、为我采集的、买来的、产出**。分类以后可能加，前端不写死，按后端给的分类渲染。
- 每份资料一行：名字、描述（主体、类型、期间、格式）、确认状态、来源、许可档、版本数、大小、展示到哪里（几个小标签）。
- 筛选：按分类、主体、类型、期间、展示到哪里、未确认描述。
- 批量：勾几份，一起展示 / 取消展示 / 删。
- 顶部显示空间用量（1 GB，与现在一致）。

### 2.2 一份资料的详情

- **描述**：可改；自动识别出来的标「待确认」，用户点确认后才参与解析（0043 第 2.5 节）。主体用证券代码选择（词表），类型、期间从下拉选。
- **版本**：版本列表（时间、大小、摘要前 8 位），可下载某一版；「上传新版本」。
- **展示按钮**：knowbench、knowlab 两个开关；「绑给专家」（列出我名下的专家，见第三节）；「交给 knowmart 待上架」。买来的只有 knowbench、knowlab 两个开关，没有交给 knowmart、绑给可上架专家的选项（许可继承卖家设置）。
- **许可档**：上传的显示用户声明的那一档，可以改低，改高要确认一句「我有权……」；采集来的、买来的、产出转来的由系统定，不能改。
- **谁读过**：这份资料的读数留痕（谁、凭哪种授权、哪一版、什么时候）；平台运营读的单独标出。
- **删**：逻辑删；被买家、钉住的测试或专家版本用着的，先列出来再确认（0043 第 2.8 节）。
- **下载**：本人的随时可下；买来的能下载（10-23 定「买家能下载」）。

### 2.3 上传

- 收的格式和大小照现在：PDF、Excel（xlsx、xls）、CSV、文本、Markdown，单份 50 MB。
- 选文件后先自动识别描述（文件名、首页文字、表头），让用户确认或改；不确认也能传，但标「待确认」、不参与解析。
- 许可档：默认「只许本人用」，用户可以选「可以经专家给别人用」或「可以出售」，选高档要勾「我有权」。
- 同名同描述已有一份时，问「作为新版本」还是「另一份资料」，默认另一份。
- 传完按账号默认展示（开关开着就展示给全部应用）。

### 2.4 直达上传

只在一种情况下出现：应用解析发现缺的是采不来的私有资料（0043 第 3.2 节「采不来」）。

- 应用给的链接带：来源应用、回跳地址、要的这一样的描述（预填）。
- 回跳地址只认白名单（我们自己几个应用的网页端地址）；跨应用跳转过 Origin 和 CSRF 校验（C-I6）。
- 传完，knowbase 在**自己的上传事务里**记下「展示给来源应用」（本人在 knowbase 页面上的动作就是依据），再跳回原页面；应用不能事后调接口声明这一条。

### 2.5 产出转为数据

- 在「产出」栏里对一份产出点「转为数据」：新建一份资料，从哪来 = 产出转来，自动带出处（哪位专家哪一版、哪件任务、用了哪几份数据的哪几版）。
- 许可档默认「只许本人用」；上游有受限数据的，不能选高于上游的档。
- 本地产出不在这里：要转先上传。

### 2.6 给平台的授权

- 列出我给平台的授权（knowlab 平台孵化、平台测试时留下的）：哪次过程、哪几份、到什么时候、运营读过几次（点开看留痕）。
- 每条可以撤回，撤回即停（0043 第 2.8 节）。

### 2.7 设置

- 「新数据默认展示给我的全部应用」：默认开。
- 以后的项（通知等）放这里。

## 三、名下专家从哪来

「绑给专家」要列出我名下的专家。专家在 knowlab（孵化、版本）和 knowmart（上架）里，knowbase 不管专家。做法：knowbase 后端凭本人令牌向 knowlab 读「这个用户名下的专家与准专家」（只读编号、名字、最新版本号），短时缓存。实现时也可以改成 knowlab 经发件箱推给 knowbase；二选一在实现时定，规矩是 knowbase 不存专家的业务内容。

绑定以后，knowlab 写清单 v2 时从 knowbase 读这位专家的 `expert:` 同意依据，列进绑定（0043 第 4.4 节）。页面上绑定时照实写明：「专家跑在请它的人的电脑上，绑定的原文会进入他的上下文；我们只保证没有浏览、下载入口」。

## 四、管理端

通常的管理职能（所有者 10-26：「knowfeed和knowbse的管理端就是通常的管理职能有特殊的再说」）：现有的数据集目录、数据集、入库记录照旧；加用户资料的用量、词表维护（类型枚举、词表版本）、被禁用资料的处理。
