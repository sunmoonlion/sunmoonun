## 一、两件事

| | 第一期：远程目录 | 第二期：远程机器上装本地 link |
| --- | --- | --- |
| 解决什么 | 项目的文件在另一台机器上（NAS、家里另一台电脑、服务器上的资料目录） | 命令要在那台机器上跑（用它的环境、软件、算力） |
| 怎么做 | 装有本地 link 的电脑上的本地 link 把远程机器的目录**挂载**过来；远程机器不装本地 link | 远程机器自己装本地 link：是 Windows 就装 Windows 包，是 Linux 就装 Linux 包 |

| 什么时候 | 第一期 | 第二期，未排期 |

## 二、第一期：远程目录

### 1. 新建项目选目录：三种方式

| 方式 | 做什么 |
| --- | --- |
| 本地目录 | 在装有本地 link 的电脑的工作区里新建文件夹，或选已有的文件夹（现在就有） |
| 拉取仓库 | 把 git 仓库拉进工作区（现在就有） |
| **远程目录**（新） | 选远程机器上的目录：本地 link 先把它挂上，再在里面选项目 |

### 2. 选「远程目录」的流程

1. 新建项目时选「远程目录」。
2. 看本地 link 上已经挂好的远程目录：
   - 有：列出来，选一个；
   - 没有，或要的那个不在里面：点「添加远程目录」，填协议（SMB / sshfs）、远程机器的地址（IP 或主机名）、远程路径，**本地 link 当场挂上**。
3. 挂好后直接选项目：在这个远程目录里选已有的文件夹当项目，或新建文件夹，或把仓库拉进来——和本地目录一样。
4. 登记项目，以后当普通项目用。

### 3. 关键：挂载归电脑管，不归项目管

挂载是本地 link 的设置，和白名单目录一样：本地 link 记着「挂了哪几个远程目录」（协议、地址、远程路径、挂在哪），开机自己重挂。**对项目来说，挂载目录就是那台电脑上的一个普通文件夹**，项目记录不加任何东西；远程项目 = 建在挂载目录里的本地项目。

所以：

- 新建还是已建、浏览器开在装有本地 link 的电脑上还是远程登录 link 的电脑上，都和本地项目完全一样（远程登录 link 的电脑走会合点服务流，账 165 已做）。
- 地址只出现在挂载设置里；不按 IP 认电脑，电脑照旧按设备编号认（会合点备忘第三节）。

### 4. 本地 link 要做的

| 项 | 做法 |
| --- | --- |
| 挂载的位置 | 固定的「远程目录」文件夹（在用户家目录下，名字实施时定），每个远程目录挂在它下面一个子文件夹里 |
| 两种协议 | SMB：Windows 自带，不用装东西；sshfs：Windows 上要 WinFsp 驱动和 SSHFS-Win，第一次用时引导安装 |
| 添加 / 删除 | 托盘「这台电脑上的设置」和网页都能加、删；网页上的「添加远程目录」和新建项目里的是同一个功能 |
| 开机重挂 | 本地 link 启动时把记着的远程目录重新挂上；挂不上不挡别的 |
| 连不上 | 远程机器没开（以前定的「外存储用时才开」）或地址变了：照实报「连不上 192.168.1.20」，不当成空目录；设置里能改地址，改了重挂 |
| 凭据 | 先用这台电脑现有的（SSH 钥匙、Windows 凭据管理器）；没有时才要：在装有本地 link 的电脑上填就只交给本机本地 link，在远程登录 link 的电脑上填就提醒会经云端转发、不落盘（同拉私有仓库，账 165） |
| 白名单 | 「远程目录」文件夹整个进白名单一次（第 5 小节），以后在它下面挂新的不再问；本地 link 现在会拒绝 junction、链接这类路径，要对**它自己建的**挂载点放行，别的照旧拒 |

### 5. 第一次的准备：只能在装有本地 link 的电脑前做

1. 把「远程目录」文件夹加进白名单（放宽白名单要在电脑前点允许）；
2. 第一次用 sshfs 时装 WinFsp 和 SSHFS-Win（要管理员确认）。

用户人不在那台电脑前时，第 2 步的页面照实提示「第一次要在『电脑名』前做一次准备」；做过以后在哪都能直接添加远程目录、建远程项目。

### 6. 网页要做的

- 新建项目对话框加第三种「远程目录」，按第 2 小节的流程。
- 设置「电脑与沙箱」里列出挂了哪些远程目录：地址、远程路径、连没连着；能添加、删除、改地址。
- 远程目录连不上时，项目页和文件树照实写原因。

### 7. 不做

- 项目上不记文件在哪、不记远程地址。
- 换了装有本地 link 的电脑时，不把远程目录自动搬过去：新电脑上重新添加一次；旧电脑上建的项目，和本地项目一样提示「在旧电脑上」（重新颁发令牌回旧电脑、拷文件后搬家、归档三条路，另记）。
- 不按 IP 认电脑。

### 8. 实施前要先核、先实测的

| 项 | 怎么核 |
| --- | --- |
| SMB 盘、SSHFS-Win 盘在 Codex 的 Windows 内沙箱里能不能读写（受限身份可能看不到按登录会话挂的盘） | 在所有者的 Windows 或虚拟机上挂一个共享目录实测；要先问所有者 |
| 本地 link 的路径检查（真实路径、junction、链接）对挂载点的处理 | 读 `pathuri.ts`、`service.ts`、`localFiles.ts`、`localProjects.ts`，再实测 |
| 挂在文件夹下还是挂成盘符（WinFsp 能挂到文件夹；SMB 要用 `\\机器\共享` 或映射盘） | 实测后定 |
| 慢 | 局域网与经公网各测一次 Codex 跑一轮的耗时，写进说明 |
| WinFsp、SSHFS-Win 的许可与安装方式（能不能随安装包带、还是引导用户装） | 查许可后定 |

## 三、第二期：远程机器上装本地 link

- **按远程机器的系统选安装包和安装方式**：
  - Windows：现有的 Windows 包，浏览器确认页颁发令牌；
  - Linux：现有的 Linux 包只给集群里的测试电脑用，交给用户前要补安装脚本、systemd 开机自启、bwrap 外沙箱、网页下载；没有浏览器时的颁发令牌（启动时显示确认码）已有。
- **必须改「一个账号同时只配给一份本地 link」**（旧账 63「多台电脑同时在线」）：每份本地 link 各一份令牌、按设备编号区分；会合点按设备而不是按账号接沙箱和本地 link；委托时按项目所在的电脑（`environment_id`）把 Codex 指过去；浏览器在哪的判断改成拿编号甲和**这个项目所在电脑**的编号比；设置页列出多台电脑。
- **和第一期的关系**：建在远程目录里的项目，以后可以「升级」——在远程机器上装好本地 link，项目改登记到它，命令就直接在远程跑。
