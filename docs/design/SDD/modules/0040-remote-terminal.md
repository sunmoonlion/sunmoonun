## 一、要解决什么，不做什么

**要解决**：用户不在装了本地 link 的那台电脑前（在外面用手机、在公司用别的电脑），要在那台电脑上敲命令。

**不做**：

| 不做的 | 为什么 |
| --- | --- |
| 本机终端：坐在电脑前，在网页里开本机终端 | 等于网页里嵌一个 PowerShell，用户自己开就行；为这点方便担云端代码驱动本机 shell 的风险不划算。10-23 撤掉了右边栏的「终端」占位栏 |
| 沙箱终端：打开云端沙箱的 shell | 沙箱里没有项目文件，Codex 真正干活在用户电脑上；开 shell 等于让用户在我们的集群里随意执行代码，用户的模型 key 也在沙箱进程的环境里 |

用户坐在电脑前时远程终端照样能用（走的还是云端），但不为这种情况专门优化。

## 二、链路

```
别处设备的浏览器 ──HTTPS──▶ knowbench 工作台：核本人、核设备，发终端票
        │
        └──WSS──▶ 会合点 /terminal ◀══ 本地 link 控制通道（出站）── 伪终端 ── shell（在用户电脑上）
              内容端到端加密：会合点、工作台只转发看不懂的字节
```

- **会合点新开一种通道** `/terminal`，和 Codex 的 `/sandbox`、服务流 `/service` 分开；本地 link 控制通道 hello 的 capabilities 里带 `terminal-v1` 才配。每个用户同一时间只配 1 条。
- **本地 link** 收到 `open`（kind=terminal）后，在当前项目目录起一个 shell：Windows 用 ConPTY 起 PowerShell，Linux 用 pty 起用户默认 shell。
- **身份**：本地 link 进程的用户。是不是套 Codex 同样的沙箱，见第八节第 6 条。

## 三、安全：用户不在电脑前，没法在电脑上点确认

要挡的两种人：**云端（工作台或会合点）被攻破的人**，想借远程终端进所有用户的电脑；**偷到某个用户登录的人**，想进他的电脑。

| 关 | 做法 | 挡住谁 |
| --- | --- | --- |
| 1. 电脑上的总开关 | 默认关。只能在托盘「这台电脑上的设置」里勾「允许远程终端」；不进服务流能改的设置项，网页、云端都改不了 | 没开的电脑，云端被攻破也连不进来 |
| 2. 登记设备 | 勾选时托盘显示登记码（二维码 + 短码）。用户在要用的那台设备上打开工作台，输入或扫码；浏览器生成一对密钥（私钥不可导出，只存在这个浏览器里），公钥随登记码直接交给本地 link 记下，不经云端转手。以后只有登记过的设备能开终端；托盘里能看、能删已登记的设备 | 只偷到账号登录的人；云端伪造的设备 |
| 3. 打开时再验本人 | 打开终端前重新登录或输入动态码；工作台只在刚验过时发 10 分钟的终端票 | 只偷到登录状态（cookie）的人 |
| 4. 端到端加密 | 浏览器和本地 link 用登记时交换的公钥协商会话密钥；会合点、工作台只转发密文 | 云端看内容、云端做中间人 |
| 5. 电脑上有痕迹、能叫停 | 有人连着时托盘图标变样，菜单显示「远程终端正在使用（设备名）」和「断开」；完整的输入输出记在电脑本地，不上云，托盘里能看 | 事后可查、当场可断 |
| 6. 限制 | 同一时间只开一个；闲置超时断开；单次有最长时间；断线不自动接回，要重新打开 | 忘了关、被挂着 |

**剩下的风险照实写**：设备的私钥在浏览器里，而网页代码是从云端下载的。云端被攻破时，攻击者可以给已登记的设备送恶意网页代码，在用户打开页面时借这把私钥开终端。能挡的只有关 3（要用户当场验本人）和关 5（电脑上有痕迹、能断）。要彻底挡住，得换成不从云端下载代码的客户端（比如单独装一个小程序），第一版不做。

## 四、流程

1. **开启**（在电脑前做一次）：托盘「这台电脑上的设置」勾「允许远程终端」→ 显示登记码 → 在要用的设备上打开工作台「设置 → 电脑、link、沙箱与令牌 → 远程终端 → 登记这台设备」，输入或扫码 → 托盘列出新登记的设备。
2. **打开**（在别处）：工作台右边栏「终端」→ 重新验本人 → 工作台核三件事：这台设备登记过、那台电脑允许远程终端、它的本地 link 连着 → 发终端票 → 浏览器连会合点 `/terminal`，用登记的密钥和本地 link 握手 → 本地 link 起 shell。
3. **使用**：按键和窗口大小经加密流送到电脑，输出送回；电脑本地记日志。
4. **结束**：用户关掉、闲置超时、到最长时间、托盘点「断开」、本地 link 退出，任何一个发生就结束；本地 link 收掉 shell 及其全部子进程。

## 五、各部分要改什么

| 部分 | 改什么 |
| --- | --- |
| sunmoon-link | 伪终端（Windows ConPTY 要原生模块，安装包与打包重新验证；安装包没签名，杀毒软件可能更敏感，要实测）；终端通道与加密；设备登记与删除；本地日志；托盘「允许远程终端」勾选、「正在使用 / 断开」 |
| 会合点 | 新路径 `/terminal` 与新角色；按用户限 1 条；只转发密文 |
| knowbench 后端 | 终端票：新的令牌用途，10 分钟，带设备标识和「刚验过本人」的证明；后端只记哪台设备登记过、用来显示，不作为信任依据（信任依据在本地 link 记的公钥） |
| knowbench 网页 | 右边栏「终端」栏（终端模拟组件）；设置里「远程终端」：登记这台设备、看已登记的设备 |
| Casdoor | 动态码（多因素认证）开通；重新登录的参数。支持情况实施前核 |

## 六、和已有原则的关系

- **服务流只看文件、改设置，不下发任务**（2026-10-12，0022）：远程终端另开一条通道，服务流本身的规矩不变。
- **代理不执行用户指定的进程**（账 83 原文）：远程终端是唯一的例外，靠第三节的六道关和用户本人在电脑上打开总开关来成立。
- **用户文件一个字节不出电脑**（2026-10-12）：终端的输入输出要经过云端，但端到端加密，云端看不懂；本地日志不上云。
- **会合点只转发不解析**（D17）：不变，终端流对会合点就是密文。

## 七、测试与验收

- 没勾总开关：连不进来；勾了、设备没登记：拒；登记后在托盘删掉：拒。
- 没重新验本人：拿不到票；票过期：拒。
- 在会合点抓包只看到密文；换一把公钥（模拟云端做中间人）：握手失败。
- 托盘显示正在使用，点「断开」立即断；闲置、最长时间到点断；本地 link 退出时 shell 及子进程都收掉。
- Windows：ConPTY 下中文、颜色、窗口改大小、Ctrl+C 正常；安装包在干净的 Windows 上装得上、用得了。

## 八、待定（要所有者定）

1. 重新验本人用什么：重新输密码，还是动态码；动态码要不要强制。
2. 登记设备这一关要不要。建议要：多一步「在电脑前登记」，换来云端被攻破时也进不来；不要就只剩关 1、3、5。
3. 闲置超时与单次最长时间的数值。
4. 本地日志存多久，记不记输出（输出可能很大、可能含敏感内容）。
5. 第一版是不是只做 Windows（用户的电脑都是 Windows），集群里的 Linux 测试电脑不开。
6. 终端要不要套 Codex 同样的沙箱（只在白名单内可写）：套了更安全，云端被攻破时损失有限；但用户开远程终端，常常就是要做白名单外的事。
