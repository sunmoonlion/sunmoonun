## 一、两台电脑

远程终端里有两台电脑，本页只用下面两个叫法：

| 叫法 | 是什么 | 上面有什么 | 在远程终端里的角色 |
| --- | --- | --- | --- |
| **装有本地 link 的电脑** | 用户自己的电脑，装着本地 link，本地 link 配给了这个账号（会合点备忘第三节） | 本地 link 和托盘、项目文件 | **被登录的那台**：命令在这台上执行，文件在这台上读写 |
| **远程登录 link 的电脑** | 用户人在别处时手边的另一台电脑（手机、平板也算，有浏览器就行），不用装本地 link | 浏览器、登录了同一个账号的工作台 | **敲命令的那台**：只显示终端、送按键，不存文件、不执行命令 |

- 同一台电脑不会同时是这两种：坐在装有本地 link 的电脑前，直接开它自己的 PowerShell 就行，不走远程终端（第二节）。
- 远程登录 link 的电脑要先「登记」过（第四节第 2 道关），没登记的电脑开不了远程终端。
- 一个账号同时只有一台装有本地 link 的电脑（会合点备忘第三节「配给」）；远程登录 link 的电脑可以登记好几台，但同一时间只开一个远程终端。

## 二、要解决什么，不做什么

**要解决**：用户不在装有本地 link 的电脑前（在外面用手机、在公司用别的电脑），要在那台电脑上敲命令。他手边的就是远程登录 link 的电脑。

**不做**：

| 不做的 | 为什么 |
| --- | --- |
| 本机终端：坐在装有本地 link 的电脑前，在网页里开它自己的终端 | 等于网页里嵌一个 PowerShell，用户自己开就行；为这点方便担云端代码驱动本机 shell 的风险不划算。10-23 撤掉了右边栏的「终端」占位栏 |
| 沙箱终端：打开云端沙箱的 shell | 沙箱里没有项目文件，Codex 真正干活在装有本地 link 的电脑上；开 shell 等于让用户在我们的集群里随意执行代码，用户的模型 key 也在沙箱进程的环境里 |

## 三、链路

```
远程登录 link 的电脑（浏览器）
   │  ① HTTPS：工作台核本人、核这台电脑登记过，发终端票
   │
   └─ ② WSS ──▶ 会合点 /terminal ◀══ 本地 link 控制通道（出站，一直连着）══ 装有本地 link 的电脑
                                                                          └─ 伪终端 ── shell
        两台电脑之间的内容端到端加密：会合点、工作台只转发看不懂的字节
```

- **会合点新开一种通道** `/terminal`，和 Codex 的 `/sandbox`、服务流 `/service` 分开；装有本地 link 的电脑上，本地 link 控制通道的 hello 里带 `terminal-v1` 才配。每个账号同一时间只配 1 条。
- **装有本地 link 的电脑**上，本地 link 收到 `open`（kind=terminal）后，在当前项目目录起一个 shell：Windows 用 ConPTY 起 PowerShell，Linux 用 pty 起用户默认 shell。
- **远程登录 link 的电脑**上只有网页里的终端窗口：显示输出、把按键和窗口大小送过去，不落任何文件。
- **身份**：shell 以装有本地 link 的电脑上本地 link 进程的用户运行。是不是套 Codex 同样的沙箱，见第九节第 6 条。

## 四、安全：人不在装有本地 link 的电脑前，没法在那台电脑上点确认

要挡的两种人：**云端（工作台或会合点）被攻破的人**，想借远程终端进所有用户的电脑；**偷到某个用户登录的人**，想在他自己的电脑上进那个用户的电脑。

| 关 | 做法 | 在哪台电脑上做 | 挡住谁 |
| --- | --- | --- | --- |
| 1. 总开关 | 默认关。只能在托盘「这台电脑上的设置」里勾「允许远程终端」；不进服务流能改的设置项，网页、云端都改不了 | 装有本地 link 的电脑 | 没开的电脑，云端被攻破也连不进来 |
| 2. 登记远程登录 link 的电脑 | 勾选总开关时，托盘显示登记码（二维码 + 短码）。用户在要用的那台电脑上打开工作台，输入或扫码；那台电脑的浏览器生成一对密钥（私钥不可导出，只存在这个浏览器里），公钥随登记码直接交给本地 link 记下，不经云端转手。以后只有登记过的远程登录 link 的电脑能开终端；托盘里能看、能删已登记的电脑 | 两台都在：在装有本地 link 的电脑前，用远程登录 link 的电脑扫码 | 只偷到账号登录的人；云端伪造的电脑 |
| 3. 打开时再验本人 | 打开终端前重新登录或输入动态码；工作台只在刚验过时发 10 分钟的终端票 | 远程登录 link 的电脑 | 只偷到登录状态（cookie）的人 |
| 4. 端到端加密 | 两台电脑用登记时交换的公钥协商会话密钥；会合点、工作台只转发密文 | 两台之间 | 云端看内容、云端做中间人 |
| 5. 有痕迹、能叫停 | 有人连着时托盘图标变样，菜单显示「远程终端正在使用（哪台远程登录 link 的电脑）」和「断开」；完整的输入输出记在装有本地 link 的电脑上，不上云，托盘里能看 | 装有本地 link 的电脑 | 事后可查、当场可断 |
| 6. 限制 | 同一时间只开一个；闲置超时断开；单次有最长时间；断线不自动接回，要重新打开 | 两台之间 | 忘了关、被挂着 |

**剩下的风险照实写**：远程登录 link 的电脑上的私钥存在浏览器里，而网页代码是从云端下载的。云端被攻破时，攻击者可以给已登记的远程登录 link 的电脑送恶意网页代码，在用户打开页面时借这把私钥开终端。能挡的只有关 3（要用户当场验本人）和关 5（装有本地 link 的电脑上有痕迹、能断）。要彻底挡住，得在远程登录 link 的电脑上换成不从云端下载代码的客户端（比如单独装一个小程序），第一版不做。

## 五、流程

1. **准备（一次，人在装有本地 link 的电脑前，手里拿着远程登录 link 的电脑）**：
   1. 在装有本地 link 的电脑上，托盘「这台电脑上的设置」勾「允许远程终端」，托盘显示登记码；
   2. 在远程登录 link 的电脑上打开工作台「设置 → 电脑、link、沙箱与令牌 → 远程终端 → 登记这台电脑」，输入或扫码；
   3. 装有本地 link 的电脑的托盘里列出这台新登记的远程登录 link 的电脑。
2. **打开（人在别处，用远程登录 link 的电脑）**：工作台右边栏「终端」→ 重新验本人 → 工作台核三件事：这台远程登录 link 的电脑登记过、装有本地 link 的电脑允许远程终端、它的本地 link 连着 → 发终端票 → 浏览器连会合点 `/terminal`，用登记的密钥和本地 link 握手 → 装有本地 link 的电脑上起 shell。
3. **使用**：远程登录 link 的电脑把按键和窗口大小经加密流送过去，装有本地 link 的电脑执行并把输出送回，同时在本地记日志。
4. **结束**：用户在远程登录 link 的电脑上关掉、闲置超时、到最长时间、在装有本地 link 的电脑的托盘点「断开」、本地 link 退出，任何一个发生就结束；本地 link 收掉 shell 及其全部子进程。

## 六、各部分要改什么

| 部分 | 在哪台电脑上起作用 | 改什么 |
| --- | --- | --- |
| sunmoon-link（本地 link） | 装有本地 link 的电脑 | 伪终端（Windows ConPTY 要原生模块，安装包与打包重新验证；安装包没签名，杀毒软件可能更敏感，要实测）；终端通道与加密；登记、删除远程登录 link 的电脑；本地日志；托盘「允许远程终端」勾选、「正在使用 / 断开」 |
| knowbench 网页 | 远程登录 link 的电脑 | 右边栏「终端」栏（终端模拟组件）；设置里「远程终端」：登记这台电脑、看已登记的电脑；密钥生成与存放（浏览器里，不可导出） |
| 会合点 | 云端 | 新路径 `/terminal` 与新角色；按账号限 1 条；只转发密文 |
| knowbench 后端 | 云端 | 终端票：新的令牌用途，10 分钟，带远程登录 link 的电脑的标识和「刚验过本人」的证明；后端只记哪几台远程登录 link 的电脑登记过、用来显示，不作为信任依据（信任依据是装有本地 link 的电脑上本地 link 记的公钥） |
| Casdoor | 云端 | 动态码（多因素认证）开通；重新登录的参数。支持情况实施前核 |

## 七、和已有原则的关系

- **服务流只看文件、改设置，不下发任务**（2026-10-12，0022）：远程终端另开一条通道，服务流本身的规矩不变。
- **代理不执行用户指定的进程**（账 83 原文）：远程终端是唯一的例外，靠第四节的六道关和用户本人在装有本地 link 的电脑上打开总开关来成立。
- **用户文件一个字节不出电脑**（2026-10-12）：终端的输入输出要从装有本地 link 的电脑送到远程登录 link 的电脑，途经云端，但端到端加密，云端看不懂；本地日志只在装有本地 link 的电脑上，不上云。
- **会合点只转发不解析**（D17）：不变，终端流对会合点就是密文。

## 八、测试与验收

- 装有本地 link 的电脑没勾总开关：连不进来；勾了、远程登录 link 的电脑没登记：拒；登记后在托盘删掉：拒。
- 远程登录 link 的电脑上没重新验本人：拿不到票；票过期：拒。
- 在会合点抓包只看到密文；换一把公钥（模拟云端做中间人）：握手失败。
- 装有本地 link 的电脑的托盘显示正在使用，点「断开」立即断；闲置、最长时间到点断；本地 link 退出时 shell 及子进程都收掉。
- 装有本地 link 的电脑是 Windows 时：ConPTY 下中文、颜色、窗口改大小、Ctrl+C 正常；安装包在干净的 Windows 上装得上、用得了。
- 远程登录 link 的电脑用手机浏览器时：能打字、能复制、窗口改大小正常。

## 九、待定（要所有者定）

1. 远程登录 link 的电脑上重新验本人用什么：重新输密码，还是动态码；动态码要不要强制。
2. 登记远程登录 link 的电脑这一关要不要。建议要：多一步「在装有本地 link 的电脑前扫码登记」，换来云端被攻破时也进不来；不要就只剩关 1、3、5。
3. 闲置超时与单次最长时间的数值。
4. 装有本地 link 的电脑上的日志存多久，记不记输出（输出可能很大、可能含敏感内容）。
5. 第一版是不是只支持装有本地 link 的电脑是 Windows（用户的电脑都是 Windows），集群里的 Linux 测试电脑不开。
6. 终端要不要套 Codex 同样的沙箱（只在白名单内可写）：套了更安全，云端被攻破时损失有限；但用户开远程终端，常常就是要在装有本地 link 的电脑上做白名单外的事。
