# 本机工位对齐

配置目标工位，命令指定基准。将目标工位的已提交代码快进到基准工位，保留目标自己的分支名。

## 用法

在本目录执行：

```bash
./align.sh qwen --check   # 先核对全部目标并显示计划，不移动分支
./align.sh qwen           # 以本机 qwen 为基准，执行对齐
```

也可以从任意目录使用入口的完整路径。比如在 kimi 工位执行：

```bash
./sunmoonun/docs/sync-cowork/align/align.sh qwen
```

**参数是基准工位，不是目标工位。** 从 kimi 的脚本启动也可以采用 qwen 的版本。基准取本机已提交的 HEAD，不自动拉取 Git 远端；需要远端最新代码时，先在基准工位执行 `sync.sh pull`。

## 配置

同目录 `config.sh`：

```bash
ALIGN_WORKSPACES=(cursor fable kimi luna qwen agy)
ALIGN_REPOS=("${REPOS[@]}")
```

- `ALIGN_WORKSPACES` 是要对齐的目标工位。执行时会跳过基准自身，以及本机不存在的工位，并逐项打印。本机存在的工位缺少仓库时会停止，不会默默漏仓。
- `ALIGN_REPOS` 默认沿用 `../sync/config.sh` 的全部顶层仓；每个父仓包含其递归子仓。可改为 `ALIGN_REPOS=(sunmoonun knowbench-app)` 缩小仓范围；这里不接受单独子仓路径。
- 工位路径为当前机器的 `~/worktrees/<工位>`，主目录为 `~/master`，由入口所在目录推导，不写死用户名或 SSH 地址。工位名须与分支名一致。
- master 的业务历史可能独立，默认不作为目标。确需整仓对齐才把 `master` 加进目标清单；也可以用 `./align.sh master` 指定它作为基准。不会只复制工具后宣称业务已对齐。
- 远程只有 fable、qwen、agy 时，同一份配置会明确跳过不存在的其它工位。

修改配置后先提交，再对齐包含 sunmoonun 的范围。对齐会采用基准仓的整份内容，因此目标自己的配置差异也必须先合入基准。

## 检查与执行

1. 锁住参与的工位，与 `sync.sh` 使用同一把工位锁，避免同时同步。
2. 核对基准和全部目标：工作区干净、分支正确、子模块齐全、基准子仓与父仓已提交指针一致。
3. 从本机基准读取 Git 对象，核对每个目标的 HEAD 和已有同名分支都是基准提交的祖先。目标领先或分叉则整轮停止，先由开发者把需要保留的提交合进基准，再重跑。
4. 全部检查通过后，逐仓快进。子仓采用基准父仓钉住的版本，仍挂回目标工位的同名分支；最终核对提交和工作区。

不联网、不访问开发机 SSH、不创建工位、不自动提交、不推送、不强推、不执行硬重置。`--check` 不改分支或工作文件，但为了核对祖先可能更新本机 Git 对象库和 `FETCH_HEAD`。

运行期间请暂停这些工位上的开发写入。跨仓操作不能成为一个 Git 原子事务：预检查发现问题时不会移动任何分支；执行途中遇到磁盘或并发写入错误时，会列出已处理的仓并停止，不自动回滚。保留现场，解决问题后重跑；已一致的仓可以再次执行。

## 对齐后如何交回

对齐只更新本机。默认仍由助手验证、提交、汇报，由所有者在需要交回的各工位执行 `sync.sh push`；另一端再执行 `sync.sh pull`。对齐命令不会替你推送所有分支，也不授权部署或付费测试。
