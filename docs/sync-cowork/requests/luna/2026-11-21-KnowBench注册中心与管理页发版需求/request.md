## 目标环境验收

1. 用测试账号进入「设置 → 注册中心」。确认默认页列出正式工具方法及没有安装 ID 的组合专家，脚本和指令叶子分别标示隔离脚本环境与独立模型轮次。核对安装修订、同源正式版本、依赖及最近记录。用第二个账号请求第一个账号的安装和方法，核验访问被拒。确认记录只展示摘要。
2. 用合成连接验证同一安装的原生操作和两个正式方法分别解析，批准与调用 ID 独立。撤回一个正式版本后，另外两个入口按各自资格使用。停用底层安装后再次核验旧修订。使用测试数据和测试对端。
3. 用获准的测试 Link 和临时项目请求具体读写范围，核对审批卡、允许本轮、拒绝、超出目录及换轮后的回执。检查托管连接调用与原生工作操作各自的记录。目标环境缺少专用测试设备时，把设备联验标为待验。
4. 记录 API、runner、Web 运行修订、镜像摘要、测试范围和未验项。异常时先回退 Web，再把 API 和 runner 同组回退到上一已验收版本，保留原调用、审批记录及独立来源版本表。应用回退时保留新表及用户正文。

Luna 本地交付验证包括 PostgreSQL 注册中心末轮 24 项、Web 507 项通过与 2 项既有跳过、Chromium 管理页 1 项。开发集群临时命名空间另跑 3 项脚本真实容器回归，全部通过，测试命名空间已回收。

增加目标验收：用空测试账号在「脚本和指令」直接上传合成脚本、粘贴指令正文，各登记 v1。修订后读取旧版并核对摘要，换账号应不可见。该验收无需 Skill、KnowLab 草稿或真实外发。

场景验收用同一份方法和两个账号。在作者编辑器核对直接登记来源及正式方法；取得适用市场资格前后检查「即时编排候选」，撤权后重查；在固定步骤核对方法 ID、版本及摘要，新增同名方法后原步骤仍锁原版。各项分别记录登记、资格与实际派发结果。即时自组执行另列后续任务。KnowBench 关联回归的一项公开纯指令交付用例在本轮之前已失败，当前登记仅允许有私有单轮执行证据的指令版本。
