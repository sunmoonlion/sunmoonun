1. 在独立 PostgreSQL 测试库运行 KnowBench 后端 `app/tests/test_connection_oauth_db.py` 和 `app/tests/test_capability_routes_db.py`。测试库名以 `_tests` 结尾，通过 `AGENT_TEST_DATABASE_URL` 配置。核对一次性 PKCE、发起人及签发方、过期和取消回调、跨账号续授权、旧修订及公开回执的字段。对照托管连接原有手填 bearer 流程。
2. 在两个独立数据库会话竞争刷新，检查一次刷新、同一结果、原授权修订保留。覆盖断开早于刷新返回、外部拒绝或撤销未确认、轮换进程中止以及稳定账号或 scope 改变。查调用账核对旧批准不能转移到另一账号。复跑 `app/tests/test_capability_mcp.py`，核对派发后认证失败保留未知结果且不会重发。
3. 从会话工具准备、真实动作批准到适配器分别走 MCP 和 A2A。A2A 的 `GetTask` 只返回目标 ID 和状态。HTTPS 回环用例实测证书、SNI、表单参数、账号接口、令牌刷新、任务查询和撤销。数据库用例另覆盖实际密钥轮换与移除旧钥后的读取。
4. 核对方法目录的必需连接、条件连接及缺少候选时的提示。检查网页消费者锁、设置组件和 Chromium 跳转。网页 `app` 下运行 `pnpm check`，再运行 `pnpm exec playwright test -g 'selected account revision'`。浏览器测试使用配对身份和合成服务地址，可按 Playwright 配置指定专用端口。
5. 真实供应商联调尚待专用服务、应用注册、已登记回调和账号。请分别记录供应商、实际允许的 scope、刷新与撤销能力、账号标识和失败语义。运行凭据不写入回执。
