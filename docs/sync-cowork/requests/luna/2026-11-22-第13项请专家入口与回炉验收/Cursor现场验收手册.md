# Cursor 现场验收手册

Cursor 在本卡完成发布、技术验收和回执。先跑一笔有确定答案的 Kimi 调用，再拿本轮产物验复核、交付与回炉。三道业务盲测可以在独立项目准备。zymun 负责判断实际财务交付是否可接受，Luna 收回本卡核对证据。

首轮 L105 失败的运行与账目见[原始回执](replies/cursor.md)。下一次点击前，先完成[控制面路由复验](request.md#callbacks)，两项探针都应返回 401。空目录受理、刷新和未匹配结案可先在独立项目验，分别记录委托、回执和零调用。

新版部署后，方法撤回可独立验收，无需等待 Kimi 试跑。按[三个撤回入口和 Q01–Q04 来源清单](request.md#withdrawal)逐项核对，把现场结果追加到本卡回执。

## 第一个通过条件：让 Kimi 原样返回 L105

1. 核对部署候选及访问入口。在 sunmoon-kind 的 KnowLab 和 KnowBench 分别通过正常 Casdoor 会话确认登录名为 `sig-am`。现场共享入口使用 `knowlab.dev.sunmoonai.com:30443` 和 `knowbench.dev.sunmoonai.com:30443`。若发版使用隔离入口，用该入口的可信 TLS 和账号登录；记录实际入口。曾在本地遇到默认 DNS 指向另一套环境，查不到私有申请时先核对站点、集群和身份。登录若需本人操作，请用户在窗口完成。
2. 从 [原私有申请的正式方法页](https://knowlab.dev.sunmoonai.com:30443/zh-CN/names/5c4fa327-e511-40a5-9ead-e8597cdc7ef2/formal-method) 打开“Luna105 标记回执”。绑定应为 KnowBench 方法技能管理中心里的“Luna #105 私有标记”，指令 v1，来源编号 `b0a48ce7-546e-42e4-981a-3676fbbf29c5`。该申请和下方备份均使用合成标记。
3. 在“实际执行验证”填下表，选 `sig-am` 当前在线的电脑和其已授权测试目录。上次在线电脑显示为 `zymun`，这是设备名。使用 sig-am 已配置的 Kimi 和本次有效报价，预算覆盖一次请求，上次填的 1 元只属于上次试跑。
4. 点一次“开始实际验证”。记下申请、工作稿修订、方法、运行编号和开始时间。等待终态后核对输出、断言、实际模型与用量，再刷新原运行，确认仍是同一笔。通过条件为实际运行成功、`/receipt` 等于 `L105`、供应商用量和平台账可关联。记录预留与实耗各是多少。此时才有该版本的执行依据，可以继续验仅自用冻结或图内交付。

| 表单项 | 填入值 |
| --- | --- |
| 调用方、预期结果 | 宿主发起，执行成功 |
| 输入值（JSON 对象） | `{"marker":"L105"}` |
| 结果断言（JSON 数组） | `[{"kind":"equals","pointer":"/receipt","value":"L105"}]` |
| 重复次数、至少通过次数 | 各 1 |

**隔离环境里没有这份申请时，由 Cursor 在该环境补建。** 用 KnowBench「设置 → 方法技能管理中心」登记本人指令，名称用“Luna #105 私有标记”，内容原样用下行，不加引号或末尾换行。内容的 SHA-256 应为 `9b242b8923ac2a65631613a02d18de2c3dd72190f7328eef09b8c71cc7615de4`。

```text

```

在 KnowLab 新建“自己来”的私有申请，给它独立的测试名称和合成标记用例。进入“正式方法定义与验证”，从“导入方法定义文件”选择 [L105-方法定义.json](L105-方法定义.json)，在“选择已有实现来源”重新选该环境中刚登记的指令版本，选“宿主程序”，保存定义。刷新并核对来源编号、版本和摘要，再跑上表。新环境会分配自己的来源和申请编号，把实际编号写进回执。

## 上次为什么停在 502

| 现场现象 | 下一步 |
| --- | --- |
| 编辑器没有来源、返回 404 | 核对当前站点和登录账号，在本人方法技能管理中心查 v1，再到 KnowLab 重开。隔离库为空时按上节重建正例。缺依赖负例的 404 是预期行为。 |
| “提交验证”返回 pending，或不能冻结 | 读取缺项；从“实际执行验证”运行并核对回执。另一个 [负例草图](https://knowlab.dev.sunmoonai.com:30443/zh-CN/names/60b41ccb-da13-4e15-8328-8fc0f2b84d93/formal-method) 的第 3 版刻意缺隔离和已登记依赖，用于验阻断，保留它的原始角色。 |
| KnowLab 返回 502 `capability_unavailable` | 按时间、请求编号追到 KnowBench 接收接口，读取实际状态和原因。#105 当时内部为 409，指令路由数为 0。核对新 API **和 runner** 已装载 Kimi 路由、规范地址、有效价目、供给器及签名配置。部署问题由 Cursor 修复并复验。 |
| 超时、刷新时显示未知，或未见用量 | 在原运行查看 Attempt、线程、网关回执和账本。先核对是否已发出，再决定恢复或重试；已提交的请求按原编号对账。若确定根本未建运行，修好前置条件后再开一笔。报告中标出旧、新运行和各自费用。 |

本地及集群隔离复验可从以下已有程序着手。选择与待验版本对应的源码和镜像，从并列仓的工作区根目录运行。将 `AGENT_TEST_DATABASE_URL` 和 `DELIVERY_TEST_DATABASE_URL` 分别指向本地回环的两个专用 `*_tests` 库。

```sh
knowlab-app/knowlab-backend/app/.venv/bin/python sunmoonun/scripts/local-integration/instruction_author.py --registered-instruction
python3 sunmoonun/scripts/local-integration/formal_market_delivery.py --expert
```

第一个程序使用合成指令服务跑作者到登记；第二个跑两家真实后端、测试买方与两次批准。跨节点网关和工作目录隔离按[集群验收脚本](../../../../../scripts/local-integration/instruction_cluster.py)指定测试 context、发布沙箱镜像和两个 worker。[上次逐条用例表](../../../archive/luna/2026-11-22-作者草图和普通专家委托合并发版/replies/luna-测试结果.json)可用于选取本次改动涉及的数据库与实体容器用例。使用发布镜像、同源本机镜像或合成接收端时分别注明。

## 三道业务盲测

[首轮输入清单](../../../../../scripts/results/第二轨联调/2026-11-22-即时自组盲测/首轮输入.json)列出三条原题及五份 PDF 的摘要。[验收约定](../../../../../scripts/results/第二轨联调/2026-11-22-即时自组盲测/验收约定.md)给出了对照组、耗时、成本记录与独立判定口径。

- 本机公开年报位于 `/home/zymun/sig-am-data/财务分析与预测/`。清单中的贵州茅台 2021–2025 五份 PDF 已逐份核对 SHA-256。先查 sig-am 在目标 KnowBase 可用的资料编号、版本和摘要；缺少副本时通过正常导入和项目授权补齐所需公开报告，其他工位可按文件名和摘要核对。仅选该题所需文件，私有附件留在原项目。
- 每题建独立委托，只把清单中的 `question` 交给规划器，按约定保存目录快照、资料来源、计划、交付与实耗。Q3 问的是五粮液，包内五份 PDF 都是茅台；先查本人获准目录。缺五粮液依据时保留澄清、补资料或停止的实际结果，交 zymun 结合当时目录判定。该题和其余两题都要留记录。
- 把各题原问题、实际交付、可用来源和轨迹给 zymun。业务复核人的判定与技术验收各自署明身份；尚待业务复核时，Cursor 可先交已经完成的技术结果。

## 回执交在哪里

在本卡创建 `replies/cursor.md`，写明部署环境、构建号、候选修订、镜像摘要、就绪情况和实际生效配置。对各场景按“输入或引用 → 运行编号 → 实际观察 → 费用 → 结论”记录，注明真实账号、隔离夹具或未运行。遇阻写清停在哪一层、做过什么恢复、其余场景结果和需要谁提供哪一项外部条件。真实调用以模型回执和使用记录核对；token、Cookie 和密钥留在各自凭据系统。
