## 用户操作与复验

1. 从含澄清问题的旧委托链接进入。问题下方显示“你的回答”和“提交回答并继续匹配”。空白回答不可提交。输入期间没有匹配请求。
2. 提交时通过现有 v5 接口传原轮次编号、新需求及本轮 ¥2 费用上限。默认新需求为用户原问题与用户回答；模型列出的建议不会自动写入用户需求。超出 2,000 字符时可缩短回答，或明确选择用回答改写本轮需求。
3. 用失败响应模拟网络重试，回答仍在，再点提交沿用同一幂等键。成功后地址转到新轮次，刷新可读取补充后的问题。旧轮次显示最新修订链接。专家执行仍由用户另行确认。

## 刷新后侧栏和回答挤出屏幕

Luna 用现场 Windows Edge 已登录会话重新打开并刷新一项已完成的“你好”匹配。1366 像素窗口内，展开侧栏宽 2253 像素，折叠按钮左沿位于 2216 像素，正文宽度为 0。浏览器报告页面的内容安全策略拦截服务端输出的内联样式。页面按长项目或对话标题的自然宽度布局。现场将窗口缩至 700 像素再拉回 1366 像素，侧栏恢复至 240 像素，正文恢复至 1126 像素，原回答仍在。

候选使用样式表确定首屏宽度，再在挂载和拖动时应用保存的像素宽度；登录容器的显示与隐藏也改用样式类。未更改内容安全策略。专项浏览器回归位于 `tests/e2e/expert-sidebar.e2e.ts`，覆盖长项目名称、刷新已完成的匹配、调整宽度并重载、折叠后重载，以及窄屏展开。同一用例先在仅含追问修复的版本重现回答位于视口外，再在合并本次修复的生产构建上通过。
