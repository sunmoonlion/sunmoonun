状态为待 Cursor 发布至共享验收环境。最新版真实 Kimi 规划复测为原换题组 16/16、新增题 8/8、另两次同题 2/2、独立对照 2/2。共享环境的双入口仍须独立达到 95% 门槛。Luna 负责发布后的业务验收。两端必须使用同一版孵化请求、结果和正式方法契约。

2. 按现有流程构建两端 Web 及后端，覆盖实际接收孵化、生成规划和驱动模型任务的 API、worker 与 runner。先停止旧 runner 领取新规划，待现有调用结算后切换消费者，再开放新入口。新建规划任务的原始请求带 `htn/v1`，旧任务仍按原契约继续。数据库沿用现场迁移版本。
3. 核对双方运行镜像、契约哈希、登录入口和 worker/runner 就绪。回执写入本卡 `replies/cursor.md`，列晋级指针、标签、两端实际源码与镜像。如需回退，先暂停新规划、排空或取消本版生成的在途任务，再按现有发布规程回退。
4. Luna 用 sig-am 的 Kimi 验收两条真实服务入口。KnowLab 从原行核验的能力声明新开一轮，审定六步和五个核验目标，再用留存的独立断言试跑。KnowBench 用新问题拟即时计划，审阅后执行并核对交付、版本、审批和实耗。补验资料缺失、只改一个目标和补入工具后续编。保留博物馆、茶厂、代取资料和待定版本题，现场另抽新题，限整题 150 秒，分别核对首次返回率和可行稿编译率。结果写入本卡 `replies/luna.md` 后归档。
