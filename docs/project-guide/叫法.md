# 叫法：账号、用户、平台、作者、产品、动作

界面、文档、卡片说到这几样时，只用本页的叫法。所有者 2026-10-29 定，原话与取代了什么见 [decisions](../design/decisions.md)「叫法：账号不分类型……」那一条。账号、电脑、本地 link、沙箱、令牌、会合点的叫法见 [账号-电脑-link-会合点](账号-电脑-link-会合点.md)。

## 一、总的一条

**账号不分类型，用来做什么事才区分。** 所有账号都一样，没有「平台账号」「测试账号」「运营账号」；只说某个账号这次拿来做什么。人也一样：一个人以什么身份做这件事，这件事里他就是什么。

## 二、各个词

| 词 | 是什么 | 不是什么 |
| --- | --- | --- |
| **账号** | Casdoor 里的一个用户 | 没有类型 |
| **用户** | 用账号做事的人 | — |
| **平台** | 平台人员做的事。以平台身份做事的就是平台人员；同一个人做自己的事时不是。用 web端还是管理端的账号都行 | 不是账号；也不是后端：knowfeed 替用户采、knowbase 替用户存是系统在做事，写应用名（「knowfeed 替用户采」） |
| **管理端** | 只有平台人员用的界面，在里面做的都算平台；进不进得去、能做什么看授给账号的权限（admin、operator） | 不是一类账号 |
| **作者** | 提出创意的那个用户。产品一生不换作者。作者就是用户；平台人员以平台身份提创意时，平台就是这个用户 | 不是账号的属性：同一个账号对自己提的产品是作者，请别人的专家时是请专家的人 |
| **产品** | 从创意起的同一个东西，名称一生不变，形态依次是**创意、准专家、专家** | — |
| **动作** | 对产品做的事：受理、孵化、出一版、测试、审核、交付、上架、请。谁做就用谁的账号；花 token 的那一半在作者名下、用作者的 key（decisions ⑯） | 不是账号，也不是电脑 |
| **平台模式 / 自助模式** | 一个动作（孵化、测试）是平台做还是作者自己做；是动作的属性 | 不是账号的属性 |
| **平台电脑** | 集群里的电脑，配给一位平台人员的账号，一人一台，按名单开；平台人员以平台身份当用户干活时用（平台当作者时的孵化与自测、在 knowbench 以平台名义做工作、发版走查） | 不是「测试电脑」：用户转平台测试仍在用户自己的电脑上跑（⑯） |

## 三、几个常见说法怎么说

| 不说 | 说 |
| --- | --- |
| 平台账号 | 平台人员用的账号，或直接写账号名 |
| 测试账号 knowbot-tester | knowbot-tester（配着平台电脑的那个账号） |
| 测试电脑 | 平台电脑 |
| sig-am 是平台的 | sig-am 是一个用户；所有者用它做专家时是作者 |
| 平台跑腿、平台加工（指后端） | knowfeed 替用户采、knowbase 替用户存 |
