## 清理及双端差异处理

已结束的功能/修复分支、归档分支、一次性集成基线以及不再被检出的历史发布分支，从远端分支列表移除。删除前均先把原提交发布为 `archive/branch-cleanup-20261106/<原平台>/<原分支>` 标签，并在 GitHub、Gitee 两端核对 SHA。共 253 个标签名，每个平台各有一份；标签用于恢复，不是新开发分支。

7 条旧 `qwen` 分叉（knowbase/knowbench/knowfeed 父仓与 backend，以及 sunmoonun）在 Gitee 上保留的是已被替代的旧 WP 实验和完成声明。它们的原提交已单独存入两端归档标签，再将 Gitee 对齐到 GitHub 已有分支；未把这些实验重新合入现用代码。其余差异按祖先关系快进或补建缺失分支，没有回退领先端。

每次变更都使用显式原 SHA 的 lease，防止覆盖并发提交。处理根仓时发现 `agy` 及 `work/*` 从 `72b4170e` 前进到 `a9486df5`，操作停止后重新读取并保留新提交，再继续处理。

本地和已配置远程机器的工作目录、未提交内容及本地历史分支没有被删除；本轮整理的是托管平台分支。按既有同步流程拉取新代码，不把“远端分支已整理”理解为“工作目录已同步”。

## 恢复历史

先在清单中找到对应仓库、原平台和原分支，再从任一托管平台取归档标签。例如在相应仓库恢复旧 Gitee `qwen` 为独立本地分支：

```bash
git fetch origin tag archive/branch-cleanup-20261106/gitee/qwen
git branch restore/qwen-20261106 archive/branch-cleanup-20261106/gitee/qwen
```

只在清单确有该标签的仓库执行。恢复时使用新分支，避免覆盖现用 `qwen`；需要重新发布历史代码时另行评审。
