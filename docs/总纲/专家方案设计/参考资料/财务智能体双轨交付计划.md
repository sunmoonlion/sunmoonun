## 一、我们真正要交付什么

### 1.1 长期产品目标

SunMoonAI 要把用户自己的知识与方法变成可孵化、可测试、可交付、可反复使用和持续改进的专家。价值不止于一次问答、一份提示词或一张财务报告，而在于方法、数据、执行、验收与版本迭代形成完整闭环。

两条产品线共同支撑这一目标：

```text
数据线：需求 / 订阅 → knowfeed 供给与加工 → knowbase 资料、版本、权利与读数
        用户上传 ─────────────────────→ knowbase（需加工时委托 knowfeed）
                                             ↓ 合法、钉版的输入
专家线：用户方法 → knowlab 孵化与测试 → knowmart 交付与供需 → knowbench 委托与验收
                       ↑                                      ↓
                       └──────── 作者依据测试证据改进下一版 ──────┘
```

上图是业务关系，不是每次读数据都经过 knowfeed：已有合法数据直接经 knowbase 读取；knowfeed 不可用不得拖垮这条读路径。上传只在 knowbase web端，需加工时交 knowfeed；资料交易建立使用权，不复制真源。

本计划的成功意味着：

1. 一位作者能用同一套正式产品流程把方法做成专家；另一位作者、另一种问题、另一组合法数据也能复用，不依赖开发人员代填数据库或贴清单。
2. 专家方法变化主要落在工作稿、清单与测试集；新增渠道主要落在目录配置或适配器；共用执行体、权利体系、数据契约和发布链不随每个案例复制。
3. 每次委托能说明用了谁的数据、哪个版本、何种依据，算得是否正确；失败、等待、取消和权限撤回都有可靠结局。
4. 版本升级、进程重启、断线、索引重建和备份恢复后，合法历史仍可核验；无法复现的证据如实标注，不伪造历史。
5. 数据线与专家线能长期维护、运营和受控开放；一次现场跑通不能替代这些条件。

## 二、项目理解与当前证据边界

### 2.1 通用的是工程容器，不是预制投资方法

第一档专家的逻辑随版本固定，作者挑定的数据引用随交付冻结、可以为空；使用者的数据则按每件委托的问题，由第 0 步模型提出、使用者确认。**专家清单不包含作者预先限定的用户数据需求声明，通用请专家页不强制填写证券代码。**主体可以是公司、机构，也可以不限主体。

作者用白话编辑方法层；AI 起草与运营修改只是建议，作者接受后才进入工作稿。程序生成工程层和模型指令，模型指令由作者原话与平台固定文字组成。发布版本只增不改；固定测试集重测不再让模型重新选择输入。工程测试验证运行与边界，不替作者调整投资判断；用户验收按作者确认的输入和判据进行。

第一档仍是一位专家、线性步骤、允许既定返工与向前回退。同一项目的专家执行按现有串行策略。2026-11-02 所有者将第二档中的动态方法提前纳入本轮：按作者方法论在任务中选择步骤和工具，复用现有 Task/Attempt、预算、等待恢复与验收。作者按委托挑自己的数据和专家团没有一并获准提前；不新增无真实用途的上级委托或专家团占位。

## 三、双轨重新定义与范围

### 3.1 主轨：长期通用工程建设

交付数据线、专家线及其横切机制，使完整生命周期可以重复运行。成果是正式代码、版本化契约、可迁移数据结构、自动化测试、真实运行回执、发布和运维能力，而不是专门服务某场演示的一组脚本。

### 3.2 验证轨：财务专家产品化

作者作为普通用户，从孵化到测试、交付、请用、反馈、再出版本，把主轨纵向走透。财务语义复杂、数值可复算，适合检验通用工程，但不能代表所有专家或所有数据类型。

财务轨交回两类东西：

- 一位有明确方法、范围和版本的可用专家及其合法成果。
- 可归属的缺陷和复用证据：容器问题回 knowlab / knowbench，权利与版本问题回 knowbase，供给问题回 knowfeed，领域解析问题回财务模块，判断问题交作者。

### 3.3 本期、既定数据工程与后续扩展分清

| 范围 | 本计划的处理 |
| --- | --- |
| 当前已定第一档、数据第四版、补齐表全部项 | 本批完整目标，不能因只演示财务而裁掉 |
| 公开披露主动订阅、全市场事实查询、网页全文搜索、规模与恢复验证 | 保留既定工程目标与放量前置；采集覆盖、读法覆盖、金融专业抽表覆盖分别报告 |
| 财务基础分析与预测 | 按作者定稿的专家范围验收；先验基础数值是测试次序，不自动把“分析与预测”改成只查营收 |

### 5.1 供给不能退化成单渠道财报抓取

需求描述“要什么”，不写供应商、采集器或作业。供给描述“能提供什么”，共用 knowbase 的版本化词表。适配器落实“列、取、看新的、搜”；渠道能复用现有插件时登记配置，确需新协议才写适配器。网络访问、限速、排队、留存和交付由框架管理。

用户、应用、任务或订阅轮次、确认修订、需求项形成不可变需求依据；同用户同描述的未完成请求可合流，作业可跨用户共享。取消只撤自己的依据，不误取消别人的请求或共享作业。调度保留四档、同档按用户轮流、渠道与出站地址全局限速，后台回填不挤占有人等待的任务。

渠道按渠道审，通用网页按网站审，不恢复逐单运营审批。只允许 HTTP/HTTPS；私网、环回、链路本地和元数据地址不可访问，重定向逐次检查、连接后核地址。渲染工作负载独立、无业务秘密、出口受控，子资源同样受限；时间、内存、体积和下载量有界。未审、未配或无许可均须如实等待或拒绝。

### 5.2 检索与全市场能力不能被“数值不依赖 RAG”删掉

- 精确数值和计算输入走 PostgreSQL 事实；专家/会话的证据片段走 RAGFlow + Infinity；网页全文搜索走 Elasticsearch。只有 knowbase 裁决数据访问，索引不是权威副本。
- 专家运行检索限制在钉住版本，空文档集合直接回空，不能变成全库搜索；全市场查询是另一种受资格、权限、平台总开关控制的访问范围。开关默认与环境配置沿用现行决定，并验证关闭面，不由演示需要改动。
- 内容、读法、禁用和删除事件驱动增量同步；重建使用固定读法内容，重新抽取才产生新读法版本。个人撤引用不删除别人合法共用的索引；真正清除要等相关回执。
- 全市场筛选、排序、排名、统计与全文检索保留；私有资料不进入跨用户统计。不能把本专家七个字段当成平台数据模型的上限。
- 全量前按 0047 做 **100 家、近五年定期报告**实测，含大中小企业和银行、券商、保险；报告下载、存储、加工、索引指标分别记。金融类专业抽表未支持则标未支持，不判成已具备，也不从原件规模样本剔除。
- 报告勾稽与主要会计数据互核通过率，并按 0047 随机抽 50 个数人工对 PDF；财务验证题的逐数核验另做。记录两套索引占用和恢复耗时，再定全量节奏、热温分层与备份容量。分层不是备份，粗估不是实测。

## 六、四条必须贯通的正式业务链

### 6.1 作者方法 → 可迭代的专家

1. 作者从问题、六问、skill 或自己的旧专家出发，进入同一工作稿；可以从空白直接写。直接编辑方法层不依赖模型调用。
2. AI 起草或按指令修改使用作者的 key 与每轮上限；判断缺口问作者，提议逐项或整步接受。运营修改也不能绕过作者接受。
3. 出版本前核每个方法格子的出处与原话，程序编出结构、工具、预算和验收；编译失败返回对应格子，不能后台强行放行。
4. 作者写测试问题，经第 0 步、解析和本人确认形成测试集；冻结输入组合与测试集版本。之后重测沿用固定输入，重新申请合法授权，不重新选择数据。
5. 测试证据按现有通路进产出区。修改方法出新准专家版本；相同测试集版本才能直接比较，换数据则测试集升版。
6. 用户同意与运营审核两道门分开；自用轻审、公开完整审核与重跑按现行规则。运营人授权与机器授权分开，过程结束撤回；自助私有材料不对运营敞开。
7. 交付时冻结作者数据绑定，knowmart 再硬查许可、类目与资格；使用者请用同一发布版本。反馈回到工作稿，历史版本不被覆盖。

### 6.2 问题 → 数据确认 → 运行 → 可再次取得的交付

1. 请专家页选择专家、写问题；运行固定清单快照。第 0 步读逻辑、问题与作者绑定数据的份数，不读取绑定内容来替用户选数据。确实不需要用户数据时走现有空需求分支；作者绑定数据仍按其权利与运行授权规则处理。
2. 有需求时，模型查主体、提出描述；knowbase 解析，knowfeed 对待确认项预切合。向用户列明实际期间、候选、必需/可选、缺口、许可与供给条件。
3. 用户可换、改、去掉、加，修改后重解析、出新修订；本人确认由应用凭本人令牌交 knowbase，绑定任务、修订、条目和供给条件，逐项确认 7 天内有效。偏好和默认展示不能代替确认。
4. 已有合法依据且内容/读法齐全，直接钉组合、签授权；本人尚无依据但已有内容/读法，按确认建引用或关系，不伪造等待；缺原件、缺读法或需刷新版本才交 knowfeed。
5. knowfeed 交付后取得 knowbase 回执，再经 Outbox 通知应用需求状态。knowbench 核当前任务、清单、确认时效与权利，重解析、凭有效依据签授权、恢复。下载完成不等于所需读法就绪。
6. 模型经工作台 MCP 中继读 knowbase 钉住的数据、调用确定性计算；结果回工作台再交模型。按步骤契约核数源、公式、引文、上游覆盖与输出结构，失败按既定返工/询问规则处理。
7. 运行中追加仍走“提出数据—用户确认—独立追加授权”，不扩大旧授权、不漂移已冻结部分。必需项未取得，问用户带缺口继续还是取消；不完整交付不算完整成功。
8. 最终结果、验收、证据、预算和副作用状态可靠持久化，任务唯一合法终态提交；有权用户断线或重启后能重新取得结果，通知重试不重跑整件事。复用 [九站流程](../../../process/pipeline.md)，不另造交付状态机。

普通会话另按展示给 knowbench 的范围及用户名下可用公开原件引用读数，首读每份签小授权、钉组合，会话结束交还；新增尚未取得的数据仍经预切合与本人确认。会话范围不能偷渡为专家委托的输入范围，相关隔离纳入 U07。

### 6.3 独立数据需求与上传加工

用户不先有专家也能提精确描述、网址或订阅，主题找先展示候选再由用户勾选。订阅范围同意与逐项确认是不同依据；有效范围内每轮不重复逐份确认，超范围、续订按规则新确认，撤回或到期不再生成需求。

私有资料取不到时，去 knowbase 直达上传并返回原任务重新查。knowfeed 只凭一份内容、一个目的的加工授权读原件，产出读法回 knowbase，不能读该用户其他资料。不得恢复应用各自上传和已退役本地知识库来填演示缺口。

### 6.4 市场交易与撤权

另一用户从小店购买一份可出售知识，成交以 knowbase 建立交易版本使用权为准，同交易重试不重复建权，不复制内容。卖家普通下架、降许可或关店与违规禁用分开：历史合法权益按取得依据保留；违规处置按规则收回，紧急撤回停止新的读取与受影响运行。专家普通下架阻止新请用，不能因此误停本可完成的既有运行。

自用专家的绑定可符合本人用途，但转公开必须重新核查每项绑定的许可及发布资质。解绑只影响下一版本，禁用按现行规则处理；店铺恢复不自动恢复被单独下架的条目。

### 6.5 成果不是来源，link 不是任意工具授权

当前清单编译器只给受控读数据、查主体、提出数据与计算等工具，专家步骤交回结构化结果；平台已有成稿文件与产出区写入机制应当复用。**不能因为本地 link 能操作文件，就宣称专家可以自行跑任意建模脚本。**图表、PDF、XLSX 等逐项核实际交付能力；缺能力回所属通用模块设计和验收，不靠手工包装掩盖。

用户自管的项目文件不普遍由平台钉版本、逐文件数值验收。本地路径、文件清单或模型自报摘要不是数据来源证明。受平台数值验收的依据是钉住的 knowbase 数据与计算证据；成稿按现有指纹核对、服务身份写产出区，失败可见。产出区不参与来源解析，只有用户明确“转为数据”才形成新资料，许可不得因此升级。

| U08 共享供给与调度 | 两用户要同一报告；同用户重复提交；取消一方；前台需求与后台回填竞争 | 一份内容、各自权利；幂等不重复作业/运行；取消不伤另一方；四档、公平性、配额与全局限速有效 |
| U09 等待恢复 | 重复、丢失、乱序通知，回执后应用重启，确认过期，取消后迟到交付 | 可查单对账，死信可处理；不重复开跑/结算；过期确认不续签；迟到资料可入库但不复活终态 |
| U10 权利变化 | 撤平台授权、订阅撤回、普通下架、违规禁用、依法清除 | 各动作按其语义生效；应保留的历史权利不误撤，应停止的读与运行不继续；清除追踪回执 |
| U11 检索隔离与重建 | 同数据集不同用户；空文档集合；固定旧版本；索引故障/重建/删除 | 不跨版本、不跨用户、不空集合查全库；结构化读仍可用；重建不改输入；真正清除覆盖两套索引 |
| U12 数值与引文 | 伪造数源地址、计算编号、引文、遗漏上游项，以及正确对照样本 | 通用 `sourced`、`computed`、`identity`、`quoted`、`covers` 等验收拒绝错误、接受合法结果，不只检查 JSON 格式 |
| U13 外部失败与安全 | 401/403、额度不足、429、超时/5xx、空结果、口径冲突；重定向与浏览器子资源访问内部地址 | 错误分类、有限重试、限速与截止时间生效；许可内才切源；SSRF 被阻断；无权/knowbase 故障不当缺失补采 |
| U14 运行资源与交付 | 模型额度不足、沙箱/link 不可达、预算耗尽、步骤返工、断线再取结果 | 预算覆盖执行/返工/验收/工具；不擅自追加、不换执行位置；终态与结算一致；交付通知可独立重试 |
| U15 市场闭环 | 两账号知识交易、公开专家绑定许可、资质失效、停店与恢复 | 不复制主档，成交幂等；公开门后端硬查；个人/店铺/条目处置语义正确；不借自用绕公开门 |
| U16 容量与恢复 | 100 家规模测试、全量计划、备份恢复、索引重建、版本回退、告警送达 | 有实际量测与容量依据；来源/权利/撤销记录一致恢复，旧备份不复活撤权；回退不假定数据库随镜像回退 |

U01 是现有孵化验收要求的跨领域落地，不要求同时开发第二个大型行业产品。U05 的外部验证受渠道许可与可用性约束：只测过仿真的格子不能标为真实可用，缺口继续阻止对应完整交付声明。U16 的全量回填分批执行不等于删范围，执行规模与费用沿用既有批准边界。

### 7.1 验收子项与证据归属

U01—U16 是验收分组，不是一个勾选框。各组在所属仓既有测试计划中展开为可独立判定的子项，保留与原任务及 U 编号的对应；不在本页复制测试步骤。每个子项记录前置条件、操作、预期结果、执行环境、证据位置和判定，注明属于单元/契约、集成/故障模拟还是实际环境验证。仿真通过不能替代该子项要求的真实证据。

子项失败或待判时，明确阻止哪个 G/V/W 准出条件和交付声明，并检查共用模块影响；一组必需子项未齐，不得把整组标为通过。已通过的独立子项可保留证据，涉及的实现、契约、环境或判据变更后按影响重验。

`undecidable` 的转判权归所有者或独立验收角色，转判须写明补充证据及其位置。G5 准出不允许携带 `undecidable`；确需保留的逐项经所有者书面豁免并列入剩余风险，不并入通过率。

U16 分别验规模与容量、备份恢复、索引重建、版本回退和告警送达。恢复演练前，在所属运维或测试计划中确定恢复范围、恢复时间目标、允许的数据损失范围及计时口径；恢复后核对内容与读法版本、摘要、使用权、撤权/禁用记录，以及相关任务终态、结算与待处理事件。明确旧备份之后的撤权记录如何恢复或重放，核验前不开放受影响读取。判据未定或无相应证据，不声明恢复门通过。

## 八、财务验证轨：以真实专家检验主轨

### 8.1 V0：作者方法与验收题准备

由作者确定专家的“接什么、不接什么、不接的去哪问”、步骤、口径、公式、阈值、必需输入、交付形状及预测方法。平台可提供工程建议，不能把本页样例直接变成平台预置投资方法。

首个财务专家按现行决定服务沪深北 A 股一般工商企业；银行、保险、证券明确拒绝。其他市场不因模型能回答而自动纳入。公司和年份属于测试问题或本次委托输入，不写死进通用执行体。

基础数值验收拟覆盖营业收入、营业成本、归母净利润、资产总计、负债合计、经营活动现金流量净额、购建长期资产支付的现金；派生覆盖同比、适用时的 CAGR、毛利率、归母净利率、资产负债率。**这是验证集的最小覆盖，不是替作者定完整方法，也不是平台字段上限。**沿用 knowbase 科目与指标定义，方法新增需判明领域语义与作者判断归属。

V0 冻结作者认可的问题、输入要求和判据，并把每条公式映射到通用计算工具实际支持的表达式与精度；不能把“支持整数次乘方”当成 CAGR 分数次幂或其他求解已经可用。不支持的归回通用计算能力补齐并验收，不能让模型心算补上。

初始专家若包含预测，V4a 是 X1 完整验收的必过项；基础题通过只能报基础子集通过，不能自行跳步后宣称“财务分析与预测”交付。

### 8.2 V1：本人孵化、固定输入回归与交付

全部相关开发与受控发布条件满足后，所有者在本人账号按现行孵化方案操作，或另有明确授权；走 AI 起草、多轮改定、出处、出版本、测试、交付完整流程，不复活废弃专家或清单 v1 兼容线。

保留贵州茅台 `600519.SH` 作为**回归用例，不是工程建设起点**：

- 问题：“分析贵州茅台 2023—2025 年营业收入、归母净利润和经营现金流，给出 2024、2025 年同比、各年归母净利率及来源。”2023 年只作同比基期；年份是目标输入，不是已获得数据的声明。
- 作者确认输入组合、测试集与判据后，新建三次独立合法运行，3/3 通过；输入、数值与公式可核，不要求生成文字逐字一致。
- 全部题内事实逐数对照原件、公式独立复算，相关财务勾稽单列。交回方法版本、测试集版本、三次运行证据及正式成稿，不以手工修稿代替原运行结果。
- 任一运行失败，先按第 3.2 节的五路归因（容器、权利、供给、领域解析、作者判断）分类并留存证据，修复后重新计数；失败运行本身计入交付证据，不得静默重跑凑 3/3。
- 如缺输入，按正规补采或合法上传补齐；改变题目、期间或输入需作者确认并改测试集版本；只改方法则出新准专家版本，可继续用同一测试集比较，不能为通过而静默缩题。

### 8.3 V2：真实动态供给闭环

保留宁德时代 `300750.SZ` 的 2023—2025 年营收为起始冷路径题，走同一正式专家和工具链：

1. 在隔离测试环境或合法的新报告组合中，证明至少一份原件确实未收录；未收录以时间戳化的 knowbase 主档查询或审计导出为证，该可核验查询能力列入 G1 验收。经本人确认，已审官方渠道真实下载、加工、交付 knowbase、钉版并自动恢复。
2. 另验原件已有而所需读法缺失，只补加工、不重复下载。
3. 再验内容/读法都有而当前用户尚无引用，确认后立即取得，不做假的办理中。
4. 对照 U07—U10 验共享、幂等、取消、权限和迟到通知。保留需求依据、请求、作业、回执、确认、授权与运行的关联。

不得删共享数据制造未命中，不把 fixture 冒充真实外部取数。外部真实调用失败就记失败；官方链通过不代表其他渠道已通过。

### 8.4 V3：边界内盲测与产品可用性

方法冻结后，由非实施验收者提出至少三家不同行业一般工商企业的题，分别覆盖事实、趋势与比率；至少一个主体或期间未预采。非实施验收者指未参与本批实现与联调的角色，实现方及其直接协作者回避；不同行业按申万一级行业计。另验银行、保险、证券各一条拒绝，以及简称歧义、缺失、零/负值、重述和历史截至时点。

“盲”是冻结方法后才给题，不妨碍验收者事先准备金标准；涉及作者验收的数据仍须作者合法取得和确认，不把平台工程测试资料悄悄混入用户输入。题内事实和公式的证据覆盖均须 100%，失败与不支持项逐条列出。这不是全市场覆盖率，也不证明任意公司、任意指标都能算。

性能初测至少记录 20 次热路径、10 次冷路径，注明原件、读法与缓存命中层次；不人为制造供应商限流。报告样本量、成功/失败/超时数、P50/P95/最大值、各阶段耗时和费用。小样本只说明本次测量，不外推长期 SLA。

### 8.5 V4a：预测的完整验收

作者明确目标变量、历史窗口、频率、假设和适用条件；按时间切分训练与验证，与朴素基线比较，保留误差和情景底稿。不用三个年度点声称具备季度季节性预测，不在亏损或近零序列上机械用 MAPE；情景范围与统计置信区间分开。

预测涉及的数值、假设和版本都可追溯；历史不足时明确拒绝该类预测。工程验收只能说明按方法运行正确，不据此宣传投资收益、胜率或预测优势。方法修改由作者决定，不能为了盲测成绩由平台悄悄调参。

## 九、财务语义与确定性验收

通用表格的基础地址是读法版本、表/工作表和物理行列；科目、期间、币种等是财务领域语义，不强加给所有文本或表格。财务加工分取回检查、加工检查、需求匹配；原件成功与事实可计算分别判。

| 项目 | 必须执行的规则 |
| --- | --- |
| 主体和范围 | 统一名录解析，歧义由用户确认；行业边界按作者范围拒绝，模型不自编代码 |
| 报表口径 | 合并与母公司分开；净利润、归母净利润、少数股东损益不可互换；基础样例采用作者确认的合并口径 |
| 期间与知识时点 | 期末余额、期间流量、累计、单季分开；报告期、实际披露时间、获取时间、分析截至时点分别记录；相对期间展开后确认 |
| 重述与回测 | 最新口径和历史时点可得口径分开；后来更正不得泄漏到此前回测；审计状态单记，不假定季报与更正公告都有审计意见 |
| 单季换算 | 仅同一合并范围、同一口径下累计差分；第四季度用全年减前三季时引用两项输入，不一致则停算 |
| 单位与计算精度 | 保存原值、原单位、归一值；金额、比例、股数分开；十进制计算，展示才舍入；币种转换有汇率依据，不只改标签 |
| 零、负数与缺口 | 合法零负值不判错；未披露、不适用、解析失败、查询不支持分开；空结果不能证明未披露，不填零补缺 |
| 增长与比率 | 分母零、基期负、跨零、期间不等长按作者已定规则处理，否则不输出误导百分比；三个年度值通常只有两个年度间隔 |
| 资本开支 | 购建长期资产支付现金与扣处置回收现金后的净资本开支分开命名；不等同全部资产新增 |
| 勾稽 | 资产＝负债＋权益；现金期初、净增加、期末按同定义；主要会计数据与三表互核；同一 PDF 两种抽取不称独立来源 |
| 来源与公式 | 原始数定位到资料/响应、内容版、读法版、页/表行或字段、科目映射及质检；派生数给公式与全部输入；不存在的页码不可编造 |

原始抽取值在原件披露精度上逐格一致，单位换算用精确倍率；派生结果独立复算并在约定展示精度上一致。勾稽容差由参与项各自披露精度推导、落底稿，不用统一宽容差吞掉抽错。发现冲突先核附注和口径，相关计算停止或明确不完整，不能只在报告末尾附一句免责。

- **同等验收**：以同组样本核主体、口径、单位和数值，记录差异与原因，并通过权限、异常及切源测试；没有公告页码的响应如实标注。

### 10.2 V4b：DCF 是作者方法扩展，不是平台硬编码估值

按 待你决定“以后要做 DCF 这类估值”（`docs/总纲/数据拓扑重构/待你决定.md`，2026-11-09 已删，原文见本仓提交 `cd049767f`） 保留后续方向：

1. 作者选择 FCFF/WACC 或 FCFE/股权成本等匹配方法，确认预测年数、增长、税率、营运资本、资本开支、折旧、折现和终值。平台只补真正需要的通用数学与数据能力。
2. 行情、利率、风险溢价、必要时的贝塔与资本结构另核来源和许可；股数随行情数据接入，股本金额不能代替股数。每股价值需要可靠总股数/稀释口径，当前股价仅在市场比较时必需。
3. 预测资产排程需要期初、增加、处置、折旧等依据，不能凭折旧总额反造 PP&E；融资、现金与权益未勾稽不称完整三表模型。
4. 永续增长模型要求折现率大于永续增长率；币种、名义/实际、税前/税后与折现时点一致；终值、企业价值到权益价值桥接、敏感性均能独立复算。
5. **先解决当前工程守卫与用途门**：现有编译器固定生成“不含评级、目标价、买卖建议”的验收。估值结论与该守卫、资质/类目、工具能力是否相容，须在专项设计中明确并经批准；不能只改提示词、删验收或加免责声明就放行。
6. 若需要现有白名单以外的模型求解或文件产出能力，先走通用能力设计、契约、权限、预算与验收，再供该专家使用；不能借 DCF 绕过执行体边界。

DCF 方法可装入线性步骤，不因此要求先造专家团或 DAG。未通过本节各门，保留为未交付扩展，不影响对已经完整验收的既定基础能力作准确结论。

**G4 现状（终审订正）**：release #39 已把本批代码按正式链部署到 kind，但 G4 准出**尚未满足**——缺第四轮完整候选评审、缺一次最小备份恢复演练证据，G0 映射也未建。所以 release #39 记为「部署已完成、G4 待补准出」，不倒推成 G1—G3 已过；补齐办法见 WP-0、WP-5、WP-6。此后再改代码，照常按正式链再发版，不因 #39 已上而跳评审。

G0 的范围与证据映射写入既有实施主账，沿用 B/F/C/L/M/X 与对应 SDD 原任务编号；补齐表未单列的既定范围链接原实施条目，不另起进度编号。每条至少包含：原任务及依据版本、U/V/W 验收子项、实现提交及环境/部署版本、责任人或明确执行角色、阻塞项、原始证据链接、当前判定。未执行的标“待验”，已执行但证据不足的标 `undecidable`，不混同失败或通过。

G0 准出判据：上述每条映射字段齐全，并按不低于十条或总数 5%（取多者）抽查映射与代码、部署、证据的实际状态一致。映射可按依赖分批冻结，G1 对应的数据与权利条目先行冻结，不得以后续批次的映射工作拖延 G1 启动。

冻结时记录本批范围和验收判据的依据版本，同时给出 G1—G5 与 V1—V4a 的周级粗估量级和评审点，写入实施主账；滑期超过一个评审点须在主账显式记录原因与裁决。无时间基线不得启动 G1；演示与工程是否构成冲突按此基线判定，不凭感觉取舍。冻结后仍按批准边界持续实现。新决定记录是否影响本批范围、依赖或判据，变更经既有规则确认后更新基线并重验受影响项，不因引用文档更新而自动扩大范围，也不借冻结遗漏已经批准的工作。

判定“受影响项”至少核对四类：跨应用契约变更、共用模块或模板变更、执行环境或部署版本变更、判据或词表/科目/映射变更；命中任一类即重验对应 U/V 子项，影响分析随基线变更一并留痕。

开发依赖仍按补齐计划：B3/B4/B2 → 数据页面与 C1；F 系列按其依赖展开；C3/L2 → L1 与 M3/M5；B5 → F3；再收尾 C2/C4。能并行的是独立模块的工程工作，不是提前启用未经验证的业务能力。公共机制先入模板再同步实例。

发布与验收按同一批次的三个阶段衔接：**发布前完成实现、契约与集成测试及完整候选评审 → G4 受控发布 → 发布后完成 X1 与 G5 真实业务验收，才认定本批完整交付。**候选评审核查 X1 的实现、工程测试和正式验收准备，不以尚需候选环境的真实验收结果作为发布前置；真实验收失败则回所属任务修复并按正式链重新发布、重验，不把待验记成完成。这是区分验证环境与放行阶段，不拆减本批范围，也不授权提前对外服务。

V0 的方法与题单可提前准备；**所有者真实孵化与 V1—V3 在相关完整开发和受控发布后进行**，与 G5 的通用真实验收互相提供证据。V4a 按作者已定专家范围纳入验收，W0/W1、V4b 各按专项依赖推进。G5 不由三家公司跑通代替，X1 也不由通用模块单测通过代替。

开发期间在隔离环境持续进行跨应用端到端验证，使用明确标识的工程测试账号和合法测试资料，走同一正式实现；及早覆盖确认、共享作业、等待恢复、迟到通知、撤权和交付等链路。模拟与真实调用分别记录，调用沿用已有授权和预算。这些证据不替代发布后的作者验收，不构成演示专线，也不改变发布批次。

### 11.2 资源冲突与性能预算

资源首先用于补齐已批准范围、隔离与权利、数值正确性、恢复及跨专家复用；财务题用于暴露这些问题；排版、彩排和录像不得挤掉前两者。供给作业优先级沿用正式调度规则，演示没有隐藏优先队列。

区分用户等待、受理、排队、取回、加工、索引、运行与交付耗时；重试次数、退避、任务截止时间、到上限后的去向和对账入口在对应契约/配置写明。401/403 不盲重试，额度不足不自动加购，429 遵守限速，服务故障不伪装成缺数据；任务超时样本不得从成功率和耗时统计中删除。

G0 在实际资源和许可条件下、测试开始前确认性能目标及费用上限，统一记录判据。实测前无法定稿的，允许以“暂定目标＋推导依据＋复核时点”记录，复核不晚于 G5 实测分析；暂定目标同样适用下述修改约束。上一版的“5 秒受理、180/600 秒完成、120 秒现场等待”只是提议，没有实测依据，**本版不把它们当正式 SLA 或工程截止时间**。未定性能判据则不能声明性能门通过；测试后修改目标须显式确认并重验，不偷偷放宽。展示可用时间只决定展示多久，不修改后台任务状态。

批次级预算指定归口角色，按周或按里程碑核对模型、渠道、渲染与存储的累计消耗；达批次上限 80% 时向所有者报告并确认后续测试安排。运行级预算硬停不免除批次级核对。

### 11.3 每次验收的最小证据组合

记录问题原文与明确期间、方法/专家/测试集版本、清单修订与确认编号、逐项输入组合（资料编号、内容版本、读法版本及各自摘要）、权利与授权引用、词表/科目/映射/加工器/公式版本、执行工具与依赖版本、模型标识和参数、部署摘要、运行编号、起止时间、预算及判定理由。

模型供应商若不提供不可变版本，记录限制；要求输入、数值和证据可复核，不许诺文字逐字复现。授权凭据与模型 key 不进回执。影响结果的版本变化触发对应回归，共享模块变更同时重验非财务与财务用例。

技术证据放执行仓既有结果位置并链接原回执；含用户数据的底稿、测试证据和成稿留在获授权的产出区或用户目录，不直接提交 Git。不得预建空回执后标通过，也不把历史资料当本轮生成。

## 十二、工程与产品的放行标准

| 要声称的结果 | 必须满足 | 不能拿什么替代 |
| --- | --- | --- |
| 通用工程本批完成 | 既定范围未遗漏，G1—G5 与通用矩阵有可追溯证据，跨专家复用和运维门通过，X2 跟上 | 单公司成功、代码已提交、发布页面能打开 |
| 财务专家完成 X1 | 作者本人按正式链孵化测试交付；V1—V3 及已定范围要求的 V4a 通过，失败/不完整语义准确 | 固定数字报告、人工贴清单、删掉预测步骤 |
| 某渠道或 DCF 可用 | 该渠道真实取数/许可与同等验收通过；DCF 另过 V4b 专项门 | IDE 中能调用、模型知道公式、提示词声明支持 |
| 可对外服务 | 上述相应工程/产品门，加资质、数据用途、公开审核及 C-R10 上线门 | 内部测试通过、免责声明、一次演示成功 |

任一越权读取、确认绕过、版本漂移、错误主体、伪造来源、缺失填零、取消终态复活或账实不一致，阻止相关范围通过；查明共用影响前不能仅以“换个样例”规避。判不了写 `undecidable`，不能按成功计算。

同一验收子项连续两次重验失败，或同一阻塞使里程碑滑期超过一个评审点，必须升级所有者裁决（调整设计、缩减范围或改排里程碑），不得无限循环修复重验。

所有者决定目标、方法、预算和最终接受；应用实现方对所属契约与代码负责；平台发布方对发布、资源、恢复证据负责；渠道审核方对来源与用途负责；验收由独立于实现的角色或所有者完成。人的批准沿用 [批准规则](../../../process/turn/approvals.md)，不由实现者自批。

## 十三、从属安排：只展示已验收的能力

**本节不产生新的工程里程碑，不改变前述任何准出门。**展示内容优先讲清可复用能力：作者如何改方法、测试如何固定和比较、用户如何确认数据、缺数据如何补齐与恢复、每个结果如何追溯；公司名和报告外观只是载体。

- 实时展示只选已有运行证据且当日条件成立的能力；尚未完成的能力可讲设计，但明确未验证，不暗示已经产品化。
- 现场等待过长可停止展示或打开合法导出的历史成果，清楚标注时间、专家版本、输入期间与“非现场生成”。后台继续、取消或重试由用户按正式流程决定，切画面不改任务终态。
- 如确需报告、录像等辅助材料，只选正式流程已生成且许可允许展示的成果，脱敏并核对版本；历史成果不能作为离线绕权数据源，也不能用工程测试结果宣传投资效果。
- 展示环境故障、许可不足或材料不可用，可以取消演示。不得因此借账号、预答用户确认、降低守卫、跳验收、恢复旧接口或另造专用执行链。
- 演示完成不更新 G/V/W 工程状态；只有正式验收证据才能更新。
- 演示现场收到的反馈按普通用户反馈进入作者工作稿与需求流程，不设演示反馈绿色通道，不因此新增工程项或调整验收判据。

#### WP-2　计算工具支持分数次幂

- **文件**：knowbench-backend `app/app/domain/workbench/compute.py`；测试 `app/tests/test_knowbot_compute.py`；文档 [0030](../../../design/SDD/modules/0030-knowbot-compute.md) §3.2 与 [0048](../../../design/SDD/modules/0048-model-data-tools.md) 中计算能力的描述；knowbench MCP 工具描述里若写了「整数次乘方」一并改（`grep -rn 整数次`）。
- **做法**（我定的方案，不要换成浮点或 `math.pow`）：
  1. `_power(base, exponent)`：整数指数沿用现逻辑；非整数指数只在 `base > 0` 时允许，`base <= 0` 拒绝并给明确错误（`a fractional power needs a positive base`）。
  2. 计算用 `decimal` 的 `ln`/`exp`：在 `localcontext()` 里 `prec = PRECISION + 10`，算 `(base.ln() * exponent).exp()`，再回到 `PRECISION` 精度舍入（`ROUND_HALF_EVEN` 由上下文决定，展示舍入仍走 `rounded()` 的 `ROUND_HALF_UP`）。Python 的 `Decimal.ln/exp` 按规范正确舍入，同输入同精度结果逐位确定，满足原注释「结果要能逐位确定」的要求。
  3. 指数绝对值上限沿用 `MAX_POWER`；指数本身可由表达式算出（如 `1/3`）。
  4. 不新增函数名（不加 `root`/`cagr`），CAGR 由作者写成 `(end / start) ** (1 / years) - 1`，保持「领域概念不进通用计算」。
  5. 改模块文档字符串：「四则、乘方（整数次任意底；分数次只许正底，十进制 ln/exp 求值）」。
- **验收层一致性**：`acceptance_numbers.py` 的 `computed` 复算若调用同一个 `evaluate()`，无需改；若有独立实现，必须改成调用同一函数，并加一条「模型交回的 CAGR 与复算一致才过」的测试。
- **测试**（全部加进 `test_knowbot_compute.py`）：`1.21 ** 0.5 == 1.1`（精确）；`8 ** (1/3)` 舍入到 10 位 `== 2.0000000000`；茅台式 CAGR 用金标准数算到 4 位小数与手算一致；负底分数次拒绝；`0 ** 0.5` 拒绝；`0 ** -1` 仍是除零；同一表达式算两次逐位相同；指数超上限拒绝；原有整数次用例全部不变。
- **完成判据**：ruff/pyright/pytest 全过；文档同步；补齐计划记一行。属行为扩展，不改契约字段，knowlab 无需改锁，但 knowlab `compile.py` 若有给作者看的「可用算式」说明文字要同步。
