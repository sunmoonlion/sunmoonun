# 和 WorkBuddy 比较：我们的产品与腾讯 WMA

> Opus 以 qwen 身份 2026-11-09 写，记的是当天和所有者的讨论。所有者：「把你之上写进一个和workbuddy比较.md」。
> **资料范围**：腾讯的说法只取腾讯云官方页面（产品页、产品介绍、API 文档、渠道接入），2026-11-09 读取；虎嗅的报道只用来查到 WMA 这个名字，不作事实依据。只看得到腾讯的文档，它内部有没写进文档的东西，这里比不到。
> 同目录相关：[workbuddy-opus](workbuddy-opus.md)（WorkBuddy 的专家、专家团、项目、开放平台）、[agent-team-opus](agent-team-opus.md)（四家专家团产品对照）。

## 一、先分清 WMA 和 WorkBuddy

腾讯的 WorkBuddy Enterprise 是一组产品，共用一个 WorkBuddy Harness 内核：

| 产品 | 是什么 |
| --- | --- |
| **WorkBuddy** | 给全员用的 AI 工作台（客户端）；有专家、专家团、技能、连接器、项目 |
| **CodeBuddy** | 给研发用的 |
| **WMA**（WorkBuddy Managed Agents，托管智能体服务） | 底层的云端托管运行服务：撑着上面两个应用，也能托管企业自己做的 Agent；腾讯云控制台公测中 |

本页比的是 **WMA**。**专家团是 WorkBuddy 客户端的功能，WMA 的文档里没有**——它的 API 对象只有 Agent、版本、路由、会话、消息事件、技能、专家、连接器、外部 Agent（A2A）、内置模型、沙箱模板。讨论中 Opus 一度把两者混在一起，所有者指出：「wma现在没有专家团」。

## 二、WMA 是什么（腾讯文档原意）

- **定位**：面向企业级 Agent 的托管智能体平台；企业 IT、平台工程与 Agent 开发者在控制台可视化配置模型、系统提示词、技能、连接器，或用 ADK、OpenAPI 写代码，建出 Agent；Agent 在云端沙箱里跑，持续迭代。
- **版本**：Agent 版本是"冻结快照"，含模型、Manifest（系统提示词、编排的技能与专家、外部服务）、沙箱模板；分测试版、生产版；"生产版本不支持原地修改，需新建版本迭代"；同一 Agent 的几个版本可按权重分流量。
- **运行**：一个会话独享一个沙箱，存算分离，实例销毁不丢数据；休眠唤醒 P95 不超过 300 毫秒、百万级并发（腾讯自己的说法）；7×24 云端运行，闲置休眠不计费。
- **治理**：统一身份、全链路 Trace、安全审计、成本管控与配额核算；VPC，数据不出域；消息事件只回放脱敏的消息与工具调用。
- **连接**：MCP、OAuth 等连接器开箱即用；继承 WorkBuddy 的技能与专家生态；支持 A2A（把不在本平台运行的外部 Agent 登记进来，绑定给某个 Agent）。
- **交到人手上**：在 WMA 控制台建好的 Agent，一键下发到企业 WorkBuddy 管理端，再发给对应范围员工的客户端；也能接进企微 AIBot、QQ 机器人、钉钉、飞书等 IM（员工在 IM 里直接和 Agent 对话，不用另装应用），或嵌进 OA、经 API、Web 发布。

## 三、讨论经过与所有者的判断

所有者的原话，按时间：

1. 「我觉得我们的项目和腾讯的wma很类似」
2. 「它的一键下发和我们的用户注册是类似的」——两者都是"在一处办一次，下游各处自动就有了"；不过 WMA 下发的是 Agent（同一个 Agent 推给一批人），我们注册下发的是人（同一个人进所有应用）。我们这边和"把 Agent 交到人手上"最像的，是 knowmart 上架后用户来请，以及平台电脑按名单配给账号。
3. 「从本质来讲，我们的产品和wma是高度一致的，很多情况下只是实现方式不同」
4. 「从功能开发方面我觉得我们比他好」（撇开性能，性能是资源决定的）
5. 「你说的很多还是资源决定的，比如入口 对开发者开放，我说的仅从功能实现来看，我们比他强」
6. 「入口api那些对于个人开发者，比这个不公平」
7. 「wma现在没有专家团」
8. 「我不认为大部分都实现，就是全部实现，除了资源垄断原因之外（你说的入口，api等都是应该算资源），你要是不服，你举例」
9. 「版本按权重分流量其实不算一个功能」——它是发版手段，不是给用户的功能；放在我们这里也不合适：我们的专家在市场上卖，用户请哪一版、钉哪一版由用户定，按权重随机分版本反而违背"谁请谁定、不静默换版本"。
10. 「你说的A2A应该实现很简单」——协议这层（名片、消息、任务、成果，HTTP 加 JSON-RPC）确实简单，现有的服务身份、契约、任务状态机都能套上去。
11. 「如果我们把财务专家其实就是专家，不一定是财务专家，跑通，我觉得我那句话站得住，你再认真考究一下，这对我很重要」

**口径**（按所有者第 5、6、8 条）：比"设计出来的功能"，不比"铺开的面"。入口、开放 API、ADK、第三方生态、企业治理、规模性能，都算资源。

## 五、要先补上或说清楚的

1. **A2A**：简单，但"简单"不等于"已经实现"。要说"全部实现"，要么做了，要么明确归进开放接口一类、和 API 一起算资源。做的话要套进我们的规矩：外部 Agent 交回来的只当资料、不当验收过的结论；给它的数据要在用户授权范围内并留痕；它的费用记进委托的花费；在专家的能力声明里写明用到了外部 Agent。
2. **需要登录的第三方连接器（OAuth）**：WMA 写的是"MCP、OAuth 等连接器开箱即用"，能替用户接邮箱、日历、网盘这类要登录的外部服务。我们的 link 只接受不带凭据的 MCP 地址（`sunmoon-link/agent/src/mcp.ts` 明确拒绝凭据），用户没法把需要登录的外部服务接给专家。"接得了哪些服务"算资源，但"能接需要登录的服务"这个机制本身是功能，我们现在没有。要么补上，要么对外不提这一项。

另两处差别可以算资源，但被问到要答得上：

- **隔离粒度**：WMA 一个会话一个沙箱；我们一个账号一个沙箱。更细的隔离主要是成本。
- **用户电脑关机还能不能干活**：WMA 全在云端；我们的专家在用户电脑的项目目录里干活，电脑关了就停。给每个用户配一台云电脑（平台电脑已经是这个形态）是成本问题。

## 六、我们比它强在哪

只在专家这一块，而且要等跑通才算数：

- **专家不只是提示词**：按腾讯文档，WMA 的 Agent 定义是"系统提示词 + 编排的技能与专家"，WorkBuddy 的专家包主体是一段提示词，工具由系统统一分配。我们的专家是结构化的方法：输入输出有约束，每一步由程序执行、确定性验收，每个数追得到原件页码或计算收据。
- **专家的机制更全**：固定流程；在作者给定的方法范围内按问题动态挑；方法和专家各有不可变版本、精确引用；测试集钉住；作者市场，有审核、能力声明、自用与公开分开。
- **数据真源与逐项授权**：谁的数据、凭什么能读、给哪件委托用，用户逐次确认；要什么数据只说要什么，平台按渠道先后去取，入库带出处。WMA 是靠连接器接企业已有的系统，没有对应的这一层。
- **合规边界**：投资逻辑和数据只来自用户，平台只做工程化，不选不推荐。

这些不是加资源能补上的，是从数据层到执行层的设计。

## 七、原话要改的三处

所有者最初想对外说的是：「我们的产品除了腾讯垄断资源我们无法实现外，它的功能我们都实现了，而且在专家模型功能实现方面我们场景更多，功能更强，代码更底层（因为它的专家多在提示词）」。

1. **"场景更多"要改**：WorkBuddy 专家中心按 15 个行业分类，WMA 面向企业各种办公场景；就算我们把专家做通用了，上架的数量和覆盖的行业也比不过。站得住的是**专家的机制更全**（第六节）。
2. **"代码更底层"要改**：别人听不懂，也容易被反驳成"底层是腾讯的内核"。换成具体的：他们的专家主要是提示词加技能编排，我们的专家每一步由程序执行和核对。
3. **"垄断资源"换成"规模和生态"**：前者带指控意味，容易把话题引开。

## 八、"跑通"要跑到什么程度

所有者第 11 条说「不一定是财务专家」，这一点关键：要说通用，**至少要有一位非财务专家**也在线上走完全程，不然会被说成"只是一个财务工具"。计划里本来就有一位非财务小专家（[双轨计划](财务智能体双轨交付计划.md) WP-8 U01）。

- **财务专家**：在线上对任意 A 股（不含银行、保险、证券）走完全程：孵化、测试、上架、手选和 AI 找都请得到、定数据、执行、验收、交付进 knowbase；双轨 8.2 回归题 3/3、盲测、预测验收都过。
- **非财务专家**：同一套流程走通一次，执行代码不改。

## 九、结论与可以对外说的话

跑通、并满足第五节以后，所有者这句话的主干站得住。改完的说法：

> 我是一个人开发的。撇开腾讯的规模和生态，WMA 的功能我们都实现了。在专家这一块我们做得更深：WMA 的专家主要是提示词加技能编排；我们的专家是结构化的方法，可以是固定流程，也可以在作者给定的范围内按问题挑方法，每一步由程序执行和验收，每个数都追得到原件或计算过程，用户的数据谁能用、给谁用逐项授权。

说之前要先满足三条：

1. 财务专家和一位非财务专家都在线上跑通（第八节）；
2. A2A 做了，或者归进开放接口一类（第五节第 1 条）；
3. 需要登录的第三方连接器补上，或者不提这一项（第五节第 2 条）。

**宣传材料要注意**：私下讲、给投资人讲没问题；写进对外宣传材料时，广告法不允许贬低其他经营者的商品或服务，点名说"比腾讯强"有风险，宣传里只讲我们自己能做到什么。
