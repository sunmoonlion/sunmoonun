## 一、WorkBuddy 是什么

腾讯云文档的说法是"全场景 AI 工作台"，能连腾讯办公生态：用户用日常语言提需求，它自己拆目标、排流程、做完，交付能直接用的成果；任务覆盖文档、表格、PPT、数据分析，授权后能读写本地文件，能"多任务并行"。适用场景列了七类：日常办公、深度调研、代码与应用开发、设计创意、项目协作、专业任务、服务与知识。

**运行在本机还是云端，产品简介没写明**；只说授权后能处理本地文件。有个人版（标准、高级、旗舰）和企业版（WorkBuddy Enterprise）。

## 二、专家

**是什么**："角色切换"机制，用"**人设 + 方法论 + 工具链**"让 WorkBuddy 以某个领域专家的身份干活。

**权限边界**：专家本身不主动拿系统权限，**只处理用户主动给的对话和上传的文件**；配了技能（Skill）或 MCP，才会在用户授权下间接访问文件或外部服务。任务中途要用一个还没连接的服务（如腾讯文档、TAPD），输入框上方弹出连接卡片，授权后任务自动接着跑。

**怎么用**：左侧边栏「专家·技能·连接器」→「专家」页签，浏览卡片、点召唤，进对话描述任务；对话里也能从"最近使用"里找、置顶。

**专家中心**：按行业分类浏览专家与专家团；首页有推荐模块，按使用热度、新上架、编辑精选展示。

**自建专家**：「我的专家」→「创建专家」，内置工具引导配头像与显示名、人设身份、擅长领域、提示词；**名称建好后不能改**。建好的可以修改、分享、删除：
- **分享是生成链接，别人召唤的是副本**，用不影响你的配置；
- 分享**不会上架到专家市场**；要上架，得按规范打专家包提交（第四节）；
- 删除后不能恢复，已经分享出去的对方也用不了了。

**什么时候用哪个**（文档原意）：有一个明确的单点问题，用专家；任务复杂、要多个角色配合，用专家团；只要某种工具能力，用技能。文档还提醒：涉及医疗、法律、投资、合规等重大决策，要咨询专业人士。

## 三、专家团

**是什么**：多位专家分工协作，团长统一调度；团长"自动拆解任务、分配给成员、执行并返回完整结果"，"并行执行、整合交付"。用户的用法和单个专家一样：召唤后用自然语言描述任务。在专家团会话里换专家要开新对话。

**用户中途能做什么**：取消、追加要求、审批，文档**都没写**；只写了连接外部服务时的授权卡片。

**费用**：专家团会并行调用多位专家、多轮模型交互，积分消耗"**通常为单专家的 3–5 倍**"，召唤前先看积分余额，免得中途不够。

**开发侧怎么写**（开放平台「专家团」）：

```text
my-team/
├── .codebuddy-plugin/plugin.json   配置（必须）
├── avatars/                        团队、主理人、成员头像（必须）
├── agents/
│   ├── {team}-team-lead.md         主理人（名字必须带专家团前缀）
│   ├── member-a.md
│   └── member-b.md
├── skills/                         共享技能（可选）
├── .mcp.json                       MCP、连接器依赖（可选）
├── settings.json                   设置主理人（必须）
└── README.md
```

- `plugin.json` 里 `expertType` 填 `team`，`teamInfo` 写 `leadAgent` 和 `memberAgents`；另有一组展示字段（显示名、职业、简介 40–50 字、行业分类、3 个标签、3 条快捷提问、默认开场提示等）。
- 每个成员一个 Markdown 文件：头部写名称、描述、显示名、职业、`maxTurns`（默认 50）；正文是系统提示词（角色定位、分析维度、输出格式）。**主理人的正文里写团队成员表、标准工作流程（SOP）和协作规则**。
- **协作规矩**（原文要点）：
  1. 建团"必须且只能由主理人执行"；
  2. 主理人按 SOP 分阶段拉成员、下发独立任务；**成员的产出必须由成员本人输出，主理人只编排和汇编**；
  3. **成员之间不直连**，跨成员的信息都经主理人转交；
  4. 每个阶段结束，**把完整产出原文**交给下一阶段的成员；
  5. 派活时在工具参数里写成员的中文角色名。
- **工具**："开发者不可自行添加 tools，所有工具权限由系统统一分配"。系统内置读、写、搜索、命令、联网搜索与抓取等工具；**派活（AgentTool）和发消息（SendMessage）只有主理人能用**。
- 官方模板是一个交易团队，五个阶段：数据采集（并行）→ 多空辩论 → 交易决策 → 风险评估（并行）→ 最终报告。
- 模型怎么配、发布审核、版本规则、计费，这一页**都没写**。

## 四、开放平台与上架

**能发布什么**：技能、专家、专家团、连接器、外部应用接入。

**流程**（开放平台操作指引）：注册入驻 → 完成开发者或企业资质认证 → 创建业务类型 → 完善基础信息和能力配置 → **提交平台审核** → 审核通过后发布上线 → 持续看运行数据、做版本维护。

**单个专家包**：结构和专家团一样，`expertType` 填 `agent`；可以声明预加载的技能；必须依赖外部 MCP 或企业连接器时才声明 `dependencies`，鉴权方式可选 OAuth、令牌或无；**"专家包内严禁硬编码任何真实 Token / 密钥"**；行业分类从 15 个里选。也可以在市场里「我的专家」→「创建专家 / 创建专家团」，用对话补全提示词在线创建。

**文档没写的**：审核标准、上架后怎么展示与分发、版本更新的具体做法、收益分成与计费、资质的具体材料。

## 五、项目

**是什么**：团队协作的容器，"项目"和"任务"两层，让成员共享上下文、标准与知识。

| 项目里有什么 | 说明 |
| --- | --- |
| 指令 | 被项目里的任务继承，统一 AI 的行为规则 |
| 连接器 | 公共授权（大家共用一个账号）或个人授权（凭据只存本地）；**个人授权的在协作任务里用不了** |
| 专家与技能 | 项目配置的可复用能力，任务里优先展示 |
| 资产 | 统一资料中心，能上传文件或保存任务产物，显示更新人和时间；默认 5 GB |
| 任务 | 成员在项目里开的对话会话 |
| 计划 | 安排工作事项，有看板、列表、表格、甘特、日历视图，能设负责人、起止时间；**计划里的事项和任务是两回事** |
| 项目动态、定时任务 | 近期变更；按时间自动执行提示词 |

- **人和 AI 怎么协作**：项目指令、项目资产、当前用户的个人记忆自动进任务上下文。
- **任务怎么交给别人**：**分享**（邀请成员，打开链接进同一个会话）、**流转**（把产出和完整上下文复制到新会话，交给别人接着做）。"与我相关"列出别人分享或流转给我的任务。**怎么给某个成员指派任务、任务有哪些状态，文档没写**。
- **钱算谁的**：任务里的对话**花任务所有者的积分**，只有所有者能换模型。
- **权限**：项目所有者管项目和成员；项目管理员管成员和设置、审批加入；项目成员建任务、参与任务、用共享能力。任何成员都能邀请人，但要管理员审批才能加入。

## 六、权限、数据与积分

**默认权限与安全沙箱**：两档——默认权限（建议日常用），和"允许完全访问"（关掉二次确认，对当前客户端所有任务生效）。默认权限下要确认的：写受保护或敏感路径（密钥、凭据、安全配置）；删受保护文件、重要目录或批量删除；执行脚本、命令或外部程序；联网或命中安全中心规则的敏感能力。普通文件写入通常直接过。
- 文件以工作空间为界，超出范围或高风险时暂停请确认；
- 命令先在沙箱约束下跑，被拦再按风险决定要不要确认；安全中心能按命令前缀设允许、询问、禁止；
- 远程 HTTP 默认询问，本地默认放行，白名单域名不受限；macOS 可开网络严格模式；
- 这些管控对客户端里所有 Agent 统一生效；**专家、专家团在这套权限下怎么跑，这页没单独写**。

**数据**：必要收集是账户信息和对话内容；上传文件、工作区文件只在你主动上传或技能明确触发时收集；不收集通讯录、精确位置、设备唯一标识、生物特征、产品外的浏览记录。上传前要确认自己有权利，注意他人个人信息与商业秘密。

**积分**：所有对话相关请求都花积分，按模型定价和任务复杂度算；被暂停、没执行的工具调用不扣；先扣最早到期的。个人版积分按月发、当月有效不结转；个人会员到期降回体验版额度；企业版到期后"无法继续使用产品的任何功能"。**专家、专家团各自怎么扣、余额不足时任务怎么办，积分页没写**（专家页只说专家团通常 3–5 倍）。

## 七、对我们的启示（我的判断，不是腾讯的说法）

| WorkBuddy | 我们现在 | 可以借的 |
| --- | --- | --- |
| 专家 = 人设 + 方法论 + 工具链；专家包里写提示词 | 专家 = 作者的方法、规则、验收，冻结成清单版本；平台按步注入，不整包交出 | 他们的专家主要是一段提示词，我们多了逐步验收和数据授权，这是我们要守住的不同点 |
| 专家团的 SOP 写在主理人正文里，由开发者定 | 专家团还没设计 | 协作规则就是作者的方法：作者写、随版本冻结（[专家团方案设计](../../专家团方案设计/README.md)） |
| 成员不直连，全经主理人转交；阶段间交完整原文 | 单个专家里，方法之间按计划绑定、按确切版本取成果 | 团里同样只经团长交接，交接物按版本钉住、可验收，"成员之间传的产出算什么"就有了答案 |
| 工具由系统统一分配，开发者不能自加 | 工具是作者范围与平台许可的交集，每次调用核权限 | 一致；团里成员各按自己的范围，团长不自动拿到成员的权限 |
| 专家团 3–5 倍积分，召唤前提示余额 | 模型费用户出，实时显示、随时能停 | 请专家团前给"大概几倍"的提示 |
| 分享是副本，不上架；上架要打包、过审核 | 自用与公开分开，公开要过审核与特批（审核人不能是作者） | 一致 |
| 项目：指令、连接器、专家、资产、计划看板；分享与流转 | 项目是用户电脑上的一个文件夹加对话与底稿；看板视图已有 | 计划事项和任务分开、看板上设负责人，接近所有者设想的任务看板；"流转"（带上下文交给别人）是我们没有的 |
| 个人授权的连接器在协作任务里用不了 | 谁的数据谁挑，运行授权逐项记依据 | 团里谁的授权就只给谁的那一段用，不随团共享 |
| 默认权限：敏感路径、批量删除、命令、联网要确认 | link 的白名单、上限、本机当面确认 | 大致一致，我们在 Windows 上还有沙箱 |
