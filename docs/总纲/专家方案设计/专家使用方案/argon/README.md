# argon 的专家使用方案（knowbench）

本目录存放 `argon` 独立编写的 `knowbench` 专家使用与执行方案设计稿（基于仓库一手契约、领域代码与所有者决定独立完成，定稿前不动代码）。

## 文档导航

- **[专家使用方案：声明匹配请入、统一执行架构与按计划定数据](专家使用方案.md)**
  - **一、核心定位与四大架构决断**：确立声明匹配、固定/动态统一执行引擎、先排计划再定数据、三类困难分流四大核心设计。
  - **二、用户入口与「请专家」机制设计**：统一入口组件、AI 找专家（`FIND_EXPERT`）与自主去 `knowmart` 挑专家双路径、`MatchReceipt` 收据核验与无匹配时的两条主补救路径（转通用模式聊天、提本人孵化申请）。
  - **三、统一执行架构：一套引擎承载固定专家与动态专家**：通过 `FixedMethodPlan`（`fixed-plan/v1`）与 `CapabilityMethodPlan`（`method-plan/v2`）统一投影为 `ExecutionPlan`（`StepContract[]`），实现零双轨分叉，并详述 `validate_plan` 六道确定性校验铁闸。
  - **四、按计划定数据与 Wind / 巨潮协同供给链**：先定计划再按入选方法提数据（`要数` vs `要资料`，需求不写渠道）、用户一次确认（7 天有效）、`knowfeed`「Wind 优先、巨潮原件保底」与就绪后自动续签运行授权接着跑。
  - **五、执行效率、行为审批、确定性验收与三类困难分流**：多期批量查数与批量 `compute`（1–50 项）、按影响触发的行为审批，以及缺数据、能力不适合、平台故障三类困难的分流与转交。
  - **六、待所有者拍板确认的事项**。
