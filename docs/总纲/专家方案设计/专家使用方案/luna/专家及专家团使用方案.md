# 专家及专家团使用方案

日期：2026-11-14。状态：所有者接受两份评审的限定采纳意见后形成的目标设计；尚未完成对应产品与执行机制。方法定义、分类、权限、编排及验收唯一真源为[孵化主稿](../../专家孵化方案/luna/专家及专家团孵化模板.md)，本文只规定 KnowBench 使用流程。实施依赖主稿 M0–M5，C1–C6 状态见[接入清单](../../../mcp和skill接入实施方案.md#176-本次先发布发布后补齐的工作单所有者-2026-11-13-确认)。

## 一、从选择到委托

用户可在市场请入、让 AI 按声明查找，或在聊天/工作中请求已孵化专家。先确认问题修订、所选方法版本与使用资格；检索异常不冒充没有匹配项。普通 MCP/Skill 安装仍是“安装/连接 → 配置 → 启用”，不触发专家孵化。

聊天请求专家/专家团时，宿主创建关联项目、源会话轮次及调用的委托，立即返回委托引用和当前状态，让聊天轮次收尾。后续澄清、确认、采数、执行和交付沿普通委托推进，不占住一次 MCP 请求等待整个过程。重复提交或重连按同一受信调用身份返回既有委托。工具方法不必经过专家计划页，但耗时或等待型工具也可异步派发，仍使用同一调用记录。

## 二、准备一张可修改的确认页

| 阶段 | 宿主与模型的工作 | 用户看到什么 |
| --- | --- | --- |
| 取得基准 | 读取精确版本的能力、基准图、允许变化、接口及使用资格 | 适用/排除范围、作者承诺、价格与限制 |
| 按题具体化 | 用户沙箱中的 AI 提议本题计划；唯一合法计划由程序生成；宿主核依赖、必做、备选、映射及类别 | 顶层步骤、预计交付、与作者基准的差异及谁提出 |
| 推导需求 | 由计划及依赖生成输入槽、权限需求、账号用途和费用估算 | 本次必需项、条件预估、已有选择和缺项 |
| 准备资源 | 在现有合法权限内查找资料与匹配连接；需要新授权则显示缺项或完成必要前置交互 | 具体数据版本、账号身份、可预授的条件范围；不自动勾选所有候选 |
| 确认提交 | 将计划、数据、连接和预算分别核验并关联同一确认批次 | 在同一页确认本次范围，OAuth 返回后接续当前修订 |

准备不自动购买数据、下载未授权内容或批准外发。资料不足影响排计划时先澄清必要信息，不能承诺任何题都“一次点击开跑”。初始计划先于完整定数据形成，但需求解析、缺项补充和计划修改可以有界往返。

用户改计划、数据或账号后，旧预览失效，重新推导需求和费用，再展示差异。后端按计划/数据/连接修订及预览依据核验提交；修订冲突返回具体差异，不按页面未展示的新内容执行。重算失败保留草稿并标出未完成项，不能用旧估算放行。

下层未展开需求分为已选路径必需项与条件需求上界。用户可明确预授条件范围，也可留待触发时补确认；必要账号缺失时解释对应步骤，不因为候选存在就强制绑定全部账号。费用展示估算、不确定部分和硬上限；所有层共同消耗根预算。

## 三、确认后的执行与调整

宿主按持久计划推进，显示正在做什么、等待谁、哪些成果已验收。子方法在已确认范围内按自身基准图具体化；下层展开不反复弹顶层确认。条件、按项展开、运行中调整和纠错分别遵循主稿 §2.9，不能用一次计划确认授予无限后续变化。

| 情形 | 页面和执行行为 |
| --- | --- |
| 范围内合法展开或已预授条件触发 | 记录并显示实际展开，继续执行，不重复要权限 |
| 作者允许且用户已确认的运行调整 | 核所有约束及调整次数，保存计划差异与理由后继续；未执行部分才可调整 |
| 新账号、外发、权限、预算或交付变化 | 暂停受影响路径，展示新增范围供确认；原批准不自动扩张 |
| 发送等具体写动作 | 公共审批卡展示精确账号、对象、内容及附件版本；计划确认不能代替 |
| 父权限失效或撤销 | 停止受影响的新访问，提示重授权或结束；保留已发生事实 |
| 结果未知 | 显示需核实，禁止自动重发；不以重新排计划掩盖未知副作用 |

用户要求删必做或增加范围外方法时，展示对原专家承诺的影响。只有显式选择“用户修改计划”并通过新计划核验才继续；成果明确标识，不再宣称原专家完整履约。该功能未实现时拒绝非法计划，不暗中解除限制。接口、资源资格和平台底线始终有效。

## 四、交付、复用与回炉

只交付已导出的成果及许可内证据，区分完成、有效不适用、部分交付和失败。文件目标和覆盖行为单独核验；委托完成后向源会话/项目附回结果引用，重复通知不重复创建成果。内部中间资料和作者私有方法内容不自动回传。

保存计划复用时重核问题、方法版本、输入口径、连接和当前授权，不能复制旧动作批准。二次编排或执行无法在原边界内解决问题时，提供回炉入口，按主稿 §2.8.3 展示缺口、接收方和拟发送内容。

原作者进入新修订，有派生许可的用户创建来源可查的工作稿，仅有运行权的用户只能提交改进需求或从自己的需求另起孵化。计划本身可能敏感，反馈前预览并授权。原工作稿不得覆盖；新版本不自动替换本次任务。用户可以等待、结束、接受获准的部分结果或选择合规的自行修改计划，不被强迫继续。

## 五、验证与实施衔接

验收包括：聊天重复请求只创建一件委托；计划变化带动需求重算；条件预授与实际触发对应；修订冲突、OAuth、等待采数可恢复；未声明调整被拒；撤权阻止新访问；写操作审批及未知结果不重放；回炉不泄露私有定义或覆盖工作稿；源会话获得且只获得许可内导出。

本页是流程要求，C2 提供准入、公共核权及派发/记录基础；完整确认页、二次编排、异步交接、运行调整和回炉在主稿 M2–M3 实施，M4 机制验证、M5 真实模型验证。本次仅静态文档走查，不以本页存在视为前端或端到端验收通过。
