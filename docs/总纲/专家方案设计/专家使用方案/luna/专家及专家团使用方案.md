# 专家方法使用方案

日期：2026-11-14。状态：所有者接受两份评审的限定采纳意见后形成的目标设计；尚未完成对应产品与执行机制。方法定义、分类、权限、编排及验收唯一真源为[孵化主稿](../../专家孵化方案/luna/专家方法孵化与递归编排方案.md)，本文只规定 KnowBench 使用流程。实施依赖主稿 M0–M5，C1–C6 状态见[接入清单](../../../mcp和skill接入实施方案.md#176-本次先发布发布后补齐的工作单所有者-2026-11-13-确认)。

## 一、从选择到委托

### 工作台只提供一个「请专家」主入口

用户在项目中写一次问题，即发起一件委托。从聊天、工作或市场带回的问题和用户点名的专家版本都进入同一受理流程。KnowMart 保留独立浏览与获取入口。受理后保留项目、问题修订及同一委托引用，后续确认、恢复与交付都能回到这件事。重复点击或刷新可取回当前进度。

| 当前判断 | 用户看到什么、接下来做什么 |
| --- | --- |
| 问题明确 | 先从 KnowBench 方法技能管理中心取当前用户有正式使用资格的专家版本。AI 将本题交付与候选的能力声明、适用及排除范围对照。用户点名的版本优先核对；若明确指定必须使用，失配时说明原因，由用户决定是否放宽。需要付费匹配时，在启动模型前展示本轮费用范围并沿用已获准预算。 |
| 现成专家能承接 | 在当前页展示推荐理由、适用边界、版本、交付与费用。多位相似时只展示影响本题的差别，必要时问一个能区分选择的问题。由用户选择并确认，即使免费也须确认。按选中的冻结图进入本次范围确认，版本或资格变化时重新核验。 |
| 问题缺关键口径，或服务异常 | 口径不清就在原页反问，沿原委托继续。目录或资格服务异常时显示原因并提供重试。查询未覆盖全部范围时写明已查边界，不能据此断言没有专家。 |
| 已查范围内没有合适专家 | 在同页说明缺口，给出「拟临时计划」「去 KnowLab 孵化」「结束」。用户可直接去孵化或结束。「让模型直接答」属于普通聊天。 |
| 用户选「拟临时计划」 | 在原委托页展开即时编排。以本题及获准资料选方法，展示拟用版本、步骤、输入、交付、所需权限和费用。只对会改变计划的缺项提问。「拟计划」只启动规划，用户点「确认执行」后才可派发业务步骤。排不通时保留草图及缺口，可去孵化或结束。 |
| 用户选「去 KnowLab 孵化」 | 此时才切换到 KnowLab。先预览传递的问题、缺口和获准的方法或成果引用。有原专家需要修订时按作者或许可走回炉，只有使用权的用户可向作者提需。没有对应专家时新建孵化。保留原项目和委托的返回位置。 |
| 用户选「结束」 | 结束本次请求并保留已发生记录，停止后续规划和业务调用。 |

后台对产品暴露一个发起专家委托的入口。选择专家、同意拟计划、确认执行和转孵化是原委托上可分别核验的动作。用户在确认后改题或改变方案，宿主按新修订重新核验，旧批准只覆盖原范围。

聊天请求专家时，宿主创建关联项目、源会话轮次及调用的委托，立即返回委托引用和当前状态，让聊天轮次收尾。后续澄清、确认、采数、执行和交付沿普通委托推进，不占住一次 MCP 请求等待整个过程。重复提交或重连按同一受信调用身份返回既有委托。工具方法不必经过专家计划页，但耗时或等待型工具也可异步派发，仍使用同一调用记录。

### 正式专家匹配的首段实现（2026-11-21）

在工作台首页选择项目、填写问题，进入匹配页。也可从方法技能管理中心的获权目录点「用此版本请专家」。页面在发起前显示本轮模型预算上限 ¥2。未点名时先按本题从可正式使用的专家中取最多 8 个精确版本，再逐项核对其公开声明及对应的校验输出；点名只查该版本。每次只查一个资格窗口。窗口里全是工具且还有后页时，工作台提示「继续查找下一批专家」，由用户决定是否续查。每次续查重新核资格；空页不建模型任务、不产生模型费用。查尽才撤下续查入口，改题从首批查起。目录失联、指定版本不可用与超出上下文上限均按错误处理。候选声明合计上限 64,000 字节，页面标出仅检查部分目录的情形。

匹配使用用户项目自己的找专家任务和模型。宿主保存实际送审的声明，核对每项必要交付的原题引文、候选版本、承诺引文及已定义输出。用户可对照最多三个候选的交付、限制及条件再选定一个版本。选择时重新核对所选版本的资格和声明，保存到原匹配任务。用户改题再提交会关联上一轮，查询旧轮能定位新轮，原轮的选择不能继续确认。首次目录空时直接返回，尚未建立持续委托；发生在已结束轮次之后的空目录查找也不会新建模型轮次。

用户确认版本后，重开同一匹配任务可看到冻结图的首层执行范围。工作台按依赖展示步骤、调用方输入和导出成果，列出声明中涉及的账号操作、资源角色、外发目的和需审批的动作。每次读取都核对当前市场资格、登记版本摘要和原选择回执。模型匹配用量归原查找轮次。

选定专家后点「准备本次委托」，可在原页为输入槽选参考资料，为声明的操作选执行账号，并填写本次执行的人民币预算上限或明确勾选不设上限。浏览资料时才用本人身份向 KnowBase 取目录。新增选择指向当时持有的版本；重开时核对原版本编号和内容摘要，新版入库后仍保留用户原选。这里只读元数据，资料能否提供槽位所需的业务值须在后续具体化时核验。账号候选取自本人已登记且启用的连接，核对服务地址、工具描述、核定操作及资源约束。工作台保存连接修订和操作策略摘要。

准备清单可以留有空项。填写本题的实际输入时，文本槽可直接输入，其他槽按冻结契约填写 JSON。保存参考资料时只核对版本信息。保存会追加修订，同时编辑同一版会提示重读。重开时标出失效绑定。改题或撤销使用资格会阻止旧方案继续派发。

保存后点「核对执行步骤与费用」。页面列出实际走到的工具版本、执行账号、操作、外发目的地及字段。依赖上一步的输入显示产物来源。具备报价依据的步骤列出费用上限，缺输入、依赖、权限或报价时显示具体缺口。固定图可逐层调用同一或不同的冻结子专家。页面可展开每个子专家，按调用路径分别查看方法编号、版本、摘要和交回父级的输出。当前可执行两种工具步骤。受管 MCP 使用本人选定的连接。KnowBase 的 `read_method_input` 使用方法技能管理中心登记的函数和本人的资料权限。两者都核验使用资格、来源执行许可和运营核定的费用依据。脚本、独立指令和要求协作隔离的图仍会提示具体缺口。

读取 KnowBase 文本时，在读取步骤的资料编号输入槽选一份资料版本。宿主沿冻结图逐层追溯到用户填写的输入槽；父子专家使用不同槽名时，仍从同一份已选资料取得编号和版本。由运行中产物决定资料身份时，预览显示无法绑定。手填值或步骤中的固定版本与所选版本冲突，或资料未接到读取步骤时，预览会列出对应缺口。核对通过后，读取步骤会显示资料编号、版本及 SHA-256。

点「确认并发起委托」后，可在同一项目查看审批和进度。重复确认同一版会打开同一张委托。每次外发前审批具体动作及所读的前序产物；运行器再核资格、连接和操作策略。递归委托的调用范围从执行委托建立时起最长 24 小时，审批等待和重启都沿用原截止时间。子专家资格或上层调用范围撤销后，后续动作停止。每次子专家调用独立记录产物，父级按冻结的交接边读取。成功后原匹配页显示根专家声明的导出成果，停止的任务可打开查看处理记录。[执行预览及建单](../../../../../../knowbench-app/knowbench-backend/app/app/application/workbench/formal_expert_preparation.py)

委托走到读取步骤时，在审批卡核对资料、用途和摘要，点「授权此版本并读取一次」。KnowBase 按当前委托、方法调用、版本和到期时间授予读取权限。收回成果时，宿主核验正文摘要、资料版本及调用归属。回执内容偏离已确认摘要会留下未确认结果，停止交付。

未命中后的即时编排与转孵化在第 13 项接入。当前工程检查使用合成模型应答，实际问题的推荐质量按主稿单独盲测。[受理实现](../../../../../../knowbench-app/knowbench-backend/app/app/application/workbench/formal_expert_intake.py)

## 二、准备一张可修改的确认页

| 阶段 | 宿主与模型的工作 | 用户看到什么 |
| --- | --- | --- |
| 取得基准 | 读取精确版本的能力、基准图、允许变化、接口及使用资格 | 适用/排除范围、作者承诺、价格与限制 |
| 按题具体化 | 用户沙箱中的 AI 提议本题计划；唯一合法计划由程序生成；宿主核依赖、必做、备选、映射及类别 | 顶层步骤、预计交付、与作者基准的差异及谁提出 |
| 推导需求 | 由计划及依赖生成输入槽、权限需求、账号用途和费用估算 | 本次必需项、条件预估、已有选择和缺项 |
| 准备资源 | 在现有合法权限内查找资料与匹配连接；需要新授权则显示缺项或完成必要前置交互 | 具体数据版本、账号身份、可预授的条件范围；不自动勾选所有候选 |
| 确认提交 | 将计划、数据、连接和预算分别核验并关联同一确认批次 | 在同一页确认本次范围，OAuth 返回后接续当前修订 |

准备不自动购买数据、下载未授权内容或批准外发。资料不足影响排计划时先澄清必要信息，不能承诺任何题都“一次点击开跑”。初始计划先于完整定数据形成，但需求解析、缺项补充和计划修改可以有界往返。

用户改计划、数据或账号后，旧预览失效，重新推导需求和费用，再展示差异。后端按计划/数据/连接修订及预览依据核验提交；修订冲突返回具体差异，不按页面未展示的新内容执行。重算失败保留草稿并标出未完成项，不能用旧估算放行。

下层未展开需求分为已选路径必需项与条件需求上界。用户可明确预授条件范围，也可留待触发时补确认；必要账号缺失时解释对应步骤，不因为候选存在就强制绑定全部账号。费用展示估算、不确定部分和硬上限；所有层共同消耗根预算。

## 三、确认后的执行与调整

宿主按持久计划推进，显示正在做什么、等待谁、哪些成果已验收。子方法在已确认范围内按自身基准图具体化；下层展开不反复弹顶层确认。条件、按项展开、运行中调整和纠错分别遵循主稿 §2.9，不能用一次计划确认授予无限后续变化。

| 情形 | 页面和执行行为 |
| --- | --- |
| 范围内合法展开或已预授条件触发 | 记录并显示实际展开，继续执行，不重复要权限 |
| 作者允许且用户已确认的运行调整 | 核所有约束及调整次数，保存计划差异与理由后继续；未执行部分才可调整 |
| 新账号、外发、权限、预算或交付变化 | 暂停受影响路径，展示新增范围供确认；原批准不自动扩张 |
| 发送等具体写动作 | 公共审批卡展示精确账号、对象、内容及附件版本；计划确认不能代替 |
| 父权限失效或撤销 | 停止受影响的新访问，提示重授权或结束；保留已发生事实 |
| 结果未知 | 显示需核实，禁止自动重发；不以重新排计划掩盖未知副作用 |

用户要求删必做或增加范围外方法时，展示对原专家承诺的影响。只有显式选择“用户修改计划”并通过新计划核验才继续；成果明确标识，不再宣称原专家完整履约。该功能未实现时拒绝非法计划，不暗中解除限制。接口、资源资格和平台底线始终有效。

## 四、交付、复用与回炉

只交付已导出的成果及许可内证据，区分完成、有效不适用、部分交付和失败。文件目标和覆盖行为单独核验；委托完成后向源会话/项目附回结果引用，重复通知不重复创建成果。内部中间资料和作者私有方法内容不自动回传。

保存计划复用时重核问题、方法版本、输入口径、连接和当前授权，不能复制旧动作批准。二次编排或执行无法在原边界内解决问题时，提供回炉入口，按主稿 §2.8.3 展示缺口、接收方和拟发送内容。

原作者进入新修订，有派生许可的用户创建来源可查的工作稿，仅有运行权的用户只能提交改进需求或从自己的需求另起孵化。计划本身可能敏感，反馈前预览并授权。原工作稿不得覆盖；新版本不自动替换本次任务。用户可以等待、结束、接受获准的部分结果或选择合规的自行修改计划，不被强迫继续。

## 五、验证与实施衔接

第 12 项验普通委托受理与现成专家路径，覆盖点名、多个相似版本、澄清、服务异常、确认前撤权和重连。第 13 项验未命中后拟计划、拒绝或结束、计划确认前零业务调用，以及 KnowLab 新建、原作者修订、使用者提需及返回原委托。用原有项目和在途委托验证切换前后均能继续。全部分支可用后再替换工作台的三个旧入口。

验收包括：聊天重复请求只创建一件委托；计划变化带动需求重算；条件预授与实际触发对应；修订冲突、OAuth、等待采数可恢复；未声明调整被拒；撤权阻止新访问；写操作审批及未知结果不重放；回炉不泄露私有定义或覆盖工作稿；源会话获得且只获得许可内导出。

本页是流程要求，C2 提供准入、公共核权及派发/记录基础；完整确认页、二次编排、异步交接、运行调整和回炉在主稿 M2–M3 实施，M4 机制验证、M5 真实模型验证。本次仅静态文档走查，不以本页存在视为前端或端到端验收通过。
