# 财务专家执行与验收方案（Luna，knowbench）

日期：2026-11-09。状态：讨论稿。来自两份 11 月 8 日 Luna 原稿的数据、计划、验收和工程部分；本次按职责归位，并修正供给渠道的责任表述。代码细节沿用原审查基线，未作本轮实现验证。

作者内容见[孵化方案](../../专家孵化方案/luna/新财务专家孵化方案.md)，M/A/Q/P/C 编号见[方法详稿](../../专家孵化方案/luna/财务方法原子化与组合模板.md)，公开声明和旧版本见[市场方案](../../专家市场方案/luna/财务专家能力声明与版本方案.md)。

## 一、执行时共用机制，按题形成有限计划

用户指定或 AI 按 knowmart 公开声明合理选择真实专家；不要求选专家时先证明所有方法组合一定可行。请回专家、提交问题、确认数据与实际运行分别记录。没有合适专家时，按既有入口让用户选择通用模式、孵化或结束，不自动换成另一种付费任务。

受理后，绑定专家版本及包摘要，明确本题范围，按照冻结的方法和作者规则形成计划，核依赖、取得实际授权数据，然后执行、验收、交付。固定与动态计划共用同一执行体系，不能为原子方法、组合模板或后续专家团另建一套财务运行器。

支持 Opus 把组织机制共用的方向，但“每阶段一次模型调用”“每个方法固定一轮”不是方法定义的必然结果。确定性工作和相容的独立计算可以批量处理，仍逐项保留证据；需要不同授权或存在依赖的工作不能越过边界合并。是否合并定范围与排计划，要看结构化结果能否独立验收及实际成本，不在此先固定轮数。

运行中重排仅在已授权能力和规则内进行，保留已开始工作及历史计划依据。新方法、新关键假设、新授权和新增费用不得被普通重排隐含批准。停止任务与停止供给作业的边界也需显示清楚。

## 二、同一财务专家的三种计划

**完整年度分析加季度预测：**题目与范围确定 → 所需事实及原文授权／准备 → 作者要求的Q01—Q04 → A03单季还原 → A04/A05/A06题定指标 → P02最近四季回测及P01两季预测 → E04管理层讨论核对 → C15报告。管理层讨论具体依赖哪些结论、何时执行由作者确定；没有理由为此增加DCF、质押或Altman。

**人均创收：**题目范围确定 → 收入与员工数据、相关原文 → 必要数据质量核验 → A06人均创收配置 → 按作者规则选择E04 → 报告。员工数缺失，提出真实缺项或按已有规则交局限；不去要四年季度报表，不跑单季还原、预测和回测。是否缩减四式范围是作者内容变更，不能由优化自动决定。

**另一家A股年度营收：**主体与期间确定 → 对应主体实际授权数据 → 必要核验 → A04及走势描述 → 报告。未授权不能读取，原专家范围不覆盖则交用户决定；不能借“通用模型有常识”制造财务数字。

此外，问DCF或股权质押时，仅当这位专家新版明确接受了相关方法与声明范围，才可执行；市场上存在这些模板不等于它已经具备这些能力。

## 三、数据契约：让每个方法真的拿得到输入

### 3.1 分开四类输入

| 类型 | 示例 | 要求 |
| --- | --- | --- |
| 披露事实 | 营收、资产、员工数、股本 | 原始出处、主体、期间／时点、范围、单位、版本、披露时间 |
| 推导事实 | Q4收入、平均权益、同比 | 输入事实或上游成果引用、公式变体、compute收据、精度 |
| 假设参数 | 增长率、资本成本参数、情景税率 | 参数值、由谁提出／接受、依据、适用期；不能伪装成披露值 |
| 质量与约束 | 勾稽未平、原文缺失、重述不一致 | 哪个事实／结果受影响、是否允许继续、采取哪条作者规则 |

建议的业务输入样式如下；优先映射现有 FactRequest、事实引用和成果契约，不新增同名的第二套事实库：

```yaml
subject: 600519.SH
metric: revenue
period: {start: 2024-01-01, end: 2024-12-31, kind: annual_flow}
statement_scope: consolidated
currency: CNY
unit: yuan
value: "..."  # 金额以十进制保真；这里不提供示例真数
source: {material_id: "...", version: 1, fact_ref: "...", page: 63}
disclosed_at: "..."
revision_basis: as_reported  # 或明确重述版本，不能只写latest
status: available
```

计算与原文可以是不同但相互可核对的证据。不是所有市场数据都具有PDF页码；Wind结果保存查询、字段、期间、供应回执和版本等实际证据。要求核原文的结论仍需对应报告原文，不能把Wind数值回执伪造成页码证据。

### 3.2 依赖的两条线

**数据线：**收入与成本 → 毛利率；季度序列 → 同比 → 预测。

**质量线：**某期间勾稽结果 → 是否允许该期间进入某种预测。

方法输入既可来自已授权事实，也可来自另一方法的结果。M02的“已平衡”不能当作营收金额，M04的ROE不能当作股东质押公告。每个必需槽必须能找到明确的生产者；绑定时校验类型、期间、范围、单位和可用状态。

保留数据准备和方法执行的分工：准备阶段根据所选方法汇总初始需求；执行发现真实缺口时走补充需求与确认，不把数据理解成只发生一次的第0步。

### 3.3 供应顺序与可得性

职责按 qwen 当前方案明确：knowbench 提出“要什么、为什么、是否必需”，用户确认；knowbase 解析已有授权资料，缺口再由供给链按适用且获准的渠道处理。原稿“知识库 → Wind → 巨潮”的描述是供给侧的优先策略背景，**不能写成 knowbench 模型挑渠道的指令**；具体可用能力和供应政策以当前数据拓扑及供给实现为准。来源：[请专家与执行](../opus/请专家与执行.md)的定数据部分、[数据拓扑](../../../数据拓扑.md)。

只补缺失的事实或读法；已有原件缺结构化加工，不应无意义重采同一原件。waiting必须有实际加工或采集状态依据，不能仅凭未过期确认记录宣称在取。任务停止、供应是否继续及费用各按现有授权状态处理，不能因本方案自动重启。

回测绑定每个预测起点当时可得的数据。后期重述值若被用于历史回测，必须明确是事后重构评估，不能冒称当时可实现结果。报告期、披露日、任务日是三个不同维度。

## 四、验收改造：核对正确做法，也允许真实坏消息

### 4.1 结果与执行分开

建议在现有交回物内表达业务状态，不立即新增一套平台状态机：

- `computed/observed`：完成计算或证据观察。
- `missing`：必需事实／证据缺失，说明缺哪一项。
- `not_applicable`：有事实但方法适用条件不成立。
- `unverified`：不能完成要求的验证。

勾稽结果另有 `balanced/unbalanced`，结论对照另有 `支持/不支持`。这些是不同含义：**算出了不平 ≠ 平台出错；未核验 ≠ 已平；原文不支持 ≠ 计算一定错。**

有效不平结果交给专家质量规则决定后续，而不是不断重试直到算成零。无效结构、篡改计算或错误来源仍须拒绝。若“缺数”导致题目没解决，任务可以有诚实但不完整的成果，不能把方法正确交回缺项当作整题成功。

### 4.2 每个定义的六类检查

1. **结构：**字段、类型、唯一键、状态与数值是否一致；不强制用假数填满表。
2. **语义输入：**主体、期间、单位、合并范围、版本及适用域相容。
3. **计算：**本任务收据、固定公式、关键操作数、结果与容差；金额、比例、天数分别定义容差及展示舍入。
4. **证据：**事实可读取、引文原话存在、授权和版本正确；原话存在与结论得到支持分别检查。
5. **覆盖：**题定输出及实际需要的期间都处理，缺项须逐项说明；不是把全部授权材料都强制加入覆盖集合。
6. **交付：**已执行、未执行、不适用和失败结果能在最终报告区分，文件与成果记录一致。

工程上先复用现有 `computed/input_keys/sourced/quoted/covers`。现有 `_computed` 已能核公式语法树和报告操作数，但这还不能独自保证所引事实属于正确主体期间；输入绑定与证据层要补相应检查。不能简单删除所有精细验收，也不能用关键词命中“不提供目标价”就判成提供目标价。

### 4.3 独立测试，不再只从被测公式生成期望

每个新定义至少提供：手工可核算的正例、适用域边界、缺项例、错误公式／操作数例、错误来源／期间／范围例。非数字方法提供原文支持、部分支持、反证和没有对应内容的例子。

重点案例：

| 类别 | 必须拦截或正确表达的反例 |
| --- | --- |
| 四式 | 用A=负债和权益总计替代缺E；用现金流量作期初余额；残差非零却报平 |
| CAGR | 五年题仍用1/3；年度行数代替年间隔；零负基期假算 |
| 季度 | 缺H1却推Q3；不同重述链混减；资产负债表作差称单季 |
| 杜邦 | 归母利润与总权益错配；重复算同一乘积冒充独立验证 |
| 预测 | 跳过原回测；历史起点使用未来数据；区间上下界错位；将历史范围称统计置信区间 |
| 估值 | CFO-CapEx直接冒充FCFF；不满足终值域；净债务和现金双重调整 |
| 证据 | 引文存在但只支持半条结论；不同口径方向相同就判支持；来源另一公司 |
| 无发现 | 没有KAM／重分类／三条风险而编造条目；把未查到等同不存在 |
| 计划 | 年度营收题强制DCF；人均创收题强制季报；依赖未满足仍放行 |

业务结果期望应由独立算例或明确原文先写，再对实现核验。合成数据标明合成；普通测试只读比对冻结快照，更新golden用独立显式命令。真实案例与模型回归在另行授权后执行，不继承旧轮预算。

## 五、开发落点与执行次序

### 5.1 不另起炉灶的实现边界

| 仓／现有落点 | 具体工作 | 完成依据 |
| --- | --- | --- |
| knowlab：`atomic_methods.py`、`methods.py` | 用已有v3定义表达选定原子方法；逐一核对状态、参数配置和证据输入能否表达 | 新定义脱离原工作流可冻结、可绑定、可独立验收；不预先发明v4 |
| knowlab：`method_composition.py`、工作稿编译及方法服务 | 数据槽／质量槽绑定，精确版本引用，模板展开和冲突提示 | 编译实际schema与作者看到的一致；无伪数据边；升级显式 |
| knowlab 前端：现有工作稿／方法选择入口 | 原子方法和创意模板分开展示，选择后加工；展示适用域、所需数据、增加的能力和必做规则 | 作者能组装年度题模板并删除无关项；原创内容不被强迫先入成熟库 |
| knowbench：`method_catalog.py`、计划校验及规划入口 | 按专家授权配置选方法，闭合数据与质量依赖，阻止无关分析和缺输入计划 | 选择正确／拒选正确的确定性测试及后续实际计划验证 |
| knowbench：`acceptance_numbers.py`及成果／数据读取边界 | 复用现有检查，补缺失的输入语义验证和有效不平结果处置 | 不改阈值、不伪造通过，方法失败／数据异常／平台故障分清 |
| knowbench：计算工具与调用编排 | 先复用已有批量能力；缺失才补有限批量请求，逐项返回收据及失败项 | N个独立计算无需N轮模型；不同权限／依赖不可越过批量处理 |
| knowbase / knowfeed | 逐配置核事实、原文和供应能力；仅补确有缺口的字段或读法 | 不再由“有PDF”推断“结构化事实齐全”；采集与加工状态可追溯 |
| knowmart | 同一专家新版的实际能力声明与选择 | 不因库里有DCF就给该专家标DCF；不改变已有市场匹配主线 |
| sunmoonun | 定稿后更新实施账、依赖和验收记录 | 提案、实现、验证、发布状态分别清楚，不把本文当发版回执 |

模板和原子内容的正式存放位置，在现有作者资产服务与创意模板路径内确定。测试目录里的合成候选继续作为测试资产，不能把 `ALL_20_SPECS` 导入脚本当正式发布接口。

11 月 8 日审查时，目录契约多处限制为30个方法／来源，规划 `max_steps` 类型上限为100；现有20项夹具又自行设为25。**不能把本文45个定义整体装入同一个专家，再靠盲目调高限额解决问题。**方法库可以更大，单专家只装其声明需要的子集；指标配置和批量数据实例也不应重复膨胀方法定义。若经真实能力拆解仍超过现有限额，先提交规模、编译和规划成本分析，再调整契约及锁文件。

### 5.2 按可验证产物分六步

| 顺序 | 工作内容 | 应交回的具体结果 |
| --- | --- | --- |
| 1 内容纠偏表 | 将[方法详稿](../../专家孵化方案/luna/财务方法原子化与组合模板.md)中的 M01—M20 问题落实为“原定义→修正定义→是否改变作者要求” | 每项有去向；无孤立输出、无承诺超出输入，争议项明确待定 |
| 2 三份贯穿样例 | 完成Q四式、A05 CAGR、A03/P01/P02季度预测链的独立定义与算例 | 证明可表达缺项、质量门、期间、精确引用及批量计算，不先写45个空壳 |
| 3 第一专家组合 | 完成A06题定指标、人均创收、E04及C15，装成同一财务专家新稿 | 原三题计划不同；公式、原文要求、回测和报告承诺有逐条映射 |
| 4 扩充可明确候选 | 按经营→治理审计→估值顺序逐组补入，去重参数与数据契约 | 每组独立测试、组合测试和来源核对；不为凑20项一次标成熟 |
| 5 补规格较重的组合 | O08/P03/P04—P08及C08/C09的完整业务建模 | 独立预测／估值算例、情景和适用域，不能仅靠平表通过 |
| 6 作者接受与发布 | 作者核对方法和组合差异，生成同一专家新版，执行正式测试或既有可追溯发布流程 | 具体版本、接受记录、实际结果及未验证范围；历史版本不改写 |

第1—3步不是只分析八步后放弃20项；它们建立可复用实现，再按方法详稿中的处置表扩展。当前优先级以把既有能力做好为准，不能让尚未规格化的三表估值模型拖住年度分析和人均创收。

### 5.3 性能目标与执行办法

- 一次查清本题所需主体、期间、指标及证据范围，按数据服务允许的粒度批量读取；未缺失的数据不重复请求。
- 同一事实版本在同一授权任务内复用；跨用户、版本、范围或授权变化不能复用错误缓存。
- 独立数值计算批量提交，每条保留语义实例、输入引用、compute_id和错误；后续依赖只能消费已可用的结果。
- 报告和解释使用已计算结果；禁止为了写一段文字再把所有指标逐个算一遍。
- 记录模型轮次、读取次数、重复率、计算项数、每阶段费用和耗时。以相同问题及数据比较，而非用猜测承诺“必定几分钟”。

本方案不自动恢复此前被所有者取消的硬时限，不增加费用授权。无进展、预算和取消机制沿现有批准规则；需要修改时另列具体差异。

## 六、整体任务的验收与目前状态

1. **选择正确**：同一专家处理不同问题时，计划随题目变化；必要依赖不被删掉，无关分析不自动加入。应同时测应选与不应选的反例。
2. **方法正确**：实际公式、口径和窗口符合作者定型内容；四式核验不替代，未核验不算通过，预测不绕过原回测要求。
3. **数据正确**：实际绑定有权使用、版本明确、期间与单位一致；原文与计算事实满足各自要求，缺项真实反映，回测无未声明的未来信息。
4. **证据正确**：计算收据能对应输入与结果；引文支持完整结论，口径不一致不判支持。“不支持”不等于原计算错误。格式失败、平台失败、方法验收失败分别报告。
5. **交付完整**：报告覆盖本题要求和所有有效分析成果，未执行或不具备条件的部分明确说明；文件真实可读，不能仅显示“完成”。
6. **耗时和成本可接受**：记录规划、读数、计算、验收和交付耗时及调用数；批量确定性计算不拆成逐指标模型轮次。具体时间与预算目标另定，不自动重新加回此前被取消的时限。
7. **版本和权限可靠**：方法来源和修改可追溯；专家升级不改写旧任务包、授权、费用与历史结论。行为审批不能给现有专家凭空增加能力。

完整分析预测题保留为质量基准，但不能用它一次通过代替其它场景。无需逐条复制旧流程中的无关步骤来追求形式等价；需要保留的是作者要求和结果质量，而非旧的执行浪费。

上述是未来实施的验收要求，不是本轮通过记录。99 项合成探针仅见[原审查证据](../../专家孵化方案/luna/财务方法原子化与组合模板.md)第二节；本次只检查方案归位和链接。真实数据、真实模型、线上库及发布均未操作。

## 七、与专家团的衔接

专家团可复用单专家的计划、授权、证据、验收和恢复机制；但成员间成果传递、项目并发、团队预算和责任汇总还需要单独方案。单专家计划中的若干方法，不因此自动成为几个专家。新增讨论见[专家团使用建议](../../../专家团方案设计/专家团使用方案/luna/协作任务与成果交接.md)。
