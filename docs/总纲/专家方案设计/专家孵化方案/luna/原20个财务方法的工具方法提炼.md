# 原20个财务方法的工具方法提炼

日期：2026-11-14。定位：从原 M01—M20 的财务内容中提炼可复用的工具方法。本轮仅用少量例子说明提炼思路；完整的逐项提炼另行专项开展。

工具方法的定义和公共结构遵循[方法、步骤、组合与模板](方法、步骤、组合与模板.md)。本文的产出对象只有工具方法，不讨论专家方法、专家团方法或它们的编排。

## 一、要从原20个方法中提炼什么

原 20 个财务方法包含不同的业务处理职责。本次关注其中能够独立接收输入、完成固定职责并交付可验证结果的能力，将其提炼为工具方法候选。

例如，原“CAGR 与趋势”中的增长率计算、原“勾稽与重述”中的单项勾稽核验、原“审计或有事项”中的审计意见识别，都可以作为提炼示意。具体拆出多少项、哪些职责合并复用、每项采用什么实现，在专项提炼时确认。

旧方法与工具方法不要求一一对应：一个旧方法可以提供多个工具候选，不同旧方法也可以复用同一个工具。方法数量不作为完成标准。

## 二、工具方法的提炼标准

| 标准 | 含义 |
| --- | --- |
| 职责完整 | 能说清处理什么问题及结果边界；不把每个加减乘除单独包装为财务方法 |
| 输入明确 | 声明所需数值、文本、配置及证据；不依赖未说明的前置会话状态 |
| 处理有界 | 职责、流程、适用域和停止条件固定，在平台可治理边界内不调用其他方法 |
| 结果可验证 | 返回业务结果及必要依据，缺项、不适用、未核验等状态可以区分 |
| 可以复用 | 不绑定某位专家或某一步，其他调用方提供合适输入也能使用 |

工具方法可以包含多个内部程序步骤、共享库计算或固定职责内的模型判断。需要模型判断不妨碍其成为工具方法；模型交互同样须有预算与停止条件。

需要的事实和材料应在输入中明确声明。不能为省略输入，把搜集资料、任意调用其他方法等职责隐藏在工具内部。共享程序库须有版本与验证依据，不等于调用另一个已注册方法。

## 三、从原内容到工具候选的提炼过程

1. 阅读原方法，标出其中处理数值、核验关系、识别证据等具体职责，并保留来源。
2. 选择有独立用途、可复用且可验证的职责，界定它接收什么、处理什么、交回什么。
3. 检查输入是否齐全、内部是否调用其他方法，避免把隐含依赖带入工具定义。
4. 按主稿的五要素描述候选，由做法中的声明生成输入和返回两视图。
5. 专项提炼时再定业务口径、实现载体、环境、独立样例与孵化证据；待定内容如实保留。

提炼记录至少能对应“来自原方法哪一部分 → 提炼什么工具 → 为什么值得独立复用”。本轮不填写完整 20 项对照表。

## 四、从原方法提炼工具的示意

| 原财务方法 | 其中可提炼的职责 | 工具方法候选示意 | 输入示意 | 返回示意 |
| --- | --- | --- | --- | --- |
| M12 CAGR 与趋势 | 按固定口径计算一段期间的复合增长率 | CAGR 计算工具 | 口径相容的起终值、期间及获准配置 | 增长率、期间依据、适用性和计算证据 |
| M02 勾稽与重述 | 对资产、负债和权益执行一项勾稽检查 | 资产负债平衡核验工具 | 同时点、同范围的资产负债权益值、单位和精度 | 差额、核验结果、输入依据及不能核验的原因 |
| M18 审计或有事项 | 从给定审计报告识别意见并定位证据 | 审计意见识别工具 | 获准的报告内容、版本、完整性信息和分类判据 | 意见类别、原文位置、覆盖范围与未明确项 |

这三行只表示提炼方向，不代表最终名称、完整字段或已接受的规格。正式提炼时还要核对原内容与作者要求；不因填写表格而视为通过孵化。

CAGR 保留完整业务用途，不拆成除法、乘方和减法三个工具。平衡核验可以正确返回“不平”，不应把业务不平误记成程序故障。审计意见识别可以包含受控模型判断，但应区分报告未读全与无法识别，不能自行补造原文结论。

## 五、提炼后的工具方法怎样表达

以 CAGR 计算工具为示意，按照统一结构描述其职责。这里只展示填写方式，数值适用域、公式变体、精度及正式字段在专项提炼时确定。

| 作者维护的五要素 | 示意内容 |
| --- | --- |
| 能力声明 | 在明确适用域内计算复合增长率，不从历史增长推断未来增长 |
| 所需权限 | 仅使用本次获准的输入；无额外外部访问需求时明确说明 |
| 做法 | 声明起终值、期间和口径输入，检查相容性，执行已确认算法，声明结果及依据输出；不调用其他方法 |
| 校验 | 核主体、期间及口径，用独立正反例验证计算，区分缺项与不适用 |
| 审批 | 按实际动作声明审批要求；无额外审批不取消平台的数据使用与费用规则 |

程序从做法生成并校验对外输入和对外返回两视图，不另维护一套会漂移的接口。运行时再绑定实际值、资料版本和有效授权。

实现选择与业务定义分开。确定性公式、隔离脚本、用户沙箱中的指令和经治理的外部服务，都须符合主稿的运行边界与实际支持情况。本次不把候选名直接当作平台后端函数，也不先指定每项实现载体。

工具进入可调用目录前须满足主稿的孵化要求：来源与作者接受依据可追溯，五要素及两视图完整，输入与执行边界闭合，实现和环境真实，独立验证及未覆盖范围明确。模型判断的语义质量须有相应证据，不能只检查返回格式。
