# 原20个财务方法的工具方法提炼

日期：2026-11-14。定位：依据新架构说明提炼思路，供后续专项提炼参考。本文只做示意，不逐项确定原 20 个方法的新规格，不生成正式方法目录，也不代表完成孵化或实现。

统一定义以[方法、步骤、组合与模板](方法、步骤、组合与模板.md)为准。本文说明如何从旧财务内容识别工具方法，以及哪些职责应交给专家或专家团组合；作者组织新版本见[新财务专家孵化方案](新财务专家孵化方案.md)，运行验收见[财务专家执行与验收方案](../../专家使用方案/luna/财务专家执行与验收方案.md)。

## 一、提炼的目标与范围

原 M01—M20 是旧财务方案的内容划分，混合了计算、证据判断、取数、计划组织和综合交付。旧的一项不必对应新的一种方法：可以拆出若干工具方法，也可以与其他内容共用一个工具方法，还可能保留为专家的组合职责。

提炼的目标是找到职责清楚、可独立验证、可在不同组合中复用的处理能力。不能按章节数量定方法数量，也不能把每个加减乘除拆成方法，或把全部工作塞进一个脚本来减少表面调用次数。

本次确定的是提炼原则、表示方式和少量边界示例。正式提炼另行开展，届时再逐项核对旧内容、作者要求、算法来源、输入输出、实现和测试。本文中的示例不是正式接口，不赋予使用资格。

## 二、按三类方法判断边界

| 类别 | 判断依据 | 对财务提炼的意义 |
| --- | --- | --- |
| 工具方法 | 在平台可治理边界内不调用其他方法；职责、流程和停止条件固定 | 可承担一个完整计算、核验或限定证据判断；内部允许有程序步骤、共享库和有界模型交互 |
| 专家方法 | 组织工具方法及零种或一种专家方法，不调用专家团方法；至少调用一个下层方法 | 负责将取数、计算、核验和交付等方法按依赖组合起来 |
| 专家团方法 | 调用两种或以上专家方法，或调用已有专家团方法；可以同时调用工具方法 | 适用于多个不同专家能力的组合，仍使用同一编排机制 |

专家种类按方法身份计数，不按调用次数或版本数计数；分类依据孵化时冻结的允许依赖，不因本次只走一条分支而改变。三类共用五要素两视图、权限、调用记录和版本机制。

是否确定性计算、是否使用模型、是否通过 MCP 接入，都不能单独决定类别。模型提出工具请求，由宿主执行；工具方法不能借模型请求绕过“不调用其他方法”的边界。平台方法之间的调用必须经过统一调用机制。

共享程序库不等于调用另一个注册方法，但其版本和验证依据仍须固定。若某项工作确实需要调用另一方法，应该明确组合关系，不能把调用藏进工具方法实现。

## 三、正式提炼时如何开展

### 3.1 先厘清业务职责，再确定方法边界

| 工作 | 要回答的问题 | 正式提炼时的产物 |
| --- | --- | --- |
| 核对来源 | 旧项承诺什么？哪些内容来自作者，哪些只是工程建议？ | 原内容与来源版本、保留要求和争议项 |
| 拆开职责 | 哪些是取数、计算、判断、编排、成稿？哪些可以独立复用？ | 职责及输入、结果之间的关系 |
| 判断分类 | 是否调用其他方法？允许哪些专家依赖？ | 候选类别及判断依据 |
| 补齐定义 | 何时用、需何权限、如何做、如何校验、何时审批？ | 五要素作者定义及生成的两视图 |
| 明确实现 | 作者内容由什么载体承载，在哪里执行？ | 实现与环境约束，不预填虚构函数或服务地址 |
| 验证准入 | 正反例是否独立、业务口径是否确认、依赖与权限是否闭合？ | 孵化证据、未覆盖项及可否进入目录的结论 |

同一职责可以服务多个旧项，旧项到新方法可以是一对多或多对一。正式提炼须保留这些映射，不能因拆分而漏掉原专家的交付承诺。

### 3.2 候选工具方法采用什么结构

下表是后续专项提炼的填写框架，不是已经完成的财务方法规格。公共字段只遵循主稿，不另造一套接口。

| 作者维护的五要素 | 提炼时应写明 |
| --- | --- |
| 能力声明 | 处理什么问题、适用及排除范围、承诺什么结果；不把指标值扩大解释为投资结论 |
| 所需权限 | 资料与资源角色、可信操作、范围及外发要求；无外部访问需求须明确，不因持有引用就自动获权 |
| 做法 | 固定处理流程、输入与输出声明、业务口径、实现引用、环境、预算及停止条件；不得调用其他方法 |
| 校验 | 输入相容性、业务规则、结果及证据检查、独立正反例；技术成功与业务验收分开 |
| 审批 | 需要批准的动作及条件；无额外审批也不能取消平台或资源方要求 |

程序从做法生成、规范化并校验对外输入和对外返回两视图，作者不另维护一套相互漂移的接口。运行时才绑定具体值、资料版本、连接和授权。

输入可以是数值、文本或带来源的成果引用。工具方法不必自己负责寻找所有输入；上层可以先调用取数或加工方法，再将结果传入。宿主按声明解析已绑定材料，不等于允许该工具任意检索、调用连接器或扩大授权范围。

### 3.3 实现载体与业务定义分开

确定性公式可由通用计算引擎执行，作者脚本在隔离环境执行，指令及证据判断由用户沙箱使用用户的模型完成，外部 MCP 经 KnowBench 治理入口访问。具体支持情况和准入条件以主稿及接入实施方案为准。

平台后端函数承担通用基础能力，不因提炼财务工具就把作者的财务投资判断写入平台代码。工具方法脚本不能再调用连接器；需要读取、计算、发送时，由上层编排为独立方法调用。确定性工作不为形式统一而增加模型轮次。

## 四、少量提炼示意

以下只展示如何思考边界。名称、公式变体、输入字段、判据及验收规格均留待专项提炼，旧候选编号只用于追溯。

### 4.1 从增长分析中识别计算工具

以原 M12 的 CAGR（复合年增长率）为例：若职责是对已提供、口径相容的起终值与期间执行一个固定算法，并交回结果及依据，可以作为工具方法候选。取数、补全资料、决定是否适合本题，由上层或其他方法承担。

| 五要素 | 示意内容 |
| --- | --- |
| 能力声明 | 在明确适用域内计算增长率，不由历史增长推断未来增长 |
| 所需权限 | 使用本次获准的输入；不自行调用外部取数方法 |
| 做法 | 声明起终值、时间及口径输入，检查相容性，执行已确认算法，声明结果与依据输出 |
| 校验 | 检查期间、主体与口径；用独立样例验证计算，缺项与不适用分别处理 |
| 审批 | 纯计算的额外审批需求按实际契约说明；数据使用和费用仍受平台规则约束 |

输入视图由这些声明生成，返回视图只包含承诺的结果及依据。本次不确定所有正负值政策、变体或正式字段，也不把它拆为除法、乘方、减法三个方法。

### 4.2 从证据分析中识别模型判断工具

以旧 E04“限定证据核对”为例：接收指定结论、已获准的材料及作者判据，在固定职责和预算内判断支持程度并提供引用，可以作为工具方法候选。需要模型判断不妨碍其属于工具方法。

工具内部不能再调用一个读数方法去搜集证据。若任务还要求搜索报告、筛选材料、调用别的方法核实数据，就应由专家步骤先组织这些调用，再将结果交给证据核对工具。范围不足时返回缺项或未覆盖，不自行扩大范围。

校验应区分“引用确实存在”和“引用支持结论”；支持判据、材料完整性和停止条件均须专项定型。本文不把旧样例的“模型请求读取工具”保留为工具方法通用能力。

### 4.3 预测与回测的组合边界

旧 P02 将滚动回测写成一个工具候选，同时又要求使用 P01 的预测能力。这需要按实际依赖重新判断：

| 实际做法 | 分类示意 |
| --- | --- |
| 使用固定且有版本依据的内部算法库完成回测，不调用其他方法 | 可以评估为工具方法候选；不能为了分类而复制原本需要独立复用的方法 |
| 多次调用已注册的预测工具方法，再调用结果评价方法 | 属于专家方法，不因全程确定性计算而成为工具方法 |
| 多次调用同一个预测专家 | 若无其他专家身份或专家团依赖，仍属于专家方法 |
| 允许调用两个不同预测专家，或调用已有专家团 | 属于专家团方法，实际本轮只选一个不改变冻结类别 |

本次不替 P02 选定最终实现路线。正式提炼要同时考虑职责、复用、版本与独立验收，而不是以减少方法数量为唯一目标。

## 五、旧内容如何留给专项提炼

不在本轮为 M01—M20 分配最终类别、方法数量或实现入口。后续专项提炼应逐项核对三件事：原承诺是否保留、可复用职责如何提取、组合及待定内容交给哪里负责。

旧稿中的编号只保留为历史定位线索：

| 编号 | 旧稿用途 | 本轮处理 |
| --- | --- | --- |
| M01—M20 | 原 20 项财务内容 | 待专项逐项对照，不等于 20 个工具方法 |
| A / Q / O / V / R / E / P | 变换与比率、勾稽、经营、估值、事件、证据、预测等候选索引 | 不作为当前可调用目录；具体表格从第七节所列 Git 版本查阅 |

原候选调用名 `fin_*` 不表示已有平台函数或线上注册项。缺少定义、实现或测试的条目保持待提炼状态，不以文档改名代替孵化。

专项提炼应保留并复核已有业务约束，例如原四式与 1 元阈值、原 4/8 季预测要求、回测不使用未来信息、现金流口径区分、原值与证据留存、资料缺失与业务不适用的区别。这些在本轮是需要追溯的既有要求，不新增财务准则结论或作者投资判断。

组合的具体编排归[财务专家孵化方案](新财务专家孵化方案.md)，通用模板和执行约束归方法主稿。本文件只解释如何识别工具能力及其边界。

## 六、专项提炼的完成条件

正式工作开展后，每项须具备来源与作者接受依据、完整五要素及两视图、分类与依赖检查、真实实现与环境约束、独立测试和未覆盖说明。只有完成主稿规定的孵化准入，才能进入可调用目录。

验证至少包含：输入缺项及口径冲突、职责边界、结果证据、取消与恢复、越权和隐藏方法调用拒绝。组合还须验证各层承诺和导出映射；子方法通过不等于专家整体通过。需要真实模型时另行验证语义质量，不能用固定假结果代替。

固定财务专家在等价迁移验收前保持可用，验收后删除旧执行路径；不因此长期保留两套契约或兼容分支。

本轮交付只包括示意文档、改名和相关引用调整，不包括具体方法提炼、代码实现、资产注册、模型调用或部署。下一次专项工作再按作者确认的范围逐项产出方法定义和验证证据。
