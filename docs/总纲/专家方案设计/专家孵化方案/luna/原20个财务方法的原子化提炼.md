重写日期：2026-11-11。依据：[方法、步骤、组合与模板](方法、步骤、组合与模板.md)第一节。状态：按工具契约重新提炼的设计稿；不是已经注册或通过业务验收的方法资产。

本稿于 2026-11-11 按“原子方法就是工具”的口径编写，逐项回答原 M01—M20 应提炼出哪些可调用能力、调用需要什么输入、交回什么结果、程序怎样执行以及怎样验收。旧稿的“45个职责”不再直接当作45个原子工具，旧审查作为历史来源保留。

通用定义和 C01—C15 组合模板在[依据文档](方法、步骤、组合与模板.md)维护；本稿只记录旧内容的提炼去向。作者流程见[孵化方案](新财务专家孵化方案.md)，运行机制见[执行与验收](../../专家使用方案/luna/财务专家执行与验收方案.md)。

2026-11-12 通用结构已统一为“方法”。本稿保留原文件名和提炼编号，“原子”仅描述当前拆分边界，不表示固定注册类型或最低层级；下文候选契约仍需补齐新定义的六要素、对外输入和步骤内部映射，本次仅更新依据及定位，不将旧稿标为已完成新契约迁移。

## 一、按原子工具要求重新判定

### 1.1 提炼的交付物

一个原子方法应交出业务定义与调用接口相统一的工具契约，而非只有名称、正文或职责描述。

| 依据文档要求 | 本稿的提炼要求 |
| --- | --- |
| 独立用途与适用域 | 说明解决的问题、可接受输入和结论边界 |
| 可独立调用 | 有候选调用名；不能依赖“先跑过M02”等隐含会话状态 |
| 输入输出明确 | 事实、参数、证据、结果都有字段和含义；质量摘要不能代替数值 |
| 规则与验收 | 固定算法或判断规则，规定缺项、不适用、冲突及正反例 |
| 程序执行入口 | 指明拟采用的函数、接口或进程；需要模型时由程序组织推理和处理工具请求 |
| 接入与实现分开 | 同一契约可以直接注册或经MCP接入，不按协议重复创建业务方法 |
| 调用来源分开 | 程序直接调用与程序处理Tool Call使用同一契约、权限和验收 |
| 版本与复用 | 不绑定某位专家或某一步；冻结定义并记录实际执行绑定 |

有接口提案但没有实现、绑定和验证的条目仍是候选。缺少公式、适用域或验收判据的条目不得进入可执行目录，即使已经有英文调用名。

### 1.2 拆分边界

提炼后的内容分为：能形成独立调用契约的原子工具候选；组织多个业务工具的组合；尚缺输入、规则或验收的待补规格。

原子工具内部可以包含多个公式、程序步骤和基础工具调用。CAGR不拆成相除、乘方、减一；杜邦分解与量价桥可以保留完整业务用途。当若干业务能力需要由作者分别选择、替换和验收时，在组合中表达关系。

本轮将 A06、O03、V06 明确为**目录分组**，下属能力各有具名接口和输入规则。实现可以共用函数库，不要求每项独立服务或文件。A04的同比／环比可以保留受限枚举，但不能开放任意公式字符串。这是本稿采用的具体提炼方案，不改写通用文档允许固定配置的原则。

授权、审批、等待、预算和交付动作继续使用通用运行机制；文件读取等基础工具可以注册，但不因注册而自动成为某个财务专家的业务方法。

### 1.3 编号与实现状态

M编号追溯旧20项；A/Q/O/V/R/E/P编号保持与组合模板对应。`fin_*` 是候选调用名，尚不是线上注册名。组合引用A06/O03/V06时须选定具体子项，不能执行分组名。

目录使用两个实现说明标记，**不是新增执行类型枚举**：

- **D：**确定性程序处理，优先用函数实现；部署时也可通过HTTP、进程或MCP绑定访问。
- **N：**程序组织证据提取或模型推理，并检查结果；入口仍是函数、HTTP或进程。模型生成内容和调用请求，程序执行调用。

全部条目的工程状态都是“候选，本轮未实现、未绑定”。标注“待定”的条目另有业务缺口，写出程序也不能代替作者定型。

## 二、原子工具共同契约

### 2.1 输入、输出和上下文

| 内容 | 共同要求 |
| --- | --- |
| 事实输入 | `fact_ref`指向具体版本；包含或可解析主体、指标、期间／时点、范围、单位、币种、数值、来源、披露时间、重述口径。金额保真，不从模型自由文本猜数 |
| 成果输入 | `artifact_ref`指向上游方法版本、调用及结果版本；检查业务类型，不能把勾稽摘要作为营收 |
| 文本证据 | `evidence_refs`限定材料版本、章节或段落；输出引文能回到对应原文 |
| 配置与假设 | `config_ref`引用已接受的公式、口径、阈值和适用域；本题假设有提出与接受依据。选择配置不等于任意改写配置 |
| 业务输出 | 具体业务字段，加`status`、原因、主体期间范围、输入及证据引用；计算保留`compute_id`或等价收据 |
| 调用上下文 | 用户、授权、任务、方法版本、绑定和预算由宿主提供，不信任模型自报权限或验收结论 |
| 运行记录 | 分别保存技术执行状态、业务结果和验收判定；返回成功不等于业务正确 |

业务状态沿用方案中的`computed/observed`、`missing`、`not_applicable`、`unverified`语义。非法结构、越权属于调用错误；事实缺失列出缺项；口径冲突交未核验及冲突项，不静默拼接。`balanced/unbalanced`或支持／不支持是工具自己的业务结果。

数值工具的一次完整调用包含事实解析、相容性检查、算法计算和证据生成，可复用现有基础能力。只返回裸数值的通用计算函数不足以直接代表完整财务原子方法。证据工具允许有依据的零项、未知或不适用，不强迫凑数。

### 2.2 定义、绑定与调用

原子工具保存`id/version/digest`、用途、适用域、输入输出、规则和验收。执行绑定保存`binding_id/method_ref`及类型专属配置：

| 接入配置 | 必需内容 |
| --- | --- |
| `direct` + `function` | 已注册函数标识、实现版本、输入输出映射；N类可指向组织模型推理的程序函数 |
| `direct` + `http` | 服务引用、请求和响应映射、错误约定；HTTP成功不替代业务验收 |
| `direct` + `process` | 程序和参数；脚本另含解释器与脚本版本；输入输出约定 |
| `mcp` | 服务引用、远端工具名、契约映射、可得的实现版本依据；发现工具不等于业务契约完备 |

本稿仅规定绑定所需内容，不编造函数文件、服务地址或现有MCP能力。当前候选保持未绑定；真实实现、授权环境和验证依据齐备后才可执行。业务参数不能任意替换程序入口。

程序直接调用和模型Tool Call最终走同一执行入口；用`origin=program/model_tool_call`记录来源。注册、获得使用权限、展示给模型是不同环节，执行时再次检查。方法版本与实际绑定须可追溯，目录刷新不能无记录地替换实现。

## 五、三个完整的提炼样例

### 5.1 A05 CAGR：确定性计算工具

| 契约项 | 规格 |
| --- | --- |
| 身份用途 | 候选名`fin_cagr`；求可比完整年度间复合增长率。版本及摘要在定义冻结后产生 |
| 输入 | `start_fact_ref`、`end_fact_ref`、`metric`、`config_ref`；事实解析后包含主体、年度、币种、单位、报表范围、重述口径、十进制值及证据 |
| 适用域 | 两端可读取且相容，终年大于起年；首变体两端均正；不把季度间隔当年度 |
| 参数边界 | 程序生成`n=end_year-start_year`；不接收模型自报n替换年差，不开放公式参数 |
| 程序过程 | 解析事实→核相容性与适用域→计算`(end/start)^(1/n)-1`→生成收据→结构化交回 |
| 输出 | `status`、指标、起终年、`years`、`cagr`、输入引用、`compute_id`和口径；非computed时不伪造数值 |
| 异常 | 缺端点为missing；范围或版本冲突为unverified并列冲突；非正端点为not_applicable；非法参数及越权由调用层拒绝 |
| 绑定建议 | 优先direct/function；可采用等价的进程或MCP绑定。当前未实现、未绑定，不编造入口 |
| 验收 | 独立核身份、年差、公式、操作数、收据和数值；精度与容差在配置冻结，展示舍入不污染计算 |
| 合成正例 | 2021=100、2023=121，years=2，cagr=0.10；2021=100、2024=133.1也为0.10 |
| 反例 | 第一例交回years=3须拒绝；混公司、未转换单位、缺端点、零负端点、季度冒充年度分别验证 |
| 复用 | 年度财务分析和研发增长各传自己的事实；调用不含固定专家或上游步骤ID |

程序直接调用和模型请求调用传相同业务参数、走同一执行入口。未来若允许终点为零，另立明确配置，不在本变体中临时解释为-100%。
