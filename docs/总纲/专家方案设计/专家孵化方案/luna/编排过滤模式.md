# 编排过滤模式

编排从交付目标出发。**最先发生的是权限过滤**，由宿主确定当前身份能查哪些版本。随后，模型与作者根据任务筛选方法，读取候选契约，再据此修改草图。一个新选中的步骤可能暴露新的输入缺口，需要回到目录补查。通过校验并获确认的草图才形成执行清单。方法分类、冻结契约、核权和审批以[方法主稿 §1、§2.8、§3.2.1](专家方法孵化与递归编排方案.md)为准。

## 一、先确定谁在选、从哪里选

**孵化问“哪些方法能持续解决这类问题”，即时编排问“解决用户眼前这一题需要哪些方法”。** KnowLab 以作者对一类问题的通用声明筛选候选，以代表性场景检验覆盖范围。KnowBench 从本次问题要求的具体交付出发，先用现成专家的声明判断能否整体交付，未命中且用户同意拟计划后才开始补步骤。候选的声明是两处共用的比对材料。

例如同一作者同时获准使用按交易号对账和缺号核对的方法。孵化声明若承诺两种情况，就要为两种情况设计并试跑。若用户只要求核对本月两张有统一交易号的表，且获准的结构信息已证实该字段，就只安排按交易号核对；字段未知时先澄清或申请探查。

| 场景 | 可见范围和选法责任 | 选定后得到什么 |
| --- | --- | --- |
| 聊天、工作中的原生 MCP／Skill | 平台与用户限定本轮暴露范围，Codex 在当前会话已加载的能力里发现和选择。聊天服务于对话，工作服务于本地任务。 | 本轮原生请求。受管操作派发前仍核验当前授权。 |
| KnowLab 孵化工具或专家 | 作者按孵化引用资格查本人已登记工具、平台授权工具及已获取且允许引用的版本。作者与模型起草，宿主核验，作者逐项采用。孵化试跑可使用未上架草稿。 | 可保存的工作稿。实测通过后冻结、登记，正式自用须自用上架。 |
| KnowBench 即时自组（设计） | 按使用者本人正式使用资格限定目录，结合当次请求、获准资料和预算选法。 | 供本次确认的计划。保存复用时重新核权；需要成为正式专家时送回 KnowLab。 |
| 运行已有专家 | runtime 按精确版本解析孵化时冻结的清单。固定计划直接展开；含允许变化的专家只在已冻结的候选与条件内选。 | 唯一的本次执行清单与逐层调用记录。子专家按同一规则展开。 |

目录中只有工具方法和专家方法。一个 MCP／Skill 可按可独立声明、授权和验收的业务动作孵化成一个或多个工具方法；需组合多个方法并对整体交付负责的业务做法，可孵化成专家方法。P1–P5 只出现在规划和编辑阶段。完整样例及孵化粒度见[方法主稿 §1.4.3、§1.10](专家方法孵化与递归编排方案.md)。

## 二、从可查目录到可确认的计划

### 2.1 首轮选法与有界循环

1. **宿主先限范围。** 按身份、场景、版本资格与许可确定可查目录，记录快照。把当前运行器支持的结构和 §4 的五行选用提示放进规划上下文。查询、采用和派发时分别核验相应资格。目录条目可见与本次有权读取资料是两项独立事实。KnowBench 的规划查询先向 KnowMart 取当前主体有使用资格的确切版本，再与方法技能管理中心登记相交，按步骤类型与本题文字筛选排序。买家未取得的公开版本不会占其检索窗口。单窗最多 100 个资格引用，窗口内仍可能只有工具或缺少合格专家，分页未尽时保留范围提示。
2. **先核对整体交付。** 目录完整且名称和一句话能力说明放得下时，模型先看全图，再点选少量契约；目录过大或尚未完整枚举时，先描述交付目标，由宿主限量召回，记录分页和覆盖范围。两种入口都先核对能整体承接的冻结专家。工作台「请专家」先核对专家版本，匹配后交用户确认。若已查范围内无命中，先等用户选择拟临时计划、去孵化或结束；选择拟计划后才考虑单个工具或短链。孵化时按作者声明判断整体覆盖，可以直接核对足以承接的版本。
3. **把缺口写成可查的槽位。** 已查候选无法整体承接时，从必交产物倒推，将目标步骤的必需输入逐项标记为调用者提供、前序产物提供或待补。模型提出要找的产物和业务口径，宿主按输出的 `meaning`、Schema 和必需性查可用版本。名称相似只值得进一步核对。口径或单位不同时须有明确转换方法。对兼容版本，作者可采用前置绑定；接不通时可换下游方法，再验受影响的连线、导出、权限及费用。
4. **资料结构未知时保留未知。** 例如对账方法要求两表都有交易编号。只看文件名，无法判定该字段存在或缺失。优先读取本人获准、绑定确切资料版本的结构摘要（列名、类型、期间等）；无可用摘要时暂停依赖这一判断的路径，单独申请轻量只读探查，按批准范围返回结构及证据。检索不会自动读正文。探查后恢复同一草图和剩余预算；若确认缺列，则补查能生成该槽位的方法，或请用户裁定替代匹配口径。
5. **宿主决定本轮出口。** 对同一缺口契约、可达输入、已知结构、授权和目录版本，保存已查页、已试版本与绑定、排除依据。改写查询、改节点名或切换 P1–P5 都沿用这份记录。每次再查、探查或付费规划前检查取消、权限及剩余额度。

| 出口 | 可检查的条件 | 留下什么、由谁接手 |
| --- | --- | --- |
| 完成 | 必交成果可达、必需输入有合法来源或约定的补充方式、无环，关键歧义及能力缺口已解决 | 停止搜索。作者审定并试跑，或由使用者确认本次计划。 |
| 继续 | 仍有缺口，且有预算内能改变判断的未试动作 | 记录下一页、待验版本、前置绑定或替换的下游，改图后重验。 |
| 等待 | 剩余可行路径都依赖探查、授权或口径答复 | 保存修订、已试项和余额，停止自动查询；新事实到达后只重查受影响部分。 |
| 结束 | 取消、无可行新动作，或下一必要动作超预算 | 保存最后有效草图、具体缺口和已查范围；部分召回只能说明本轮未命中。取消后迟到的回执归原记录。 |

KnowLab 允许在作者认可的费用和时间内多轮比较。KnowBench 即时自组默认优先整包专家、单一工具或短 P1；明确需要多角度分工、独立复核或逐对象比较时才展开相应结构，并在确认页展示增加的轮次和费用。即时自组首期预算按主稿设计为最多补一个前置、换一次下游；三轮目录查询、八个候选节点是待盲测的试验初值。分页、探查恢复和换模式均计入同一累计预算。运行中的复核返工另行计数。

**KnowLab 作者页已接入的部分。** P1 的本人、共享目录都支持手动翻页和按累计页数自动补查。作者为本孵化项目设总页数并启动，界面预填 6 页，可填 1–100。后端在每次读取目录前预留一页，记录同一目标方法、目录、槽位语义、Schema 和必需性的游标与已返回的版本输出。改写槽位说明、改草图修订或重开页面保留记录。空页有后续游标且尚有额度时继续，首次有新候选时交作者预览。目录已查完或预算不足时显示该缺口已查页数和项目总用量。手动停止保留草图，本次已经发出的页计入用量。目录授权或内容变更后可手动复查，采用、试跑和冻结仍各自核权。本项限额仅覆盖自动目录读取。结构探查、模型规划费用及 KnowBench 即时自组另行实现。

**多步草图怎样找缺口。** 作者先指定哪一步的哪项调用者输入缺少来源。页面沿该步已有依赖向前查找契约相容的输出。多个前序都能提供时，列出具体步骤和输出槽由作者选择；选定后添加直接交接边。其他分支的同名输出不参与。没有合适产物或作者决定另查时，再到授权目录补前置，也可按原导出或下游实际消费的输出改选该步。此入口针对必做、已选定一个方法版本的步骤。资料字段是否存在仍须有对应版本的证据。

作者可先打开「核对样本表头」，再选步骤和输入。选择已向 KnowLab 展示的资料版本，填写列名；CSV 的工作表名留空，XLSX 填确切表名。点击核对后由 KnowBase 凭作者身份重查展示资格、持有权和版本摘要，在服务内按需解析原件的第一行。页面只收到所问字段的判断及版本凭据。已观测到列可确认存在；只有完整表头才能证明缺失。格式不支持、表名不符、表头截断且未见该列，均保留未知。样本没有该列时，作者可沿当前草图先看可达产物，再用项目剩余页数补查或改选。样本的结果只用于本次设计判断，专家的通用声明和下次委托的资料资格仍各自核对。

### 2.2 人审定计划时

KnowLab 的 P1 预览标出基础修订，逐项展示精确版本、输入绑定、依赖、导出、授权要求及步数上限的变化。作者采用后保存，工作稿在同一事务内记录作者身份、采用的完整定义与前后修订。相同保存请求重发可取回该次回执；若已有后续编辑，则须按新修订重新核对。

确认页应从实际草图生成适用项目。多分支时列出汇合所等的产物，独立判断时列出隔离能力及待决定的裁决人，多对象时列出数量、上限和汇总规则。每项带关联步骤、核验结果或待答问题；运行后再补实际证据。可执行性条件与证据要求以[方法主稿 §2.10](专家方法孵化与递归编排方案.md)为准。审定者至少能回答：

- 每项必交成果由哪个步骤负责，是否有遗漏或重复工作？
- 选择的方法及版本是否适用，输入能否满足，关键交接是否有验收？
- 所谓独立判断是否真的隔离了对方结论，复核是否有证据可查？
- 某步缺资料、失败、出现分歧时，计划会等待、返工、交部分成果还是结束？
- 是否增加了账号、数据、外发或费用要求，估算包含复核与汇总了吗？
- 这份计划采用了模式的哪些部分、改了哪些部分，修改后仍能达到目标吗？

创作时，人工选方法与 AI 起草进入同一编辑草图。作者审定涉及多个步骤的完整差异，核对每项承诺的责任步骤、导出、检查与测试；期望答案、金融口径与阈值、外部数据源单独采用。正式调用应能追到精确的方法身份、版本和摘要。

计划确认仍使用主稿的统一确认流程。已确认范围内的展开不因引用模式再加一次审批；具体写操作和范围扩大仍按原规则处理。人在审定时可以提出修改，但不能通过“同意此模式”绕过方法资格、数据许可或平台约束。

### 2.3 在草图中写清谁委托、谁交回、谁收口

构造协作草图时，在有交接的边上明确委托方、接收角色、绑定的输入版本、预期导出及由谁验收。实际运行由宿主按[主稿 §2.9.4](专家方法孵化与递归编排方案.md)记录请求、回执和处置。P1 可用已验收的类型化返回直接交接；P2 的各分支、P3 的各复核角色、P4 的各对象实例分别交回，P5 的子专家只向直接父调用交付声明的导出。

例如，A、B 独立复核报告 v1。A 先交回发现 F01 和证据引用，父方可以处理其他工作；若 B 是必需复核方，汇合仍须等待。期间作者改出 v2，B 的回执仍明确评的是 v1。父方把两份发现分别处置，标出 v2 中需要复查的条目。模型窗口更换、证据链接可见或其中一方写了“通过”，均不会替另一方交卷或替父方结案。

每个接收角色只追加自己的回执，注明实查版本、事实、推断、建议、缺项和证据引用。大文件留在 Artifact，汇合方按权限读取。直接父调用逐项记录采纳、未采纳或待定及理由，并负责结案。角色、方法版本和执行模型分别记录；获准换模型后沿用原调用关联，重新核对外发、预算和隔离。受阻记录缺少的条件，重复回执按原轮去重，结案或取消保留失败证据；新问题另开关联委托。产品使用现有 Task、Attempt、Artifact、Interaction 记录。[协作请求使用说明](../../../../sync-cowork/协作请求使用说明.md)

## 三、五种参考模式

以下箭头表示成果依赖，不意味着每个方框自动成为新方法。落实后每个执行步骤须绑定一个已孵化方法；有多个调用的方框须展开为多个步骤，或绑定已有的专家方法。

### P1 串行接力

**适用条件**：后续工作明确依赖前序成果，例如资料提取后才能分析，分析后才能形成报告。各阶段有可验收的交接物。

**不适用情形**：多个任务实际上互不依赖，串起来只增加等待；或者本来一个适用方法即可完成，拆开后没有独立职责。

```text
输入 → 方法 A → 验收交接物 → 方法 B → 验收交接物 → 方法 C → 整体验收
```

**可调整项**：各位置的方法、阶段数量、交接字段与资料引用、允许的缺项处理。关键关系是“后续消费前序已接受的明确版本”，不能为了赶进度跳过这一条件。

**审定重点**：A 的输出是否真能满足 B 的输入，主体、期间、单位和证据是否一致；前序修订后哪些后续结果需要重验；阶段拆分是否有价值。

**成本与风险**：总时长沿依赖累积，前序等待会阻塞后续；中间产物丢失或含糊会使恢复困难。步骤数不直接等于模型轮次，确定性调用不必开启模型规划。

### P2 多方向分工后汇合

**适用条件**：不同方面可以分别处理，最后共同支撑同一交付，例如对同一项目分别分析实施条件和资源约束。

**不适用情形**：分支依赖尚未取得的另一分支结论；多个分支只是换名称重复分析；缺少能够接收各分支成果的汇合规则。

```text
             ┌→ 方法 A ─┐
获准输入 ────┤          ├→ 汇总方法 → 整体验收
             └→ 方法 B ─┘
```

**可调整项**：分工维度、各分支方法及输入范围、必需与可选分支、汇合方法。需要汇总内容时绑定相应方法；平台仅收集引用不等于完成内容汇总。

**审定重点**：分工是否覆盖目标，是否存在隐含先后依赖；汇合等待哪些成果，失败分支怎样影响承诺；是否会无协调地写同一个文件。

**成本与风险**：多个分支增加调用和汇总成本。逻辑上无依赖不保证运行时能够并行；主稿首期按 DAG 串行执行，并行调度须另行验证。参考本模式不能承诺缩短多少时间。

**作者操作（固定必需分支）**。在 KnowLab 作者页用一个有至少两个调用方输入的冻结工具方法创建专家草稿，或在已有草稿中选择这样的步骤。在「P2 多分支汇合」选择汇合步骤，逐个选择接收产物的输入。目录按接收槽的结构和业务含义查找获权的输出。每次选择一个确切方法版本和输出，将分支加入预览。分支输入各有自己的名称；作者可以在采用后编辑它们的绑定。

预览会列出每条边、外部输入、锁定版本和权限变更。可撤回最后加入的分支；加入至少两个分支后可整图采用，再按当前工作稿修订保存。采用时重查每个候选，共享方法另外复查所选安装修订。正式试跑仍逐叶批准。已用两个隔离脚本分支及一个双输入汇合脚本核验产物流向，第二个分支等待批准到期时，账本保留第一个分支的成果并停止汇合。

**试跑缺项与接收**。作者在失败用例下可见各步骤的执行情况、依赖、原始失败原因，以及依赖缺失导出的承诺。对每个通过核验的步骤，页面列出输出字段、产物编号、版本和摘要。作者按「确认仅接收」逐步选定本次接收范围，随后可查看这个版本的输出。该决定登记在原试跑用例下。重复接收可重开同一份成果，原验收结论保留。未执行的汇合步骤没有交付物。当前支持一层固定必需分支的作者试跑。普通委托中的范围确认和可选分支另行验收。

### P3 独立分析后交叉复核

**已有成果定向复核。** 先绑定待审版本，省去重新产出候选的步骤。先跑适用的必过机器检查（V0），如字段完整、数值勾稽、引用存在；通过后才派发模型复核（V1）。普通查错默认只做一轮；严格独立复核可配置“先独立审、冻结发现、再对照作者自评”。草图展示额外轮次、费用范围、分歧处置人及返工上限。首次提交后，同一复核任务最多自动返工两次，且受计划和预算的较严上限约束。仍有分歧则交人裁定，保留各版成果、发现和未决项。[复核协议来源](../../../../process/turn/protocol/competition-protocol.md)

**作者当前可以怎样准备复核。** 在一层固定图通过的试跑中打开某一步，或在中断的分支汇合试跑中打开已核验的分支。先确认接收该步产物，再勾定要交给复核方的输出并填写检查。例如，选中 `report`，要求 `/report/unmatched_count` 精确等于 0。也可检查字符串包含、数值绝对容差。字段缺失、类型不符或任一检查失败，作者页逐项显示结果，交接清单为空。全部通过才保存该产物版本和选定输出的摘要，状态显示等待隔离复核。KnowBench 从自己的已核验证据取值，浏览器仅提交范围和检查。作者可重开草稿，两个窗口同时修改时须按最新版本继续。

交接的最小单位是一个命名输出。检查某个输出内的子字段会将整个所选输出纳入拟交接范围。需单独保密的内容应在方法契约中另设输出槽。当前实现覆盖试跑留下的精确版本，模型复核及跨次委托仍按第 12 项验收。

**严格复核草图的操作。** 在复核边上先选独立助手，可沿用同模型或要求不同家族。若复核步骤的输入均直接绑定同一待审步骤，且至少用了两个不同的输出，即可把其中一个指定为第二轮的作者自评。其余已绑定输出列在首轮。对已接收的试跑产物，也可以先给首轮各输出设置 V0 检查，再从该版本其余输出中选一个作自评。只有单一输出时，使用普通单轮复核；要采用严格模式，作者须先拆分成果和自评。

例如，作者把 `receipt` 列为首轮成果，把 `assessment` 留作自评。V0 全部通过后，作者看到首轮清单中只有 `receipt`，另列 `assessment` 的摘要和开放条件。V0 失败时两份清单都为空。作者页可以查看自己已接收的完整产物。草图把首轮发现封存作为第二轮前提，未解决的分歧交本次委托所有者。自动返工上限默认 0，作者可设为 1 或 2。已有成果定向复核已接通两轮报价、隔离执行及首轮发现封存。委托人可在项目中逐条摘录原文并记录处置及理由。第二轮缺失时页面标明缺项，允许只处置首轮已有发现。普通两步固定图已支持从产出指令向独立复核指令交接。图内严格双轮、产出步骤的自动返工及其预算计数仍在第 12 项。

**谁来复核。** 作者在已有成果的交接边上选复核要求。例如 A 产出报告、B 读取报告，作者可以指定 B 使用独立助手，允许同模型，也可以要求 B 必须使用与 A 不同的模型家族。分别绑定同一复核方法版本时，这两个步骤仍有各自的调用身份。普通前序产物绑定默认按原步骤处理。每条交接边的复核要求随草稿修订保存，并随正式图传给校验与试跑服务。

| 作者的要求 | 运行器需要取得的证据 |
| --- | --- |
| 独立助手，允许同模型 | 新线程、受隔离工作目录和受控交接；复核者首轮只收到批准的输入和已验收产物。交付卡据实写明用到的模型。 |
| 独立助手，必须不同模型家族 | 先满足独立助手条件，再按受信的模型目录核对主笔实际家族与复核候选家族。不同账号、别名、推理档位或网关名称都不足以认定家族不同。缺可用家族、报价、对该目的地的外发许可或剩余预算时，派发前展示缺口。放宽条件需明确确认并记录修订。 |

| 用户实际配置 | 隔离运行开放后的选择 |
| --- | --- |
| 一家供应商，一个模型 | 普通复核可用该模型另开隔离线程，只交付指定成果。要求不同家族时显示缺口。 |
| 一家供应商，多个模型 | 比较主笔和复核者的受信家族。两个别名属于同一家族时，严格复核仍有缺口；确属不同家族时，可在同一供应商内复核。 |
| 多家供应商或外部助手 | 按实际家族、获准外发目的地、价格及剩余预算筛选。用户明确选定的路由不可用时返回缺口。 |

已接收的试跑产物通过 V0 后，作者可进入 KnowBench 选择本次复核连接。页面列出首轮允许交出的命名输出、严格模式下延后交出的自评、计划目的地与费用上限，保存后可重开。对允许同模型的单轮复核，作者可选本人登记的指令版本，向已装载的精确连接派发。复核者在独立执行单元读取确认的命名输出，结果挂回本次委托。选择严格双轮时，首轮发现连同用量回执封存后，再开独立工作容器和线程作对照。第二轮只读取确认的首轮输出、封存发现和指定自评，两轮费用合计受根预算约束。普通 P3 委托已在本地跑通两步固定指令图的单轮交接，复核输入须直接绑定同一产出步骤的命名输出。图内严格双轮及跨家族取证在第 12 项后续验收。外部 A2A 当前仅支持 GetTask。接口字段、单供应商配置示例和恢复语义见[主稿的复核助手接口与配置](专家方法孵化与递归编排方案.md#复核助手的接口与配置)。

**适用条件**：问题需要检验推理或证据、暴露盲点，值得增加独立判断与复核环节。

**不适用情形**：简单确定性计算已有充分校验；双方没有独立证据或检查能力，只会重复相同结论；成本不允许复核和分歧处理。

```text
             ┌→ 独立分析 A ─┐
获准资料 ────┤              ├→ 复核方法 → 按规则处理分歧 → 汇总方法
             └→ 独立分析 B ─┘
```

**可调整项**：分析方法、复核方法、初始可见资料、后续开放的成果、补充分析的条件与次数。独立阶段不能提前看到对方结论；共享获准事实不等于共享结论。角色不同也不自动证明判断独立。

**审定重点**：复核依据是否具体，谁负责处理分歧，哪些差异可以由证据解决，哪些必须保留或由有权的人判断。“处理分歧”如果含分析或计算，就须落实为方法调用，不能仅写一个角色名。

**独立性验收**：A、B 可以串行，甚至引用同一专家版本。运行器为两次独立分析分别绑定 Codex 线程与受隔离的工作目录。用例要实际尝试读取对方的线程历史、草稿和工作文件，三者在恢复前后均应被拒。复核阶段只向 C 开放计划指定的已验收产物；事后能追到来源调用与版本。具备这些证据后，才可向用户展示“独立复核”。

**成本与风险**：至少增加分析、复核及可能的返工成本；一致不自动代表正确，不默认多数投票或汇总模型拥有裁决权。有限复核轮次按规则展开或修订计划，不在 DAG 中添加无限回边。

### P4 同一方法处理多个对象后比较

**适用条件**：多个对象可以按同一职责和口径处理，需要比较或合并其结果。

**不适用情形**：对象口径差异过大，无法用同一方法或预先约定的规范化处理；对象之间存在必须先处理的业务依赖；缺少比较许可或可比性依据。

```text
对象清单 → 对象 1 调用 M、对象 2 调用 M、…… → 比较方法 → 整体验收
```

**作者操作。** 在 KnowLab 先从获权目录选定汇总工具方法，再点「配置多对象比较」选择单对象工具方法。选择对象编号输入、单对象结果输出和汇总输入，核对两端的方法版本、绑定和权限差异后采用并保存。首期支持一个单对象步骤和一个汇总步骤；二者分别钉住方法编号、版本和摘要。缺少相容的汇总输入时，编辑器指出缺口。

公开输入为非空且去重的字符串编号清单。作者指定上限（1–99，初始值 10）；例如设为 3，调用方可以提交两家公司的编号，也可以提交三家。汇总方法接收具名行，如 `[{"object_id":"甲","value":12},{"object_id":"乙","value":8}]`。每行的值须符合单对象输出的结构，汇总槽须声明相同的业务口径。清单之外的共用参数仍由各自绑定提供。作者可选「停止比较」或「请求确认是否接收部分结果」，后者只声明遇到缺项时须询问。

当前作者页可重开并修改上限及缺项策略。运行器收到这类图时返回 `runtime_capability_gap`。第 12 项验收时，须以获准清单版本和对象编号关联各实例，核对逐对象授权、恢复、产物和部分接收回执。

**可调整项**：对象范围、方法版本、实例数量、单对象输入、比较方法、缺失对象的处置。每个对象形成独立调用记录，不因使用同一方法而混用输入、授权或成果。

**审定重点**：对象清单是否获准，资料时点和口径是否可比，缺失对象是否被如实标记；同一方法多次调用时是否能准确关联各自产物。

**成本与风险**：成本随实际实例及比较工作增加；样本遗漏可能扭曲整体结论。不能因内容相同就无条件复用数据或免计费用，数据版本、授权与真实计费规则仍须满足。

### P5 按问题选择分工并逐层展开

**适用条件**：问题之间所需能力差别较大，作者已提供候选方法、选择条件及必做规则，需要使用时再形成具体分工。

**不适用情形**：唯一合法计划已知，可以由程序生成；候选缺少契约或使用资格；作者只写“自由发挥”，没有可核验的选择与交付边界。

```text
本题目标与条件 → 在规则内选择方法 → 形成当前层计划 → 核验及适用确认 → 按需展开执行
```

**KnowLab 作者操作。** 在已有固定图里选「配置候选方法」，指定一个必做步骤，选它从调用方接收的必填字符串输入。为原方法和新增候选分别填写触发值。例如资料类型为“快报”时选提取工具，为“年报”时选已冻结的核对专家。当前每个槽可列 2–8 个钉版候选，每个值对应一个版本。精确比较区分大小写，缺值、未命中均停下澄清。其余必做步骤继续保留。首期作者可从本人目录选工具或专家，从共享目录选已获准的工具。

先点「核对候选和展开上限」。KnowLab 按当前草稿修订读取各候选、核对登记或共享授权，检查输入、输出和权限上限，计算各层所需的最大深度、步骤数与展开数。一个槽的互斥候选取最大值，同一次计划的必做步骤累计。例如一个必做槽在工具和单步专家之间选择，整图至少需要深度 3、步骤 2、展开 3。上限不足时页面给出这三个数，作者修改后重新核对。核对通过后才能在页面采用差异。保存重开后可逐项修改触发值并用样例预览命中结果。当前运行器报告条件选法能力缺口，普通委托中的实际选择、确认与恢复见第 12 项。

**可调整项**：在冻结规则允许范围内选择方法、安排职责和组合 P1—P4。模式本身不能扩大候选范围、删除必做、放松验收或赋予新权限。

**审定重点**：选择能否覆盖目标，未展开部分的需求和成本是否说明；没找到候选是否真的是已查范围内无匹配；选择变化是否仍处于批准范围；何时停止展开或请求变更。

**成本与风险**：规划本身可能产生模型费用；过度拆分增加交接和递归成本。正常展开与纠错重排分别记录，运行恢复沿持久计划，不能重新读参考模式后猜一份新计划。

若修改超出基准，先记录原承诺失效及差异。待普通委托入口、正式专家剪枝与暂停恢复通过验收后，用户才可现场自组；每次计划修订保存快照，继承已执行事实与确切产物，只展开未执行部分并复核新增范围。用户保存计划后可重新核验复用，若要形成可供他人调用的专家版本，须回 KnowLab 孵化。

五种模式都可用于专家方法。P4 同一专家处理多个对象时分别记账；P3 的独立分析与复核须核对过程上下文隔离、产物可见范围和执行证据。模式和角色均不改变方法类型。

## 四、怎样选用和组合

| 当前主要问题 | 可以优先考虑 | 仍须核对 |
| --- | --- | --- |
| 后续必须依赖前序结果 | P1 | 交接物可用性与依赖是否真实 |
| 几个方面分别处理后共同交付 | P2 | 汇合条件、分支覆盖、资源可用性 |
| 需要独立判断与复核 | P3 | 隔离、证据、分歧处理与额外成本 |
| 同一职责重复用于多个对象 | P4 | 输入可比、对象范围、各实例结果与授权 |
| 需按本题从候选中决定分工 | P5 | 作者规则、候选资格、必做与展开上限 |

这是选择提示，不是分类算法，也不要求每个计划只能属于一种模式。例如 P5 选定两个方向后，可用 P2 组织分支，其中一个分支采用 P1；需要独立复核时再引入 P3。每次组合都要说明增加的环节解决了什么问题，避免把模式数量当成计划质量。

### 4.1 贯穿示例：形成并复核项目方案

用户需要一份有依据的项目方案及未解决问题清单。假定已有获准资料和适用的已孵化方法，AI 可以提出采用 P3，并用 P1 安排后续交接：

| 步骤 | 调用及输入来源 | 预期产物与审定关注 |
| --- | --- | --- |
| A | 方案编制方法，读取本次获准资料 | 方案、假设与引用；不读取 B 的初始结论 |
| B | 约束检查方法，读取其获准资料 | 约束清单及证据；不读取 A 的初始结论 |
| C | 复核方法，绑定 A、B 已验收成果 | 一致项、冲突项、缺证项及其来源 |
| D（条件步骤） | 作者规则允许的补充分析方法，使用指定问题及获准输入 | 补充证据与仍未解决的问题；新增权限或费用范围按规则确认 |
| E | 汇总方法，绑定有效成果与未解决项 | 按导出映射交付方案及问题清单，不抹平分歧 |

**把本例放进选法循环。** 如果用户明确要求独立复核，首轮先查有没有能同时交付方案、复核证据和未解决问题清单的专家。已有专家如能在获准环境满足隔离及交付要求，就采用它。若只有能写方案的 A，P3 帮助指出具体缺口：还需要能独立检查约束的 B、只消费获准成果的复核方法 C，以及对应隔离能力。按这些需要查找和验证。若始终缺少隔离能力，即使 A 被调用两次也不能宣称完成独立复核；把缺口交给用户决定是否调整要求，或结束本轮。若需求只写“请复核”，先弄清是核对数据还是独立给出第二份判断，两者所需步骤和费用不同。

A、B 是职责独立的分支，并不承诺当前运行器并发执行。C 等待必需成果；D 只有在冻结条件触发时执行，补充次数受限。A 或 B 失败时，不能把空输入当作“本题未选”让 E 直接交出完整成功报告。

审定者应重点判断：B 能否检查本题真正关心的约束，C 有没有足够证据，D 是否有边界，以及最终交付是否如实保留未解决问题。若本题不需要独立检查，且作者规则允许，可以选用更简单的计划；不能仅因示例写了五步就固定照搬。

### 4.2 同一专家从单次协作到长期职责

用户可以只请该专家复核一次，也可以把同一冻结版本配置为长期职责。定时、订阅或连接器事件每次唤醒一件普通 Task，同一事件重送只建一件。需要跨期比较时，把获准的上次成稿按确切版本绑定到声明的输入槽；首次缺项和撤权按定义处理。新委托里的 A、B 仍须通过 P3 的隔离检查。跨次复用的是选定产物，临时草稿、历史线程与上次动作批准均留在原任务。此场景按主稿 §4.4 验收。

P2、P4 汇合时按分支或对象列出已完成、等待和失败项。缺项可带 ⚠ 提交现状及影响；能否交付部分成果依主稿 §2.4.1、§2.10 的契约和范围确认处理。

## 五、从参考模式到正式模板

### 5.1 在草图中一键套用

“套用模式”是编排期的编辑动作。作者或模型给出已选方法或保留空槽，宿主确定性地展开草图供审定。各方共享方法主稿 §3.2.1 的差异、采用及校验流程。预览应标明草图基础修订。重复采用同一差异应返回原结果；基础修订已变化时，重新预览受影响部分。五种骨架分别生成以下内容。

| 动作 | 展开到草图中的内容 |
| --- | --- |
| P1 串行接力 | 有顺序依赖的步骤及相邻步骤的交接槽。能确定的绑定直接展示，业务口径不明的留待选择。 |
| P2 分工汇合 | 各职责分支、汇合步骤、其等待的分支产物及绑定。分支可以串行调度。 |
| P3 独立分析与复核 | 已有成果时生成 V0、复核及分歧交付；严格模式才增加第二阶段对照。需要产生两份判断时，生成 A、B 各自的隔离要求和获准输入，C 只读 A、B 已验收产物的交接边。需要汇总时加入 E；只有明确选用并定义触发条件、次数上限时才加入补充分析 D。 |
| P4 按对象处理 | 对象清单输入、单对象方法槽、实例标识和数量上限、比较或汇合槽。动态清单保留为受限展开声明，到运行时按固定清单版本生成实例。 |
| P5 按题分工 | 待选的方法槽、允许的候选、条件、必做项、导出与展开上限。未填写的决策留为缺口，作者或使用者按场景解决。 |

例如，作者选择 A、B、C，在编辑器点击“套用 P3”。预览能直接看到 A、B 看哪些资料，C 读取哪两个产物，以及还有谁来裁决分歧。若当前 runner 无法隔离线程和工作目录，编辑器显示该缺口，作者可以保存草稿，运行入口阻止派发。运行器具备相应能力且草图通过校验后，统一执行器按普通专家步骤运行，逐层记录实际调用；P3 本身不出现在调用树中。

**KnowLab 作者页的三步 P3 草图（2026-11-22）。** 先选一个已登记、有两个调用方输入槽的复核工具方法 C 建立单步草图。在「P3 独立分析与交叉复核」中，分别为这两个槽从本人或已获准的共享工具目录选取分析方法及其确定会交付的输出。A、B 可以用同一冻结版本。编辑器会生成两个独立步骤、各自的调用方输入名和三个不同的隔离组。C 的两个输入各自指向对应分支的具名输出。

展开差异可核对方法版本、输入绑定、隔离组和交接来源。点击「采用独立分析与复核草图」后再保存，整张图与协作要求共用一个草图修订；重开可查看同一修订的采用记录和运行能力缺口。当前运行器会在缺少隔离能力时拦截试跑。已有产物的 V0 检查和严格双轮复核沿用已有成果的定向复核入口。

### 5.2 把业务做法沉淀为模板或专家

某个参考模式需要重复使用且规则足够明确时，作者可把它进一步写成方法模板：固定必要的结构与约束，将方法选择、输入范围、交接与交付等定义变量显式化，补齐五要素作者定义及生成视图规则，再按主稿验证。

参考模式的适用说明和示意箭头不足以构成正式模板。步骤、连线或候选位置的变量可以留在编辑草图；承诺、权限与验收等变量仍由通用模板约束。变量闭合后形成具体方法工作稿，经孵化、冻结和登记后才有可调用版本。运行中按已发布规则选方法属于排计划，不是每次新建模板。

### 5.3 开发进度与验收

| 结构 | 宿主必须核验的能力 | 当前工程边界（2026-11-20，本地开发分支） |
| --- | --- | --- |
| P1 | 依赖关系、相容输入输出、精确前序产物版本 | 本人目录三步链已从作者页补前置、预览采用、按修订保存重开，在 KnowBench 验过中途取消和另轮完成，逐步核对产物版本并冻结。按原交付改选下游已联调到冻结。图内复用可达产物、替换中间工具后重连消费者已过组件回归。共享前置接本人下游的两步链已在三服务联调中冻结，两步使用消费者安装。试跑前撤权会阻断派发，冻结前撤权会阻断新版本写入。 |
| P2 | 静态分支、必需回执及汇合绑定 | 作者构图、按修订采用、固定 DAG 串行试跑和私有冻结已在本地验通。已验必需分支批准过期时停止汇合并留证。作者页已接入缺项、承诺影响及逐步接收已核验产物。普通一层固定图已在本地验通审批过期或资格撤回后，由委托人在原委托按确切版本接收分支产物。 |
| P3 | 独立线程和工作目录、阶段可见性、已验收产物交接 | 作者可在交接边选独立助手或强制异模型家族，随草稿保存。缺隔离或选模核验能力时校验及试跑被阻断。已有成果的单轮及严格双轮已验容器隔离、分阶段交接和各轮恢复。普通两步固定指令图已验单轮交接、隔离和恢复；多分支、图内严格双轮及强制异家族待验。 |
| P4 | 按获准对象清单有界展开、稳定实例身份、汇聚 | 已接入有界清单、单对象与汇总槽位的作者草图，缺运行能力时阻断校验及试跑。动态展开、逐对象恢复及验收待第 12 项。 |
| P5 | 可执行条件、有界候选、必做约束及展开上限 | 已本地联验作者按字符串值选择必做槽、预检递归上限、保存重开和阻断运行。运行时决定留证与恢复待第 12 项。 |

**验收分两类。** 平台回归刻意构造缺前置、须换选和应安全停止的场景，检查宿主是否按证据推进和退出。即时自组使用获准的真实样本先盲测，再由业务人员审计，分别记首次成图率、补查后成图率、歧义主动提问率、无依据结论率及耗时费用。记录模型提出的选择与宿主自动拦截的动作，才能判断模型本身能否胜任规划。

**向使用者交付三层证据。** 平台可核验步骤版本、连线、许可、审批、真实产物及引文来源；单个工具能提供其孵化时验证过的业务检查，例如匹配与未匹配行数之和等于输入行数；临时组合的整体业务口径由使用者复核。影响结论的口径在执行前确认，交付时列出已检查的范围和仍需判断的事项。[作者 P1 联调用例](../../../../../scripts/local-integration/p1_author.py) · [当前开发待办](../../../luna-待办.md)
