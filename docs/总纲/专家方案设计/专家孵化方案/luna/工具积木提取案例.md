## 1. 从委托人要的成品反推工具

先读原方法，把“谁提供什么、按什么口径做、最后交付什么”写清楚，再拆工具。M02 的委托人提供有出处的财报披露行，拿走一份报告，能逐项回查原行、算式、有符号差额和待补资料。把“收到五份工具回执”写成专家的输入，会让正常持有报表的委托人匹配不上这个专家。五份回执是专家内部的连线。[原方法、作者口径及取舍](M02报表勾稽核验专家实施方案.md)

| 父专家要回答的问题 | 可复用的工具 | 独立验收看什么 |
| --- | --- | --- |
| 期初、期末各自是否平表 | Q01 资产平表，各调用一次 | 资产减负债再减所有者权益。两个时点分别选行，保留差额符号 |
| 全年利润归属是否勾稽 | Q02 利润归属 | 缺少少数股东损益时，写明缺项及要补的出处 |
| 全年现金期初、变动及期末是否勾稽 | Q03 现金滚动 | 三个操作数来自约定期间和范围，回执可复算 |
| 本期期初存货能否接上上期期末 | Q04 期初余额连续性 | 两个数能追到各自报告的原行，期间和口径相接 |
| 五项核验做全了多少，还缺什么 | 核验结果汇总 | 保留五份明细，区分阈值内、不平和未核验，输出覆盖统计及待补清单 |

这个拆法得到四个核验工具、一个汇总工具、六次调用。提炼下一项方法时，按它自己的业务承诺定数量。逐项查**目标作者本轮可引用的目录**，用用途、输入输出、口径、调用资格和冻结版本判断能否复用。记录已命中的方法引用和仍缺的能力。M02 的汇总还要计算覆盖数并保留缺件理由，单纯把五项装进列表交不了这份报告。

## 2. 在 agy 建立工具工作稿

工作稿记录作者正在设计什么，冻结版本供其他方法精确引用。助手按手头已有的材料选择起点。

| 手头已有的材料 | 作者操作 | 保存后核对 |
| --- | --- | --- |
| 原财务方法、独立算式，父专家还没有可保存的相应步骤 | 独立创建方法工作稿，明确选择工具。本例确定性核验使用 S1。接口对应 `CreateMethodDraftIn(method_kind="tool", archetype="S1")` | 记下新工具的 `method_id`、作者、修订号。创建默认种类是专家，须读回确认 |
| 已保存的父编排步骤，能定位哪一步缺工具 | 从该步骤派生子工作稿，传父稿当前 `revision`、真实 `step_id`、标题和用途。本例显式传 `kind="tool", archetype="S1"`；省略原型时工具走 S4 | 记下子稿自己的 `method_id`，核对 `parent_gap` 中的父方法、步骤、当时修订和预期输入输出 |

派生时，服务从父步骤输出带出交付承诺、结构、语义和基础验证规则，也把预期的输入保存在父子关联里。作者仍要补全子工具的实际输入、做法、来源和验证条件。若父稿还没有对应步骤，先独立提炼，冻结后再编入父稿。其他助手可以承担这项工作；需要走自用子稿回绑时，在目标作者获授权的身份下办理，当前回绑服务会核对父稿和子版本的所有者。

## 3. 以 Q01 为例，把一句能力声明写成可验的工具

| 作者要定的内容 | M02 的具体写法 |
| --- | --- |
| 能力与边界 | 对指定主体、范围和时点核验资产平表。对来源不足或口径不符的项目列待补。阈值和计算口径沿用作者原规则 |
| 输入 | `target` 指明核验目标，`rows` 提供有出处的原行。期初、期末传各自的目标，不能混用两组数 |
| 做法和交付 | 用选定原行计算资产合计减负债合计减所有者权益合计，返回 `check`。回执给出项目、原行证据、算式、有符号差额、状态和待补资料 |
| 独立期望 | 混合样表中，期初使用 B01、B02、B03，差额 0.00 元，阈值内。期末使用 B04、B05、B06，差额 +1.01 元，不平。分别断言证据编号及顺序、差额、状态 |
| 来源与权限 | 本例选择固定版本的隔离脚本，记录来源版本及摘要，由宿主调用。执行只需要传入的事实和计算权限。逐次按实际报价审批 |

先按原规则写独立期望，再实现算式。将作者采纳的内容保存进工作稿，绑定实现来源，读回修订。登记脚本只提供执行来源；还要用**同一工具身份**走验证、试跑和冻结。工具输入输出须能与父步骤逐槽对接，同时核对结构、业务含义、期间和单位。[披露行](M02验收样表/披露行.csv) · [独立期望](M02验收样表/独立期望.csv)

## 4. 试跑、冻结，并把版本接回父专家

1. **取得试跑申请。** 在保存的工具工作稿上取得运行申请（服务入口 `runtime-anchor`），记下返回的申请号和工作稿修订。检查正式定义的完整性，并把输入与独立期望分别保存。用例覆盖正常、阈值边界、缺件、错口径、精度和重复来源。要声明多种调用方时分别验证；M02 的计算工具使用宿主调用。
2. **拿执行回执。** 对照来源、输入、报价与预算批准实际试跑。分别记录执行状态、断言、实耗。即使草稿保存和定义校验均成功，也要读试跑结果。失败时区分口径错误、实现错误和运行条件缺失，按修改后的修订和用例重新核验。
3. **冻结工具版本。** 通过后按自用范围冻结，回读 `method_id + version + digest`。如交付要求自用上架，再从作者小店及该轮可用目录核对登记和可见性。公开销售另有发布流程。
4. **把精确引用写入父步骤。** 派生路线用父稿最新修订号、原步骤 ID 和子稿刚冻结的三元组调用 `gaps/bind`。它把该步骤的候选设为这个版本；有并行编辑时先重读父稿。独立创建的工具则在父编排中选入其冻结版本。两条路线都要复核各步输入来源、输出去向和最终交付，再保存父稿。
5. **验收父专家。** M02 将期初、期末、利润、现金、存货五项结果分别接到汇总工具。混合样表的独立期望为应核 5、实核 4、阈值内 3、不平 1、未核验 1，待补清单指向少数股东损益。逐项复算并核对最终报告，再冻结专家。从普通工作台使用委托人实际拥有的资料发起委托，核对选中版本、最终报告和费用。

agy 实现对照位置为 KnowLab 后端的 `app/app/application/services/method_drafts.py`（创建、派生、回绑）、`app/app/interfaces/endpoints/knowbot_routes.py`（`method-drafts` 路由）以及 `app/tests/test_pr2_drafts_provenance_board.py`（父子工作稿测试）。这里用服务操作名定位，界面文案可以随发版调整。
