## 一、重新孵化的出发点

从用户要解决的财务分析与预测问题出发，先确定首版承诺什么、需要什么事实、用哪些做法处理、如何验证和交付，再组织工具方法及专家规则。原八步、原固定包及旧接口不作为新定义必须适配的框架。

原方法正文、算法、业务纠偏、资料口径和测试题可以作为创作素材。是否采用，由作者逐项确认并留下来源；旧版已有不等于新首版必做，旧版测试通过不等于新定义已经验证。已采纳的公式、阈值和判据不能在运行时被模型擅自更改。

新架构不是重写所有平台设施。统一身份、数据访问、工具登记、权限审批、调用记录、计划调度与恢复等通用能力按主稿复用和完善；不为新财务专家另建运行器，也不为维持旧财务版本增加兼容分支。

## 四、用统一方法结构孵化专家

首版首先围绕工具方法组织做法，形成专家方法。后续如需调用其他专家，修订允许依赖、验收和精确引用，复用同一专家编排机制。

| 五要素 | 首版需要形成的定义 |
| --- | --- |
| 能力声明 | 用途、适用与排除范围、共同交付承诺和条件性交付 |
| 所需权限 | 可达需求、可信操作与资源范围；实际授权按调用层级收窄 |
| 做法 | 作者与 AI 第一次编排的基准步骤图、备选与允许变化、步骤依赖、输入及产物声明和导出映射；候选由图汇总 |
| 校验 | 计划合法性、工具结果和专家整体承诺的独立验收 |
| 审批 | 计划确认、数据与账号授权、具体动作审批及范围变化处理 |

人工选择与 AI 起草进入同一编辑草图。KnowLab 以有权使用的候选快照校验连线，将方法、数据源与验收条件的关联改动交作者审定。财务口径、阈值、外部数据源及期望答案逐项采用，记录来源与工作稿修订。冻结前分别列出典型题和较重分支的调用、费用、耗时及估算依据。

专家输入与返回视图从定义生成。第一次编排要落实可审阅的主干、分支、备选和连线；使用时用户与 AI 在此基础上第二次编排，记录差异及来源。可选不等于任意可改，作者未声明的变化不默认允许；唯一合法计划由程序生成。每一步安排一次方法调用，步骤不嵌业务程序块。

计划、资料清单、账号绑定和费用上限在同一确认页呈现，改计划后重新推导其余三项并按修订确认。展开、条件定案、运行中调整和纠错重排分别记录。若基准及允许变化不能解决问题，按主稿 §2.8.3 回炉；不生造未孵化方法，不自动复制他人私有定义，不自动替换当前委托版本。具体权限、确认、取消和未知副作用规则引用主稿。

### 使用、改进与新版本

以财报对比为例，若已发布的首版只能完成本期分析，而用户要求独立复核，应先检查该版本的角色和测试覆盖。遇到缺工具、缺判据或超出允许变化时，KnowBench 留下缺口与获准回传的证据；作者试跑失败也回到对应工作稿。原作者可修订，仅有运行权的用户可提需，派生工作稿待市场派生许可可核验后开放。新工具先单独孵化，再由专家引用。KnowLab 验证冻结新版，KnowMart 按许可交付，用户在 KnowBench 核对差异后确认采用；v1 的历史委托仍指向 v1，重试不重复交付或外发。私人自用按私有目录资格办理。用户现场自组及保存计划按主稿 §4.3.1 排期，正式专家资格须由新的孵化证据支撑。

## 五、以新首版的声明验收

作者选择测试问题和数据，固定版本与授权，并在测试前给出预期、阈值、重复次数及通过线。测试覆盖基准图及允许变化，包括条件分支、备选、多对象和运行调整，证据记录实际计划与基准差异；不要求复现原八步，也不只测一次固定路线。唯一计划若仍含模型判断，不能因此免除重复质量验证。

| 验证层次 | 要证明的内容 |
| --- | --- |
| 工具验证 | 输入、口径、算法或判断、结果依据及缺项处理符合已确认定义 |
| 机制验证 | 计划选择与约束、绑定、授权、审批、调用记录、导出、取消与恢复正确 |
| 真实模型验证 | 在实际模型与获准资料上，规划、证据判断及输出质量满足首版声明 |
| 专家整体验收 | 必须交付的成果齐全，条件结果说明明确，预算与停止规则有效 |

按作者采纳的每项承诺，列出触发条件、责任步骤、导出、独立检查和正反例。例如采用 C07 时，分别验点值与上下界覆盖、最近四个历史起点的预测与实际、数据当时可得性，以及回测未达作者门槛时的处置。需独立复核或长期跟踪时，另验同一专家版本的角色隔离、重启恢复、事件去重和上期获准成稿绑定；这些场景按声明选用。

测试不让预期答案进入规划输入，不把模拟通过冒充真实模型效果。历史测试题可复用为素材，但须核对新定义下的预期；旧失败记录不被改写。

事实数值与计算结果须可追溯，成稿抄数、引文和覆盖检查不得丢失；预测、假设及估计标明来源与局限。适用的金融输出检查由平台强制，作者不能删除，具体检查目录和证据语义引用主稿 §2.4.2。
