# 协作编排参考模式

日期：2026-11-14。定位：供 AI 形成计划、供人审定计划时参考的模式集。由《专家团内化方案》重写并改名；本文是参考资料，不是独立的方法契约、运行引擎或已实现功能说明。

方法定义及执行要求以[方法、步骤、组合与模板](方法、步骤、组合与模板.md)为唯一主稿。方法只分原子方法和专家；多个专家协作仍由普通专家步骤组织，每步调用一个方法。“专家团”可以是这种协作的展示名称，不产生第三类方法。

## 一、参考模式有什么用

面对一个问题，AI 和审定者需要判断：是否需要分工、怎样划分职责、哪些工作应互相独立、什么时候交接，以及怎样汇合成符合承诺的结果。参考模式提供可比较的组织办法和检查问题，帮助形成具体计划，不替代作者规则或本次判断。

| 对象 | 用途与边界 |
| --- | --- |
| 协作编排参考模式 | 描述常见结构、适用条件、调整项和风险；允许结合问题选用、组合或不采用，本身不可调用 |
| 方法模板 | 将五要素作者定义表达为固定内容、变量和约束，生成视图随定义推导；符合主稿的正式模板要求 |
| 已发布方法 | 冻结职责、做法、权限、校验和审批，经过孵化；专家定义约束本次可形成哪些计划 |
| 本次计划 | 在方法允许范围内落实具体方法版本、步骤、依赖、绑定和交付，经宿主核验及适用的确认后执行 |
| runtime | 根据合法计划调度、核权、等待、验收和恢复；不因模式名称而获得额外执行权限 |

参考模式可用于创作和使用两个阶段。创作时帮助作者组织方法或正式模板；使用时只帮助在已发布方法允许的候选和规则内形成计划。发现合适模式但现有方法不支持时，应说明缺口或回到创作孵化，不能在运行中擅自添加未孵化方法、修改必做规则或扩大承诺。

## 二、AI 怎样参考，人怎样审定

### 2.1 AI 形成计划时

1. 先明确本题目标、必须交付、资料范围、可用方法及版本、授权与预算，辨别尚未确定的条件。
2. 根据工作依赖和需要解决的协作问题选择参考模式。简单问题可以直接调用一个适用方法，不必为了套模式增加角色或模型轮次。
3. 将模式中的角色落实到有资格使用的具体方法。角色是本次职责，不是方法身份；一个方法可用于多个位置，每个位置的输入与产物分别记录。
4. 展开具体步骤与依赖，写清输入来源、交接产物、验收、失败处理和汇合条件。计算、业务转换、复核和成稿均调用对应方法，不能藏在箭头或编排代码里。
5. 说明选用理由、对模式的调整、尚未解决的缺项及成本风险。把这些依据交给宿主核验，并供人按既有确认规则审定；不要求提供模型隐藏思维链。

需要多层展开时，只为当前层形成相应计划，下层沿冻结规则按需展开。参考模式不要求一次排完全部后代，也不改变主稿的递归限制。

### 2.2 人审定计划时

审定者看到的应是“这次怎样完成目标”，而不只是一个模式名称。至少能回答：

- 每项必交成果由哪个步骤负责，是否有遗漏或重复工作？
- 选择的方法及版本是否适用，输入能否满足，关键交接是否有验收？
- 所谓独立判断是否真的隔离了对方结论，复核是否有证据可查？
- 某步缺资料、失败、出现分歧时，计划会等待、返工、交部分成果还是结束？
- 是否增加了账号、数据、外发或费用要求，估算包含复核与汇总了吗？
- 这份计划采用了模式的哪些部分、改了哪些部分，修改后仍能达到目标吗？

计划确认仍使用主稿的统一确认流程。已确认范围内的展开不因引用模式再加一次审批；具体写操作和范围扩大仍按原规则处理。人在审定时可以提出修改，但不能通过“同意此模式”绕过方法资格、数据许可或平台约束。

## 三、五种参考模式

以下箭头表示成果依赖，不意味着每个方框自动成为新方法。落实后每个执行步骤须绑定一个已孵化方法；有多个调用的方框须展开为多个步骤，或绑定已有的专家方法。

### P1 串行接力

**适用条件**：后续工作明确依赖前序成果，例如资料提取后才能分析，分析后才能形成报告。各阶段有可验收的交接物。

**不适用情形**：多个任务实际上互不依赖，串起来只增加等待；或者本来一个适用方法即可完成，拆开后没有独立职责。

```text
输入 → 方法 A → 验收交接物 → 方法 B → 验收交接物 → 方法 C → 整体验收
```

**可调整项**：各位置的方法、阶段数量、交接字段与资料引用、允许的缺项处理。关键关系是“后续消费前序已接受的明确版本”，不能为了赶进度跳过这一条件。

**审定重点**：A 的输出是否真能满足 B 的输入，主体、期间、单位和证据是否一致；前序修订后哪些后续结果需要重验；阶段拆分是否有价值。

**成本与风险**：总时长沿依赖累积，前序等待会阻塞后续；中间产物丢失或含糊会使恢复困难。步骤数不直接等于模型轮次，确定性调用不必开启模型规划。

### P2 多方向分工后汇合

**适用条件**：不同方面可以分别处理，最后共同支撑同一交付，例如对同一项目分别分析实施条件和资源约束。

**不适用情形**：分支依赖尚未取得的另一分支结论；多个分支只是换名称重复分析；缺少能够接收各分支成果的汇合规则。

```text
             ┌→ 方法 A ─┐
获准输入 ────┤          ├→ 汇总方法 → 整体验收
             └→ 方法 B ─┘
```

**可调整项**：分工维度、各分支方法及输入范围、必需与可选分支、汇合方法。需要汇总内容时绑定相应方法；平台仅收集引用不等于完成内容汇总。

**审定重点**：分工是否覆盖目标，是否存在隐含先后依赖；汇合等待哪些成果，失败分支怎样影响承诺；是否会无协调地写同一个文件。

**成本与风险**：多个分支增加调用和汇总成本。逻辑上无依赖不保证运行时能够并行；主稿首期按 DAG 串行执行，并行调度须另行验证。参考本模式不能承诺缩短多少时间。

### P3 独立分析后交叉复核

**适用条件**：问题需要检验推理或证据、暴露盲点，值得增加独立判断与复核环节。

**不适用情形**：简单确定性计算已有充分校验；双方没有独立证据或检查能力，只会重复相同结论；成本不允许复核和分歧处理。

```text
             ┌→ 独立分析 A ─┐
获准资料 ────┤              ├→ 复核方法 → 按规则处理分歧 → 汇总方法
             └→ 独立分析 B ─┘
```

**可调整项**：分析方法、复核方法、初始可见资料、后续开放的成果、补充分析的条件与次数。独立阶段不能提前看到对方结论；共享获准事实不等于共享结论。角色不同也不自动证明判断独立。

**审定重点**：复核依据是否具体，谁负责处理分歧，哪些差异可以由证据解决，哪些必须保留或由有权的人判断。“处理分歧”如果含分析或计算，就须落实为方法调用，不能仅写一个角色名。

**成本与风险**：至少增加分析、复核及可能的返工成本；一致不自动代表正确，不默认多数投票或汇总模型拥有裁决权。有限复核轮次按规则展开或修订计划，不在 DAG 中添加无限回边。

### P4 同一方法处理多个对象后比较

**适用条件**：多个对象可以按同一职责和口径处理，需要比较或合并其结果。

**不适用情形**：对象口径差异过大，无法用同一方法或预先约定的规范化处理；对象之间存在必须先处理的业务依赖；缺少比较许可或可比性依据。

```text
对象清单 → 对象 1 调用 M、对象 2 调用 M、…… → 比较方法 → 整体验收
```

**可调整项**：对象范围、方法版本、实例数量、单对象输入、比较方法、缺失对象的处置。每个对象形成独立调用记录，不因使用同一方法而混用输入、授权或成果。

**审定重点**：对象清单是否获准，资料时点和口径是否可比，缺失对象是否被如实标记；同一方法多次调用时是否能准确关联各自产物。

**成本与风险**：成本随实际实例及比较工作增加；样本遗漏可能扭曲整体结论。不能因内容相同就无条件复用数据或免计费用，数据版本、授权与真实计费规则仍须满足。

### P5 按问题选择分工并逐层展开

**适用条件**：问题之间所需能力差别较大，作者已提供候选方法、选择条件及必做规则，需要使用时再形成具体分工。

**不适用情形**：唯一合法计划已知，可以由程序生成；候选缺少契约或使用资格；作者只写“自由发挥”，没有可核验的选择与交付边界。

```text
本题目标与条件 → 在规则内选择方法 → 形成当前层计划 → 核验及适用确认 → 按需展开执行
```

**可调整项**：在冻结规则允许范围内选择方法、安排职责和组合 P1—P4。模式本身不能扩大候选范围、删除必做、放松验收或赋予新权限。

**审定重点**：选择能否覆盖目标，未展开部分的需求和成本是否说明；没找到候选是否真的是已查范围内无匹配；选择变化是否仍处于批准范围；何时停止展开或请求变更。

**成本与风险**：规划本身可能产生模型费用；过度拆分增加交接和递归成本。正常展开与纠错重排分别记录，运行恢复沿持久计划，不能重新读参考模式后猜一份新计划。

## 四、怎样选用和组合

| 当前主要问题 | 可以优先考虑 | 仍须核对 |
| --- | --- | --- |
| 后续必须依赖前序结果 | P1 | 交接物可用性与依赖是否真实 |
| 几个方面分别处理后共同交付 | P2 | 汇合条件、分支覆盖、资源可用性 |
| 需要独立判断与复核 | P3 | 隔离、证据、分歧处理与额外成本 |
| 同一职责重复用于多个对象 | P4 | 输入可比、对象范围、各实例结果与授权 |
| 需按本题从候选中决定分工 | P5 | 作者规则、候选资格、必做与展开上限 |

这是选择提示，不是分类算法，也不要求每个计划只能属于一种模式。例如 P5 选定两个方向后，可用 P2 组织分支，其中一个分支采用 P1；需要独立复核时再引入 P3。每次组合都要说明增加的环节解决了什么问题，避免把模式数量当成计划质量。

### 4.1 贯穿示例：形成并复核项目方案

用户需要一份有依据的项目方案及未解决问题清单。假定已有获准资料和适用的已孵化方法，AI 可以提出采用 P3，并用 P1 安排后续交接：

| 步骤 | 调用及输入来源 | 预期产物与审定关注 |
| --- | --- | --- |
| A | 方案编制方法，读取本次获准资料 | 方案、假设与引用；不读取 B 的初始结论 |
| B | 约束检查方法，读取其获准资料 | 约束清单及证据；不读取 A 的初始结论 |
| C | 复核方法，绑定 A、B 已验收成果 | 一致项、冲突项、缺证项及其来源 |
| D（条件步骤） | 作者规则允许的补充分析方法，使用指定问题及获准输入 | 补充证据与仍未解决的问题；新增权限或费用范围按规则确认 |
| E | 汇总方法，绑定有效成果与未解决项 | 按导出映射交付方案及问题清单，不抹平分歧 |

A、B 是职责独立的分支，并不承诺当前运行器并发执行。C 等待必需成果；D 只有在冻结条件触发时执行，补充次数受限。A 或 B 失败时，不能把空输入当作“本题未选”让 E 直接交出完整成功报告。

审定者应重点判断：B 能否检查本题真正关心的约束，C 有没有足够证据，D 是否有边界，以及最终交付是否如实保留未解决问题。若本题不需要独立检查，且作者规则允许，可以选用更简单的计划；不能仅因示例写了五步就固定照搬。

## 五、从参考模式到正式模板

某个参考模式需要重复使用且规则足够明确时，作者可把它进一步写成方法模板：固定必要的结构与约束，将方法选择、输入范围、交接与交付等定义变量显式化，补齐五要素作者定义及生成视图规则，再按主稿验证。

参考模式的适用说明和示意箭头不足以构成正式模板。模板也不因写好就可调用；变量闭合后形成具体方法工作稿，经孵化、冻结和登记后才有可调用版本。运行中按已发布规则选方法属于排计划，不是每次新建模板。

本模式集可供 AI 按问题选读，也可在人工审定材料中引用相关部分。本文未实现自动检索、提示词注入或前端展示；模式引用只解释计划依据，不代替持久计划、具体方法版本、作者规则及审批记录。
