# 协作编排参考模式

2026-11-20 按方法主稿修订。定位：供 AI 形成计划、供人审定计划时参考的模式集。由《专家团内化方案》重写并改名；本文是参考资料，不是独立的方法契约、运行引擎或已实现功能说明。

方法定义以[专家方法孵化与递归编排方案](专家方法孵化与递归编排方案.md)为准。工具直接派发，专家逐步调用工具或专家；每步引用一个方法版本。

## 一、参考模式有什么用

面对一个问题，AI 和审定者需要判断：是否需要分工、怎样划分职责、哪些工作应互相独立、什么时候交接，以及怎样汇合成符合承诺的结果。参考模式提供可比较的组织办法和检查问题，帮助形成具体计划，不替代作者规则或本次判断。

| 对象 | 用途与边界 |
| --- | --- |
| 协作编排参考模式 | 描述常见结构、适用条件、调整项和风险；允许结合问题选用、组合或不采用，本身不可调用 |
| 方法模板 | 将五要素作者定义表达为固定内容、变量和约束，生成视图随定义推导；符合主稿的正式模板要求 |
| 已发布方法 | 冻结职责、做法、权限、校验和审批，经过孵化；专家方法的定义约束本次可形成哪些计划 |
| 本次计划 | 在方法允许范围内落实具体方法版本、步骤、依赖、绑定和交付，经宿主核验及适用的确认后执行 |
| runtime | 根据合法计划调度、核权、等待、验收和恢复；不因模式名称而获得额外执行权限 |

参考模式可用于创作和使用两个阶段。创作时帮助作者与 AI 第一次编排基准图及允许变化；执行正式专家时，在已冻结基准及允许变化内辅助第二次编排，展示实际差异。发现合适模式但现有方法不支持时，记录缺口，由用户依主稿 §2.8.2–2.8.3 选择可用的后续路径，不能在运行中擅自添加未孵化方法、修改必做规则或扩大承诺。按对象展开使用主稿 §2.3 的有界展开和稳定实例记录，不把 P4 多对象模式当成单步隐藏循环。

## 二、AI 怎样参考，人怎样审定

### 2.1 AI 形成计划时

**在选法循环里，模式帮助模型把协作要求变成可检索的方法职责和可检查的步骤关系。** 实施时，宿主把 §4 表中的五行简要提示常驻规划上下文，与实际运行器支持的能力摘要一起提供。需要解释某种结构时，再使用相应说明或示例。基本选用无须让模型先发一次读文档请求。正式方法目录仍只列有身份和版本的候选。

1. 先按主稿 §3.2.1 核定可查范围。小目录先看极简目录，大目录按整体交付检索。用户明确要求独立复核、逐对象比较等条件时，从首轮就用相应模式的检查问题核对完整专家的承诺。已有合适版本能整体交付时，采用该版本；固定计划直接展开。
2. 需要自组或补图时，按眼前缺口选读相应模式。前一步产物要接给下一步，读 P1 查交接；多个方向共同交付，读 P2 查分工和汇合；要求独立判断，读 P3 查隔离与复核；同一职责覆盖多个对象，读 P4 查对象清单和可比口径。在专家允许按题选择分支或子专家时，P5 帮助判断本层要选哪些、何时展开下一层。简单的一步可以直接完成。
3. 把相关说明落到当前草图。模型提出本步需要的输入、产物、职责和约束；宿主在获准目录中检索具体方法，检查版本、绑定、运行能力和预算。候选契约可以反过来改变草图，例如已有专家能同时承担两个职责，就核对它的交付和证据，决定是否合并原拟步骤。
4. 每轮只看实际进展。新增合法绑定、排除有依据的候选或取得新证据后，按主稿 §3.2.1 决定完成、继续、等待或结束。单换模式名称不能重置预算或触发重试。强制协作条件无法落实时记录具体缺口；修改用户明确要求须由用户决定。

孵化时，作者采用的结构进入专家基准图和允许变化。即时自组按本人正式使用资格形成当次草图。已有专家运行时沿冻结规则选择，不能临时套用 P3 增加一个未获准的复核步骤。只为当前层形成计划，子专家沿冻结规则按需展开。同版方法承担两个角色时分别记录调用、输入及产物。交给人审的是方法版本、步骤、选用依据、交接物、隔离条件和未解决项。恢复依靠持久计划和调用记录。

**两个场景采用不同的默认做法。** 在 KnowLab，作者可以与 AI 比较 P1—P5，明确职责和代价，并用作者用例验证所采用的结构。在 KnowBench，即时自组默认优先采用能整体交付的现成专家、单一工具或最短的 P1 链。只有用户的明确要求在语义上需要分工、独立复核或逐对象比较，才把新增的 P2—P4 结构纳入草图；用户无须说出模式名。展开前在原确认流程说明新增职责、预计轮次、费用及不确定项。用户说“写个方案，顺便挑挑毛病”可先安排普通检查，若是否要求第二份独立判断会改变做法，则先问清。已选专家冻结的必做复核照常披露与执行。

### 2.2 人审定计划时

确认页应从实际草图生成适用项目。多分支时列出汇合所等的产物，独立判断时列出隔离能力及待决定的裁决人，多对象时列出数量、上限和汇总规则。每项带关联步骤、核验结果或待答问题；运行后再补实际证据。可执行性条件与证据要求以[方法主稿 §2.10](专家方法孵化与递归编排方案.md)为准。审定者至少能回答：

- 每项必交成果由哪个步骤负责，是否有遗漏或重复工作？
- 选择的方法及版本是否适用，输入能否满足，关键交接是否有验收？
- 所谓独立判断是否真的隔离了对方结论，复核是否有证据可查？
- 某步缺资料、失败、出现分歧时，计划会等待、返工、交部分成果还是结束？
- 是否增加了账号、数据、外发或费用要求，估算包含复核与汇总了吗？
- 这份计划采用了模式的哪些部分、改了哪些部分，修改后仍能达到目标吗？

创作时，人工选方法与 AI 起草进入同一编辑草图。作者审定涉及多个步骤的完整差异，核对每项承诺的责任步骤、导出、检查与测试；期望答案、金融口径与阈值、外部数据源单独采用。正式调用应能追到精确的方法身份、版本和摘要。

计划确认仍使用主稿的统一确认流程。已确认范围内的展开不因引用模式再加一次审批；具体写操作和范围扩大仍按原规则处理。人在审定时可以提出修改，但不能通过“同意此模式”绕过方法资格、数据许可或平台约束。

## 三、五种参考模式

以下箭头表示成果依赖，不意味着每个方框自动成为新方法。落实后每个执行步骤须绑定一个已孵化方法；有多个调用的方框须展开为多个步骤，或绑定已有的专家方法。

### P1 串行接力

**适用条件**：后续工作明确依赖前序成果，例如资料提取后才能分析，分析后才能形成报告。各阶段有可验收的交接物。

**不适用情形**：多个任务实际上互不依赖，串起来只增加等待；或者本来一个适用方法即可完成，拆开后没有独立职责。

```text
输入 → 方法 A → 验收交接物 → 方法 B → 验收交接物 → 方法 C → 整体验收
```

**可调整项**：各位置的方法、阶段数量、交接字段与资料引用、允许的缺项处理。关键关系是“后续消费前序已接受的明确版本”，不能为了赶进度跳过这一条件。

**审定重点**：A 的输出是否真能满足 B 的输入，主体、期间、单位和证据是否一致；前序修订后哪些后续结果需要重验；阶段拆分是否有价值。

**成本与风险**：总时长沿依赖累积，前序等待会阻塞后续；中间产物丢失或含糊会使恢复困难。步骤数不直接等于模型轮次，确定性调用不必开启模型规划。

### P2 多方向分工后汇合

**适用条件**：不同方面可以分别处理，最后共同支撑同一交付，例如对同一项目分别分析实施条件和资源约束。

**不适用情形**：分支依赖尚未取得的另一分支结论；多个分支只是换名称重复分析；缺少能够接收各分支成果的汇合规则。

```text
             ┌→ 方法 A ─┐
获准输入 ────┤          ├→ 汇总方法 → 整体验收
             └→ 方法 B ─┘
```

**可调整项**：分工维度、各分支方法及输入范围、必需与可选分支、汇合方法。需要汇总内容时绑定相应方法；平台仅收集引用不等于完成内容汇总。

**审定重点**：分工是否覆盖目标，是否存在隐含先后依赖；汇合等待哪些成果，失败分支怎样影响承诺；是否会无协调地写同一个文件。

**成本与风险**：多个分支增加调用和汇总成本。逻辑上无依赖不保证运行时能够并行；主稿首期按 DAG 串行执行，并行调度须另行验证。参考本模式不能承诺缩短多少时间。

### P3 独立分析后交叉复核

**适用条件**：问题需要检验推理或证据、暴露盲点，值得增加独立判断与复核环节。

**不适用情形**：简单确定性计算已有充分校验；双方没有独立证据或检查能力，只会重复相同结论；成本不允许复核和分歧处理。

```text
             ┌→ 独立分析 A ─┐
获准资料 ────┤              ├→ 复核方法 → 按规则处理分歧 → 汇总方法
             └→ 独立分析 B ─┘
```

**可调整项**：分析方法、复核方法、初始可见资料、后续开放的成果、补充分析的条件与次数。独立阶段不能提前看到对方结论；共享获准事实不等于共享结论。角色不同也不自动证明判断独立。

**审定重点**：复核依据是否具体，谁负责处理分歧，哪些差异可以由证据解决，哪些必须保留或由有权的人判断。“处理分歧”如果含分析或计算，就须落实为方法调用，不能仅写一个角色名。

**独立性验收**：A、B 可以串行，甚至引用同一专家版本。运行器为两次独立分析分别绑定 Codex 线程与受隔离的工作目录。用例要实际尝试读取对方的线程历史、草稿和工作文件，三者在恢复前后均应被拒。复核阶段只向 C 开放计划指定的已验收产物；事后能追到来源调用与版本。具备这些证据后，才可向用户展示“独立复核”。

**成本与风险**：至少增加分析、复核及可能的返工成本；一致不自动代表正确，不默认多数投票或汇总模型拥有裁决权。有限复核轮次按规则展开或修订计划，不在 DAG 中添加无限回边。

### P4 同一方法处理多个对象后比较

**适用条件**：多个对象可以按同一职责和口径处理，需要比较或合并其结果。

**不适用情形**：对象口径差异过大，无法用同一方法或预先约定的规范化处理；对象之间存在必须先处理的业务依赖；缺少比较许可或可比性依据。

```text
对象清单 → 对象 1 调用 M、对象 2 调用 M、…… → 比较方法 → 整体验收
```

**可调整项**：对象范围、方法版本、实例数量、单对象输入、比较方法、缺失对象的处置。每个对象形成独立调用记录，不因使用同一方法而混用输入、授权或成果。

**审定重点**：对象清单是否获准，资料时点和口径是否可比，缺失对象是否被如实标记；同一方法多次调用时是否能准确关联各自产物。

**成本与风险**：成本随实际实例及比较工作增加；样本遗漏可能扭曲整体结论。不能因内容相同就无条件复用数据或免计费用，数据版本、授权与真实计费规则仍须满足。

### P5 按问题选择分工并逐层展开

**适用条件**：问题之间所需能力差别较大，作者已提供候选方法、选择条件及必做规则，需要使用时再形成具体分工。

**不适用情形**：唯一合法计划已知，可以由程序生成；候选缺少契约或使用资格；作者只写“自由发挥”，没有可核验的选择与交付边界。

```text
本题目标与条件 → 在规则内选择方法 → 形成当前层计划 → 核验及适用确认 → 按需展开执行
```

**可调整项**：在冻结规则允许范围内选择方法、安排职责和组合 P1—P4。模式本身不能扩大候选范围、删除必做、放松验收或赋予新权限。

**审定重点**：选择能否覆盖目标，未展开部分的需求和成本是否说明；没找到候选是否真的是已查范围内无匹配；选择变化是否仍处于批准范围；何时停止展开或请求变更。

**成本与风险**：规划本身可能产生模型费用；过度拆分增加交接和递归成本。正常展开与纠错重排分别记录，运行恢复沿持久计划，不能重新读参考模式后猜一份新计划。

若修改超出基准，先记录原承诺失效及差异。待普通委托入口、正式专家剪枝与暂停恢复通过验收后，用户才可现场自组；每次计划修订保存快照，继承已执行事实与确切产物，只展开未执行部分并复核新增范围。用户保存计划后可重新核验复用，若要形成可供他人调用的专家版本，须回 KnowLab 孵化。

五种模式都可用于专家方法。P4 同一专家处理多个对象时分别记账；P3 的独立分析与复核须核对过程上下文隔离、产物可见范围和执行证据。模式和角色均不改变方法类型。

## 四、怎样选用和组合

| 当前主要问题 | 可以优先考虑 | 仍须核对 |
| --- | --- | --- |
| 后续必须依赖前序结果 | P1 | 交接物可用性与依赖是否真实 |
| 几个方面分别处理后共同交付 | P2 | 汇合条件、分支覆盖、资源可用性 |
| 需要独立判断与复核 | P3 | 隔离、证据、分歧处理与额外成本 |
| 同一职责重复用于多个对象 | P4 | 输入可比、对象范围、各实例结果与授权 |
| 需按本题从候选中决定分工 | P5 | 作者规则、候选资格、必做与展开上限 |

这是选择提示，不是分类算法，也不要求每个计划只能属于一种模式。例如 P5 选定两个方向后，可用 P2 组织分支，其中一个分支采用 P1；需要独立复核时再引入 P3。每次组合都要说明增加的环节解决了什么问题，避免把模式数量当成计划质量。

### 4.1 贯穿示例：形成并复核项目方案

用户需要一份有依据的项目方案及未解决问题清单。假定已有获准资料和适用的已孵化方法，AI 可以提出采用 P3，并用 P1 安排后续交接：

| 步骤 | 调用及输入来源 | 预期产物与审定关注 |
| --- | --- | --- |
| A | 方案编制方法，读取本次获准资料 | 方案、假设与引用；不读取 B 的初始结论 |
| B | 约束检查方法，读取其获准资料 | 约束清单及证据；不读取 A 的初始结论 |
| C | 复核方法，绑定 A、B 已验收成果 | 一致项、冲突项、缺证项及其来源 |
| D（条件步骤） | 作者规则允许的补充分析方法，使用指定问题及获准输入 | 补充证据与仍未解决的问题；新增权限或费用范围按规则确认 |
| E | 汇总方法，绑定有效成果与未解决项 | 按导出映射交付方案及问题清单，不抹平分歧 |

**把本例放进选法循环。** 如果用户明确要求独立复核，首轮先查有没有能同时交付方案、复核证据和未解决问题清单的专家。已有专家如能在获准环境满足隔离及交付要求，就采用它。若只有能写方案的 A，P3 帮助指出具体缺口：还需要能独立检查约束的 B、只消费获准成果的复核方法 C，以及对应隔离能力。按这些需要查找和验证。若始终缺少隔离能力，即使 A 被调用两次也不能宣称完成独立复核；把缺口交给用户决定是否调整要求，或结束本轮。若需求只写“请复核”，先弄清是核对数据还是独立给出第二份判断，两者所需步骤和费用不同。

A、B 是职责独立的分支，并不承诺当前运行器并发执行。C 等待必需成果；D 只有在冻结条件触发时执行，补充次数受限。A 或 B 失败时，不能把空输入当作“本题未选”让 E 直接交出完整成功报告。

审定者应重点判断：B 能否检查本题真正关心的约束，C 有没有足够证据，D 是否有边界，以及最终交付是否如实保留未解决问题。若本题不需要独立检查，且作者规则允许，可以选用更简单的计划；不能仅因示例写了五步就固定照搬。

### 4.2 同一专家从单次协作到长期职责

用户可以只请该专家复核一次，也可以把同一冻结版本配置为长期职责。定时、订阅或连接器事件每次唤醒一件普通 Task，同一事件重送只建一件。需要跨期比较时，把获准的上次成稿按确切版本绑定到声明的输入槽；首次缺项和撤权按定义处理。新委托里的 A、B 仍须通过 P3 的隔离检查。跨次复用的是选定产物，临时草稿、历史线程与上次动作批准均留在原任务。此场景按主稿 §4.4 验收。

## 五、从参考模式到正式模板

### 5.1 在草图中一键套用

“套用模式”是编排期的编辑动作。作者或模型给出已选方法或保留空槽，宿主确定性地展开草图供审定。各方共享方法主稿 §3.2.1 的差异、采用及校验流程。五种骨架分别生成以下内容。

| 动作 | 展开到草图中的内容 |
| --- | --- |
| P1 串行接力 | 有顺序依赖的步骤及相邻步骤的交接槽。能确定的绑定直接展示，业务口径不明的留待选择。 |
| P2 分工汇合 | 各职责分支、汇合步骤、其等待的分支产物及绑定。分支可以串行调度。 |
| P3 独立分析与复核 | A、B 各自的隔离要求和获准输入，C 只读 A、B 已验收产物的交接边。需要汇总时加入 E；只有明确选用并定义触发条件、次数上限时才加入补充分析 D。 |
| P4 按对象处理 | 对象清单输入、单对象方法槽、实例标识和数量上限、比较或汇合槽。动态清单保留为受限展开声明，到运行时按固定清单版本生成实例。 |
| P5 按题分工 | 待选的方法槽、允许的候选、条件、必做项、导出与展开上限。未填写的决策留为缺口，作者或使用者按场景解决。 |

例如，作者选择 A、B、C，在编辑器点击“套用 P3”。预览能直接看到 A、B 看哪些资料，C 读取哪两个产物，以及还有谁来裁决分歧。若当前 runner 无法隔离线程和工作目录，编辑器显示该缺口，作者可以保存草稿，运行入口阻止派发。运行器具备相应能力且草图通过校验后，统一执行器按普通专家步骤运行，逐层记录实际调用；P3 本身不出现在调用树中。

### 5.2 把业务做法沉淀为模板或专家

某个参考模式需要重复使用且规则足够明确时，作者可把它进一步写成方法模板：固定必要的结构与约束，将方法选择、输入范围、交接与交付等定义变量显式化，补齐五要素作者定义及生成视图规则，再按主稿验证。

参考模式的适用说明和示意箭头不足以构成正式模板。步骤、连线或候选位置的变量可以留在编辑草图；承诺、权限与验收等变量仍由通用模板约束。变量闭合后形成具体方法工作稿，经孵化、冻结和登记后才有可调用版本。运行中按已发布规则选方法属于排计划，不是每次新建模板。

实施时从 §4 同一份选用表生成规划上下文的简表，按需展示详细说明。五行提示、一键套用、运行能力预检和确认页联动尚待开发。执行与恢复继续使用持久计划、方法版本及审批记录。
