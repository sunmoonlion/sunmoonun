# 方法市场方案

日期：2026-11-14。状态：按[孵化主稿](../../专家孵化方案/luna/专家及专家团孵化模板.md)形成的目标设计，尚未实施新的完整市场流程。KnowMart 共用一套目录、版本、许可与资格机制，提供工具方法、专家方法、专家团方法三个分类入口；不另定义三套方法契约或执行器。

## 一、谁来选什么

| 使用者 | 操作与所需信息 |
| --- | --- |
| KnowLab 作者 | 为基准图主干、分支及备选选择已孵化方法，核对接口、引用/组合许可、来源和依赖交付权 |
| KnowBench 用户或模型 | 找符合问题的工具、专家或专家团，查看能力、结果承诺、权限、价格和局限，再创建真实调用或委托 |
| 执行中的选择器 | 仅在冻结的槽位规则和获准目录内选方法，宿主重核资格并钉住实际版本 |

普通聊天/工作安装的 MCP、Skill 保存在账号的已安装/已连接列表，不自动成为市场商品。将其用于专家须复用安装来源，经孵化、验证和冻结获得正式方法资格；公开上架另外检查发布主体与相应服务资质。

## 二、目录视图与私有定义

目录内容从冻结方法及发布信息派生，不允许另写一份不一致的能力承诺。

| 信息 | 目录与选择用途 |
| --- | --- |
| 方法 ID、精确版本、摘要、类别和发布者 | 确认身份、来源、冻结类别及更新边界 |
| 能力声明 | 解决什么、适用与排除、具名能力项与承诺 |
| 生成的输入/返回摘要 | 共有与条件需求、结果格式和口径、是否匹配上游与下游 |
| 所需权限摘要 | 资源角色、操作、外发与用途；不展示用户真实账号或秘密 |
| 验证与限制 | 可核对验证范围、未覆盖项及适用版本；结构校验不冒充业务效果 |
| 价格、许可、可获取状态 | 运行、组合、派生、内容交付各自权利和必要费用条件 |

私有基准图、方法正文、脚本和作者数据不因公开声明自动披露。平台可在合法授权范围验证引用与版本，向调用方返回必要的接口和资格结论，不能以查询依赖为由下发整套私有实现。

## 三、引用资格、实际使用与费用分别核验

作者在孵化时核验能否把某个方法版本纳入主干或备选，以及能否随包交付相关 Skill 内容；获得运行权不自动等于组合、派生或交付权。平台基础方法也不能绕过孵化登记。

终端用户实际选择某一分支时，再核对其所选方法及必要依赖的运行资格、价格和数据授权。未选中的候选不据此产生本次调用费用或强制购买；若许可本身另有固定订阅或整体授权条件，须事先明示，不能隐藏到执行后扣款。查询、推荐、加入候选和计划预览都不是购买授权。

费用与总预算沿共同调用记录关联：平台不把上层和实现派发算成两次相同方法调用，不用候选数量推算已发生费用。明确计费动作前须核准当前价格/许可修订与用户确认范围；实际费用、估算和预留分别展示。本方案不预定尚未批准的分账比例或商业模式。

## 四、运行时市场选择与版本变化

分类按主稿 §1.1 对全部允许的直接依赖判定，运行查询遵循 §3.1.6。只选工具、限制同一专家身份、允许多个专家身份或专家团是不同边界；“本次只选一个”不能把允许多个专家身份的方法降为专家。开放专家身份查询需专家团边界及明确契约、权限、费用和许可上界，无法证明约束时不发布。

宿主先限制可见目录，再提供合格候选供模型或用户选择，最后重核并固定精确版本和摘要。目录异常、分页未完只能报告查询未完成；不能推断不存在方法。选择的证据记录目录依据、问题修订、候选及采用结果，不回写作者定义。

已启动任务不因市场更新换成最新版本。普通下架、安全撤销、资格失效按主稿 §1.12 分别处置；更新的影响范围从允许依赖和实际调用派生。当前调用权限重新核验，不能等待通知才阻断撤权；历史成果保留，不保留被退出方法的运行入口。

回炉时另核派生许可，具体交互见[使用方案](../../专家使用方案/luna/专家及专家团使用方案.md)。市场上的使用者无权复制私有步骤时只发送获准的需求诊断，不因回炉创建侵权派生资产。

## 五、实施和验收

先在主稿 M0 固定提供方契约与消费者锁，M1–M2 贯通孵化资格和登记，M3 连接三类目录、使用确认和实际选择。多级模板市场、开放式运行查询及商业结算不能因本文列出目标就视为已交付。

验收至少覆盖：未孵化安装项不进正式目录；私有定义不可越权读取；三类使用同一契约；组合权与运行权分别检查；未选候选不冒充已调用并收费；开放选择不越分类/接口/权限上限；价格变更需重核；安全撤销阻止新访问，普通下架不误撤合法历史权利；回炉不扩大复制权。
