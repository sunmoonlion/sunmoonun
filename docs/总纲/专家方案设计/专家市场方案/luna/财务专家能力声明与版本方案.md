# 财务专家能力声明与版本方案（Luna，knowmart）

日期：2026-11-09。状态：讨论稿。由 Luna 两份原稿的能力、版本、来源与迁移边界整理；未查询线上专家、交易、授权或历史运行数据。

作者内容见[孵化方案](../../专家孵化方案/luna/新财务专家孵化方案.md)，执行见[使用方案](../../专家使用方案/luna/财务专家执行与验收方案.md)。同侧参照：Opus 的《能力声明与版本》第一稿（已删，原文见 sunmoonun 提交 `7a1d33854`）。

## 一、同一专家的新版本，不新增一个“动态财务专家”产品

用户仍面对同一位「财务分析与预测」专家。新版的价值是按题使用适当做法，不是让用户理解固定、动态两套工程路线。

knowmart 负责已批准发布的声明、版本、价格与授权，以及向运行方交付一致的清单。方法主档、来源接受和组合编辑仍在 knowlab；本题计划、实际数据绑定及成果仍在 knowbench。市场不能编辑冻结方法来修补一次执行。

## 二、能力声明应忠实于实际定型内容

| 拟承接能力 | 对外必须说明 | 内部应有的支撑与限制 |
| --- | --- | --- |
| 指定期间历史财务分析 | 可处理的主体、期间与指标范围 | 明确指标配置、必要质量核验、可追溯事实 |
| 人均创收 | 收入和人数口径，缺数时的处理 | 不能只凭报表猜人数，不隐含季度预测 |
| 累计转单季 | 适用流量、来源与版本条件 | 不对时点余额做差分，缺前期不造数 |
| 原季节性预测与回测 | 原方法、支持期间、数据前提及局限 | 保留作者窗口、必要质量门和完整回测 |
| 结论对照管理层讨论 | 选中时的原文章节与支持判据 | 完整结论逐条核，不扩大引文含义 |

这是内容核对提纲，不是可直接发布的最终 `statement`。声明须由作者确认，内部能力绑定应能指向确切方法与依赖；公开目录不因要匹配专家而暴露私人方法和数据。

方法库中有 DCF、三表预测、质押或审计候选，不等于本专家已获得这些能力。新增能力要先回到工作稿、作者接受与测试，再出版本；一次用户审批不能临时扩大已发布能力。

## 三、几种版本和记录不能混为一谈

| 对象 | 变化时如何处理 | 禁止的混淆 |
| --- | --- | --- |
| 方法定义版本 | 新口径、新输出或新规则生成新版本，记录来源及拆分关系 | 覆盖已有冻结摘要 |
| 组合编辑素材 | 作者选用后展开、核对并纳入工作稿 | 运行时递归拉取“最新模板” |
| 专家发布版本 | 钉住内容、规则、能力与必要引用 | 方法库更新自动改变已发布专家 |
| 市场授权与成交依据 | 保留对应商品、版本、价格和条款依据 | 免费旧版推导未来全部新版免费 |
| 本次任务快照 | 受理时钉版，保留授权、计划、实际输入和费用 | 正在运行时静默换公式或包 |
| 历史结果 | 按原版本与输入可追溯 | 新测试通过后重写旧失败记录 |

建议新请入采用当前可用版本；已钉旧版本的工作台条目显示升级差异，由用户明确选新版。已经开始的委托仍按原快照处理；需要切换时应形成清楚的新任务或迁移记录。具体升级默认和权益仍待所有者定型。

## 四、作者接受、来源与验证

1. 现有20项候选保留身份与历史；新职责、新口径、新输出产生新定义／版本，并记录拆自哪一项、改了什么。不得覆盖已冻结digest。
2. 已上架财务专家保留为同一产品，新版接受新的方法选择和组合；已开始任务继续使用原包快照，不能中途换公式。
3. 库内容区分候选素材与已经作者确认、有实际使用证据的沉淀。合成正例不是实践认证，引用某本书／准则名也不是该实现已经验证。
4. AI可以辅助提出原子方法、组合模板和缺口；作者可修改或提出库外原创方法。孵化时确认的是完整创意与专家行为规则，不只是勾选一张方法清单。
5. 作者需要核对：拆分后的含义、输入口径、适用边界、缺项策略、何时必做、交付与验收。工程修复和业务方法变更分别标明，不以“优化性能”默改四式、窗口或支持判据。
6. 内容确认、离线验证、真实测试与上架批准分别留痕；此提案不代替其中任何一项。历史失败、不完整结果和费用不重写。

knowlab 记录作者原话、AI 提议和接受过程；knowmart 校验并交付已通过发布流程的版本。测试说明只能写实际覆盖范围，不能将“合成探针 99 项通过”改写成“全部财务方法正确”或“线上已验收”。

## 五、旧格式清理前要有引用证据

Opus 提出新格式统一、部分旧动态格式删除、已发 v2 保持历史可读。Luna 的建议是先盘点真实对象，再定清理范围：未对外请过，不等于没有冻结方法、工作稿、测试记录或其他消费者引用。

| 盘点对象 | 清理前要回答 |
| --- | --- |
| 已发布和未发布清单 | 有哪些格式与版本，作者是谁，是否仍可请入 |
| 冻结方法与工作稿引用 | 删除后是否破坏来源、摘要或版本追溯 |
| 在跑和历史委托 | 哪些必须继续执行，哪些至少需要可读和可下载 |
| 作者测试、审核和交易 | 是否依赖旧格式解释结果及权益 |
| 契约提供方与消费者 | 哪一方定义、哪几仓锁版，能否一起迁移 |

统一执行体系不要求未经验证地统一删除历史表示。先证明等价迁移与读取边界，再写明确清理清单；需要删除实际测试记录时仍按已有授权处理。本次不执行数据库或契约清理。

## 六、市场侧验收与待定问题

验收应覆盖：声明不超出能力；目录返回的版本与摘要真实；请入与任务快照一致；付费或授权不足时不自动运行；升级不影响旧任务；撤回销售不破坏历史证据；失败和目录未查全不被说成“没有合适专家”。

待定：最终能力文案、旧用户升级默认、新旧版权益、允许继续发布的格式范围、旧格式保留与迁移清单。团队商品另外见[专家团市场建议](../../../专家团方案设计/专家团市场方案/luna/团队声明与成员版本.md)，不能直接沿用单专家授权来推导整团授权。
