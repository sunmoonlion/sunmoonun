# 财务专家能力声明与版本方案

日期：2026-11-14。按所有者决定，以新身份孵化“财务分析与预测专家”第一版，删除原专家所有版本。本稿替代此前同一产品升级、旧版长期可运行及等价迁移要求。当前为方案，未完成线上资产清理或新版本发布。

首版定义和清理范围以[孵化方案](../../专家孵化方案/luna/新财务专家孵化方案.md)为准，方法结构以[方法主稿](../../专家孵化方案/luna/专家及专家团孵化模板.md)为准，运行见[执行与验收](../../专家使用方案/luna/财务专家执行与验收方案.md)。

## 一、创建新身份，从第一版开始

显示名称可以继续使用“财务分析与预测专家”，但新身份及版本线与旧专家分离。不能复用旧身份重置版本号，也不能把新包写到原版本下。新专家按统一孵化及市场流程进入目录，不设置财务专用发布通道。

KnowLab 管理作者定义、来源、孵化与冻结版本；KnowMart 校验发布资格、能力声明、交付版本及使用资格；KnowBench 固定本次版本、计划、授权和执行证据。三方不得用名称猜测应调用哪一个版本。

## 二、声明只包含新首版已确认并验证的能力

先明确目标问题、适用范围、资料条件、结果承诺和排除项，再确认工具及规则。原年度分析、人均创收、季节性预测等内容只作为可评估素材，不自动继承为首版承诺。

能力声明必须与冻结定义、依赖版本和验收证据对应。方法库有某项工具不等于该专家拥有相应整体能力；旧专家曾通过的测试也不能直接证明新首版有效。价格、费用范围与条款按实际发布内容确定，不由本次重建方案虚构。

公开声明用于理解和选择，不能因此暴露私人方法正文或用户资料。发布主体资格、依赖许可和本次用户授权分别核验，仍遵循主稿及既有市场规则。

## 三、版本与来源

| 对象 | 处理要求 |
| --- | --- |
| 新专家身份及第一版 | 新建、独立孵化和验收，不映射成旧专家升级 |
| 工具依赖 | 只引用已孵化的精确版本及摘要，不因库更新改变冻结专家 |
| 旧内容素材 | 记录来源和作者采纳依据，不把引用素材等同于沿用旧运行契约 |
| 首版后续更新 | 正常产生新版本，复核变更影响，不覆盖既有摘要 |
| 历史任务与成果 | 保留原版本身份、输入、结果和费用证据，不改写为新专家产生 |

作者接受、工具验证、整体验收和发布分别留证。采用原算法或阈值须明确来源与适用范围；修改它们也须明确接受依据，不借工程调整默改业务定义。

## 四、旧专家全部版本退出

清理对象与执行要求统一在孵化方案第六、七节维护，不另列第二套清单。市场删除旧专家的全部版本与可获取条目，工作台清除旧版可调用安装引用，旧任务不自动转用新身份。不存在“仍可请入的旧版保底”或“等新首版等价迁移后再清理”的安排。

成交、费用、使用依据及已交付成果保留历史可读性；历史记录不能再形成可运行的旧包入口。若实际存在未履行交易或未结束任务，清理执行时列出并完成相应结案处理，不能把删除资产视为已经履行或退款。本文未核查线上是否存在这些记录。

删除仅限经身份和归属确认的旧财务专家，不按名称模糊匹配删除其他作者资产、共享工具、原始资料或全部专家会话。

## 五、验收与当前缺口

市场验收须证明：新身份与第一版一致；声明有对应证据；目录、请入及受理钉住同一版本；旧身份无法新获取、启动、重试或恢复；旧成果和必要历史证据仍可读取；用户没有被静默换到新身份。

旧资产清单、真实清理结果、新首版的能力文案、测试证据和发布记录均尚待完成。文档更新不表示旧版本已删除或新专家已上架。
