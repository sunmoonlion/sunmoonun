# 注册中心实施方案

## 产品入口和责任

用户在 KnowBench「设置 → 注册中心」查看自己的安装、由这些安装孵化的正式方法版本，以及 Codex 原生动作的处理方式。用户从这里管理安装状态，查看同一安装会影响哪些正式方法，并进入已有的连接与技能管理页完成安装、凭据更新和卸载。正式方法的定义和冻结归 KnowLab，上架、获取及撤回使用资格归 KnowMart。

注册中心位于 KnowBench API。API 和 runner 使用同一应用的持久化记录、登记解析及核权规则。远端 MCP 服务执行连接器操作，隔离环境执行脚本，Codex 与本地 Link 在会话绑定的环境执行命令或文件操作。工具方法与专家方法仍是两类方法。

## 登记、查询与变更

| 对象 | 身份与版本 | 管理及执行 |
| --- | --- | --- |
| 原生安装 | 用户、安装 ID、修订及操作或文件入口 | 沿用连接和 Skill 的安装、发现、续接、停用和移除接口。远端同名条目歧义阻断，长期凭据留在连接服务 |
| 正式方法 | 方法 ID、版本和定义摘要 | 冻结后登记。保留来源安装修订、入口、摘要；组合专家保留子方法引用。新版本另行登记 |
| 原生动作 | Codex 协议动作、会话、线程、轮次和请求或条目 | 命令和文件变更可收审批及事件，搜索可观察，提问交回 Interaction。额外权限按具体资源和当前执行环境核验 |

管理目录按登录身份提供安装及正式版本。单项详情沿用 `GET /api/workbench/registry/installed/{asset_id}` 和 `GET /api/workbench/registry/formal/{method_id}/{version}?digest=…`。页面显示实际账号、安装状态、版本及来源；停用时展示受影响的本人登记。正式登记保留原修订，当前安装状态和市场资格由执行路径重新核验。更新使用现有修订号和 CSRF 保护，冲突后重读。

## 发现、执行与证据

1. 原生会话在当前轮次已加载范围内选工具；作者在 KnowLab 的可引用目录选版本；正式专家沿确认图解析依赖。管理目录只展示登记事实。
2. 同一安装允许多个派生方法。各自的精确引用决定路由，运行前绑定实际账号和修订。两个方法或两条路径即使选中同一个底层操作，批准、父级、费用和产物也分别关联本次调用。
3. 调用前检查真实会话或步骤身份、使用资格、父授权、具体参数、资源和预算。恢复优先找回原调用和回执；已派发而结果未知的操作保留未知状态。审批、计量、产物和原生事件继续使用各自权威账本。
4. 原生额外权限按 Codex 0.170.0 的权限请求与响应契约处理。在当前用户控制的工作轮次内展示具体文件范围和网络要求；核对电脑绑定、根目录和本机上限，批准后再核对一次。返回本轮获准范围。过期、取消、环境变化和无法约束的范围返回空授权。正式专家使用冻结步骤已有的授权机制。

## 管理页和接口

管理页入口为 KnowBench「设置 → 注册中心」，中文路径为 `/zh-CN/workbench/settings/registry`。本人查询走现有网页登录鉴权，响应使用 `private, no-store`。数据库沿用安装、正式版本、调用、审批及会话事件表，本次无需新迁移。

| 页面 | 数据及操作 |
| --- | --- |
| 原生安装 | 按名称、账号或安装 ID 搜索，展开当前修订的入口，查看直接派生的本人方法版本。启停复用带修订号的变更接口。安装、更新凭据及移除可进入对应连接或技能页 |
| 正式方法 | 按名称、方法 ID 或来源入口搜索，核对确切版本、摘要、登记来源、当前安装状态及冻结的子方法依赖。作者到 KnowLab 修订，使用资格交 KnowMart 核验 |
| Codex 原生动作 | 展示 runner 已接入的协议动作、可观察的条目类型，以及请求使用审批还是提问 |
| 最近记录 | 展示本人非孵化试跑会话最近 40 条调用、审批及执行事件。逐条保留来源路径、会话及记录 ID，有底层安装或正式方法引用时一并展示。文件正文、原始协议载荷和凭据留在原服务 |

目录总览用 `GET /api/workbench/registry`，最近记录用 `GET /api/workbench/registry/activity`。两个单项接口用于按确切身份复核。旧的 Codex 事件按真实协议条目类型识别。安装当前修订与孵化时修订分别展示；单独撤回某份正式方法的使用资格后，同源的其他入口仍按各自资格使用。

## 验收与发布

- 本人、他人、旧修订、安装已停用、正式方法尚未上架及无数据各有明确结果。
- 同一邮件安装可同时保留原生入口和两个正式方法。覆盖独立调用、交叉批准被拒、单独撤回正式资格和底层安装停用。
- 管理页覆盖分类、版本、来源、影响提示、启停、刷新和错误处理。原生审批覆盖具体范围展示、允许本轮、拒绝、过期和越界。
- 本地联调用独立 PostgreSQL、合成连接及本地测试工作目录。目标集群、真实电脑及供应商验证由发布单注明实测条件。发版由 Cursor 执行。

开发分支实测覆盖同一轮使用三份独立登记、单独撤权、工作 Link 实际读写合成报告及按报告内容审批受管邮件调用。另在 sunmoon-kind 临时命名空间跑通三级专家脚本、启动后取消与失败的用量结算，3 项均通过，命名空间已删除。Web 通过生产构建和 Chromium 管理页导航测试。目标发布进度见[Cursor 发版需求](../sync-cowork/requests/luna/2026-11-21-KnowBench注册中心与管理页发版需求/request.md)。
