## 三、要先讲清的问题：清单里有一半不是作者能写的

清单里的一步（knowbench `StepContract`）有两类东西。下面拿样本「数据摸底」那一步看：

| 层 | 字段 | 样本里是什么 | 0029 说归谁 |
| --- | --- | --- | --- |
| 方法层 | `title`、`summary`、`why`、规则、开步前问什么、交回哪几项、怎样算对 | 「数据摸底」「看清你的数据有哪些表、哪些报告期、单位与合并口径」；合并、母公司两种都有时问用户 | 作者 |
| 工程层 | `method_text` | 一段英文指令，告诉模型怎么读表、列哪几项、只交回一个 JSON | 我们 |
| | `tools` | `list_my_data`、`read_my_table`、`read_my_data` | 我们 |
| | `output_schema` | 交回物的 JSON 结构 | 我们 |
| | `acceptance` | `json_object`、`required_keys`、`list_min` | 我们（「什么算对」本身是作者的） |
| | `on_reject`、`max_reworks`、`reserve`、`input_max_chars` | 重做、1 次、0.05、24000 | 我们 |

0046 第二节写的是「自己写：编辑器一步一步填：步骤、每步的规则、交回物、验收」。照字面，作者连工程层也要自己填，普通用户填不了。平台孵化里，工程层是运营或 AI 写的；到了自助，要先定由谁写。

## 四、总的做法：一份工作稿，两种改法

- **一个准专家名称下只有一份工作稿**。自己写、AI 帮我写、导入，改的都是这一份，随时能换着用：可以先让 AI 起个稿再自己改，也可以自己写一半再让 AI 补缺口。
- **作者只写方法层**，用白话填格子；**工程层由程序按格子生成**。所以自己写不用模型、不用电脑、不花钱。
- **给模型的指令也由程序拼**，内容只有两种：作者确认过的话，和平台对所有专家都一样的固定文字。AI 不写自由发挥的指令。
- **出处看是谁写的**：作者本人写的是原话；别人写的（AI、运营）是提议，作者确认了才算。
- **出一版才能测**：工作稿自动保存；点「出一版」时程序把关，过了才出准专家第 n 版（只增不改），拿去测试。

市面上是这么做的（凭记忆，未逐一核实）：GPTs 的编辑页有两个标签，「Create」是和 AI 对话来建，「Configure」是自己填表，两边改的是同一份配置；Coze 的智能体是作者自己写人设与回复逻辑，旁边有个「AI 优化」按钮；Dify 是画布上拖节点，每个节点填表。共同点：AI 帮写和自己写是同一个对象的两种改法，不是两条路。

## 五、自己写

### 5.1 编辑器里填什么

整个专家一处：

| 格子 | 写什么 | 进清单的哪里 |
| --- | --- | --- |
| 名称、一句话介绍 | | `name`、`tagline` |
| 接什么、不接什么、不接的去哪问 | 白话 | `pack.scope`（0029 E5） |
| 数据 | 从作者自己的 knowbase 里挑：作者放开给 knowlab 的、名下的引用、公开原件 | 交付时冻结成 `bindings`（草稿里不写，现有的把关已守） |

每一步一处，可以加、删、调顺序：

| 格子 | 写什么 | 例子的形状（不是内容） |
| --- | --- | --- |
| 这一步叫什么 | 几个字 | |
| 做什么 | 一两句白话；要提示模型「这一步一般要什么数据」也写在这里 | |
| 为什么 | 一句白话，专家处理期间摆在页面上给用户看 | |
| 用上哪几步的结果 | 从前面的步骤里勾 | |
| 规则 | 一条一条写：口径、阈值、换算、方法、碰到什么情况怎么办、什么时候停下来问 | 「……时用……」「……超过……算……」 |
| 开步前问用户什么 | 问题，可以给几个选项 | |
| 交回哪几项 | 每项起个名字，选类型：数、表、文字、列表；列表的每项再列它有哪几项 | |
| 怎样算对 | 从验收模板里选，再填参数（见 5.2） | |
| 没过怎么办 | 默认重做一次，再不过停下来问；可以改成退回前面某一步 | |

模板：开一个新专家时可以选一个模板，模板只给一套空格子和每格下面的提问（比如「这一步的数从哪来」「算不出来怎么办」），不预填步骤名、方法和数（0029 第九节）。

### 5.2 程序怎么生成工程层

| 作者填的 | 程序生成 | 对应现有的 |
| --- | --- | --- |
| 交回哪几项（名字、类型） | 交回物的 JSON 结构；这几项自动带「必须有」 | `output_schema`；`required_keys` |
| 怎样算对：必须有、不能空 | | `required_keys`、`non_empty` |
| 列表至少几项、必须是空的 | | `list_min`、`list_empty` |
| 列表每项都有哪几项、某项只能取哪几个值 | | `each_has` |
| 列表每项的某项都等于 | | `all_equal` |
| 数是用平台的计算工具算出来的（可以指定算式） | | `computed` |
| 两个数相等（恒等式、加总），容差多少 | | `identity` |
| 数和原数据那一格对得上 | | `sourced` |
| 说法要附原文引文 | | `quoted` |
| 上一步列出的每一项这一步都要有，不多不少 | | `covers` |
| 字数上限 | | `max_chars` |
| （不用填，每一步都带） | 交回的是一个 JSON；不给买卖建议、评级、目标价 | `json_object`、`no_positioning_advice` |
| 用上哪几步的结果 | | `input_refs` |
| 开步前问用户什么 | | `ask_before` |
| 没过怎么办 | 默认重做 1 次（所有者 10-04 定的 1 次），再不过停下来问 | `on_reject`、`max_reworks` |
| （不用填） | 这一步能用的工具：运行环境的只读读数据、计算、查引文工具全给 | `tools` |
| （不用填） | 每步额度、读入上限用默认值 | `reserve`、`input_max_chars` |
| 做什么、规则、交回哪几项 | 拼成给模型的指令（见 5.3） | `method_text` |

「高级」里可以直接改工程层的字段（工具删几个、改额度、手写结构），给懂行的人用；改过的照样过 knowbench 的包校验。工程层不进 `rule_sources`，和 0029 第二节一样。

### 5.3 给模型的指令怎么拼

```
[平台固定：你是谁、只用给你的工具读数据、数只来自数据或上游交回物、不给买卖建议]
这一步：<作者写的「做什么」原文>
规则：
1. <作者的规则原文>
2. …
用上：<上游交回物名>
交回一个 JSON，包含：<按「交回哪几项」生成的说明>
[平台固定：交回格式的要求、不要改文件、调用工具时带委托号]
```

- 作者写的话逐字放进去，不改写、不翻译。
- 平台固定的文字是我们的工程手艺：所有专家共用，我们改一次所有专家一起受益；改它出平台的新版本，不算改某个专家。
- 理由：模型在运行时看到的每一句，要么是作者确认过的，要么是平台对所有专家都一样的固定文字，C-L1（方法只来自用户）就能由程序核实。0029 让 AI 写 `method_text`，判断可能混进措辞里，「自查」核不出来。
- 代价：指令不如人工逐句打磨的精致。样本里那种精细的英文指令，其中属于作者判断的部分（比如「合并、母公司都有时问用户」），本来就应该写成作者的规则；属于格式的部分进平台固定文字。

## 六、AI 帮我写

### 6.1 一轮怎么跑

1. 作者在孵化栏点「AI 帮我写」，设这一轮的费用上限（默认 20 元，0029 第 6.5 节的提议），选电脑（同自助测试：默认上次那台，记住目录）。
2. knowlab 建一条孵化记录（第几轮、方式「自助 AI」、状态「起草中」），经服务关系 `knowbench:incubate`、契约 `knowbot-incubation/v1` 交给 knowbench。交的东西：作者是谁、孵化号、创意原文（六问或 skill）、**当前工作稿**（含作者改过和确认过的）、答过的缺口、作者挑的数据的**格式**（名字、表名、列标签、行标签，不给内容，0029 第 6.4 节）、费用上限。
3. knowbench 在作者的工作台里建固定项目「孵化」，开一件委托，跑我们写的孵化方法。作者在 knowbench 里看得到这件委托和花了多少钱。
4. 交回的 JSON 有四样：
   - **出处表**：工作稿里每个格子出自创意的哪一句，或者「提议」；
   - **缺口表**：创意里没说、又必须作者定的，每个写成一个问题，附提议和选项；
   - **建议**：对工作稿逐格的改动（加一步、改一条规则、加一个交回项、选一个验收模板……），每条带一句理由；
   - **自查**：哪些建议对不上出处，已经改成了缺口。
5. knowlab 取回（同测试的轮询），存成孵化记录的这一轮，跑原话核对（见第七节）。

### 6.2 建议怎么进工作稿

- AI 的建议**不直接改工作稿**。编辑器里每个格子旁边显示「AI 建议」，作者可以接受、改了再接受、不要，或者一键接受某一步的全部建议。
- AI 只能对**方法层**的格子提建议，加上选验收模板。不写 `method_text`，也不改工程层的「高级」字段。
- 作者自己写的、已经确认过的格子，AI 只能提修改建议，不能直接覆盖；下一轮会带着作者的现稿去，作者的改动不会被冲掉。

### 6.3 缺口和下一轮

- 缺口进「待办」，和测试中的问题在同一处答，可以答「按提议」。
- 都答完（或作者觉得够了），作者点「再来一轮」才开下一轮。不在答完后自动跑：钱是作者的，由作者按。
- 到费用上限停下，记「超预算」，作者可以加钱再来一轮，或者自己接着写。
- 测试没过回来时，作者可以带上测试报告点「再来一轮」（0029 第三节第 5 步）。

### 6.4 要电脑

现在 knowbench 的委托都挂在某台电脑的项目上（第 0 步也一样）。孵化只产出文字，本可以不要电脑，但那要改 runner。本期先照现状：要一台在线的电脑，没有就停在「等你接入电脑」。「不要电脑的委托」以后另定。

## 七、出处

### 7.1 怎么记

| 格子是怎么来的 | 来源 | 引用指向 | 程序怎么核 |
| --- | --- | --- | --- |
| 作者在编辑器里自己打的字 | `user_text` | 那次保存的编辑记录（谁、什么时候、哪个格子） | 编辑记录只增不改；格子的文字和记录里的逐字一致，记录的作者是作者本人 |
| AI 或运营提的，作者原样接受 | `user_confirmed` | 接受记录（作者本人、什么时候、接受的是哪一条建议） | 记录在、是作者本人、文字一致 |
| AI 或运营提的，作者改了再接受 | `user_text` | 编辑记录 | 同第一行：改过的就是作者的原话 |
| AI 从创意里抽出来的 | `user_text` | 创意第几版的哪一句 | 现有的原话核对：原话逐字出现在那一版创意里 |
| 作者答的缺口 | `user_confirmed` | 那个问题 | 现有的：指向一条作者答过的问题 |
| 还没接受的 AI 建议 | 待确认 | | 不进工作稿 |

- 方法层的每个格子都带来源标记，不只是规则：做什么、为什么、开步前问什么都会拼进给模型的指令，所以都要有出处。
- 规则与怎样算对另外汇成清单的 `rule_sources`；其他格子的来源记在 knowlab 的工作稿里，不进清单。

### 7.2 出一版时程序把关

- 方法层有一个格子没有出处，或者引用核不上，就不能出版本，页面标红那一格。
- 现有的 `draft_manifest_problems` 照旧。
- 生成的 pack 过 knowbench 的包校验。

## 八、导入

- **导入专家包**（清单 JSON）：方法层的内容算作者原话，记成一条「导入」编辑记录（作者本人、文件摘要）；工程层照导入的保留，作者可以在「高级」里改。只导入作者自己的文件，页面上照实写明「导入的内容算你的原话」。
- **导入 skill**：当作种子，作为创意的一种（`skill`）存一版，然后交给 AI 帮我写去拆；作者也可以不跑 AI、照着 skill 自己写。

## 九、出版本与测试

- 工作稿自动保存，不能直接拿去测。
- 点「出一版」：第 7.2 节的把关都过了，就出准专家第 n 版，照 0037 的版本号（只增不改），记模式「自助」。
- 测试照 0046 第三节；没通过就回到同一份工作稿接着改，再出一版。

## 十、平台孵化跟着怎么变

- 运营在管理端用**同一个编辑器**改工作稿，代替现在的「贴清单 JSON」。运营写的格子和 AI 的一样是提议，作者在 web端接受了才算数（第 7.1 节）。
- 0029 的三种平台孵化都落在这上面：手工是运营在编辑器里写；辅助是 AI 出建议、运营挑过改过再交给作者；自动是 AI 的建议和缺口直接交给作者。
- 管理端只看得到平台模式的工作稿（0046 第四节），作者点「我自己来」后运营立即看不到。

## 十三、要所有者定的

1. **工程层由程序按格子生成，给模型的指令由程序拼，AI 不写自由措辞**（第五节）。这一条改了 0029 让 AI 写 `method_text` 的做法，平台孵化也跟着改。
2. **作者在编辑器里打的字算原话，凭编辑记录核对**（第 7.1 节）。和 0037「规则出处只认创意版本里的句子」不一样：0037 那一条针对的是运营替作者写草稿，作者的原话只能在创意里；自助时工作稿就是作者本人写的。照 0037 的另一种做法是：作者写的规则要先写回创意、出一版创意，再引用那一句，作者要在两处写同一句话，我不建议。
3. **AI 帮我写本期要电脑**（第 6.4 节）。
4. **下一轮由作者点「再来一轮」**，不在缺口答完后自动跑（第 6.3 节）。
5. **运营也用同一个编辑器，运营写的算提议、作者接受才算数**（第十节）。这一条把平台孵化从「运营贴 JSON」改成编辑器。
