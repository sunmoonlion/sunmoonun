## 三、本次故障修复

1. `chosen_data.source` 改为 `z.literal('knowbase')`，匹配后端 20261028_0030 迁移后的来源约束。没有改成任意字符串，也不复活 cloud/local。200 响应里的非空资料不再阻断整个步骤与采单页面。
2. 将 401、403、404、契约不匹配和服务故障分别呈现。步骤、采单、项目看板读取失败可分别显示原因并只读重试，不再统称“没有取到这件委托”。
3. 公共能力先进入 tpl 并完整通过门禁，再串行同步工作台。HTTP 401 使当前标签页停止业务网络请求、关闭工作台事件流，隐藏旧身份页面但保留内存输入。在新标签页登录后，原页明确执行 `/api/auth/web/me` 核对；同一 actor/app 更新 CSRF 并恢复查询，账号变化清空缓存和旧输入后重新打开。
4. 不自动重放确认、派单、消息等写操作，不把输入/令牌另存浏览器持久存储，不延长 Web/Admin TTL。旧会话迟到响应不更新新会话。
5. 全量回归发现远程 Git 认证也返回 401；对应代理接口先向会话真源只读核对，避免把 Git 凭据提示误判为工作台注销。原本本地和远程建项目流程均保留。

确证的两类故障需分开记录：后端真实 knowbase 来源必然触发旧 Zod 拒绝；qwen 也记录了 board 401。原用户那次 /steps 的 HTTP 状态没有独立现场记录，不能声称它一定只有其中一种原因。会话为何失效尚无足够证据，不将 TTL 当作已证根因。
