## 2. 实施规格（修订后）

### 2.1 StepIdleGuard：活动 ≠ 进展

正式方法 turn（非 `data-plan`、非 lookup、非 `PLAN_STEP`）挂守卫。**禁止**「任意 `item/completed` 都刷新有效进展」。

分开两类时钟 / 状态：

| 概念 | 刷新条件 | 用途 |
| --- | --- | --- |
| 最近活动 | 去重后的 `item/started` / `item/completed`（含 reasoning、agentMessage、工具） | 仅表示「还有通知」；**不能单独续保** |
| 有效进展 | 去重后的**新**工具成功结果，或交回物方向的实质进展（例如首次出现非空 `agentMessage` 交回候选且与上一次内容指纹不同——以你们现有可判定信号为准，宁缺勿滥） | **只有有效进展才重置无进展计时** |

硬性约束：

1. **通知去重**：同一 `item.id` 只计一次（同定数据 / compute 守卫）。
2. **循环守卫**：同一工具 + 相同参数指纹 + 相同失败/相同结果，达到次数上限（建议对齐定数据 `MAX_IDENTICAL_RESULTS=3`）→ 判循环，触发中止；**重复失败或相同查询结果不得当作有效进展**。
3. **长工具**：`mcpToolCall` 已 `started` 尚未 `completed` 时，按**工具时限**监视，不得把这段算成「模型空转」；工具超时与模型无进展分开记账/文案。
4. **等人**：`waited()` / 审批等待期间，无进展计时暂停（与定数据一致）。

### 2.2 180 秒是保护时限，不是「模型卡死」断言

- 阈值：**连续 180 秒无有效进展**（活动有无不论）→ 中止本轮。
- 对用户文案必须可执行、可核对，例如：**「超过无可见进展时限，已中止本轮」**；费用照记；等人选择重做本步或停止。
- **禁止**文案写成「模型已卡死 / 确认无响应」之类无法证明的断言。
- **保留**正式步骤 900 秒总时限作兜底；**不自动重试、不加预算**。

### 2.3 必须确认旧 turn 已停，才能提供「重做」

沿用现有 `_stop_guarded_turn` 分支：

- `turn/interrupt` 发出 ≠ 停止成功。
- 确认停了：记 `idle_failure`（或等价），再进入 `WAITING(INPUT)`，选项「重做本步 / 停止」。
- **未确认**：`idle_stop_unconfirmed`（命名对齐 planning/tool），`settle_unattended` 一类路径；**禁止**开下一轮，避免双跑与重复计费。

接线参考：`runner.py` 里 planning / compute 的 failure 与 `*_stop_unconfirmed`；`TurnResult` 增字段；`advisor` 收口与定数据 / tool 守卫同构。

### 2.4 运行绑定 ≠ 费用已结算（勿提前写 turn_ids）

现码已区分（不要改坏）：

- 运行绑定：`refs.runtime_turn_id`（`bind_turn`）
- 费用结算去重：`attempt.turn_ids`（`attempt_transition` / `record_late_cost`）

`record_late_cost`：若 `turn_id in turn_ids` **直接 return**。把 turn 编号过早写入 `turn_ids`，取消后的迟到费用会被跳过。

正确做法：

1. **绑定成功**：可把 attempt 标为 `RUNNING`、写 `started_at`、只更新 `refs.runtime_turn_id`（及必要的非结算字段）。
2. **不要**在绑定时把该 turn 写入 `turn_ids`。
3. `turn_ids` 仍只在费用结算路径追加。

固定专家也要覆盖：

- `capture_attempt()` 当前对 `not is_dynamic(task)` 直接 `return None`（`method_tools.py`），只改动态路径则现场固定专家仍可能长期 `CREATED`。
- 运行态更新必须对**固定与动态**正式执行 turn 生效；查 `release-arrival` / 现网同构路径，按真实执行入口补绑定，而不是只修动态分支。
