## 2. 已证实的问题与修复

用户的确认确实在 **08:29:27+08** 成功，不是没有点击，也不是此前 Kimi tool_call 400 再现。巨潮原件已有留存，阻塞发生在加工交付：

1. 抽表原样行存在空 `label`，违反 knowbase 的 `minLength=1`，整批 facts 返回 422。修复沿现有唯一跨行科目解析保存真实 `source_label`；无唯一匹配的空标签行保留诊断，不编造科目。处理版本升为 `periodic-statements-2`，标准值保持原有解析规则。
2. 公开原件 references 请求额外发送 `basis`，违反提供方 `extra=forbid`，返回 422。公开引用按已发布契约仅发送 `subject/ref`；私有受益人流程仍保留其合法的 `basis`，没有取消授权。新增 knowbase user-data/v2 consumer lock，测试实际 HTTP 请求体与提供方 schema，避免 mock 总回 200 掩盖漂移。
3. WAITING 被统一写成“等你决定”，长原因按每年重复。现在区分“已确认、等数据服务”和“等本人处理”；面板按主体/报告种类/读取形式分组，显示期间、数量、状态、失败原因和最近核对时间，不再让长段落挤走步骤栏。
4. DataWaiter 更新进度/失败不一定产生对话事件；原页只随事件数变化重取，可能一直显示旧状态。现在等待中的采单快照与 DATA 等待原因通过已有 query 每 10 秒刷新；采单办结后停止该快照轮询，不伪造进度。
5. 失败旧单不能靠普通 open-job requeue 恢复。现在同一任务支持“重新核对采单 → 本人确认”：保留原 needs、任务与记录，新轮确认独立幂等键；重复核对不换键，重复确认不重复派单。knowfeed 作业去重仅作用于 queued/running/waiting，新需求不复用 terminal failed 作业。
