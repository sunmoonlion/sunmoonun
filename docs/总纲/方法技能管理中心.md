# 方法技能管理中心

## 产品入口和责任

KnowBench 方法技能管理中心负责版本登记、按用途提供候选目录、核验使用资格、解析执行入口，以及查询调用、审批与产物记录。按**可调用实现从哪里来**，有三条登记途径。

| 实现来源 | 谁来登记 | 得到什么 |
| --- | --- | --- |
| 安装登记 | 用户安装 MCP 连接或 Skill | 该用户的安装记录、修订及原生入口 |
| 作者直接登记 | 作者提交独立脚本或指令正文 | 本人名下的来源 ID、版本及原文摘要 |
| 服务登记 | 提供服务以获准的服务身份发布业务函数 | 提供方、函数名、版本及契约摘要，例如 KnowBase 的 `query_facts` v1 |

**正式方法版本另有登记入口。** KnowLab 在孵化试跑通过后冻结工具方法或专家方法，向 KnowBench 提交方法 ID、版本、定义摘要和试跑证据。例如，KnowBase 服务只需登记一次 `query_facts` v1，作者可用它孵化自己的工具方法，专家步骤再引用冻结的工具方法版本。组合专家也可以只引用已有方法。KnowMart 管上架、获取和使用资格。

同一组件还提供原生安装的技术登记，以及 Codex 原生动作的审批和事件查询。每次请求先确定引用对象。专家清单持有方法引用；聊天或工作也可能按安装修订选择原生入口。一次安装可以被多个方法版本引用。

## 登记真源在 KnowBench 的哪张表

**孵化可选目录、即时编排可选目录、步骤过滤目录的登记真源，都在 KnowBench 方法技能管理中心对应的数据库表。** 三个目录按需查询同一组记录。每条候选必须能按下表的键回查到确切登记。

| 候选对象 | KnowBench 登记真源 | 查询和引用依据 |
| --- | --- | --- |
| 已登记的工具方法、专家方法 | `workbench_formal_methods` | 方法 ID、版本、定义摘要，核对登记主体；组合专家还按冻结图解析其依赖 |
| 服务直接登记的业务函数 | `workbench_registry_service_functions` | 提供方、函数名、版本及完整契约摘要。管理端可反查方法，作者可选作来源；已接通的函数版本通过专用宿主适配器执行 |
| 作者直接登记的脚本、指令 | `workbench_registry_sources` | 所有者、来源 ID、版本、原文摘要 |
| 已安装的连接器和 Skill 的原生入口 | `workbench_capability_assets` | 所有者、安装 ID、当前修订、发现或安装时记录的条目 |

KnowLab 保存作者定义和孵化证据。KnowMart 保存自用及公开上架、获取、许可范围和撤权事实。查询正式使用候选时，管理中心取**已登记的精确版本与该用户适用许可的交集**。任务快照记录用户已经确认的范围；固定步骤进一步与该范围取交集，并在派发前复核。KnowLab 工作稿、KnowMart 商品、任务快照或管理页缓存单独出现一个条目，都不能补出缺失的登记；撤权也不会删除历史登记。

## 三个场景的目录统一由管理中心提供

管理中心回答某个身份为某种用途可以查哪些精确版本。KnowLab 用待建专家的能力声明筛选这些候选，KnowBench 用当次问题与候选声明比对。工作台先匹配有使用资格的专家，只有用户选择拟临时计划才查本题所需的工具与子专家。市场浏览、管理页都不替用户发起委托。完整流程见[专家方法使用方案](专家方案设计/专家使用方案/luna/专家及专家团使用方案.md)。

KnowLab 和 KnowBench 向管理中心提交当前身份、场景及用途。管理中心按登记对象的精确版本和相应权限返回该场景可选的条目。KnowLab 维护方法定义与输入输出契约，KnowMart 维护正式方法的上架、获取、许可范围及撤权事实；管理中心按需向相应服务核验。管理页显示本人登记，场景查询还可返回他人已授予当前用户相应用途许可的版本。

| 谁来查询 | 管理中心按什么范围返回 |
| --- | --- |
| KnowLab 孵化 | 按作者的来源使用、依赖引用或试跑资格区分用途。直接登记的脚本可作为实现来源；已登记、有引用资格的工具或专家版本可作为步骤。本人尚未自用上架的正式版本仍可按孵化资格试跑 |
| KnowBench 即时编排 | 按使用者、本次用途及适用的正式使用资格给出可查范围。编排器在此范围内先找能整体交付的专家，再按步骤契约与缺口反复查询，确认时锁定版本 |
| KnowBench 步骤过滤 | 从已确认计划中该步骤声明的精确引用或允许候选出发，叠加父级授权、当前账号、资源和环境约束。固定步骤只解析已锁定版本。新登记、新上架或同名版本均不扩大步骤范围；撤权后报告该步骤的具体缺口 |

例如，作者直接登记的 `reconcile.py@v1` 可以只存在于管理中心。正式方法在 KnowMart 自用或公开上架时，市场记录关联其精确版本；市场可展示尚待用户获取的公开方法。只有取得本次用途所需资格，该方法才进入使用者的相应可选目录。市场资格撤回后，管理中心保留原登记与历史引用，后续选用和派发重新核验。

**候选查询与精确派发已本地验通。**

- 在 KnowLab 保存能力声明后，作者编辑器按这份声明查询本人的已登记方法。查询使用标题、用途、适用条件和承诺交付中的用词；没有声明时展示可查目录。共享工具先核市场孵化资格和作者自己的连接，再在当前授权页排序。补前置步骤时，只保留中心返回的精确版本，再按输出的业务含义、Schema 和必需性核对，保留中心顺序。
- 在 KnowBench「方法技能管理中心 → 即时编排候选」填入本题，先查有正式使用资格的专家。选择查看可组合的方法后，目录才包括工具。两阶段都可以翻页，未出现相同用词的获权版本也可查看。展开某个版本的声明时重新核登记与市场资格，展示用途、适用条件、排除范围和承诺交付。排除范围供判断适用性，检索不会把其中的词计作匹配依据。
- 本批提供候选排序和声明对照。作者输入的是面向一类问题的声明，工作台输入的是本次问题。工作台统一受理、模型判断整体适配、用户确认和即时计划执行分别在原待办第 12、13 项推进。固定和递归专家执行时只解析已确认的精确引用。

两端查询以 POST 正文传递声明或问题，KnowMart 只收到查询资格所需的用户和方法版本引用。已用本地 PostgreSQL 对照同一组登记的两种排序，验证试跑先于上架、已有专家继续使用 v1、新查询可见获准的 v2，以及资格撤回后详情不可读。

## 各服务登记可独立选用的函数（下一批）

当作者、用户、模型或 runner 需要按任务从多个业务能力中选择时，管理中心以数据库登记和本次资格提供候选。平台自研可选业务操作统一以提供方的函数身份登记。KnowBase 将原数据 MCP 的业务实现抽为函数；同服务按确切登记调用本地实现，跨服务通过受认证的业务 API 调到提供方的函数。提供服务负责实现和数据核权。登记对象是实现入口；孵化试跑、正式方法冻结登记、市场上架及取得使用资格各沿现有流程。方法仍分工具方法和专家方法。

普通函数由编写它的系统直接调用。例如读取步骤产物时，KnowBench 选定已登记的读取工具，核对本次批准后在本进程调用 `read_approved`。其中的字段校验、查库和分页由代码选分支。任务结束时释放 KnowBase 运行授权也是程序按生命周期直接发起的内部请求。将来某一步若需向作者或模型单独开放，再给它定义业务契约并登记。

下表是实施起点。每一行都要追到具体操作和调用者；同一操作兼有原生、孵化或正式使用入口时分别记下权限与验收结果。

| 范围 | 已定位的入口与下一批核对内容 |
| --- | --- |
| KnowBase 数据 | 十个资料函数由 KnowBase 发布版本契约，KnowBench 按登记用途、调用身份与当前步骤选用。宿主读取和模型调用共用提供端，执行前核对任务、会话、市场或正式方法的资料授权。[提供端契约](../../../knowbase-app/knowbase-backend/app/app/application/services/data_query_revisions.py) · [提供端入口](../../../knowbase-app/knowbase-backend/app/app/interfaces/http/internal/function_calls.py) · [运行端读取](../../../knowbench-app/knowbench-backend/app/app/application/workbench/run_reader.py) |
| KnowBench 业务工具与执行 | 逐项核对项目会话列表与读取、发现数据源、查主体、请求资料、找专家、计算，以及 `read_task_output`。用后者验证已有连接登记与新服务登记并存时的身份、权限和既有冻结引用。核对宿主确定性调用、模型请求、固定图与递归执行。[工作台工具定义](../../../knowbench-app/knowbench-backend/app/app/domain/workbench/platform_tools.py) · [中心场景查询](../../../knowbench-app/knowbench-backend/app/app/application/workbench/registry_catalog.py) |

| KnowLab 与 KnowMart | 作者编辑器、输出槽反查、草稿重开、试跑、冻结及回炉均按确切登记查询或引用。市场自用上架、公开上架、获取、引用及撤回分别核对；买方用自己的账号和资格。查市场资格的内部 API 继续履行核权职责。[作者服务](../../../knowlab-app/knowlab-backend/app/app/application/services/formal_methods.py) · [市场交付](../../../knowmart-app/knowmart-backend/app/app/infrastructure/external/formal_method_delivery.py) |

| Codex、Link、供给器与管理页 | 聊天和工作按原生可见范围加载；专家按确认清单派发。核对实际线程、Link 本机白名单、隔离环境、审批、取消恢复和计量。管理页展示登记提供方、版本、用途和可用状态。产品 Web、管理端、服务间契约和部署清单按实际消费者核对；模板仓只在共用契约或脚手架受影响时更新。[本机执行](../../../sunmoon-link/agent/src/execServer.ts) · [执行供给器](../../infrastructure/applications/component-images/sandbox-platform/provisioner/provisioner.py) |

### 提供端和调用端逐项核对（2026-11-21）

KnowBase 的十项数据操作均按服务函数 v1 登记，原 `/api/mcp/data` 入口已撤下。Codex 通过 KnowBench 的工作台 MCP 协议发现当前获准的登记函数。KnowBench 解析确切版本并签发绑定本次调用的短票，KnowBase 在内部函数接口核验票据和实际资料范围。[数据函数](../../../knowbase-app/knowbase-backend/app/app/application/services/data_functions.py)

| KnowBase 操作 | 实际调用者、资料范围与迁移验收 |
| --- | --- |
| `list_inputs` | 委托列出本任务获准的资料和钉住的版本，聊天和工作列本会话已有有效授权的资料。撤权、停用或版本不可读后从清单退出。列清单本身只返元信息，不创建资料读取授权。 |
| `read_input` | 聊天、工作及已选中该操作的专家步骤经登记函数读资料。宿主用同一函数按页核对引文，脚本用它分页取得批准的资料版本和文本读法。每次固定取数关联父调用或任务根调用。 |
| `query_facts` | 模型查询冻结任务资料、会话已读资料或公开市场。首个贯通样例按三类范围分别核验，并验证服务登记不能替代用户资料授权。 |
| `query_metric` | 聊天、工作和固定专家按各自的资料范围查指标。返回指标名、公式、计算值和参与计算的事实引用。已用毛利率核对金额、页码、撤权及移除登记后的行为。 |
| `read_facts` | 模型按引用查当前获准的任务、会话或市场事实。宿主计算和数值验收只取当前任务的授权，另查中心登记的步骤场景并逐次记账。已核标准化与原样引用、撤权、移除登记，以及计算和复核同一组引用的独立回执。 |
| `describe_items` | 聊天、工作或已选该项的专家步骤查询受控条目、指标定义和词表。权限为 `vocabulary.read`，无需资料授权引用。 |
| `search_evidence` | 使用 `evidence.search` 在本任务或本会话仍获权的资料中检索，可按资料描述缩小范围，结果带确切资料版本、读法和页码。支持作者试跑及固定专家引用。 |
| `lookup` | 聊天、工作或选中该项的专家步骤按描述查询资料可供应状态。KnowBase 按用户及执行方计算可见状态，权限为 `materials.lookup`。 |
| `list_library` | 仅原生聊天和工作可见。按当前用户、执行方和会话列可展示资料及引用，权限为 `library.list`。 |
| `read_method_input` | 使用 `method.inputs.read`，仅供正式方法试跑和已批准的步骤。宿主或试跑模型发起后分别取得操作批准及资料所有者同意，KnowBase 核对用户、用途、完整调用路径、资料版本及有效授权。返回叶调用与授权回执。 |

KnowBench 自有的七项工作台操作中，`list_project_conversations`、`read_project_conversation` 和 `compute` 已从中心登记发现，在 KnowBench 进程内执行。其余四项当前由代码构造 `platform / knowbench / 操作名`，后续逐项迁移发现、准入和派发。

| KnowBench 操作 | 实际执行与迁移验收 |
| --- | --- |
| `list_project_conversations` | ProjectRecords 据在办任务列同项目会话。跨项目请求须被拒。 |
| `read_project_conversation` | ProjectRecords 按在办委托核对所有者、项目与目标会话，分页读同项目的其他会话。步骤须获准调用正文读取。调用账与读取事件通过同一调用 ID 关联到目标会话及实际页码。 |
| `compute` | 工作台核对已登记的 `knowbench/compute@1` 和当前步骤后，在本委托记录单笔或整批计算。每条计算底稿保留计算编号、输入引用和本次调用 ID；需要读取资料时，以此调用为父调用派发 `read_facts`。 |
| `discover_source_tools` | 工作台由任务解析账号，再向 KnowFeed 查供应商及技术操作。以实际账号、服务及发现快照对照，不能将发现结果直接拼进候选。 |
| `find_subject` | 工作台核验任务，再经 KnowFeed 查主体名称。验任务归属及同名主体选择。 |
| `request_data` | 工作台据任务向 KnowBase 提交需求，后续按确认的供应条件采集。验未确认、重复确认及对账回执。 |
| `find_expert` | 工作台据任务和所有者向 KnowMart 查目录。验两账号可见范围，查找本身不能创建委托或产生市场资格。 |

### 服务身份登记接口（本地实现）

KnowBench 在自己的数据库迁移 0054 建立 `workbench_registry_service_functions`。每条记录由提供方、函数名和正整数版本唯一标识。契约含用途、场景、所需权限、输入输出 JSON Schema 和提供方本地操作标识。提供方填本地逻辑函数名，入口只接受函数契约。执行地址和服务凭据由获准的适配器解析。契约摘要包含提供方、函数名、版本和契约全文。

服务以 `knowbench:function-publish` 关系访问 `PUT /api/internal/v1/method-skill-center/functions/{name}/{version}`。中心从服务身份绑定取提供方。同一版本重复提交同一契约返回原记录，冲突返回 409；同路径 GET 读取本服务登记的精确版本。集成方应给请求设置超时，仅对连接中断、限流或短暂不可用做有界退避重试，耗尽后保留待登记项并 GET 对账。提交校验失败或版本冲突时交提供方修正。此接口只写实现来源，用户可见性、试跑、冻结和运行授权由相应消费入口核对。

迁移按业务入口切换。某操作接入后，发现、选择与执行时重新核验均读取中心记录；缺记录即拒绝。原来通过常量、实时 `tools/list` 或名称拼出的业务候选和派发分支随该入口一起移除。外部供应商连接仍可用协议发现检查其技术描述。十项 KnowBase 数据函数已完成切换，KnowBench 自有工作台操作按待办第 5 步继续迁移。

### 查询服务函数、反查正式方法与作者选源

KnowBench 管理端的「方法技能管理中心」面向获准的管理员和运营人员。输入提供方、函数名或完整摘要，可翻页查看各版本。点开某一行可看输入输出契约、实现函数、声明的场景和所需权限，以及直接引用该版本的正式方法。引用来自 `workbench_formal_methods` 已登记的冻结文档，须同时匹配来源类别、提供方、函数名、版本和摘要。列表显示方法名称、ID、版本和摘要。普通用户的浏览器会话没有管理端访问权。

管理 API 入口是 `GET /api/admin/v1/method-skill-center/functions` 与其下的 `/{provider}/{name}/{version}`。前者的 `q` 查询提供方和函数名、或精确匹配完整摘要；后者分页返回直接引用该版本的方法。两者用 `limit`、`offset` 翻页，响应的 `has_more` 分别对应登记或方法引用。

KnowLab 作者仍使用原有选源框。KnowBench 把作者有效的来源使用许可与真实登记按完整身份匹配，只返回声明用于孵化的来源。许可过期、撤销、摘要不同或缺少登记都会使它退出候选。作者选中后，草稿以 `service_function` 标明来源，保存提供方、函数名、版本、契约摘要和许可依据。该字段属于实现来源，方法仍分工具和专家两类。本地已验草稿保存，以及下述私有试跑和冻结。

KnowBase 和 KnowBench 各自在本服务镜像中运行 `python -m app.bootstrap.publish_functions`，用各自的服务身份向同一个内部接口提交契约。KnowBase 一次发布上表十项资料函数的 v1，KnowBench 发布项目会话列表、正文读取和委托计算三个 v1 函数。发布进程使用获准的 `DOWNSTREAM_BASE_URL`、`DOWNSTREAM_ALLOWED_PATH_PREFIXES`、`DOWNSTREAM_CLIENT_ID`、`DOWNSTREAM_CLIENT_SECRET` 及 `DOWNSTREAM_SCOPE=knowbench:function-publish`。两端各自核对 KnowBench 回执中的身份、契约和摘要。短暂不可用时同版最多提交三次。验收用本地服务身份；目标集群发布该登记和授权记录由 Cursor 按发版需求执行。

### 首个正式步骤怎样调用已登记函数

三项事实函数、证据检索和资料清单函数的作者试跑和私有专家步骤使用宿主执行。各项各自绑定来源许可、操作名和对应版本的内部目标。宿主从中心读取精确版本，复核作者许可、步骤用途和运营核定的读操作与费用依据。作者声明可查询的范围，用户逐次批准本次参数。查本次任务时，宿主补入已确定的运行授权引用，作者和模型不能另填任务或会话 ID。查市场事实时，KnowBase 核验当前用户的市场数据资格。`list_inputs` 的步骤只接受本次任务范围，按 `inputs.list` 单独核定。

KnowBench 向配置的 KnowBase 内部函数接口发送签名短票，绑定用户、沙箱、调用 ID、版本摘要和实际参数摘要。KnowBase 在查询时检查当前资料授权，按登记契约返回结果。两端按调用 ID 对账；已撤权资料不再返回。试跑保存实际产物与来源，凭可核验的宿主函数回执私有冻结。跨进程本地用例用同一冻结工具完成专家的两次独立批准，与原生数据查询对照事实和页码。[本地联调](../../scripts/local-integration/service_function_execution.py)

### 原生会话与同进程函数怎样使用登记

Codex 通过工作台 MCP 网关发现和请求工具。对于已迁移的函数，网关先从中心表读取提供方、函数名和精确版本，核验契约并生成模型可见的参数说明。请求到达后核对真实轮次、调用身份与步骤范围，将函数身份、版本、契约摘要及参数摘要写入共同调用账，并在派发前重读登记。移除登记后，该函数退出发现目录，新请求被拒；已记账但尚未派发的请求若发现登记变化，也会停止。

- 跨服务查询用 `knowbase/query_facts@1`、`knowbase/query_metric@1` 和 `knowbase/read_facts@1`。网关从当前会话或委托解析 KnowBase 的授权引用，经内部函数接口发送签名请求。会话只能查询本次会话已读且仍获授权的资料，委托按它的运行授权读取。公开市场查询另核当前账号资格。KnowBase 的读取记录可按同一调用 ID 与 KnowBench 对账。原数据 MCP 已移除这三项操作。
- `knowbase/list_inputs@1` 返回已有授权的资料、版本、来源及可用读法。请求工作台时填写当前任务或会话，由宿主换成授权引用。会话初次列清单可以为空；用户向该应用展示的其他资料和公开引用沿 `list_library` 查询。列清单留下函数调用回执，正文读取另行留证。
- `knowbase/read_input@1` 使用 `inputs.read`，登记用途为原生会话和步骤。模型可按正文、页码、格式或文本原件读取。KnowBase 按当前用户和执行方核查任务授权或会话授权。普通会话首次读取可按已有展示范围或公开资格取得该版本的会话授权。正式方法按逐层批准读材料时，使用单独登记的 `read_method_input@1`；其票据还绑定资料、用途与完整方法调用路径。
- 引文核验按任务授权取指定页，平台故障与该任务读不到该页分别记录。脚本只读取批准的资料 ID、版本和文本读法，按字符偏移分页、按 UTF-8 字节限量。容器就绪后重新核权并比对两次读取内容。后续页和重读只认仍然有效的授权，撤权或移除函数登记即停止投递。固定取数账本保存摘要，调用 ID 可回查 KnowBase 的实际读取。
- `knowbench/compute@1` 按 `task.computations.record` 登记，执行会写入本任务的计算记录。单次或批量计算引用事实时，以及宿主核对交付的 `sourced` 数值时，KnowBench 均选定 `read_facts` v1，按当前任务的运行授权签票读取。计算中的取数记在计算调用下面；验数记录关联任务与当前执行尝试。调用账保存函数摘要、参数摘要及已核回执，可用调用 ID 对应 KnowBase 的读取记录。无法核实回执时保留未知结果。
- 同进程查询用 `knowbench/list_project_conversations@1` 和 `knowbench/read_project_conversation@1`。列表使用 `project.conversations.read`，读取指定页使用 `project.conversations.content.read`。KnowBench 调用项目记录服务，按在办委托、当前所有者和项目查询，并校验返回结构。项目读取事件和调用账共用调用 ID。重复提交同一次成功调用只返回已存回执。

目标环境由 Cursor 在同一维护窗口协调两端切换，准备两端镜像、中心表、签名配置和两个发布身份，登记并核对精确版本，再开放业务流量。目标环境须分别验原生、专家、撤权和缺登记。

## 作者直接登记脚本或指令

在「设置 → 方法技能管理中心 → 脚本和指令」选择「新建登记」。例如上传 `reconcile.py`，或选择「指令」后粘贴正文，提交即可取得本人名下的 ID、版本和内容摘要。直接登记不要求安装 Skill、创建 KnowLab 草稿、完成试跑或上架。脚本和指令在登记簿中可独立存在。只有对象本身被定义为方法时，才适用工具方法与专家方法的分类。

接口使用 `PUT /api/workbench/method-skill-center/sources/{source_id}/{version}` 接受类型、名称及 UTF-8 正文。首次使用 v1，再提交的版本依次递增。相同版本、名称、类型和原文支持幂等重试；冲突返回 409。摘要按原文 UTF-8 字节计算。本人列表 `GET /api/workbench/method-skill-center/sources` 仅返回元数据，精确读取用 `GET /api/workbench/method-skill-center/sources/{source_id}/{version}?digest=…`。记录存于 `workbench_registry_sources`，当前单文件上限 256 KiB。

### 在专家项目中执行一个已登记版本

KnowBench 在现有专家项目会话提供两次请求，复用 Task、Attempt、根预算和产物表。向 `POST /api/workbench/sessions/{session_id}/method-skill-center/source-tasks/preview` 提交本人来源 ID、版本、摘要、JSON 对象参数和费用上限，返回确切来源、参数、当前报价与确认摘要。预览不会派工。确认时将同一份输入、`approval_digest` 和 `idempotency_key` 提给同路径去掉 `/preview` 的接口，取得一件可恢复、可取消的任务。换参数、来源、会话或报价要重新预览。普通聊天和工作继续使用原生会话。

| 登记来源 | runner 怎样派发和交付 |
| --- | --- |
| 独立脚本 | 供给器在隔离容器中运行已确认的单文件入口，沿用 Python、Shell、Node.js 的支持范围。脚本从 `SUNMOON_INPUT_DIR/arguments.json` 读本次参数，向 `SUNMOON_OUTPUT_DIR/result.json` 写一个 JSON 对象。以原调用 ID 收取回执、结算实际容器秒数并保存任务产物。 |
| 独立指令 | runner 在专用执行单元开一个受限模型轮次。发送前重新核对所有者、同一任务、批准的路由、账号、正文摘要和参数；只向已批准的供应商发送本题输入。返回 `{"result":"文本"}`，按用量回执结算并保存任务产物。 |

管理中心的最近记录按任务列出来源版本和摘要。用户修改同一来源后，已确认的任务继续引用原版本。任务取消或授权变化时停止新投递，对状态未知的外部调用按原身份对账。同一登记脚本还可作为本人私有工具方法的实现。作者在 KnowLab 选定来源版本，声明输入、输出、隔离执行权限和验收用例，通过试跑后冻结。

独立登记的指令也可在 KnowLab 孵化为本人私有工具方法。作者选择确切来源，声明单轮输入、输出和用例断言。KnowBench 从来源表重读正文并核对摘要，按每次试跑的模型用量结算，成功后在方法表登记冻结版本。固定专家直接或递归引用该工具时，每步在发送前核对本次外发批准、来源版本和前序产物。登记 v2 后，引用 v1 的旧专家仍执行 v1。公开交付另列待办。

## 方法从哪里登记，runner 到哪里执行

KnowLab 冻结后调用服务间接口 `POST /internal/v1/knowbot-runtime/formal-method-registrations`。KnowBench 将冻结版本与此前成功试跑的回执、定义摘要及所需执行证据核对，通过后记入 `workbench_formal_methods`。同一作者、同一版本的重复登记核对已有记录。作者试跑使用候选草稿及绑定的测试委托；日常使用按场景另查上架及使用资格。管理页按作者查询整份正式版本记录集，安装记录可以为空。

| 方法及实现 | 方法登记锁定什么 | 步骤实际去哪里执行 |
| --- | --- | --- |
| 工具方法 · MCP 操作 | 方法版本、操作接口及摘要，绑定获准账号 | runner 可以按已确认步骤直接发起；模型发起时另核轮次，共同调用服务核权后由连接器访问远端 |
| 工具方法 · 确定性脚本 | 方法版本、脚本包摘要、入口和输入输出契约 | 宿主取得清单中的版本与参数，核验来源及批准，交给脚本供给器，在隔离容器执行；用量与产物回到该次调用 |
| 工具方法 · 纯指令 | 方法版本、指令入口、摘要及产出契约 | 宿主组织受控的独立模型轮次，按本次输入执行固定指令，校验输出并记录产物和用量。已接作者私有试跑和固定专家图的纯指令步骤。通过子专家递归调用时，发出模型请求前逐层核对登记与授权 |
| 专家方法 · 编排 | 专家自己的方法版本、步骤图、输入输出绑定、子方法精确引用 | KnowBench runtime 沿冻结图调度，遇到子专家继续展开；脚本、指令或 MCP 叶子分别进入对应执行器。组合专家没有直接安装 ID |

“宿主发起”和“需要模型推理”分别描述发起方与执行方。例如，runner 可以直接发起纯指令步骤，该步骤的计算仍要由模型完成。模型为一次调用填的参数属于调用记录，方法定义及冻结版本可被后续调用复用。管理页展示冻结版本声明的发起方以及代码中接入的宿主执行方式，实际执行仍受场景、资格、绑定及开关约束。

**正式方法的执行来源。** 正式脚本可引用已安装的 Skill 脚本，也可引用本人直接登记的单文件脚本。后者以来源 ID、版本、入口名和正文摘要授权，每次执行单独审批，实际容器费用计入试跑任务。调整登记版本后，旧方法继续读取原版。单轮纯指令方法可选已安装的 Skill 指令或本人直接登记的确切指令版本，均已验通私有试跑和冻结。

例如，「读取步骤产物」（`read_task_output`）由 KnowBench 本地执行。连接登记时，服务把该入口的描述存入 `workbench_capability_assets`。孵化选源按作者查询这条登记的 ID、修订和接口摘要，试跑还需相应许可。私有冻结后，工具方法另以方法 ID、版本和定义摘要记入 `workbench_formal_methods`。专家步骤引用这个方法版本，每次读取核对用户批准的产物和字段。单有服务代码、地址或运营许可，不能把该工具加进孵化目录。

正式目录按冻结过程区分直接工具方法和编排专家方法。现有编译器还对部分多子专家图产生历史内部标记 `expert_team`，在登记页同样归入专家方法，既有定义摘要保持有效。

## 登记、查询与变更

| 对象 | 身份与版本 | 管理及执行 |
| --- | --- | --- |
| 独立脚本、独立指令 | 用户、来源 ID、版本及原文摘要 | 作者直接登记，按确切版本读取，修订保留旧版本 |
| 原生安装 | 用户、安装 ID、修订及操作或文件入口 | 沿用连接和 Skill 的安装、发现、续接、停用和移除接口。远端同名条目歧义阻断，长期凭据留在连接服务 |
| 正式方法 | 方法 ID、版本和定义摘要 | 冻结后登记。保留来源安装修订、入口、摘要；组合专家保留子方法引用。新版本另行登记 |
| 原生动作 | Codex 协议动作、会话、线程、轮次和请求或条目 | 命令和文件变更可收审批及事件，搜索可观察，提问交回 Interaction。额外权限按具体资源和当前执行环境核验 |

管理目录按登录身份提供安装及正式版本。单项详情沿用 `GET /api/workbench/method-skill-center/installed/{asset_id}` 和 `GET /api/workbench/method-skill-center/formal/{method_id}/{version}?digest=…`。页面显示实际账号、安装状态、版本及来源；停用时展示受影响的本人登记。正式登记保留原修订，当前安装状态和市场资格由执行路径重新核验。更新使用现有修订号和 CSRF 保护，冲突后重读。

## 发现、执行与证据

1. 原生会话在当前轮次已加载范围内选工具；作者在 KnowLab 的可引用目录选版本；正式专家沿确认图解析依赖。管理目录只展示登记事实。
2. 同一安装允许多个派生方法。各自的精确引用决定路由，运行前绑定实际账号和修订。两个方法或两条路径即使选中同一个底层操作，批准、父级、费用和产物也分别关联本次调用。
3. 调用前检查真实会话或步骤身份、使用资格、父授权、具体参数、资源和预算。恢复优先找回原调用和回执；已派发而结果未知的操作保留未知状态。审批、计量、产物和原生事件继续使用各自权威账本。
4. 原生额外权限按 Codex 0.170.0 的权限请求与响应契约处理。在当前用户控制的工作轮次内展示具体文件范围和网络要求；核对电脑绑定、根目录和本机上限，批准后再核对一次。返回本轮获准范围。过期、取消、环境变化和无法约束的范围返回空授权。正式专家使用冻结步骤已有的授权机制。

## 管理页和接口

管理页入口为 KnowBench「设置 → 方法技能管理中心」，中文路径为 `/zh-CN/workbench/settings/method-skill-center`。本人查询走现有网页登录鉴权，响应使用 `private, no-store`。已有安装、正式版本、调用、审批及事件沿用现有表。独立脚本与指令采用新增迁移 `20261121_0052`。

| 页面 | 数据及操作 |
| --- | --- |
| 脚本和指令 | 可新建、粘贴正文或载入 UTF-8 文件；展开可看精确版本原文及摘要，从最新版本创建修订 |
| 原生安装 | 按名称、账号或安装 ID 搜索，展开当前修订的入口，查看直接派生的本人方法版本。启停复用带修订号的变更接口。安装、更新凭据及移除可进入对应连接或技能页 |
| 正式方法 | 默认展示全部本人正式版本。可按名称、方法 ID、类别、宿主执行方式或来源入口搜索，核对发起方、确切版本、摘要、登记来源及冻结的子方法依赖。作者到 KnowLab 修订，使用资格交 KnowMart 核验 |
| Codex 原生动作 | 展示 runner 已接入的协议动作、可观察的条目类型，以及请求使用审批还是提问 |
| 最近记录 | 展示本人非孵化试跑会话最近 40 条调用、审批及执行事件。逐条保留来源路径、会话及记录 ID，有底层安装或正式方法引用时一并展示。文件正文、原始协议载荷和凭据留在原服务 |

新开发接口统一使用 `method-skill-center`。KnowLab、KnowBench Web、设置导航及 OpenAPI 同步采用同一命名。

目录总览用 `GET /api/workbench/method-skill-center`，最近记录用 `GET /api/workbench/method-skill-center/activity`。两个单项接口用于按确切身份复核。旧的 Codex 事件按真实协议条目类型识别。安装当前修订与孵化时修订分别展示；单独撤回某份正式方法的使用资格后，同源的其他入口仍按各自资格使用。

- 本人、他人、旧修订、安装已停用、正式方法尚未上架及无数据各有明确结果。
