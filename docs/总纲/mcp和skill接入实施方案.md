## 1. 问题与结论

后端登记了一个工具，沙箱 Codex 不会自动获得它；Codex 获得工具描述，也不代表每一步只向模型暴露该步允许的工具。Skill 同样如此：Codex 可以发现已有技能文件，但不会自动取得后端方法库里的技能包，也不知道当前步骤选中了哪个版本。

因此必须完整建设以下链路：

```text
能力登记与执行绑定
    → runner 解析当前执行上下文、能力需求及授权
    → 准备本次能力包与工具范围
    → 将描述、文件和必要配置交付给 Codex
    → 确认实际可加载及范围约束
    → Codex 组织模型请求
    → 接收调用、核权、执行、记录结果
    → 返回会话结果或验收步骤产物、推进或等待、支持恢复
```

建议首选“后端管理注册信息和受管连接执行，runner 按步骤交付能力，Codex 继续承担模型交互”的路线。2026-11-13 固定版实测确认：`dynamicTools` 不能通过本次测试的 turn／设置／resume 请求替换，但 MCP 工具可以在同一 thread 内通过解除订阅、带新白名单恢复来切换，保留历史且不改其他线程。因此不再默认每一步新建 thread；优先“一任务一主线程＋步骤边界重载 MCP 范围”，独立复核、并行或隔离场景另开线程。Skill 与其他基础能力的完整隔离仍待验证，不能由 MCP 测试推定。

## 2. 术语、边界与本轮讨论的修正

| 概念 | 本文准确含义 |
| --- | --- |
| 方法 | 具有五要素两视图、身份、版本及孵化依据的正式能力；包括工具、专家和专家团方法，不等同所有会话安装项 |
| 步骤 | 专家内部的执行单元；每步一次方法调用，持有输入/输出映射、条件及恢复，不要求独立方法契约 |
| 工具注册 | 登记工具描述和程序可使用的执行绑定，不授予本次调用权限 |
| 工具发现 | 从已知 MCP 服务取得它提供的工具，例如调用 `tools/list`；发现结果可以被导入注册记录 |
| 模型侧暴露 | 请求组织程序把选中的工具描述提供给模型；和注册、授权分别处理 |
| Tool calling | 模型返回结构化调用请求，再由程序执行；模型自己不执行工具 |
| MCP | 工具发现、调用等交互协议；不决定客户端或实现必须位于哪一个 Pod |
| Skill | 作业指令及配套资源的一种交付形态；加载到上下文，不等于增加一个函数调用接口 |
| runtime | knowbench 的步骤与任务运行机制，当前由 runner、Advisor 等协作承担 |
| Codex app-server | 当前运行在用户沙箱容器内的进程，组织模型请求并处理工具交互 |

正式方法采用能力声明、所需权限、做法、校验、审批五要素，生成对外输入与返回两视图。Skill 可以承载方法的指令实现，但不是每个外部 Skill 都已满足正式方法契约；原生 MCP 工具也不能仅因发现成功就成为已验证方法。会话能力技术登记可独立存在，不要求先形成方法身份或孵化证据；用于专家时须经孵化建立正式方法映射，共用来源内容而不维护两份相互漂移的正文。

需要纠正的几种简写：

- “同一个后端”指同一个应用代码工程和镜像体系，API 与 runner 是两个 Deployment，各有进程和内存。
- “注册中心在 API”指 API 提供管理入口、注册数据持久化；不是 runner 直接取得 API 内存里的对象。
- “给模型注册工具”应拆成执行端登记和模型请求暴露。共享注册中心不会自动完成暴露。
- 同一工具被两个执行端加载，可以是一个定义、两个调用绑定；不必重复部署远端工具实现。
- Skill 扫描、Skill 正文加载、依赖可用、权限满足是四件事；发现目录不构成逐步骤隔离。
- 一项能力是否由模型选择，与它通过函数、HTTP、MCP 或命令执行是不同维度。

## 4. 部署分工与注册中心的位置

```text
knowbench 后端代码与镜像
    ├─ API Deployment → API Pod → API 进程
    └─ runner Deployment → runner Pod → runner 进程

用户沙箱 Deployment → 沙箱 Pod → 容器
    ├─ Codex app-server 进程
    └─ 桥接等辅助进程
```

API 与 runner 不共享内存。建议同一 knowbench 应用内复用领域模块、Repository 和持久化注册数据，各自持有有界缓存；不是跨应用读库。knowlab、knowmart 等应用仍只通过版本化契约交付内容，不共享库或对象存储访问权。

| 责任方 | 建议职责 | 不承担的职责 |
| --- | --- | --- |
| knowlab | 方法六要素、Skill 源文件与依赖声明、版本冻结和作者确认 | 使用者凭据与运行授权 |
| knowmart | 发布、可用条件、权利与精确版本交付 | 替使用者批准外部账号操作 |
| knowbench API | 工具登记查询、连接配置、凭据生命周期、授权与审批入口；发起发现和交付请求；通过现有工作台 MCP 暴露受管工具并接入统一调用检查 | 在普通 HTTP 请求中长期等待模型或执行任意用户脚本 |
| knowbench 存储 | 受管注册记录、连接与绑定、运行快照、账本与调用回执 | 存放另一份可独立修改的方法主档 |
| runner | 驱动步骤、解析工具范围、准备和交付能力、处理模型工具回调、执行后端适配器、恢复 | 直接执行不受信任的用户代码 |
| 沙箱 Codex | 加载工具与 Skill、组织模型请求、回交动态调用；按获准绑定处理本地能力 | 自动获得后端注册中心或扩大任务权限 |
| 沙箱能力准备组件（待新增） | 校验并落地获准技能包、形成只读文件和交付回执 | 执行模型提供的任意下载或安装命令 |
| link／本机执行端 | 守住本地目录、网络、命令等访问边界 | 接收外部连接器的原始凭据 |

工具发现由 API 发起，可能耗时的网络探测应复用现有异步作业能力；实际请求由受控后端 MCP 客户端完成，成功后提交候选描述。工具注册管理放 API，不意味着所有工具调用都走 API HTTP 请求。

程序直接调用和动态工具回调可由 runner 内的执行适配器处理；优先的逐步骤模型路径则由现有 API 工作台 MCP 入口接收请求，接入同一套后端核权及执行模块。这里没有把 runner 和 API 合成一个进程。长时间等待与任务派发须进入既有持久化作业机制，不能用同步 HTTP 长等承担整个专家任务。

缓存按工具版本、绑定修订和所有者区分；任务冻结版本不能被缓存更新替换。授权与连接撤销须在每次执行时重核，不只依赖 TTL 或失效通知。

## 5. 三条调用路径与选择规则

### 5.1 runtime 直接调用

```text
runner 中的专家步骤／工具方法派发
    → 解析精确工具绑定
    → 参数与权限检查、必要审批
    → MCP／HTTP／可信函数／方法流程入口
    → 结构化结果与调用记录
```

步骤已知调用对象时无需启动模型，也无需把工具暴露给模型。调用上下文来自运行程序，不能伪造一个模型 turn 来满足旧守卫。用户脚本和命令要交给声明的沙箱或本机执行器，不在共享 runner 进程直接运行。

### 5.2 模型选择，后端执行：优先 MCP，保留动态工具适配

同一主线程中逐步骤改变业务工具范围，优先扩展现有工作台 MCP 入口作为受管工具入口：

```text
runner 读取当前步骤工具快照
    → 空闲边界解除订阅并恢复同一 thread
      配置 mcp_servers.<平台服务>.enabled_tools
    → Codex 从平台 MCP 获取工具并按白名单提供给模型
    → 模型请求 → Codex tools/call → API 工作台 MCP
    → 统一调用检查 → 后端适配器 → 外部服务／方法实现
    → 结果回到 Codex → 步骤验收
```

runner 负责决定范围和配置，工具描述由平台 MCP 根据注册信息提供；不必把注册中心对象复制到沙箱，也不把外部账号凭据下发。MCP 服务端仍按可信任务／Attempt 绑定核权，不信任客户端白名单或模型参数。本次只验证了固定版 MCP 筛选与调用机制，通用平台工具入口的接线尚未完成。

动态工具路径仍可用于能力集合固定的线程或独立执行块：

```text
runner 选定工具描述 → thread/start.dynamicTools
    → 沙箱 Codex 将描述提供给模型
    → 模型提出调用 → Codex item/tool/call
    → runner 核对执行绑定 → 统一调用检查与执行
    → 结果返回 Codex → 模型继续 → 步骤验收
```

传递的是本次允许的名称、描述和参数结构，不是完整注册中心、连接对象、密码或函数实现。runner 保留模型侧别名到精确工具版本、执行绑定的映射。工具可在后端或远端执行，Codex 不需要为它再连接一次目标 MCP。

### 5.3 Codex 直接接入 MCP

保留 Codex 接入既有 MCP、沙箱 stdio MCP 或经已确认本机通道访问 MCP 的能力。是否适用取决于绑定与实际控制能力，不按“聊天／工作／专家”简单划分。

带外部账号凭据的新连接器沿用连接器方案，走受管后端路径；不把凭据复制进沙箱来缩短接线。已有不带凭据的本机 HTTP MCP 保留其边界。云端 stdio MCP 的软件、依赖、启动和回收需要单独实现，不能把远程 URL 配置等同于安装服务程序。

若该路径不能提供某个专家步骤所需的强制权限限制、调用身份或结果证据，就不能作为该步骤的合格绑定。注册中心需记录实际接入方和执行环境，不得在后端不可达时偷偷切换到拥有其他权限的本机连接。

同一能力可能具备多条绑定，但本次执行明确选择一条。避免把同一业务能力同时以动态工具和原有 MCP 别名重复暴露，也不能因名称相同就合并两个不同账号或服务的工具。

## 6. 执行上下文能力准备与交付

### 6.1 在模型执行前增加明确阶段

聊天、普通工作和方法步骤共用能力准备服务。每次需要模型的执行先完成：解析会话请求或方法执行块及其输入 → 解析候选和依赖 → 核对连接与资源授权 → 冻结能力包 → 交付 → 核验 → 才发送业务模型请求。程序直接调用也复用能力解析、绑定和核权，但不经过模型暴露。准备失败不计为业务方法成功，也不能让模型自行猜测缺失工具。

方法输入仍是对外契约；步骤输入从方法输入、前序已验收产物和固定配置等来源映射。能力准备是运行基础机制，不强迫每个方法都添加一个“输入／安装工具”的业务步骤。

按 11-14 主稿，每个专家步骤只调用一个方法。被调工具方法的固定模型实现不再调用其它方法；被调专家方法或专家团方法则沿同一编排形成子计划。范围绑定实际方法调用及其模型执行上下文，不以一个步骤隐藏多个调用，也不把步骤变成方法类型。

### 6.2 建议能力包字段

以下是运行快照建议，不是新六要素，也不是已发布协议。

| 部分 | 建议内容 |
| --- | --- |
| 执行归属 | 所有者、会话、任务、调用链、步骤实例、Attempt、执行块 ID；普通聊天按真实会话与轮次绑定 |
| 冻结依据 | 能力选择来源、用户启用配置修订、能力包摘要、编译／适配版本；存在方法和计划时另记其精确版本与修订 |
| 工具及接入配置 | 工具精确引用、模型别名、输入结构、描述摘要、执行绑定引用、接入路径和 MCP 白名单；动态工具路径另存注入描述，不含外部账号原始凭据 |
| Skill | 固定版本和内容摘要、文件清单、包来源、入口文件、显式加载或候选模式 |
| 依赖 | 所需工具、资源角色、运行程序与环境要求、传输和调用位置 |
| 基础能力范围 | 文件、命令、网络、搜索、已有 MCP 和自动发现 Skill 的允许范围 |
| 运行限制 | 授权引用、调用次数、时间、预算、输出大小及嵌套深度上限 |
| 交付与核验 | 目标沙箱／环境、实际文件路径、文件摘要回执、协议版本、核验结果 |

冻结后，不用远端“最新描述”替换正在运行的任务。空工具列表表示不暴露业务工具；缺字段、无限制和空集合必须在 schema 中分别定义，不沿用可能把空列表解释为放开的框架默认值。

### 6.3 从方法市场选择

模板可以固定方法，也可以固定候选范围与选择规则。候选来源于方法市场或已授权目录时，先解析权利、输入输出兼容、版本、权限和环境条件，再生成当前步骤可选择的集合。

模型只能从这个集合提议；选中另一方法时由后端校验并启动子调用。方法市场是能力供应、版本和权利的来源，不能直接把全市场变成模型本轮工具列表。Skill 内部提到其他方法也必须解析到已声明依赖，不允许以自然语言引用自动扩权。

### 6.4 聊天、普通工作与方法步骤统一在哪里

三种场景的能力选择来源不同，但应共用登记、版本解析、准备交付、加载核验、授权检查与调用记录。不能分别建设“聊天目录工具库”和“专家后端工具库”，再要求用户重复配置同一连接；也不能为了共用接入机制，把普通聊天伪装成专家任务。

| 场景 | 本次能力需求从哪里来 | 执行方式 |
| --- | --- | --- |
| 方法步骤固定调用某工具 | 冻结的方法／步骤声明与输入映射 | runner 可直接调用，按第 5.1 节执行，无需模型 |
| 方法步骤允许模型选择 | 步骤声明的候选及依赖，与用户可用连接绑定 | 准备受限工具集合和 Skill，再由 Codex 组织模型请求 |
| 普通聊天或工作 | 用户已启用的连接、MCP 与 Skill，会话选择及本次请求 | 按用户设置和会话授权形成有效范围，准备后交给 Codex |
| 用户明确选择一个 Skill | 用户的明确选择、技能精确版本及声明依赖 | 交付文件、解析依赖并显式加载；依赖仍须单独满足授权 |

```text
步骤声明／用户启用配置／会话选择／明确的 Skill 请求
    → 统一解析能力、版本、依赖与账号绑定
    → 根据运行环境和当前授权冻结本次能力快照
    → 按执行绑定准备：
        后端直接调用绑定
        Codex 所需 MCP 配置及工具白名单
        Skill 文件、发现范围或显式加载输入
    → 核验后直接执行，或由 Codex 组织模型请求
    → 共用调用检查、审批、结果记录和恢复机制
```

用户配置回答“用户有哪些能力、启用了哪些连接”；方法声明回答“这次执行需要哪些能力”。准备阶段将两者绑定到具体版本、账号、操作和资源。方法只声明读取邮箱时，不能自动选择任意已连接邮箱；存在多个合格账号而无明确绑定规则时，应由用户选择。缺少连接、授权或依赖时，报告缺口或等待补齐，不能因方法需要就自动授权。

连接器属于这条统一链：后端服务定义、用户连接、凭据生命周期与执行检查只有一套，聊天、工作和各级方法引用同一连接身份；每次运行各自绑定用途与范围。连接器可经 API 或 MCP 实现，Skill 可依赖它的工具，因此不将三者设计成三套账号系统。切入方法或返回聊天都不能自动扩大授权，具体语义见连接器方案 10.13。

普通聊天不必事先绑定一个方法。可以按会话设置启用一组能力，由模型在有效范围内选择；“按次形成范围”不意味着每次发消息都要求用户重新配置，也不意味着模型每次选择工具都要重新安装。用户启用配置可持久保存，内容未变时复用已核验的包和配置；范围或版本变化时才重新准备，并记录新的执行快照。

### 6.5 MCP 配置和 Skill 目录是交付适配，不是第二套能力来源

MCP 与 Skill 在 Codex 侧仍使用各自的接入机制，统一准备层不能抹掉这个区别：

- **MCP**：Codex 需要有效的服务配置，再连接服务、发现工具并将选中的描述提供给模型。远程 MCP 不需要把工具实现安装到沙箱目录；沙箱 stdio MCP 则需要程序、依赖和启动配置。配置可由受管配置文件或固定版本已支持并验证的线程配置提供，不能把它描述成“扫描某个工具文件夹”。
- **Skill**：Codex 需要能读取技能文件，并通过受支持的发现机制或显式 Skill 输入加载。普通会话允许候选发现，方法步骤可以明确指定技能；两者均通过第 8 节的文件交付和加载核验。显式加载仍需要可访问文件，扫描目录也不证明正文已进入当前上下文。
- **Skill 调用 MCP**：技能正文与工具依赖一起准备，先核验对应工具绑定及授权；只有 Skill 文件而没有有效 MCP 配置或调用绑定，不能算接入完成。

因此，用户可以继续通过设置启用 MCP 和 Skill，而平台负责将选择转换为 Codex 实际可用的配置与文件；不要求用户为每个专家步骤手工编辑沙箱目录。工具注册中心保存身份、版本和绑定，Codex 配置与受管目录是其运行时交付结果；不复制出一份可独立编辑的方法主档。

对用户已有的原生配置和技能目录，先保留原有使用入口；经用户确认后可索引到统一能力目录，记录来源、所有者和修订。用户管理的配置仍以原配置为准，平台生成的配置以受管记录为准，禁止对同一项形成无规则的双向覆盖。不能未经确认把用户个人配置变成平台资产，也不能直接覆盖整个用户 `config.toml` 来应用某一步的选择。

共享包缓存不等于所有会话均可发现或读取所有包。准备服务需分别记录包已缓存、本次已交付、已发现、已加载和依赖可调用；缓存命中不免除授权核对。多会话配置应相互隔离，不能靠切换共享目录或全局 Skill 开关模拟逐会话范围。固定版的 Skill 发现与隔离仍待实测，不能把 MCP 白名单的验证结论套到 Skill。

### 6.6 执行归属与范围变化

统一运行快照按真实业务身份关联：普通聊天使用 Session、执行上下文及 turn；工作存在实际任务时关联该任务；专家方法再关联调用链、步骤、执行块与 Attempt。统一检查读取这些真实绑定，不强制每种调用都有专家 Task，也不通过伪造步骤编号满足旧守卫。

第 7 节的空闲边界切换同样适用于普通会话改变工具范围。一次模型执行中的新增能力请求先暂停或结束当前执行，核对新需求与授权，冻结新快照后再继续。用户撤权则应立即阻止后续调用，不等待下一次配置重载。历史 Skill 指令和工具结果不会因范围缩小而消失；需要隔离旧上下文时另用经验证的隔离方式。

例如，用户已启用某邮件连接及“整理报告”Skill：聊天可在会话允许范围内使用它们；财务方法的读取步骤只绑定读取工具，整理步骤显式加载对应 Skill，发送步骤才准备发送工具并检查具体邮件审批。它们引用同一连接身份和能力版本，使用同一准备服务，但每次有效范围和批准依据分别记录。这是拟实现的统一行为，不是当前系统已具备的功能。

## 7. 逐步骤工具暴露与线程边界

目标采用“一个任务一个主要模型线程，必要时有独立执行线程”。步骤和 thread 不固定一一对应，确定性的工具方法调用不创建模型线程。模型步骤需要变化工具集合时，首期使用已验证的 MCP 白名单重载路径；`dynamicTools` 固定在线程创建时，不假设 `turn/start` 能更新。

| 业务步骤 | 内部线程 | 业务工具示例 |
| --- | --- | --- |
| 读取材料 | 主线程 T | 已批准的搜索与读取 |
| 计算分析 | 主线程 T，空闲边界切换 MCP 范围 | 指定计算方法；纯计算可直接执行 |
| 汇总报告 | 主线程 T | 业务 MCP 白名单可为空 |
| 发出报告 | 主线程 T 或程序直接调用 | 发送工具，执行前核对审批 |
| 独立复核／并行分析 | 新建有明确归属的执行线程 | 仅传所需产物和工具，避免继承待复核推理 |

步骤切换顺序为：核实没有运行中的 turn 或未决工具调用 → 固化前一步产物与下一步能力快照 → `thread/unsubscribe` → `thread/resume` 携带该线程完整的受管配置覆盖和新白名单 → 核对 thread ID、工具清单及执行绑定 → 才发下一轮。已装载线程上直接调用 `thread/resume`，本次测试不会应用新 MCP 白名单。解除订阅与恢复要串行，由 runner 持有线程使用权；多个订阅者、进程重启和崩溃窗口尚需项目集成验证，不把一次成功当分布式锁。

复用线程会保留旧消息、旧 Skill 指令和工具结果；从本轮工具列表移除工具，不代表模型忘记旧内容。能力范围改变不自动构成上下文隔离。需要独立判断时，通过输入映射、必要摘要及已验收 Artifact 交给新线程。新线程不是新 Pod 或新进程，但有内存、历史存储和模型输入成本，应限制活跃数量。

注册、交付、暴露、授权、执行成功分别记录。“只向模型暴露本步骤业务工具”还不足以防止其他路径绕过：必须同时核对 Codex 原有 MCP、shell、搜索、技能发现和文件环境。不能通过每步修改用户共享 `config.toml` 或全局启停 Skill 来实现隔离，那会影响并行会话。

首期验证按线程配置是否足以约束全部入口；不满足时采用独立受限执行配置／进程或其他已验证隔离手段，具体资源成本需测量。仅换 `cwd`、新建线程、显式加载一个 Skill，都不能单独证明隔离成立。禁用 shell 不代表所有脚本能力失效，需要把实际执行适配器一起纳入检查。

首次版本不做每次模型推理中的动态扩展。模型提出新增工具需求时结束或暂停当前执行，形成明确变更与新能力包；不能在同一循环中无记录地扩大范围。完成或取消后禁止旧线程发起新调用，历史消息仍可能存在，拒绝执行与清除旧上下文是不同问题。

## 8. Skill 的交付、发现、加载和依赖

### 8.1 不能省略的文件交付

工具描述可经 RPC 传入，Skill 通常还包含 `SKILL.md`、引用资料和脚本。API／runner 文件系统与沙箱文件系统不相同；发送后端绝对路径不构成交付。用户电脑目录又是另一环境，不能用本地 link 上传技能包来默认暴露用户工作区。

建议首期在沙箱增加受控能力准备模块，按以下流程实现；接口名称和端口需在正式协议中冻结：

1. API 校验使用权后提供不可变包清单和下载入口；跨应用交付走提供方契约，不直接读 knowlab 的库或桶。
2. runner 通过内部认证通道提交准备请求，绑定沙箱、执行上下文、包摘要、执行目录和一次性请求号；存在任务／Attempt 时一并关联。
3. 沙箱准备模块使用短期、限定包与目标身份的下载凭据拉取内容；它不是外部邮箱等连接器的凭据。
4. 模块核对摘要与文件清单、大小上限、路径穿越和链接逃逸，将文件原子落入受管理目录并生成只读技能包。
5. 返回实际可访问的入口路径、摘要和准备回执；重复同请求返回同结果，异内容冲突拒绝。
6. runner 核对回执与冻结能力包，才要求 Codex 加载。下载凭据失效后由既有授权重新签发，不改变包版本。

可扩展现有 sandbox bridge 的受认证管理能力，但需新增明确的内部端口／路由、Service 和 NetworkPolicy 配置，不能开放成公共文件写入接口或复用模型可任意访问的下载地址。现有 app-server RPC 不被假定具有上传 Skill 的功能。

包内容按摘要缓存，执行上下文只读引用，工作输出放另一目录。待审批或可恢复任务持有包引用；垃圾回收不能按“文件年龄”删除仍被引用的版本。不可把技能缓存可写目录当作执行隔离边界。

### 8.2 发现与显式加载

固定版协议支持 `skills/list` 的 `cwds`、`forceReload`，以及 `turn/start` 的 `skill` 输入项。扫描的实际目录层级与权限须由固定版测试确定，不把聊天中简称的 `.codex/skill` 固化为接口；常见技能目录名称是 `skills`，但受管包路径与注册机制以验证结果为准。

本步骤已选定 Skill 时，使用经核验的名称与沙箱路径显式加载，而不是只在提示词里提到名字。示意请求：

```json
{
  "method": "turn/start",
  "id": 101,
  "params": {
    "threadId": "<本次执行线程>",
    "input": [
      {"type": "text", "text": "<步骤要求与已绑定输入>"},
      {"type": "skill", "name": "<已选技能名>", "path": "<沙箱中已核验的SKILL.md路径>"}
    ]
  }
}
```

这是协议形状示意，不是可直接运行的业务请求。路径能被文件系统读取、被技能加载器接受、正文确实进入当前模型上下文，须分别验证；显式输入不替代前面的包安装和范围控制。

本步骤允许模型在多个 Skill 中选择时，才采用受限候选发现与按需加载。候选目录、摘要和实际加载结果均记录；`skills/list` 的查询结果不等于模型只能看到这些技能。先实现显式加载，候选选择作为后续工作包，不能因候选名出现在提示词里就宣称实现完成。

### 8.3 Skill 与工具的衔接

Skill 是模型上下文中的作业说明，工具是程序执行入口。若 Skill 要求调用 MCP 工具，能力准备必须同时提供对应工具及授权；若要求运行脚本，则须准备脚本、固定运行环境和受限执行方式。技能包交付本身不授予运行其中代码的权限。

依赖版本不兼容、模型侧别名变化或运行程序缺失时，在准备阶段失败。对 Skill 的引用名适配应产生有摘要的编译产物与映射，不改写已发布源文件。正式方法六要素中的业务验收由 runtime 执行，不能仅凭模型说“已遵循 Skill”判为成功。

Skill 指令进入模型上下文后，不能宣称其正文对模型不可见；在用户可读写的环境落地时也不能靠文件名保证保密。需隐藏实现的资产应评估后端执行形态，包交付需符合发布权利，不能承诺“通过 MCP 或 Skill 就无法获取方法”。

## 9. 统一调用入口、授权与审批

直接调用、平台 MCP 请求和动态工具回调共用后端调用检查模块，但使用真实来源身份。请求或回调的执行上下文、线程、轮次、调用 ID 按对应路径匹配可信绑定；不能相信模型参数里的用户、任务、连接、批准编号或环境路径。普通会话按第 6.6 节核对真实归属，不因没有专家步骤就绕过检查或默认拒绝。

执行顺序：确认调用归属与活跃状态 → 查冻结工具快照 → 校验参数 → 解析连接与资源 → 重核当前授权及撤销 → 匹配或请求审批 → 预留预算／调用额度 → 记录准备执行 → 调用具体适配器 → 保存结果和费用证据 → 返回受控结果。

权限按“连接＋操作＋资源范围＋数据去向”判断。五要素两视图的权限要求描述依赖，审批要求描述何时需要人作决定；两者都不是现成授权。父方法只向子调用传递必要子集，工具方法实现也不得绕过检查。

发送邮件的批准绑定发件连接、全部收件对象、正文和附件版本、方法与规则版本、授权修订和具体调用。读取批准不推导发送批准，命令前缀规则不能套给邮件。批准后参数发生实质变化须重核，不使用一个模糊的“用户已允许工具”标志。

等待审批先持久化 Interaction 与调用状态，不长期持有数据库事务。正常连接可等用户答复后完成同一次回调；超时或断线时按恢复状态处理，不能把等待返回为业务成功。长时间审批的继续协议必须在固定版验证：若无法恢复旧 RPC，则以持久化调用记录和新轮次交接恢复，保留原调用身份并避免再次发送。

外部凭据仅由后端连接适配器取用；knowbase 授权和本地目录授权各守原边界。工具返回、MCP 错误、技能文件都属于输入材料，不能改变授权或执行策略。自定义 MCP 地址、重定向与令牌目标需执行连接器方案的出站限制；首期使用已审服务，不开放任意云端命令安装。

## 10. 账本、并发、失败与恢复

### 10.1 复用现有事实记录

继续使用 Task、Attempt、Artifact、Interaction 与现有费用／事件体系，新增关联和调用回执，不建立第二套任务账本。建议关系：

```text
业务 Session
    → Task／实际存在的工作任务
        → 步骤实例与执行块
            → Attempt
                → 能力包、执行线程和模型轮次
                → 工具调用／子方法调用
                → 审批、结果 Artifact 与费用事实
```

普通聊天按 Session、执行上下文和 turn 关联，不虚构专家步骤。业务会话线程与步骤执行线程分开；现有单一 `session.thread_id` 查找逻辑必须扩展。不能只新增线程创建代码而漏改通知归属、取消、审批、模型费用和成果提交。

调用记录建议保存工具与绑定版本、别名映射、参数摘要和受控输入引用、调用来源、线程／轮次／call ID、授权批准依据、外部请求 ID、结果状态和 Artifact 引用。原始敏感输入不进入常规日志。

### 10.2 关键异常的处理

| 情况 | 必需行为 |
| --- | --- |
| 回调先于 `turn/start` 响应完成处理 | 在已登记的待启动上下文中有界暂存，获得可信轮次绑定后再执行；超时拒绝，不能猜当前任务 |
| 同一回调重放 | 以执行绑定与调用身份去重；同 ID 异参数拒绝；已有结果复用 |
| 模型用新 call ID 再次请求同一写操作 | 不只依赖 RPC 去重；使用操作级业务幂等依据及已执行审批记录核对，不误删合法的独立操作 |
| 请求超时或断线 | 区分未发送、已发送未知、明确失败、明确成功；发送后未知不自动按失败重试 |
| 用户批准后 runner 崩溃 | 从同一调用记录恢复，重新核权；不再次预留同一额度或重复执行写入 |
| 外部服务不支持幂等也无法查询 | 保留结果未知，进入对账或人工处理，不承诺 exactly-once |
| 撤权、换账号、token 刷新 | 读取连接修订；合法刷新不扩大权限；撤销不能被晚到刷新或缓存复活 |
| 用户取消、步骤被替换 | 先拒绝新调用，再尝试中止外部工作；保留已发生副作用和迟到回执，不宣称远端已回滚 |
| 恢复旧线程或技能缓存丢失 | 核对固定能力包、授权及原版本，重新交付同摘要包；不能改为最新版继续 |
| MCP 描述变更、服务重连 | 新发现结果作为新修订处理；不扩大旧快照，旧绑定不兼容则停止 |

工具结果按大小与类型限制返回，完整可用产物存 Artifact 并给引用；工具成功不等于步骤通过业务验收。MCP 错误、取消、拒绝、未知结果和正常空结果须有可区分语义。

第一版顺序执行，验证后再增加 DAG 并发。连接池和缓存按用户连接、授权身份及目标隔离；按用户、任务和外部服务限制并发。线程、预算及调用租约以持久化版本控制，不能用进程内一个 `current_step` 变量决定归属。嵌套专家沿用调用链、预算与取消传播，设置深度和总调用上限。

以下为待实现的用户端设计，不是现有页面说明。账号配置、能力资产与本次选择分别呈现，共用后端身份和契约；不要求用户理解 API／runner、Pod、thread 或修改 Codex 配置文件。管理端的服务准入与用户的账号接入分开，用户拥有某连接不等于有权修改平台连接器定义。

#### 11.2.1 导航与共同规则

| 入口 | 主要问题 | 页面内容 |

| 设置 → 连接与工具 | 我接入了哪些服务、账号和工具？ | 连接器／MCP 列表、接入、认证、工具发现、状态、停用与断开 |

设置保留原有三个分区，新增前两个分区；第三个入口置于现有会话的输入区附近，并在任务详情提供同一范围的查看入口，不另建一个聊天系统。方法执行使用同一能力面板的需求模式：需求由冻结方法产生，用户绑定账号和资源，不能任意改写方法指定工具或绕过必需依赖。

“连接成功”“已启用”“本次已选”“准备完成”“实际加载”“允许执行”分别展示有证据的状态。复选框表示本次选择，不表示批准所有操作；发送邮件等具体动作仍使用既有审批卡。精确调用回执和方法验收继续进入原任务视图，不在设置页建立另一份账本。

#### 11.2.2 设置 → 连接与工具

列表以用户连接／接入实例为主，显示名称、服务提供方、账号脱敏标识、接入类别、连接状态、健康信息、可用工具数量、最近检查时间及正在使用它的会话／任务。相同服务的多个账号分行显示；操作不能只以展示名定位。暂无连接时提供“从服务目录连接”；只有后端能力已开放时才提供“添加远程 MCP”。

| 页面区域／动作 | 必需内容与行为 |
| --- | --- |
| 从服务目录连接 | 展示服务用途、提供方、可用操作及所需权限；选定服务后走其已支持的 OAuth、API Key 或无认证流程 |
| 添加远程 MCP | 录入名称、服务地址和后端支持的认证方式；后端验证地址和出站范围，执行连接、发现并返回候选；不接受任意云端启动命令 |
| 认证 | OAuth 打开受控授权流程；API Key 仅通过受保护接口提交，查询不回显明文，前端不写本地存储或日志；平台登录和外部账号授权分开展示 |
| 工具详情 | 列出工具名称、用途、参数说明、已核定的读写／外发性质、所需权限、描述版本和发现时间；未知性质明确显示待核验，不自动判为只读 |
| 测试连接 | 显示本次检查范围与结果；默认只做必要的协议／认证／发现检查，业务读取仅在已获准范围内测试，不以发信或写入试连 |
| 刷新工具 | 获取新描述并展示增删及变化；受影响工具重新校验，新工具不自动加入当前会话或运行中方法的快照 |
| 使用情况 | 展示有权查看的依赖会话、任务和 Skill；只读查看不自动授予这些入口使用权 |
| 默认选择 | “新会话默认选择”只影响后续新会话的初始候选；保存默认值不签发运行授权，也不修改在跑任务 |
| 停用／重新启用 | 停用立即阻止全部场景经此连接发起新调用；保留连接记录与凭据，重新启用前核验连接并重核运行授权，不复活过期批准 |
| 断开 | 展示影响范围；确认后先禁用新调用，再清除活动凭据并尝试外部撤销；保留审计记录，外部撤销失败单独显示 |

连接业务状态沿用连接器方案的 `connecting`、`active`、`reauth_required`、`disabled`、`disconnected`，健康检查独立显示。API Key 的实际权限未知时明确标示“服务端权限范围未确认”，平台仍限制具体操作。`active` 不代表所有工具均已核验或获得本次授权。

首期开放已审服务目录中的一个连接器和一种受控 MCP 接入。任意自定义远程地址、沙箱 stdio 安装及 A2A 分别按后端能力验收后开放；未支持项不放一个可以保存却不会生效的表单。本机已有不带凭据 MCP 仅在取得用户确认和真实可见状态时展示来源及管理入口，不宣称平台已代管；带凭据的新外部连接器继续由后端持有凭据。

#### 11.2.3 设置 → 技能

技能列表显示名称、用途、来源、精确版本、发布者、依赖完整性、启用状态及使用情况。详情展示能力说明、所需输入和访问条件、步骤概述、校验与产物要求、审批说明；已登记为正式方法的技能引用方法六要素。普通导入 Skill 不自动成为正式方法，未提供的六要素内容标为未声明，不能由前端补写成已验证契约。

用户可从已获使用权的目录选择技能，或按后端支持格式导入技能包；导入先显示清单、入口、文件大小、版本／摘要及依赖，确认后登记。文件和包校验复用第 8 节，上传不触发脚本执行。首期不提供任意 URL 自动下载执行，也不把用户电脑绝对路径直接作为沙箱技能路径。已有原生技能经用户确认后索引，保留来源及管理归属。

| 操作 | 行为与限制 |
| --- | --- |
| 查看依赖 | 展示工具／连接器操作契约、可匹配账号、文件／命令／运行环境要求；分清缺包、缺连接、缺授权和环境不支持 |
| 补齐依赖 | 已有合格连接可供选择；缺连接跳转统一“连接与工具”，不在技能页重复录入账号；脚本环境由受控准备机制提供，不让模型自行安装 |
| 启用 | 使该版本进入可选择集合；不自动加入所有会话，不自动执行技能或批准依赖操作 |
| 新会话默认选择 | 只改变后续会话候选；与启用状态、当前会话选择和运行授权分开 |
| 更新版本 | 展示内容和依赖变化，生成新版本引用；正在运行的快照保持原版本，缺失旧包不能静默换最新版恢复 |
| 停用／移除 | 停用阻止新选择和受影响执行的新调用，通知在用会话／任务并按状态暂停或结束；移除用户引用不立即删除仍被在跑或可恢复任务引用的包 |

停用不等于从模型历史中删除技能正文，也不能承诺回滚已经执行的脚本。若某条原生路径无法落实停用或范围限制，必须标明它由原生环境管理并限制其作为受管方法绑定的资格，不能展示虚假的统一强制停用成功。

技能资产状态和运行准备状态分开展示。列表可显示“校验中／可选／已停用／校验失败”，依赖另显示“待连接／缺权限／环境不支持”等原因；本次执行的“交付中／已加载”在会话面板展示。上述为展示分类，正式状态码由提供方契约定义，不另扩展 Task 枚举。

#### 11.2.4 聊天、工作与方法中的能力选择

普通会话的“本次能力”面板按服务账号、工具和 Skill 分组。用户可沿用新会话默认选择，再为本会话调整；后台计算实际可用范围并显示不可用原因。默认选择需在会话建立时固化为明确修订，不能每次读取用户全局最新设置而悄悄扩大现有会话。

| 面板内容 | 普通聊天／工作 | 方法及专家执行 |
| --- | --- | --- |
| 能力来源 | 用户已启用资产、会话选择、明确的 Skill 请求 | 冻结方法、当前分支及父调用允许范围 |
| 工具与 Skill | 选择已有候选；可明确指定一个 Skill | 展示固定要求及允许的替代候选，非候选项不能强行替换 |
| 账号与资源 | 选择具体连接、资源范围和用途 | 将 `source_mailbox` 等资源角色绑定具体连接与资源 |
| 权限说明 | 区分可读取范围、写入／外发需审批、到期信息 | 展示方法要求与本次授权的匹配结果，子方法只取必要子集 |
| 缺项 | 引导添加连接／技能、重新授权或调整选择 | 显示必需／可选；必需缺项阻止对应执行，可选按方法声明降级 |
| 运行状态 | 显示当前已生效范围、准备状态及待生效变更 | 额外显示步骤和需求归属，不显示内部线程配置作为用户操作 |

完整流程为：选择或解析需求 → 服务端预检 → 用户补齐账号、资源与必要同意 → 保存期望修订 → 准备工具配置与技能文件 → 后端确认实际范围 → 启动本次执行。预检不通过时不发送依赖这些能力的模型轮次；用户若改为不使用某能力，须形成新的选择并重新预检。服务端每次调用仍重核，预检成功不能替代运行授权。

新增能力或扩大范围在当前执行暂停／结束后的空闲边界应用；界面同时显示“当前生效”和“待生效”，不能保存成功就显示已加载。移除当前会话能力则先阻止该会话的新调用，再更新模型侧范围；其他会话不受影响。准备失败显示原因及重试入口，保留变更记录，不默默回退到更宽范围。接口冲突须重新读取后确认，不用最后一次写入覆盖其他窗口修改。

缺项卡中的“去连接／重新授权”携带后端创建的受控返回上下文，连接页成功后返回原会话或方法需求位置并重新预检。用户取消、关闭页面、任务已终止或等待已过期时不自动执行旧请求；重开页面查询后端状态，不靠浏览器是否跳转判定成功。原授权仍有效且其他条件满足时按既有恢复规则继续；具体发送动作另核审批，接通账号不自动发信。

聊天转为工作或调用方法时可以引用已有连接和选择，但必须按新执行上下文重新绑定、核权；结果返回聊天不把方法临时权限写入聊天默认设置。嵌套专家沿用相同面板和调用链记录，不为每个子专家创建一套连接配置。

#### 11.2.5 前后端接口职责与可信状态

具体路径和 Schema 通过现有提供方生成、消费者锁版机制确定。以下是必须具备的职责，不能用前端虚构数据或一个通用 `mcp_sources` 布尔字典代替。

| 接口职责 | 请求中的主要引用／输入 | 返回与执行要求 |
| --- | --- | --- |
| 服务目录与用户接入列表 | 过滤、分页、连接引用 | 定义与用户连接分开，返回能力支持情况、状态、脱敏账号、修订及依赖影响；只列本人有权查看的对象 |
| 连接创建／授权／回调 | 服务定义、支持的接入参数、受控来源上下文 | 授权事务与连接 ID、下一步动作；后端校验 OAuth 事务，查询不返回凭据 |
| 检查／发现／修订确认 | 连接引用、期望修订、操作请求号 | 有界异步检查状态、描述快照、差异与失败原因；不以目录刷新修改在跑快照 |
| 停用／断开／默认选择 | 目标引用、期望修订、明确动作 | 实际状态和影响范围；重复请求幂等，冲突返回最新修订；外部撤销结果独立 |
| Skill 目录／导入／版本管理 | 资产来源、包引用、精确版本、期望修订 | 校验结果、依赖、使用资格和版本摘要；启用资产不签发连接授权 |
| 执行需求预检 | 会话／任务／调用引用、选择与资源绑定 | 服务端解析的方法要求、可用候选、必需／可选缺项、范围差异和需要确认的内容 |
| 保存本次选择与同意 | 执行引用、期望修订、选定连接和资源、同意内容引用 | 可信能力快照与授权引用，区分已保存和已应用；方法版本与主体从后端绑定核对 |
| 准备／状态／恢复查询 | 执行上下文与快照引用 | 交付、实际加载、等待原因、当前／待生效修订；复用现有任务事件和恢复机制 |
| 动作审批与回执 | 现有 Interaction／调用引用及用户决定 | 沿用精确内容绑定、幂等执行和未知结果语义，不另建“允许所有工具”接口 |

身份从认证会话取得，前端提交的 owner、权限、工具只读性质、任务版本和“已批准”标志不能成为执行依据。管理动作沿用 CSRF 等现有约束；服务端复核所有资源归属和修订。错误响应提供稳定原因与可执行下一步，不能把 token、认证头或外部敏感错误原文直接展示。

页面刷新、OAuth 返回和网络断连后查询持久化状态；可复用现有事件订阅，无订阅时只对进行中的检查／准备有界轮询，终态停止。成功必须有后端回执：保存配置、发现工具、准备完成、实际调用成功分开。多个标签页不能重复创建授权事务、重复导入同包或重复执行写操作，客户端禁用按钮之外仍需服务端去重。

#### 11.2.6 前端归位与交付顺序

用户端位置相对于 `knowbench-app/knowbench-web-frontend/app/`：`lib/workbench/routes.ts` 和设置导航扩展入口；连接与技能的页面、API 客户端及模型放各自 feature；会话能力面板复用到聊天／工作及专家任务视图；`contracts/` 消费提供方契约，`messages/` 补齐中英文文案。既有审批卡增加连接、操作和范围展示，不复制一套审批组件状态机。

首期垂直交付必须同时包含：一个真实可用的受管服务／MCP 连接入口、一个已授权 Skill 的显式选择或受控导入与准备、聊天和方法共用的能力面板，以及审批和恢复闭环。广泛的技能市场候选、任意 MCP 地址和 stdio 安装可以后续扩展，页面只展示实际支持的操作。先补契约与后端能力，再接页面和执行链，不能以静态设置页作为完成标准。

#### 11.2.7 三个入口的验收

| 场景 | 验收结果 |
| --- | --- |
| 一次连接、跨场景使用 | 聊天、工作、方法引用同一个连接 ID，后端无重复凭据；每次范围独立，子方法不能扩大权限 |
| 多账号与缺项补齐 | 两个邮箱不混用；Skill 和方法缺账号均进入同一连接页，返回正确来源，重检后继续；取消不执行原动作 |
| Skill 实际生效 | 版本与摘要匹配，正文实际进入请求、依赖可调用；缺文件、缺权限、环境不支持在执行前给出原因 |
| 状态与并发 | 配置保存不冒充已加载；待生效状态正确；不同会话互不覆盖，多标签页修订冲突不丢失变更 |
| 默认、移除、停用、断开 | 默认只影响新会话；会话移除仅阻止本会话；全局停用阻止全部引用；断开还清除凭据，重新授权不复活旧批准 |
| 写操作与故障 | 连接成功不自动发送；批准后换账号／附件重新核权；断连、刷新、返回页面不会重复发送，未知结果明确展示 |
| 版本与兼容 | 新工具／新 Skill 版本不替换在跑快照；已有聊天、工作、方法及本机无凭据 MCP 保持既有授权边界 |

以上同时需要页面交互测试、提供方／消费方契约检查与执行链集成验证。模拟页面通过只能证明交互，不能代替真实工具调用、技能加载或外部授权验证。

### 11.3 分阶段工作包

| 工作包 | 交付与范围 | 准入证据 |
| --- | --- | --- |
| A：固定版接口验证 | 已完成动态工具更新负例、同线程 MCP 切换、历史与对照线程、模型调用正反例；Skill、长审批与进程恢复仍待测 | 见固定版验证记录；局部通过不代表整个 A 工作包完成 |
| B：登记与直接 MCP | 一种已审 HTTP MCP、精确描述快照、绑定、连接检查和直接调用 | 不启动模型完成输入→调用→结构化输出→下一步；失败、撤权和串用户反例通过 |
| C：统一模型接入链 | 聊天／工作配置与步骤声明接入同一准备服务；优先平台 MCP＋同线程范围重载；动态工具保留为固定集合适配 | 与 B 共用执行检查；会话与步骤范围正确，取消与重启不重复副作用 |
| D：Skill 显式交付 | 不可变包、沙箱准备模块、显式加载、依赖检查 | 正文实际进入请求、文件可用且范围受控；损坏包和缺依赖在模型调用前失败 |
| E：连接审批与持久恢复 | 一种连接器验证读取、写入审批、过期、撤权、未知与恢复 | 批准具体动作、参数变更重核；旧调用可对账且不误报成功 |
| F：候选选择与组合 | Skill 候选、方法市场绑定、嵌套方法与 DAG 执行块 | 候选和依赖受约束；上下文、预算与授权沿调用链正确传递 |
| G：前端统一接入 | 第 11.2 节三个入口；随 B/C/D/E 分批交付，复用同一连接与授权模型 | 页面、契约、真实准备与执行回执一致；三个场景复用、多账号、撤权、返回及恢复验收通过 |

A 可使用模拟推理端检查真实请求载荷，无需付费模型调用或并发启动大量沙箱；不能把“模型没有选择未授权工具”当成未暴露的证据。B/C 与 D 都是方案组成部分，不因工具链先完成就宣布 Skill 接入完成。完整 DAG 和候选市场不作为最小直接调用试验的前置条件。

如果 A 证明固定版缺少必需能力，按失败项选择适配或隔离方式；必要时增加后端模型请求适配器，仍接同一个步骤入口、授权和账本。不得默默升级 Codex、另建专家引擎，或将“全部暴露但执行时拒绝”冒充严格逐步骤暴露。

## 12. 验收清单与示范流程

以用户自有资料“读取→分析→形成报告→经批准发送”为示范，不引入平台自己的投资判断或数据。读取工具可先用本地模拟 MCP 验证，再接已有账号服务；真实外发测试另按明确授权执行。

| 验收面 | 至少覆盖 |
| --- | --- |
| 登记与发现 | 分页、同名工具、版本变化、无权连接、不可达服务；目录登记不自动暴露 |
| 统一接入 | 同一连接和 Skill 分别用于聊天、工作、方法步骤，无须重复登记；普通会话不依赖虚构专家任务；缺失或多账号绑定有明确处理 |
| 配置与范围 | 用户配置与平台生成配置归属明确；未变配置复用，变更在空闲边界生效；并行会话互不覆盖；撤权即时拒绝新调用；原生入口保留既有边界 |
| 前端三个入口 | 第 11.2.7 节全部场景；连接／技能管理与本次选择不混用，默认选择不等于授权，页面成功状态有后端证据 |
| 逐步骤暴露 | A 步请求有读取工具，B 步无读取工具；空集合；原有 MCP、搜索、shell 等不会绕过；并行会话不受配置变更影响 |
| 动态回调 | 正确请求、越界工具、伪造身份、参数不合法、迟到回调、重复回调、服务错误 |
| Skill | 精确版本、显式加载、引用文件、脚本依赖、扫描缓存、同名冲突、候选范围、旧版本恢复 |
| 包交付 | 目标沙箱绑定、过期下载凭据、损坏摘要、部分下载、路径与链接逃逸、用户间文件隔离 |
| 权限与审批 | 只读与发送分开，全部收件对象和内容预览，修改附件后重核，拒绝／过期／撤权／换账号 |
| 恢复与账本 | 请求已执行但结果丢失、runner 重启、Codex 断连、取消、预算去重、未知结果对账 |
| 组合 | 同一方法多次调用身份不同；父子授权不扩大；输入产物可追溯；子方法失败不伪造父方法成功 |
| 一次性切换 | 保留聊天、工作、固定财务专家的有效能力及历史证据；执行记录迁移后只走新格式；不能转换的进行中动作明确等待处理，旧语义审批重新申请 |

平台记录应能回答：当前步骤使用哪个能力包，向模型提供了什么，Skill 文件是否交付与加载，谁请求了哪个操作，谁批准了什么，外部实际结果是否确定。无法取得证据时标记未知，不能靠模型自述补账。

## 13. 发布、资源和回退

提供方 schema、消费者锁、前后端和存储同批切换，不新增旧格式读取或执行分支。切换前盘点运行任务与待批准动作，未使用结构直接替换，有数据一次性迁移并对账；无法转换的动作等待明确处理，不静默重放。历史快照保留为证据，旧语义批准重新申请。冻结仍指精确内容与契约版本，不表示保留旧实现分支。

| 变更 | 发布要求 |
| --- | --- |
| runner/API 代码、MCP 适配与存储逻辑 | 构建同一后端镜像，按相应 Deployment 发布；迁移遵循既有顺序 |
| 审批与连接页面 | 重建对应前端镜像 |
| Skill 准备组件或沙箱启动逻辑 | 重建沙箱镜像；同步内部接口、目录、网络与版本声明 |
| 已支持格式的 Skill 资产新版 | 走方法／资产发布与授权交付，通常不需重建应用镜像；新任务明确选版 |
| 登记绑定或连接配置 | 经管理入口更新修订；是否需重连由适配器决定，不改变旧任务快照 |

发布沿用 Jenkins 与现有声明晋级链。已运行沙箱如何升级和恢复需专项验证，不能用删除 Pod 当作无影响更新。回退先禁止新模式准入，保留记录和包；进行中写操作先查清结果，不能删库或重放来“恢复”。

限制活跃模型线程、MCP 连接、并发调用、包缓存及输出体积；先单用户、单任务、串行验证，再逐项测量资源后扩容。注册中心记录增多不应导致每个用户沙箱加载全部工具或全部技能。

## 15. 2026-11-13 三个入口的首期代码与设计差异

本节记录首期实现边界；不改变第 11.2 节的完整验收目标。详细 API、配置、回滚与测试说明在 [knowbench 受管能力说明](../../../knowbench-app/knowbench-backend/docs/managed-capabilities.md)，代码真源是 knowbench-backend 与 knowbench-web-frontend。首期实现边界如下；后续已通过本地 Jenkins #92 发布，发布依据见[2026-11-13 回执](../../scripts/results/capabilities-release-20261113.json)。首期代码提交：knowbench-backend `58ea7ce`、knowbench-web-frontend `e9a7ab9`；对应验证与未完成范围见两仓 `CHECKPOINT.md`。

已实现「连接与工具」「技能」「本次能力」三个入口，普通聊天／工作接通后端资产、版本选择、runner 准备、受限 MCP 网关和逐次参数审批。连接可多账号保存、验证、启停、更新凭据、刷新工具和本地断开；默认值只在创建新会话时固化。技能首期是版本固定的纯 Markdown 指令，可声明依赖本人的具体连接工具。页面显示后端状态，保存选择不冒充加载成功；范围应用以对应 turn/start 回执确认。

首期远程目录只允许审核的公网 HTTPS Streamable HTTP MCP，无认证或 Bearer。外部凭据由 API 加密保存，runner／沙箱拿到的是本平台限定会话的网关凭证。所有远程动作（包括读取）均先登记内部待批记录，由用户核对账号、工具和完整参数后，API 原子消费批准并派发。它不是以命令前缀批准外发。派发前先提交回执，失联结果记为未知且不自动重发；刷新页面恢复记录，批准不会自动开启另一次收费模型调用。

固定 Codex 0.155.1 的真实隔离探针确认以下事实，因此首期适配与理想接口存在明确差异：

1. `environments=[]` 下，文件写入、技能发现成功不代表原生 Skill 正文进入模型。首期通过显式版本正文输入交付纯指令 Skill，不为了加载 Skill 而开启本地执行。脚本和附件包尚不支持。
2. 新空线程不能直接 unsubscribe/resume；先注入既有模式说明物化历史，再按当前 idle 状态切换。分页线程的 `includeTurns=true` 存在未支持路径，使用 `thread/read(includeTurns=false)` 的实时状态。没有伪造一轮模型调用，也没有为每步创建新线程。
3. “登记待批记录”的网关注解为非只读、非破坏、封闭范围。注解描述的是内部登记行为；真实外部写操作仍须 API 的精确审批。真实探针验证了聊天的 `approvalPolicy=never` 下可到达这个登记工具。
4. 本轮完成后网关拒绝新请求；旧事件按 scope/turn 条件更新，不能覆盖新范围。停用连接可拒绝后续调用，停用技能可阻止之后注入，但不能删除同一线程已看过的文本或撤回已派发动作。

专家页已复用只读面板，展示当前冻结步骤声明的平台工具；聊天选择不会被冒充为专家权限。**冻结方法的新增受管连接／Skill 需求字段、任务绑定和步骤调用尚未实现**，所以不能把这次代码称为第 11.2.7 节“聊天、工作、方法同一连接跨场景执行”全部通过。后续仍按既定方法契约扩展与实施阶段交付，不临时修改已发布财务专家的授权语义。

同样未实现 OAuth、原生 SaaS 连接器目录、任意 stdio 安装、技能脚本包、市场候选与 A2A。页面只提供已有实现；返回设置来源只是受限站内导航，回到会话重新取后端状态，不将跳转成功作为授权。涉及上述能力的完整流程仍以第 11.2 节为完成条件。

发布前补验发现：无预置 MCP 配置时仅设置 `enabled=false` 会被 Codex 0.155.1 拒绝（invalid transport）。#91 因此在部署前中止；#92 已包含完整禁用传输定义的修复。修复探针从空 MCP 配置启动，验证首次建线程、A/B 轮换和再次禁用。线上已核 0040、三张新表的逐项 CRUD 权限、候选镜像与网关拒绝未授权请求；外部目录按所有者要求为空，没有发起真实账号的付费模型验收。


## 16. 技能自动发现与平台资源读取（2026-11-13 后续实现）

所有者修正：普通聊天／工作不应强制逐会话勾选 Skill。安装并启用即进入该账号的可用目录，模型按名称与用途选择，正文与附件按需读取。「本次能力」用于查看、明确指定和限制范围；方法步骤仍以步骤契约为边界。自动发现不授予技能所提及的工具、命令、网络或写操作权限。

本次落地采用平台目录与读取工具：API 持久保存不可变技能包，runner 在每轮冻结版本和范围，仅注入轻量目录，沙箱内 Codex 通过 `skill_read`／`skill_files` 读取。它不是 Codex 原生扫描目录，因此不在每个用户沙箱安装文件，新 Pod 只重建执行绑定。配置所在电脑与生效宿主是不同概念：用户操作网页，配置归 API；远程开发机安装的 Skill 只服务开发助手。

若使用原生目录扫描、或技能依赖本地路径和执行脚本，则确实需要由沙箱准备模块将版本包同步到 Codex 可访问目录（或挂载相应持久卷），新 Pod 重新物化、按摘要复用。此路径仍需补原生加载、隔离和执行授权证据，本次不冒充已完成，也不为了读文档启用聊天命令执行。

完整接口、包限制、账户隔离、读取回执与回滚限制以 [受管能力说明](../../../knowbench-app/knowbench-backend/docs/managed-capabilities.md) 为准。本轮提供 ZIP 导入及 Agently 官方九技能组合包，未作为全平台预装或市场分发；正文按需进入上下文后仍可能留在 thread 历史中。目录本身也占上下文，当前最多 100 个自动候选，尚未实现大型目录搜索。实现完成、发布和真实模型选择效果须分别报告，不能用合成探针证明模型一定选对技能。

## 17. 连接器与安装、MCP、Skill、方法步骤的共同实施

所有者指出连接器没有落实到本轮实现，要求一起设计。本轮统一交付对象应是“安装能力 → 连接账号 → 绑定当前用途与资源 → 执行并取得回执”。第 11.2 节的三个入口继续使用；安装入口贯穿它们，不再分别建立只认识 MCP 地址、只认识 Skill 文件的孤立依赖体系。

### 17.3 后端按依赖改造

1. **先统一提供方契约。** 方法权限在方法层独立声明；方法工具绑定引用要求编号，Skill 安装依赖仍记录技术依赖。用户连接扩充连接器定义与身份；运行绑定承载具体资源及授权。公开清单不保存个人连接 ID。通过既有生成与摘要锁更新 KnowLab、KnowBench 及前端消费者，未知版本拒绝，旧包摘要不变。
2. **再统一注册与安装解析。** API 的安装记录关联不可变资产、服务定义及工具操作映射。MCP `tools/list` 负责发现技术描述，适配器负责业务语义、范围和结果限制。无法强制某项限制的服务不能宣称满足该方法要求；不让模型从工具名猜权限。
3. **接通运行授权和共同执行模块。** 复用当前 selection、method_context、资产修订和 Task/Attempt/Interaction；增加角色到账号、操作与资源的绑定。模型工具调用、runner 确定性调用及脚本请求都进入相同的权限、批准和派发过程。API 持有外部凭据，runner 不把它们交给 Codex。
4. **处理脚本输入与专家编排。** 按 11-14 分类，专家分步调用连接器、脚本和发送工具方法，通过资料／产物绑定交接。脚本工具方法不再调用其它方法，不发方法令牌、不开放网络；公共调用机制处理各步审批、取消、撤权和恢复。
5. **联动三个前端入口和安装流程。** 先提供真实后端状态，再开放相应按钮；OAuth 返回、脚本恢复和方法继续均重新检查当前范围。能力未就绪时给具体缺项，不能靠“已安装”掩盖不可执行。
6. **同一连接器贯穿验收后发布。** 模拟服务验证机制，真实服务验证实际授权与业务效果。验证包含读取、资源拒绝、写入审批、多账号、过期、撤权、脚本子调用、断线与未知结果不重发。首个真实服务仍须落实供应商应用注册；没有外部服务时只发布并标明已经验证的能力，不能宣称完整连接器已可用。

调用存储需先消除当前脚本复用 `connection_id` 存 Skill ID 的歧义：来源资产单独标识，外部操作引用真实连接，脚本子调用关联父调用；不另建任务或费用账。旧记录按已保存的执行种类一次性转换，不根据名称猜测；迁移后删除旧列和双读分支，历史批准及未知结果保留为证据，旧语义批准不可继续执行。

### 17.4 具体流程及恢复边界

以“读取指定文件夹邮件，脚本生成周报，再发给指定收件人”为联调用例：先安装 Skill，选择邮箱账号与文件夹，解析读取／发送依赖；读取结果带来源交给脚本；脚本生成不可变报告；发送卡展示账号、全部收件人与报告版本；批准后只派发这一个发送动作。聊天与方法共用这些组件，方法额外约束允许的步骤与版本。

同一任务内一个脚本又请求读取、又请求发送时，每个外部动作都留有独立回执，关联外层脚本。脚本停止后尚未派发的批准不能继续生效；已发送内容不能因脚本失败而记作未发送。脚本断线不能从头自动重试；平台恢复既有调用结果，确需重新执行时先核已有副作用并取得相应决定。

本节经源码和方案核对形成，属于实施修订。已有无网络脚本、方法绑定及安装测试不能替代连接器权限和真实服务验收；仍需完成接口、运行测试、页面走查与本地 Jenkins 发布。

### 17.5 本轮连接依赖候选的实际范围

已接通的是技术工具依赖：安装声明保存 MCP 服务地址/工具名，界面显示当前账号候选、缺连接或未选用状态；聊天自动目录只给依赖数量，读正文时再给当前已选工具。KnowLab 作者选择 Skill 时一并声明所需工具，并冻结在该步骤范围中；使用者绑定自己的账号，账号撤销后不切换到同服务另一账号。历史精确工具键继续按原绑定处理。

| 撤权与委派限制 | 资源方仅允许特定方法、用途或作者数据使用的依据不得自动下传；父到期、取消、收窄和撤权使后代相应新访问失效；父新增授权不静默扩大已固定子范围 |
| 通用调用记录 | 方法及会话工具请求共用调用身份，派发尝试关联同一记录；按实际对象记录能力资产或 method_ref。Skill 加载记录关联来源与范围；父调用和 session/turn 来自宿主，不为会话请求伪造方法身份 |
| 确认与审批 | 初始计划、数据、账号和预算可同页一次提交，但确认事实分别记录并关联同一批次；展开范围变化需补确认，具体写入/外发继续使用现有 Interaction，不能用计划批准替代动作批准 |

以上并入第 17.6 节第 3、4 项，不另开第二套权限或调用账。登记基础不代表这些能力已实现；方法新契约、递归展开和财务专家首版重建的后续依赖及验收见主稿第 4 节。C2 分类用例须覆盖仅组合工具、同一专家多次/多版本、两种不同专家、嵌套专家团、候选允许范围及分类变化重验；三类共用两条执行路径与同一调用账。授权用例须覆盖父范围内未显式传值的资源可绑定、非委派资源拒绝、父范围失效、恢复重核、伪造父调用引用拒绝，以及聊天调用工具方法无虚构专家父节点。

#### 代码所有权与流向

| 环节 | 唯一负责者 | 输入与输出、不可越过的边界 |
| --- | --- | --- |
| 登记 | KnowBench API 的登记服务 | 保存能力来源版本、会话启用资格，以及可选的孵化方法映射与引用资格；不因会话启用自动补 method_kind。MCP 返回的 annotations 不授予只读身份 |
| 方法需求 | KnowBench 提供运行契约；KnowLab 编辑、校验并冻结 | 方法层独立的 access_requirements、审批规则 → 方法版本；MCP/Skill 实现只引用 requirement_id，不重复保存权限规则 |
| 本次选择 | runner 与现有 session/task/attempt | 方法需求或聊天用途、用户选择、父调用范围 → 当前执行绑定。runner 不持外部凭据，不让模型指定授权事实 |
| 请求核验 | API 共同调用服务 | 登记版本＋本次绑定＋真实宿主调用身份＋规范参数 → 拒绝、待批准或可派发；按业务操作解析资源，不用工具名猜读写 |
| 等待与恢复 | 现有 Ledger/Interaction、runner | 保存精确请求及批准主体；等待不持数据库事务；恢复后重核连接和任务，不能重新发送未知写操作 |
| 执行 | 已有平台、MCP、脚本适配器 | 只接收共同服务核准的调用；原有资源所有者继续复核其责任域，例如 knowbase 数据使用权、link 本地目录 |
| 结果 | API 共同调用记录＋各领域证据 | 一个 call_id 关联状态、批准、输入摘要及输出引用；计算 c<cursor>、读数证据等保持业务含义，关联 call_id，不充当第二份授权事实 |

这里不新增模型请求：解释业务任务和选择允许的能力属于模型；连接归属、资源比较、撤权、审批有效性、参数摘要、状态转换全部由程序判断。工具登记、暴露、授权、实际调用仍是四件不同的事。

#### 契约先定语义，再接字段

方法公共字段真源仍在方法主稿 §1.6，本节不另立一份定义。实际实施须把每个字段连到消费者：

| 契约内容 | 提供与校验 | 必须消费它的地方 |
| --- | --- | --- |
| requirement_id、resource_kind、resource_role | 作者定义，编译器核唯一性及引用完整 | 步骤实现、审批规则、当前账号/资源绑定 |
| capability_ref 与明确版本、operations | 平台核定操作契约；连接器适配映射到具体工具 | 登记匹配、任务预检、每次调用检查；匹配不上不得降级按 URL/工具名放行 |
| resource_constraints | 有类型的精确值、集合或受支持条件；动态值只引用已确认输入或已验收产物 | 绑定时解析、派发前复核、审批卡展示；未实现的条件拒绝，不当空范围 |
| data_transfer | 数据来源、目的资源角色及用途 | 派发和审批摘要；外发目标、附件/内容摘要改变即重新核准 |
| required_when、on_unavailable | 编译器检查可解析分支和必需/可选一致性 | runner 准备与等待；模型不能临时把必需项改成可选 |
| what_requires_approval | 作者可增加必要审批，不能减弱平台底线 | 共同策略服务；写入/外发逐次绑定精确动作，可信只读操作才可复用任务范围批准 |

先实现能够强制执行的范围类型；不接受任意表达式、脚本谓词、模型自报“已批准”或远端自报只读。通用 MCP 缺少业务映射时不能冒充受限邮箱/目录权限。会话能力须完成配置与必要治理检查、能够按已核定操作及精确请求范围强制授权；正式方法还须完成孵化准入。必要检查无法落实则保留安装记录或方法工作稿，不能仅凭用户逐次批准开放。

#### 登记、授权、批准和调用记录的具体收敛

1. 将 `workbench_mcp.py` 内置工具、DataRelay 已锁定的工具定义和受管外部工具统一投影成登记对象：稳定工具 ID、版本/描述摘要、来源、实现引用、输入输出约束、可信操作映射。内置函数与远端 MCP 可保留各自传输入口；用户连接 ID 不作为业务操作的名字。无需为了统一登记把平台静态定义复制成另一份可漂移的数据库主档。
2. `MethodToolGuard` 的真实宿主事件核验与 `Capabilities.runtime` 的令牌/修订核验收敛为同一调用上下文检查。模型请求须关联认证宿主的 session/thread/turn/call；宿主直接执行使用内部身份并核 task/attempt。移除基于“旧固定专家”的免核验分支；旧轮次消息不能靠稳定网关令牌进入新轮次。Skill 读取也经过当前范围检查。
3. 把权限判断和审批主体构造放进共同服务，输入是已解析的连接、操作、资源和数据去向。原 `tool_policy` 的命令前缀规则仅服务命令执行适配，不作为连接器授权依据。业务权限允许请求不代表已经批准写操作；拒绝、资源变更、撤权和超时有明确结果。
4. 演进现有 `workbench_capability_calls` 为通用调用记录，迁移后删除混用含义：`source_asset_id` 标识 Skill/安装资产，`connection_id` 只标真实连接且允许为空；增加登记/上下文/直接父调用引用，覆盖方法、工具和脚本调用；三类方法的计划/验收详情及脚本/外部实现派发引用同一方法调用身份，派发尝试不重复产生方法调用或费用，不另建第三本调用账。调用身份、派发尝试和方法业务验收分开，父引用由受信宿主解析，不接受模型任填。平台读数、计算与外部调用用同一 call_id 和公共执行状态语义，各领域证据通过引用关联。保留 Interaction 作为批准真源，不新建平行审批表或 Task 状态机。
5. 不再以“参数一样”推导“同一次调用”：采用受信宿主调用身份或宿主派发键作为幂等标识；参数、版本和范围摘要用于核验该标识未被改写。同一次重试返回既有记录；另一次合法调用可以参数相同，不能误合并。写操作先提交派发记录，再对外发请求；崩溃或失去回包记 unknown，不自动重发。
6. 稳定 MCP 配置只承载连接身份与可发现集合，当前轮次授权独立保存。先证明所有执行路径能核真实 turn/call，再减少线程重载；不能把短期 token 改长就算完成。正常轮次结束后已经提交的精确审批可以在原时限内等待用户；重连、接管、取消、换账号或范围变化使其不可执行，不把“轮次已结束”误判为可以开启新调用。

#### 来源、许可与公开资格的实施闸

此规则已经所有者确认，不是待决定项。第 3 项登记保存可追溯来源、版本和内容摘要；第 7 项冻结与交付分别核验安装、执行及再分发/随包交付许可，安装成功不能替代交付授权。缺来源或缺交付权时，拒绝把 Skill 随方法版本交给其他使用者；不把作者本人的账号、凭据或数据塞进包里。公开上架和使用资格仍按 C-L4 由发布/消费后端强制，界面隐藏不是授权检查。该规则写入本批公共机制设计，完整依赖交付实现在第 7 项，不提前声称已经落地。

#### 数据切换、验证和恢复

归属：登记、用户连接、授权与调用属于 KnowBench，方法定义属于 KnowLab，发布版本仍由 KnowMart 管。登记/方法是版本主档，连接是用户主档，授权/调用是运行记录，计算结果和读数回执是证据；跨 App 只用契约与引用。Skill 包存储迁移与账号生命周期在后续批次处理，不借本批改动建立第二套资产主档。

切换前重新审计新资产和方法字段；上次的空表统计只证明当时为空。未使用字段直接替换；已经存在的连接、批准和调用一次性迁移、计数/摘要对账，待批准的旧语义动作失效并提示重新申请。54 个 expert 会话不得直接删除；更改会话分类时保留会话/任务标识并一次性转换，历史快照只作证据，不保留旧格式执行入口。不同父仓的提供方、消费者、生成模型、摘要锁和前端同批更新。无新增双读双写路径。

共同机制的验收必须从两个现有 MCP 入口分别进入，而非只测新纯函数：相同操作得到相同审批决定和调用状态；未知性质不能当只读；父范围收窄；跨用户/跨轮次拒绝；刷新/撤权竞争；批准后参数或附件改变；进程重启后不重复外发；计算/读数证据仍能被现有验收读取。首批用无外部账号的模拟连接器与真实 HTTP 适配器验证公共机制，实际供应商/OAuth 验收另属于 C3–C6。

作者入口只在上述权限字段贯穿登记、冻结、绑定、核权和审批，并有跨场景验收证据后重新开放。源码完成、部署生效、真实账号验收分别记录。
