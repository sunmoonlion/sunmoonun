# Opus 评审回执：第三轮（数据拓扑定稿、0043–0045、knowmart 小店）

> 2026-10-26。收到 [Fable](fable.md)、[Kimi](kimi.md)、[Luna](luna.md)、[Qwen](qwen.md) 四份（下文记 F、K、L、Q 后跟节号）。
> 四家都认为需求、供给、切合三分与小店方向成立；意见集中在新能力之间没接上的缝：RAGFlow 归谁碰、knowfeed 开始读用户数据、订阅的长期依据、任意网址带来的安全面、发版顺序、knowfeed 自己那套旧文档模型。
> 处置分三类：**采纳**（所有者定完第二节后一次改进数据拓扑、0043、0044、0045、0018、C-L2）、**要所有者定**、**不采纳与说明**。

## 一、采纳

### 1. RAGFlow 只由 knowbase 碰（F 2.1、2.2、3.5、3.6，K 4，Q 2.3、一，L3-07、3-08）

- **规矩 2 不开例外**：删掉「knowfeed 的 RAGFlow 文档解析加工器」。扫描版、复杂版面的解析由 knowbase 在建检索索引时做：knowbase 把原件交 RAGFlow 解析，**取回完整的解析结果**（逐页文字、表格与坐标），存成一个派生读法版本（标 RAGFlow 解析器版本），扫描版的「按页文字」就来自这里。knowfeed 不碰 RAGFlow。
- **索引从已固定的派生内容重建**，不是重新解析原件；要重抽就是新的读法版本（L3-08）。
- **数据集按「内容类型 × 解析配置」分，绝不按用户分**，由运维预建（现在数据面禁止程序建数据集）；隔离只靠文档编号限定；**文档编号集合为空时不调 RAGFlow、直接回空**（F 3.6，空列表可能被当成不限定）。现在的「数据集白名单 + 单租户」校验按新划法改。
- **检索限定已是现状**（Q 一）：knowbase 现在就按 `dataset_ids + document_ids` 检索；0043 块 9 收窄为「一版本一文档的映射、删除同步、取回完整解析结果」。
- **删除分清对象**（L3-07）：取消展示、删个人引用只改这个人的依据，不删共享索引；禁用由 knowbase 先拒读；只有真正清除内容才删 RAGFlow 文档。现有客户端没有删的方法，要补；真删在块 9 之前只标「处理中」（F 2.2）。
- **建索引是异步作业**，按回执就绪，不在入库事务里等（现有超时 300 秒，CPU 模式下年报级 PDF 跑不完）；「检索索引就绪」是单独一种读法状态；恢复演练量一次「从派生内容重建全部索引要多久」，几天量级就把 Infinity 的卷一起备份（F 3.5）。

### 2. knowfeed 读用户数据：限定作业的「加工」授权（F 2.3、L3-01、Q 2.2、q4）

- **上传的加工（推）**：用户上传时按页面说明采用加工，knowbase 记依据，向 knowfeed 提交一个只指向这份原件版本的加工作业，把内容推过去；knowfeed 不留存，作业完成即删（30 天留存只对采来的原件）；派生结果只能挂回这份原件，不改所有者、许可、区；许可「只许本人用」的加工结果同样只许本人用。
- **重新加工（拉）**：knowfeed 经 knowbase 接口取原件（不碰对象存储的桶），凭限定作业、目的、版本、时限的授权。
- 运行授权加一种**「加工」**；守则 3 加 knowfeed 一行（只能凭加工授权读指定版本、只能写回派生读法、只能交需求与回执）；knowbase 按「系统加工」留痕，用户在「谁读过」里看得到；服务关系表补 knowbase → knowfeed（提交加工）、knowfeed → knowbase（受限读、写派生）。
- 反例：加工甲一份文件的授权不能换成甲的另一份、不能读乙的；加工中撤销或清除，晚到的结果不能重建可读版本。

### 3. 删掉 `app:knowfeed`（F 2.5、2.8、2.9，Q 2.1）

- 东方财富 F10 已定为一个渠道实例（E1），质检只靠勾稽与两种读法互核，不再拿第三方数据当「对」的标准；0043 第 2.3 节的 `app:knowfeed` 删掉。
- 现状更正：F10 数据集不是「SQLite 库」，而是每个证券一个 SQLite **文件**放对象存储，knowfeed `security_dataset` 与 knowbase `knowledge_dataset` 各登记一行；没有「F10 进用户的数据」这条写入口，待关清单按现状改（Q 2.1）。
- 第 1 版「财务分析与预测」读的是 knowbase 数据集接口：兼容窗口内 `knowledge_dataset` 与数据集接口保留；F10 数据集进平台账号第一区、只许本人用以后，第 1 版在窗口内只能由 sig-am 自用（F 2.8）。

### 4. 统一入口分支、预切合、命中（F 2.6，L3-03、3-04，Q 2.4 一半）

- **三种入口分支**（L3-03）：① 本人已有合法依据、版本与读法齐 → 直接用；② 本人还没取得、但内容与读法都齐 → 按确认结果建第一区关系或第二区引用，立即完成，不等不存在的作业；③ 缺原件、缺读法、要刷新来源版本 → 都进 knowfeed，以回执为准。0043 第 3.3 节「已有原件立即记引用」按此改；「已有」必须满足本次的版本与时间条件，缓存新鲜度证明不了就核源站；通用网页按网址去重只限同一次或明确的新鲜度窗口，网址是身份不是版本，重取后按内容摘要决定是否新版本。
- **预切合只查来源目录**（F 2.6）：回「这类能取 / 取不到 / 网站待审」、候选渠道的许可档，毫秒级；「渠道里有没有这一份」放到受理后，没有就转「无法满足」通知。预计时间按队列估。（这改掉第二轮采纳的「确认前对渠道列」，那会在确认前替用户查渠道、确认页也等不起。）
- **确认记供给条件快照**（L3-04）：确认关联预切合结果与可接受的来源限制、用途条件；正式切合换渠道只在满足快照的渠道之间换；不满足就回「当前供给条件不满足」让用户调整，不把更窄的许可静默当成已满足。网站审过不等于页面是法定披露，数据区与许可按实际来源与审核规则定。

### 5. 任意网址与无头浏览器的安全边界（F 3.1、K 1、L3-05、Q 一）

- 这是执行层的工程边界，不是合规审批，不和「采集本身不用管合规」冲突。硬规矩：只许 http、https；取之前解析域名，拒私网、环回、链路本地、云元数据与保留地址；每次重定向重核；浏览器的子资源与后台请求都经受控出口、同样拒内部地址；不带任何凭据；页面、附件总量、时间、内存设上限；插件不得自带网络客户端绕过框架。现有 `crawl_http.py` 的协议、端口、公网地址、重定向、体积时间限制照用。
- **无头浏览器放单独的工作负载**（F 3.1）：仍是 knowfeed 自己的，不是外部爬虫；不挂密钥，只许出公网，系统调用收紧。改掉 0045「在 knowfeed 自己的工作进程里跑」的说法（所有者认可的是「不用外部爬虫」，这一点不变）。
- knowfeed 的「休眠能力」测试里「内置爬虫引擎」「多下游分发只投 knowbase」两条，0045 做完时必须不再成立，列为块 3、块 4 的验收（Q 一、q6）。

### 6. 订阅（L3-02、3-06，F 2.4、3.11，K 四，Q q1）

- **订阅的长期依据存 knowbase**：建订阅时由本人留下一条长期、可撤、带修订的范围同意（用户、订阅编号与修订、描述或网址范围、起止、用途、自动取得方式）；每轮交付时 knowbase 核依据仍有效、没超范围；续订是新修订；暂停、取消、停用同步。逐项确认（7 天）和订阅范围确认是两种依据，0043「确认不能跳过」写明两种。数据拓扑第十八节「用户指定」加第四处：建订阅时确认的范围。
- **两种执行计划**：目录、RSS 类走「看新的」；按主题订阅走定时「搜 → 本轮候选 → 用户勾 → 确认」，不要求搜索渠道有游标。
- **共享查看两层进度**：渠道的发现游标，加每条订阅自己的消费与选取记录；新加入的订阅只收起始日之后的；某人当月超额的条目记「本月超额未取」，下月初在下月配额里优先补取，用户可以选跳过；暂停后从自己的记录处恢复。
- 第二区引用只记**需求依据编号**（需求依据自己知道来自任务、订阅还是本人）。订阅到期不续，它生成的在途需求项标「已取消（订阅到期）」。「看新的」的输出带版本线索，更正公告作为已有原件的新版本并提醒引用者。

### 7. 运行中追加需求（Q 四）

允许，落法写死：任务在步骤边界停在「等数据」→ 用户确认 → **新签一条独立授权**覆盖新的几项（不扩大已签的那条，守则 2 不破）→ 清单出新修订、冻结部分不动 → 已读的不重读 → 继续。在用户 link 上跑的，表现为工具调用返回「等数据」、专家等结果后再继续。knowlab 的固定测试集不在运行中追加。

### 8. 版本与读法两个词（Q 六）

- **版本**只指内容的替换（更正版、用户重传的修订）；**读法**指同一版本的不同派生形态（正文、按页文字、表格、检索索引），读法自己也有版本（加工器升级、质检标记改变都产生新的读法版本，钉住的要可复现）。
- 「买家拿交易那一版」指内容版本，含这一版今后的读法；运行钉的是「内容版本 + 读法版本」组合（0043 第 2.9 节）。
- 0044 的版本列表分两层：内容版本一层，展开显示每版的读法齐不齐。数据拓扑第 5.4、16.2 节，0045 第 3.4 节，回执字段跟着换称呼。

### 9. 许可改低与小店处置不殃及已有权益（L3-11、3-10，F 四，Q 3）

- **拆开**：卖家主动改低、关店，只影响新的销售与公开用途；已成交的使用权按交易时的依据继续判断。真正的内容禁用、违规处置，按规则收回受影响的权益、停止读取。授权检查按本次使用的依据判断，不只看资料当前的许可档。
- **小店有持久的处置状态**：公开列表、条目发布、审核转公开、下单、请专家都核店铺当前状态；恢复店铺不自动恢复被单独下架的条目；停店不撤销历史订单的合法权益。公开小店页和「我的小店」是两种后端投影，不把整个「我的小店」返回给前端去藏。
- 店名默认取昵称，可改、留痕，受驻场规则禁止词约束；平台账号的店标「平台账号」；一店一主体，主体可改要重审、留变更历史，条目标当时卖的主体（Q 3.2）；企业多账号先接受多家店，做租户时再并。
- 小店与条目只按时间、类目、店名排，**不做推荐、榜单、销量排序**（写进 0043「不做」）。
- 交易记录每行带直达链接到那份资料或那位专家；knowbench 专家栏对已下架的标「不可请」，小店交易记录标条目状态（Q q8）。

### 10. knowfeed 自己那套旧文档模型要退（Q 2.1）

knowfeed 现在有完整的通用采集文档模型（信息源、采集器、采集作业、原文、文档、文档版本、抽取内容、分发记录），同一条内容同时在 knowfeed 文档版本和 knowbase 知识文档版本里。0045 第六节拆旧线、0043 第六节迁移补上这一套：两边版本号语义不同（knowfeed 是网页变化产生新版本，knowbase 是内容只增不改），迁移时以 knowbase 为准、按内容摘要对齐。规模见第二节 G5。

### 11. 发版顺序与依赖（F 2.7、五，K 2，Q 五、q7，L）

- **第 0 步**：knowfeed 关旧写入口，一次独立的提前发布（只加 fail-closed 拒绝），在 `kind-flux-final` 之后、0043 块 1 之前。
- **knowbase web端和 knowbase 新模型一起发**，排在 knowfeed、knowmart、knowbench 之前（knowmart 上架、knowbench「去放开」、直达上传都靠它）。写成可执行的两阶段：先部署兼容接口与新入口，再开新路径、关旧入口。
- **knowbench 分两小步**：先接解析（「待确认」在 knowfeed 切合上线前一律回「暂不能补采」，用开关控制，fail-closed），删上传入口留到 knowbase web端上线之后。
- 0045 块 1 到块 8 之间采集停摆；0043 块 11（第 2 版）加依赖 0045 块 8；0043 块 6 加依赖 1c；0044 块 5 依赖 1c 和 0043 块 7；0044 块 1 与 0043 块 1a、1b 并行。
- **0045 先切一条竖线**：精确描述 × 目录型 × 下载 + 按页文字 × 交付回执，端到端跑通再横向补给网址、订阅、按主题找（F 五）。
- 块 6 之前实测一次用户 link 按需读云端的公网时延（Q q9）。

### 12. 其余

- **表格单元的通用地址**（L3-09）：基础地址是版本、表或工作表、物理行列；存原始值、值类型、解析值、来源位置；科目标准名、报告期间、单位、口径是领域插件给的语义标注，不是所有表都有的主键。
- **词表第一版**（F 3.9）：0043 第 2.5 节列出类型的第一批值（年报、半年报、一季报、三季报、临时公告、招股书、政策文件、统计数据、网页、其他表格、其他文本）与非上市主体的编号规则。
- **限速按出站地址全局算**，渠道登记要有总的每日上限（生产出站是家庭宽带，F 3.10）。
- **渠道试采**：白名单之前对样例描述跑一次「列」和「取」；连续失败 N 次自动暂停、告警（F 3.7）。
- **给应用用的公开索引查询**：只按一个主体查、回条目不回内容、按用户限流、记谁为哪个草稿查的（F 3.8）。
- **待审网站**有时限（N 天没人审自动转「无法满足」并通知）和数量、等待时长告警；robots 作为通用网页型适配器的默认配置、审核可逐渠道改（F 3.3、K 10）。
- **真删清单加 knowfeed 一侧**：30 天原件、作业与尝试里的内容片段、搜索与列的缓存、需求单里的说明与网址（F 3.4）。
- **配额**加每人每月新取份数（K 5）；受理时按预估大小核一次用户空间（Q q3）；「往下一层」最多 20 份，超出的列给用户看（K 6）。
- 会话小授权可以一次签多条（每条仍一份一条，K 8）；「最晚什么时候要」的默认值：亲手提的必填，应用代提的按任务时限，都没给按保守预计加系数（K 9）。
- **幂等的顺序**（L）：先认证归属、核同一请求摘要，已受理的回原结果；只有新受理才扣配额、核确认时效；同一钥匙不同内容拒绝；「再试一次」用新钥匙（K 四）。已受理的作业不因确认过期受影响（Q q2）。
- **部分就绪**的收尾写清：哪些还在加工、哪些终止可补加工；只要原文的需求不因表格加工失败而降成部分就绪（L）。
- **确认接口覆盖四种需求**，不要求每张需求单先有专家和声明（L）。
- 按主题找的候选**不重排、不评级、不截断**，顺序就是搜索给的顺序，标注只陈述渠道事实（Q q5）。
- C-L2 措辞：「白名单」是审核过的渠道与网站，不是固定站点清单（Q q10）；0018 第八节「knowmart 分区」改成「经 `market` 展示交给 knowmart」（F 2.9、K 3）。
- 迁移来的未确认描述首次进入时引导确认；向量模型比较时把「按钉住版本限定」列入验收（K 四）。
- **怎么验**加：空文档编号集合检索回空；任意网址取不到私网地址、浏览器子请求打不到内部服务；上传的资料加工完 knowfeed 不留副本；同址内容更新生成新版本、旧绑定不变；订阅跑过七天不要求逐份确认也不绕过范围依据；主题订阅未勾的不取；两个订阅共享来源、配额不同互不丢记录；已有 PDF 缺表能补加工、不重复下载；渠道回退不静默越过确认的用途条件；共享版本删个人引用不影响别人检索；店铺停用挡住新交易、保留已有权益；卖家改低许可买家照读、违规禁用后才不能读（F 五、L 末节）。
