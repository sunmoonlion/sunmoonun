## 一、做法

- 数据库只扩不缩：旧表、旧栏都留着，v1 照常写；新栏可空，新表另建。
- 旧接口 `/internal/v1/user-data` 行为不变；新开 `/internal/v2/user-data`，契约 `knowbase-app/contracts/user-data/v2/`（由 pydantic 模型生成，逐字比对）。
- 兼容期里 v1 每写一份资料，同时写第四版的第 1 版、所有者使用权与「展示给原来那个应用」，切过来的时候不用再搬。
- 测试用临时库：本地 docker 容器 `qwen-test-pg`（postgres:16，只绑 `127.0.0.1:55432`），跑完会删。

### 块 1b：同意依据（展示）、账号默认展示、名下专家、成交加使用权

knowbase-backend `d06f08c`，knowbase-app `1285d98`。

### 块 1b 余下：平台过程、订阅、加工三种同意依据

knowbase-backend `55c65e2`，knowbase-app `35594c0`。

- `platform:<应用>:<过程>:<过程编号>`：本人在 knowlab 选平台、交审、提交交付时确认这次过程能看哪几份，每份一行、钉住版本（买来的只到成交那一版）；按过程整个撤。
- `subscription:<订阅>@<修订>`：建订阅时的长期范围同意（按描述、网址、主题），必须有截止日、最长一年；一个修订定了不改，改范围出新修订；只经 knowfeed 转交。
- `processing:<内容版本>`：上传、传新版时采用加工，或事后对某一版补采用；只限上传的。

### 块 1c：运行授权、凭授权读、加工、产出区、删除

knowbase-backend `afe4d21`，knowbase-app `7aff52a`。新迁移 0011，接口在 `user_run_routes.py`。

- **输入组合**：内容版本、读法版本、各自摘要；组合编号就是它的摘要，钉住了就改不了。
- **运行授权（第四版）**：外层记过程、执行的应用、受益人；逐项记钉住的版本、权利依据（展示 / 冻结的专家绑定 / 平台过程 / 加工）、内容所有者，签发时逐项核。不碰 v1 授权。
  - 委托、会话、孵化由本人签；测试、平台过程由 knowlab 签；加工由 knowbase 签给 knowfeed。
  - 运行中追加：同一件事新签一条，修订号往上加，已签的不扩大；knowlab 测试集不许追加；别人的同名事拒。
  - 会话：每首读一份签一条小授权，累计刚过 50 份提示一次；会话结束一并交还。
  - 平台过程：运营、机器分开签，上限孵化 7、测试 14、审核 30 天；本人撤回或 knowlab 报结束，依据与授权立即撤。
  - 专家绑定：交付时冻结成 `expert:<专家>@<版本>`、每份钉在当时那一版并记下当时的许可；只许本人用的只服务作者。
- **读**：执行的应用凭授权读钉住的原件、格式或读法；所有者删了买家照旧能读，禁用、清除后谁都读不了；留痕记内容所有者、受益人、读的一方（应用、运营、机器、系统加工）。
- **加工**：knowfeed 领待加工的、凭本人的加工依据领 3 天授权、读那一版、写回正文 / 按页文字 / 表格（没成的写原因）；web端能看一版的读法齐不齐。
- **产出区**：knowbench、knowlab 替用户写，按（应用，任务，运行，文件名）幂等、只增不改、算用户空间、不能当输入；本人「转为数据」新建一份，带出处，许可不高于上游。
- **删除**：所有者删记删除事件（撤关系，内容不删）；禁用撤在跑的授权；清除删全部版本与读法的对象、清描述，别人合法用着的不删内容（依法必须删的个人信息除外），等 RAGFlow、knowfeed 的回执之前事件是「处理中」。
- 自查改过一处：专家绑定起初没核许可，任何人都能凭冻结绑定读到只许本人用的数据；已改成核冻结时的许可，补了测试。

### 块 2：按描述查、解析、确认、偏好

knowbase-backend `35619ff`，knowbase-app `9702b58`。新迁移 0012，接口在 `user_resolution_routes.py`。

- **声明**：`knowbot-manifest/v2` 的数据需求只定义在 knowbase（类型、期间规则、格式、份数、必填、要的读法、来源限制、优先策略；口径只展示）。三个应用现在各有一份的 `DataNeed` 以后收成这一份（块 4）。
- **词表**：加定期报告的报告期（一律年初起算，三季报按「年初至报告期末」）与法定披露截止（年报次年 4-30，半年报 8-31，一季报 4-30，三季报 10-31）；能不能按描述去采。
- **解析**：声明 × 任务参数展开成一条条「主体 × 类型 × 报告期」，逐条在请的人名下找，给七种结果之一；偏好先于优先策略，没写策略又有几份就是「有歧义」；要正文、表格的读法没齐算待确认；「截至任务日期已披露」时，没到截止的最新一期拿到了、且在任务日期前披露才用，用了就去掉最老的一期。运行中新需求出清单新修订，已有条目不动。
- **确认**：有清单的只认那张修订里待确认的条目（少确认几条即取消）；也收给网址、按主题勾的候选、直接按描述要；记声明与供给条件快照，7 天有效；回每条的入口分支（已经齐了 / 交 knowfeed）。knowfeed 受理前凭确认编号来核。确认过的条目再解析是「等数据」。
- **按描述查**：只认精确的键，只答「放开了 / 在但没放开 / 在但不能用 / 没有」与范围；同一用户每分钟 60 次。
- **偏好**：只读接口；记偏好的方法留给 knowbench 块 6 开跑前换数据时用。
- knowfeed 用的两种关系合成一个 `user-data-supply`（加工与核确认）。
