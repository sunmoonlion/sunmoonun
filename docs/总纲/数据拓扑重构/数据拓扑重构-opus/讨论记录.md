# 数据拓扑重构讨论记录

> 所有者把思路写在同目录上一级的 `数据拓扑重构准备`，逐条和 Opus 讨论；这里记每条的结论（所有者原话、谁做什么）和还没说到的。全部讨论完，再按这里重构 [数据拓扑](../../数据拓扑.md)。

## 1. knowbench 本地知识库：删（2026-10-26 定）

**所有者问**：「现在的knowbench的本地知识库好像没有啥用，可以删掉吗」

**Opus 意见**：同意删。
- 和项目目录重复：专家本来就在用户电脑的项目目录里读写，想让专家看的本机文件放进项目目录就行。
- 「原文件不进云端」分量轻：大脑在云端，选中的本地文件每次读都整份经会合点传到 knowbench 后端再给模型，只是不存进对象存储。
- 它是唯一不在 knowbase 的知识库，为它多一整套：钉住、核摘要、分块回读、兼容老 link、link 的目录设置与 Windows 权限、网页一页、选数据分两个来源。
- 委托跑多久，用户电脑上的 link 就得连多久。

**所有者定**：「对，如果远端要用数据，就上传进knowfeed，如果本地用，直接放进项目目录。」
- 云端要用的数据：用户上传进 knowfeed。
- 本地要用的数据：用户直接放进项目目录。

**还没说到、待后面定**：
- 上传进 knowfeed 以后落在哪、谁能用（knowbase 里这个用户的哪一部分），和 `数据拓扑重构准备` 第二段「数据的供给和需求」一起谈。
- 现在 knowbench、knowlab、knowmart 网页上各自的「上传」入口，是不是都改成经 knowfeed。
- 项目目录里的文件不算钉住的数据，不参与专家数据要求的核对：专家写了数据要求时，只能从云端选。
- 已上线的本地数据委托记录（knowbench 委托表允许 `source='local'`，随 #28、#29 与 link 0.5.3 发出）：Opus 建议新委托不再接受本地来源，老记录只读留着，不迁移、不删。生产库里有没有这种记录还没查，查要所有者授权。

**要改的**（不插进现在这批发版，随 knowfeed 那一轮）：
- knowbench 后端：选数据、钉住、回读里的本地来源；网页端：本地知识库页、选数据对话框的本地来源、设置里的目录一项。
- link 出 0.5.4：删本地知识库目录设置与服务流对它的只读范围、Windows 桌面界面那一栏；老配置里还有这一项时读了忽略，不报错。
- 文档：`数据拓扑.md` 第八节、第十六节第 2 条、第十七节「按用途分」、承诺清单第 10 条；SDD 0042 的 A 类。
