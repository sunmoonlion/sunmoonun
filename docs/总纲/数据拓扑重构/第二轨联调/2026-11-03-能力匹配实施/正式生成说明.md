# 已接受装配的正式生成

所有者已接受 `作者核对.md` 和对应工作稿正文，摘要与对话答复在
`author-acceptance.json`。该文件是作者决定记录，不是线上创建成功回执。

`create_accepted_financial_draft.py` 默认只做离线校验：核作者接受摘要、发布版编译器
输出与预览一致、八个方法可冻结成独立定义。加 `--apply` 才会调用 knowlab 既有
申请、工作稿、方法冻结、绑定及出准专家应用服务；不直接写 SQL、不启动模型、
不发起测试或交付上架。必须在本批新 knowlab 后端发布后运行，不能将本地源码挂入
旧生产 Pod 绕过发布。操作身份固定为原作者 zymun 的 subject，原准专家固定为2.8。

正式执行流程：

1. 核原作者、原准专家 manifest 摘要及测试数据同意版本；任何不一致停止。
2. 在原申请锁下按已接受正文摘要查唯一操作记录，避免并发或丢响应重复创建。
3. 新建独立动态申请，创意记录作者接受及代录依据，保留原申请全部验收题。
4. 将接受正文按正式工作稿保存，先从同一修订冻结八个独立方法，再逐个绑定确切
   ID/版本/digest。中立输入槽映射回专家别名后，逐字核执行合同、规划与公开能力不变。
5. 通过正式编译/作者来源检查后生成新准专家，返回真实 request/draft/method IDs。
   整个操作同一事务；中途失败整笔回滚。重放检查既有冻结定义和装配后返回原结果。
6. 将成功输出另存 `formal-creation-receipt.json` 并入库，才将状态更新为已创建。
   不改写接受记录或旧2.8。新增测试预算另行批准，不能沿用测试11的180元授权。

隔离 PostgreSQL 已验证：正式冻结/绑定/建稿与丢响应重放、第四次绑定失败整笔回滚、
错误作者/原稿摘要阻断，共3项通过。测试使用真实服务/迁移/仓储及隔离schema，运行方
为 FakeRuntime，没有线上写入或付费模型。运行测试需设置一次性 `*_tests` 数据库的
`DELIVERY_TEST_DATABASE_URL`，以 knowlab-backend/app 的环境和 PYTHONPATH 执行本目录
`test_create_accepted_financial_draft.py`。凭据不写入本文件或测试产物。

原c1的指标与预测断言不会删除。本批测试请求v2可核唯一方法的当前已验成果，仍须
先完成双方发布与真实测试授权；生成准专家不代表财务语义验收通过。
