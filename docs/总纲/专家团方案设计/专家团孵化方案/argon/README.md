# argon 的专家团孵化方案（knowlab）

> 当前分类以[方法主稿](../../../专家方案设计/专家孵化方案/luna/方法、步骤、组合与模板.md)为准（2026-11-14）：工具方法不调用其它方法；专家方法组合工具及零种或一种专家、不含专家团；专家团方法调用两种或以上专家，或已有专家团。按方法身份及冻结允许依赖分类，三类共用契约和调用治理；专家与专家团共用编排。以下历史正文、旧协议或评审结论保留原时点含义，“两类”“不设专家团类型”及独立团队引擎等旧表述不作为当前目标。


本目录存放 `argon` 独立编写的 `knowlab` 专家团孵化方案设计稿（基于仓库一手契约、所有者决定与一手竞品调研独立完成，定稿前不动代码）。

## 文档导航

- **[专家团孵化方案：团长委派架构、成员槽位契约与跨作者组装测试](专家团孵化方案.md)**
  - **一、核心定位**：划清「单个动态专家（`knowbot-manifest/v3`）」与「专家团（`knowbot-team-manifest/v1`）」的适用边界。
  - **二、专家团的架构模型**：团长（`TeamLeadSpec` 严格委派与统稿模式）+ 成员槽位（`MemberSlotSpec` 版本钉死与条件激活）+ 四种标准协作拓扑（多维并行深潜、工序接力流水线、红蓝交叉质询、多标的同专家横比）。
  - **三、作者身份、跨作者组装权利与逐格出处门禁（`C-L1`）**：界定团作者与成员原作者的双层责任切分、私有方法防扒取隔离及三种成团孵化入口。
  - **四、专家团测试方案**：调试期「成员固定桩回放（Member-Stub Replay）」与交付前「全团真实端到端联调（Full E2E Run）」及四道确定性验收门。
  - **五、待所有者拍板确认的事项**。
