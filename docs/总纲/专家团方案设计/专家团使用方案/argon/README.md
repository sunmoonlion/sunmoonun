# argon 的专家团使用方案（knowbench）

> 当前分类以[方法主稿](../../../专家方案设计/专家孵化方案/luna/方法、步骤、组合与模板.md)为准（2026-11-14）：工具方法不调用其它方法；专家方法组合工具及零种或一种专家、不含专家团；专家团方法调用两种或以上专家，或已有专家团。按方法身份及冻结允许依赖分类，三类共用契约和调用治理；专家与专家团共用编排。以下历史正文、旧协议或评审结论保留原时点含义，“两类”“不设专家团类型”及独立团队引擎等旧表述不作为当前目标。


本目录存放 `argon` 独立编写的 `knowbench` 专家团使用与运行方案设计稿（基于仓库一手契约、所有者决定与一手竞品调研独立完成，定稿前不动代码）。

## 文档导航

- **[专家团使用方案：确定性任务看板、四方统一交互与受控并行执行](专家团使用方案.md)**
  - **一、核心设计目标与对七大关键问题的正面回答**：逐条回答所有者提出的七个核心问题（谁拆解谁挑专家、作者选数视野、作者离线处理、预设规则代挑、项目并发锁改造、成员间产出定位、费用机制）。
  - **二、确定性任务看板（Task Kanban Board）架构设计**：用后端引擎确定性状态机驱动看板卡片流转，根治 WorkBuddy 依赖模型调工具导致状态滞后的缺陷；卡片实时高亮「谁在做」「等谁、等什么」。
  - **三、统一交互机制（Unified Interaction Protocol）**：通过 `InteractionRouter` 收束用户、团长、成员专家与成员作者的四方交互，实现全团前置数据需求去重合流一次确认。
  - **四、「作者按题选数据」完整机制**：《脱敏选数工单》隐私保护视野、预设选数规则毫秒级代挑主路径、以及作者离线超时 SLA 三级优雅兜底。
  - **五、成员间成果交接（`MemberArtifactRef`）、并发文件隔离与统一预算治理**：上下文隔离与证据链穿透核验、父委托租约下成员分目录写隔离（仅团长统稿写正式报告）、以及保底预留统稿预算池。
  - **六、待所有者拍板确认的事项**。
