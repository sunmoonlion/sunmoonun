## 一、核心定位与四大市场设计原则

当「专家团（Expert Team）」作为一种可交易、可请入的供给商品进入 `knowmart`（每个用户的个人小店与公开目录）时，它既要沿用单个专家的能力声明、资质审核与数据许可红线，又必须解决**「多专家组合带来的版本依赖、跨作者授权、合并计费与下架连带影响」**四个新问题。

本方案确立 `knowmart` 专家团市场的四大核心原则：

1. **「团能力卡 + 透明成员阵容表」双公开，团长调度与成员内部逻辑双私有**：
   - 用户和 `knowbench` 匹配器在市场上看到的专家团，不仅有统一格式的 **8 栏团级能力声明卡（`PublicTeamCapability`）**，还必须公开**成员专家阵容表（`PublicMemberRoster`：包含哪些成员专家、确切版本、所属作者小店、各自承担的子能力）**，做到「请团明明白白」。
   - 同时，团长的私有拆解/统稿提示词以及各成员专家内部的私有方法正文（`procedure`）与绑定数据仍然严格保密，不因成团而向公众或团作者泄露。
2. **成员版本编译期强钉死（Immutable Member Pinning），绝不后台静默升版**：
   - 每一版专家团清单（`knowbot-team-manifest/v1`）对每个成员槽位都通过 `(knowbot_id, version, sha256_digest)` 三元组强钉死。成员专家作者日后发布新版（如从 `v2` 升到 `v3`），**已上架的专家团版本绝不自动偷换成 `v3`**；只有经团作者在 `knowlab` 重新联调测试并交付专家团新版本后才切换。
3. **跨作者「显式入团授权（Composite License）」与透明分项计费（去重抵扣）**：
   - 单个专家的作者可在小店中自主决定是否勾选**「允许其他作者将本专家编入公开专家团（`allow_team_composition`）」**并设定入团分成价。
   - 用户请入专家团时，价格按**「团长编排费 + 成员专家费汇总」**透明列示；若用户本人就是某成员专家的作者、或此前已请过该成员专家的这一版本，系统**自动免除该成员份额的重复收费**（守 `decisions.md` 134「同一用户同一版只记一次成交」）。
4. **资质取并集、数据许可穿透硬查、成员异常连带熔断**：
   - 公开上架的专家团，其团作者与所有成员专家必须满足对应服务类目的资质要求；任一必选成员发生绑定数据许可失效（`HOLD_REASONS`）或违规下架（`taken_down`）时，专家团立即触发连带待处理或熔断下架。

## 二、专家团清单与市场公开目录契约（`knowbot-team-manifest/v1`）

### 2.1 外层信封与成员版本强钉死结构

`knowlab` 测试通过并经两道门交付给 `knowmart` 的专家团，采用与 `KnowbotManifestV3` 同构演进的不可变外层信封 `KnowbotTeamManifestV1`（契约标识 `knowmart/knowbot-team/v1`）：

```mermaid
flowchart TB
  subgraph TEAM_MAN[专家团交付清单 KnowbotTeamManifestV1]
    HEAD[外层元数据<br/>schema: knowbot-team-manifest/v1<br/>team_id / name / tagline / version / runtime / digest]
    PINS[成员版本钉死表 member_pins: PinnedMemberSlot[]<br/>- slot_id / role_title / required<br/>- knowbot_id / version / manifest_digest<br/>- invoked_capabilities: PublicCapability.id[]<br/>- data_policy: user_auto | author_curated]
    LEAD_PACK[团长内层执行包 lead_pack（私有）<br/>- public_team_capabilities（8栏团能力声明卡）<br/>- decomposition_rules / cross_check_rules / synthesis_method<br/>- max_parallel_members / budget_split_policy]
    TBIND[团长层冻结数据绑定 bindings: FrozenBinding[]]
    TRULE[团长层规则出处链 team_rule_sources: RuleSource[]]
  end

  subgraph CHECK[knowmart 收单确定性核验]
    C1[1. 核验每个 PinnedMemberSlot 指向的 (knowbot_id, version, digest) 在 knowmart 真实存在且摘要一致]
    C2[2. 核验跨作者引用的成员专家均已开启 allow_team_composition 且处于有效状态]
    C3[3. 穿透核验团长层及所有成员层的 FrozenBinding 在 knowbase 许可状态]
  end

  TEAM_MAN --> CHECK
```

### 2.2 专家团在 `knowmart` 的公开声明：8 栏团能力卡 + 透明成员阵容表

与单个专家一致，专家团在 `knowmart` 详情页及 `expert-directory` 目录中采用统一的 **8 栏结构化能力声明卡（`PublicTeamCapability`）**，并额外附带一张只读的**《成员专家阵容与分工表（`PublicMemberRoster`）》**：

| 公开部分 | 包含字段 | 对用户与 AI 匹配器的作用 |
| :--- | :--- | :--- |
| **1. 团级 8 栏能力声明卡**<br/>（`PublicTeamCapability`） | ① 团的目标与综合交付结果<br/>② 适用范围（多维度/多标的边界）<br/>③ **协作拓扑与方法边界**（写明采用并行深潜、工序接力、红蓝对决或多标的横比中的哪一种，团长如何裁决冲突）<br/>④ 汇总数据前提<br/>⑤ 最终交付物与各成员子报告形式<br/>⑥ 不适用与不承诺<br/>⑦ 条件不足与某成员降级时的处理规则<br/>⑧ 适用/不适用示例 | 供用户和 `knowbench` 的 `FIND_EXPERT` 判断「这个问题该请单个专家，还是请这个专家团」 |
| **2. 透明成员阵容表**<br/>（`PublicMemberRoster`） | 由平台根据 `member_pins` 自动生成（团作者不可手改伪造）：<br/>- 槽位角色名（`role_title`）<br/>- 绑定的成员专家名称、确切版本号（`knowbot_id@version`）及详情页链接<br/>- 成员专家所属作者小店名称<br/>- 本团调用该成员的哪几项公开能力卡<br/>- 必选成员（`required=True`）还是按题可选成员（`required=False`）<br/>- 数据准备方式（`用户确认自动解析` vs `成员作者按题选数`） | 杜绝「挂羊头卖狗肉」的空壳专家团；让用户一眼看清团里每一位成员专家的来历、版本与单价构成 |

## 三、跨作者「组合授权（Composite License）」与定价分账模型

### 3.1 单个专家如何授权被别人组进专家团

当团作者甲想把作者乙在 `knowmart` 公开上架的专家 $E_B$ 编入自己的专家团时，必须遵循严格的**显式入团授权机制**：

1. **只用自己的专家成团（同作者自组团）**：
   - 若专家团的所有成员槽位均为团作者甲自己名下的专家，无需额外跨作者授权；该专家团可留在甲的小店「自用（`self`）」，也可在通过资质与数据许可审核后「公开（`public`）」上架。
2. **引用他人公开专家成团（跨作者组合团）**：
   - **自用专家不可被他人引用**：处于 `self`（自用）状态的专家只有作者本人可见，他人无法引用。
   - **公开专家须显式开启「允许入团（`allow_team_composition`）」**：作者乙在 `knowmart` 小店上架公开专家 $E_B$ 时，可勾选「允许其他作者将本专家编入专家团」，并设定该专家作为团成员被调用时的单次分成价（默认等于其单请价格，也可设入团优惠价）。
   - **入团授权按版本冻结**：一旦作者乙对 $E_B\text{@v2}$ 开启了允许入团，且团作者甲已将其编译进专家团 $T\text{@v1}$，该授权对 $T\text{@v1}$ 即形成版本级契约（后续下架规则见第四节）。

### 3.2 透明组合定价、去重抵扣与按实际激活分账

针对所有者关心的专家团费用问题，我们在 `knowmart` 交易层（本期标价、记成交订单，待商户号开通后接真实资金托管结算，守 `decisions.md` 139）设计**「明码分项标价 + 已购自动抵扣 + 可选成员按实际激活结算」**机制：

#### A. 专家团报价公式與「已购/自有自动免单」

假设专家团 $T$ 由团长（团作者甲）和 $M$ 个成员槽位组成，团作者甲设定的**团长编排与统稿费**为 $P_{\text{lead}}$，各成员槽位绑定的专家版本价格为 $P_m$。当用户 $U$ 请入该专家团时，系统自动计算用户 $U$ 应付的去重后价格：

$$P_{\text{effective}}(U) = P_{\text{lead}}(U) + \sum_{m=1}^{M} \delta(m, U) \cdot P_m$$

其中去重系数 $\delta(m, U)$ 严格遵循 `decisions.md` 第 134 条（「作者是本人、价格为零、请过这一版——免费可请，同一用户同一版只记一次成交」）：

- 若用户 $U$ **就是成员专家 $m$ 的作者本人**，则 $\delta(m, U) = 0$（自己请自己的专家免费）；
- 若用户 $U$ **此前已经在 `knowmart` 单独请过、或在其他专家团中成交过成员专家 $m$ 的这一确切版本（`knowbot_id@version`）**，则 $\delta(m, U) = 0$（**绝不让用户为同一个专家版本付两次钱**）；
- 否则 $\delta(m, U) = 1$。

在 `knowmart` 详情页与 `knowbench` 请专家确认框中，向用户清晰展示费用明细表：

> **示例明细**：  
> - 团长编排与统稿费（作者：甲的小店）：¥20.00  
> - 成员 1：财务分析与预测 `@v5`（作者：甲的小店）：~~¥15.00~~ **¥0.00（你已拥有此版本使用权）**  
> - 成员 2：半导体产业链景气度专家 `@v2`（作者：乙的小店，必选）：¥30.00  
> - 成员 3：财报排雷审视专家 `@v3`（作者：丙的小店，按题可选）：¥10.00（仅在任务激活该成员时计入）  
> **本次必付基础合计：¥50.00（含可选成员最高 ¥60.00）**

#### B. 成交记录与多作者分账规则

- **必选成员与团长**：在用户确认请入并启动委托时，为团长及所有 $\delta(m, U) = 1$ 的必选成员生成成交记录，并在 `knowbase` / `knowmart` 为用户 $U$ 记下对应专家版本的使用权（同一用户同一版本幂等只记一次）。
- **按题可选成员（`required=False`）**：若某可选成员在本次委托中被团长激活并完成了交回（`DELIVERED`），则补记该成员的成交与分成；若本次委托根本未激活该可选成员、或因该成员作者离线超时而被跳过（`SKIPPED_CARD`），则**不收取该可选成员的费用，也不记假成交**。

## 四、成员专家升版、下架与违规撤回的联动治理

由于专家团依赖多个成员专家，当某个成员专家的状态发生变化时，`knowmart` 必须有明确的确定性状态联动规则：

| 成员专家发生的事件 | 对已上架专家团 `T@v1` 的影响 | 对已请入用户与在跑委托的影响 | 团作者的后续操作 |
| :--- | :--- | :--- | :--- |
| **1. 成员专家发布了新版本**<br/>（如从 `E_B@v2` 升到 `E_B@v3`） | **`T@v1` 不受影响、不自动换版**，继续使用钉死的 `E_B@v2`（因 `E_B@v2` 清单不可变且仍存于库中） | 已请入与新请入 `T@v1` 的用户均继续稳定运行 `E_B@v2`，保证行为 100% 可复现 | `knowlab` 向团作者推送「成员有新版 `v3` 可用」提示；团作者若想升级，可在工作稿中切到 `v3` 重测并发布 `T@v2` |
| **2. 成员作者关闭「允许入团」或主动下架 `E_B@v2`（`delisted`）** | 1. 禁止任何**新孵化**的专家团再绑定 `E_B@v2`；<br/>2. 若 `E_B@v2` 是 `T@v1` 的**必选成员**，`T@v1` 在缓冲期后转入「待处理（暂停新买家请入）」，通知团作者替换成员发新版；若为**可选成员**，新委托中该槽位自动置为不可激活 | **已经请过 `T@v1` 的老用户及正在运行的委托照常跑完**（守数据拓扑第十一、十三节：正常下架不影响已有使用权与在跑任务） | 团作者在 `knowlab` 移除或替换该成员槽位，发布 `T@v2` 恢复公开销售 |
| **3. 成员专家绑定数据失效**<br/>（触发 `HOLD_REASONS`：`binding_gone` / `binding_not_shareable` 等） | `knowmart` 巡检发现某成员的 `FrozenBinding` 失效时：若为必选成员，**`T@v1` 立即连带转入「待处理（hold）」暂停在售**，并同时通知成员作者与团作者 | 在跑任务若申请不到该成员的 `knowbase` 运行授权，在定数据阶段如实停下报错，不绕过授权检查 | 待成员作者修复数据许可，或团作者更换成员发布 `T@v2` |
| **4. 成员专家因违规被平台强制下架（`taken_down`）** | **立即连带熔断**：凡包含该违规成员的专家团版本立即从市场撤下（转 `待处理` 或 `taken_down`），留存跨应用审计记录 | **连正在跑的专家团委托中涉及该违规成员的子任务也立即终止**，收回对应使用权 | 团作者必须剔除违规成员并重新过审发布新版 |

## 五、上架资质与驻场合规要求（`C-L4` / `C-L5`）

1. **类目与证照资质硬门槛（`C-L4`）**：
   - 专家团公开上架时，运营按团的综合服务内容核定二级类目（`category`）。
   - **资质不降级绕行**：如果某专业类目（如证券/期货投资咨询类）要求特定牌照资质，不仅**团作者的发布主体（`PublisherIn`）必须具备该类目有效证照（`LicenseIn`）**，团内被引用的所有公开成员专家也必须各自已通过对应类目的资质审核；严禁无资质作者通过「套壳组装」规避资质监管。
2. **禁词与禁止内容审核（`C-L5`）**：
   - `knowmart` 在接收 `knowbot-team-delivery/v1` 及上架审核时，对团名称、简介、8 栏团能力声明卡以及团长统稿规则统一执行 `FLAGGED_WORDS`（荐股、目标价、买入、卖出、稳赚、保本、收益承诺等）扫描与人工复核。

## 六、待所有者拍板确认的事项

1. **成员专家作者「主动下架」时对既有专家团的缓冲期策略**：
   - 当作者乙把自己的单个专家 $E_B\text{@v2}$ 主动下架（非违规）时，如果它正被团作者甲的专家团 $T\text{@v1}$ 引用为必选成员，有两种处理方式：
     - **方案甲（立即停新售，保在跑）**：$T\text{@v1}$ 立即停止接受新买家请入（老买家和在跑任务照旧），倒逼团作者甲尽快换人发 `T@v2`，最大程度尊重成员作者乙随时撤回公开供给的意愿；
     - **方案乙（给 7 天替换缓冲期）**：通知团作者甲后给 7 天缓冲期，期间甲可发新版切换，7 天后未切换再暂停 `T@v1` 新售。
   - 请确认采用**方案甲（立即停新售）**还是**方案乙（7 天缓冲期）**？
2. **专家团在「我的小店」与市场目录中的呈现位置**：
   - 建议在 `knowmart` 小店详情页与 `expert-directory` 中，将「专家团」与「单个专家」放在同一「专家」商品大类下展示，通过醒目的 **`【专家团 · N 位专家协同】`** 徽章与筛选开关区分，不另起第三种顶层商品大类（保持市场「专家、知识」两大商品的简洁结构）。请确认是否按此设计？
