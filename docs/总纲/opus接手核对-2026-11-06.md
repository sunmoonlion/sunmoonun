## 二、Luna 的开发有没有错

### 2.1 确认的缺陷：线上 knowlab「挑数据」失败

- #67（11-03）上线的 knowlab 后端 `b86eedfc` 含 `c8d9a70`（把选中资料的表格式带进孵化）。作者在工作稿「数据」栏挑资料时，`application/services/knowbot_library.py` 对每一份调 `KnowbaseLibrary.read_format`，请求 knowbase `/api/internal/v2/user-data/materials/{id}/versions/{n}/format`（`infrastructure/external/knowbase_library.py:52`）。
- 这条路由在 knowbase `ada6ac9`（`interfaces/endpoints/user_library_routes.py`），**没有上线**：线上 knowbase `e6822640` 只有 `/run-grants/{grant}/materials/{id}/format`。
- 所以线上只要挑一份资料，就收到 404，被译成 `material_not_found`「No such material」，整次挑选失败。knowlab 应用说明末节写过「待同批部署」，但 #67 只发了 knowlab。**代码没错，是发版漏了跨仓依赖。**
- 没在线上实测。修法：下一次发版带上 knowbase 后端（开发头已含 `ada6ac9`），或先单独补发 knowbase；发后用作者账号挑一份资料验。

### 2.2 核过、没发现问题的

| 处 | 结论 |
| --- | --- |
| K29 迁移 `20261106_0039` | 单链接 `0038`，`test_kernel_invariants.py` 文件名清单同步（`C-D6`、`C-D7`）；回填只按 `pack_source` 与正式测试用例绑定，混合项目保留；降级不删记录；浏览视图两处查询过滤 `knowlab-test` |
| 方法库与合规 | 应用代码里没有平台内置的财务方法正文（20 项候选只在测试夹具里）；方法读、绑定、发布都按 `owner_subject` 隔离，跨作者同 404（`C-L1`） |
| 声明选择 v4 | 网页明确发 `knowbench/expert-match/v4`；后端不带版本时默认 v1，旧客户端不受影响 |
| #83 取消时限 | 五个常量与 `run_turn` 默认值为 `None`，守卫在 `None` 时不计时；app-server WebSocket 心跳（20 秒）与连接超时保留 |
| Wind 客户端 | 外部调用 180 秒超时；密钥只进请求头，不进日志 |

审查范围：未上线的代码，加已上线里风险最高的几处（跨应用接口、迁移、合规、时限、外部调用）。没有逐行通读全部改动；要全量审查，可对未上线那批再做一次代码评审。
